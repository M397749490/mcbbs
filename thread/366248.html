计划简介与背景介绍
距Minecraft 1.8 发布已有一段时间。1.8加入了新的特性，比如：新的人物模型“Alex”和UUID系统。同时，材质的存储也发生了较大的变化。
因此，旧的皮肤链接形式无法满足新版本的要求，比如，难以自由选择人物模型，无法有效利用材质存储系统导致的多余请求等。
在这种情况下，本人草拟了Universal Skin API计划，希望提供一个新的，统一的，可扩展的解决方案。
任何对本计划有兴趣，希望做出贡献的人都欢迎留言。
本计划由以下三部分组成
Universal Skin API
计划：
定义一套用于获取皮肤/披风/人物模型等数据的RESTful API
定义相关返回数据结构及含义
目标：
提供一套统一的可扩展的API，并实现皮肤站与皮肤Mod的解耦合。
即，只要皮肤站和皮肤Mod均实现该API，即可配合使用。
目前进度：
草案已完成，但是需要完善
需求：
欢迎任何人提供关于本API的意见来帮助完善草案。
欢迎任何新点子。
Universal Skin Server
计划：
完成一个符合Universal Skin API的开源皮肤服务端，包括后端和前端，提供注册/上传/管理等功能。
目标：
使得人人都能架设属于自己的皮肤站
目前进度：
正在等待API完善。
已有一个基于Python的简陋实现可供测试。
需求：
需要前端设计师重写前端页面。
需要用不同语言实现后端，比如PHP。所以欢迎各种程序猿。
远期幻想（空想？）：
提高健壮性和安全性，使能够支撑大规模用户。
Universal Skin Mod
计划 & 目标：
实现一个符合Universal Skin API的开源皮肤MOD
目前进度：
正在等待API完善。
已有一皮肤Mod，支持1.7.10/1.8，等待API支持加入。皮肤模组链接
需求：
各种求测试QAQ

再请问下 cfg配置文件中 填写的root链接是否跟Github中的API说明一样
根地址

根地址是每个URL请求的开始部分，每个请求的URL均由 根地址与Endpoint连接而成，根地址也唯一地标识了一台服务器 所有请求都是不带参数的GET请求 假设一个服务器的根地址是

http://127.0.0.1:8000/skinserver/
获取玩家Profile的Endpoint是

/{玩家名}.json
那么，从该服务器获取玩家XiaoMing的皮肤的请求即为

http://127.0.0.1:8000/skinserver/XiaoMing.json
