JVM沙箱技术 - I - 反射重定向 - JDK 8

本人目前在做关于JVM沙箱的内容, 感觉可能会有其他人有需要, 于是便将此技术分享出来

本技术适用于
  • 需要重定向反射
  • 需要让远程代码操作部分服务器但是不允许完整操作 (因此不能使用docker的)
  • ....


注: 本项目的JDK 8版本使用Kotlin编写
要不是JDK 13没找到让kotlin访问jdk.internal的方法才不会去用java呢

项目仓库: GitHub
开源协议: GNU AFFERO GENERAL PUBLIC LICENSE version 3

本章只说出接管重点, 具体实现细节请自己看README&源代码

不要喷 Java & Kotlin 混用, src唯一的java文件是属于代码自动生成, jdk13目前未找到让kotlin访问jdk.internal.*的方法

没用mvn/gradle, 因为懒得用, 别吐槽

Step 0. 生成ReflectionFactory模型

参考 ApplicationStartup#makeModel
生成一个ReflectionFactory的模型, 至于为啥不直接继承ReflectionFactory, 因为
  1. private ReflectionFactory() {}

执行上述代码后, 我们可以得到一个 ReflectionFactoryModel.java, 如果不想让kotlin项目混入一个java文件, 可以选择使用IDEA直接将其转换为kotlin代码

Step 1. 准备一个Instrumentation对象

我们需要准备一个 Instrumentation 以实现更加底层的操作. 修改字节码

准备好你的 ASM + javaagent.jar

关于 Instrumentation 的传递可以参照 JvmAgent
  1. instrumentation = Thread.currentThread().threadGroup.let {
  2.     val count = it.activeCount()
  3.     val array = Array<Thread?>(count) { null }
  4.     it.enumerate(array)
  5.     return@let array
  6. }.let {
  7.     it.forEach { thread ->
  8.         if (thread == null) return@forEach
  9.         if (thread.name == "InstrumentationThread") {
  10.             if (thread is Supplier<*>) {
  11.                 return@let thread.get() as Instrumentation
  12.             }
  13.         }
  14.     }
  15.     error("Instrumentation not found! Please add -javaagent:JvmAgent.jar")
  16. }
复制代码


Step 2. 动态修改字节码

通过 Instrumentation 把所有 extends ReflectionFactoryModel 转成 extends sun.misc.ReflectionFactory


  2. unsafe.ensureClassInitialized(ClassNode::class.java) // Preload ASM
  3. instrumentation.addTransformer { loader, className, classBeingRedefined, protectionDomain, classfileBuffer ->
  4.     ClassReader(classfileBuffer).let { reader ->
  5.         ClassNode().also {
  6.             reader.accept(it, 0)
  7.         }
  8.     }.let {
  9.         // If the class is the model, ignore it
  10.         if (it.name == "io/github/karlatemp/jll/ReflectionFactoryModel")
  11.             return@addTransformer classfileBuffer
  12.         val writer = ClassWriter(0)
  13.         it.accept(
  14.             ClassRemapper(
  15.                 writer, SimpleRemapper(
  16.                     "io/github/karlatemp/jll/ReflectionFactoryModel",
  17.                     "sun/reflect/ReflectionFactory"
  18.                 )
  19.             )
  20.         )
  21.         writer
  22.     }.toByteArray()
  23. }
复制代码


Step 3. 编写接管

好, 我们随便写个类继承ReflectionFactoryModel
  1. class MyCustomReflectionFactory : ReflectionFactoryModel() {}
复制代码


然后alloc我们自己的RF, 并替换JVM内部的RF

  2. val customReflectionFactory = unsafe.allocateInstance(MyCustomReflectionFactory::class.java)
  3. if(customReflectionFactory !is ReflectionFactory) {
  4.     error("Oops. This is not working!")
  5. }
  6. instrumentation.allLoadedClasses.forEach {
  7.     kotlin.runCatching {
  8.         it.declaredFields.forEach { field ->
  9.             if (Modifier.isStatic(field.modifiers)) {
  10.                 if (field.type == ReflectionFactory::class.java) {
  11.                     unsafe.putObject(unsafe.staticFieldBase(field), unsafe.staticFieldOffset(field), customReflectionFactory)
  12.                 }
  13.             }
  14.         }
  15.     }
  16. }
复制代码

并且清空JVM反射数据缓存
  1. val classReflectionDataOffset = unsafe.objectFieldOffset(Class::class.java.getDeclaredField("reflectionData"))
  2. instrumentation.allLoadedClasses.forEach {
  3.     unsafe.putObjectVolatile(it, classReflectionDataOffset, null)
  4. }
复制代码

然后我们把MyCustomReflectionFactory随便改改，以确认他是否正常工作

  1. // Don't use object, it is not support
  2. class MyCustomReflectionFactory private constructor() : ReflectionFactoryModel() {
  3.     override fun newMethodAccessor(var0: Method): MethodAccessor {
  4.         println(var0)
  5.         return super.newMethodAccessor(var0)
  6.     }
  7. }
复制代码


然后运行

  1. Runnable::class.java.getDeclaredMethod("run").invoke(Runnable {
  2.     println("Hello")
  3. })
复制代码


如果你能看到以下输出，恭喜，你已经成功接管反射了
