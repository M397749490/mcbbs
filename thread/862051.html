标题: Forge EnergyStorage的迷思
目前正在开发一个发电机方块，
如果要增加能量的话，我发现用receiveEnergy()是可行的，
但是在这情况下，那就必须把canReceive调成true，导致能量能从外部输入进来；
而且，就算我把canReceive与canExtract调成true，在方块中的能量不会输出；
如果不想能量从外部输入进来，只想把能量输出的话，该怎么做？
现在有一个EnergyStorage，如下:

楼主知不知道有一种叫“装饰器”的设计模式（又叫修饰模式，英文 Decorator Pattern）？
外部的方块是不知道你的 IEnergyStorage 的具体实现的，它们只能通过你的 TileEntity.getCapability 拿到一个 IEnergyStorage 的实例。换言之，如果你不想接受能量，那么其他方块拿到的应当是一个经过包装，只能输出不能输入的 IEnergyStorage：
  1. // 在你的 TileEntity 里覆写：
  2. @Override
  3. public <T> T getCapability(Capability<T> cap, EnumFacing facing) {
  4.   if (cap == CapabilityEnergy.ENERGY) {
  5.     return CapabilityEnergy.ENERGY.cast(new IEnergyStorage {
  6.       @Override
  7.       public int receiveEnergy(int maxReceive, boolean simulate) {
  8.         return 0; // 拒绝接受能量，无条件返回 0 代表没有能量被接受
  9.       }
  10.       @Override
  11.       public int extractEnergy(int maxReceive, boolean simulate) {
  12.         // energy 代表你的 BlockEnergyStorage 实例字段。
  13.         // 这里因为我们允许能量输出，所以我们把它的实现代理给真正的 BlockEnergyStorage。
  14.         return this.energy.extractEnergy(maxReceive, simulate);
  15.       }
  16.       @Override
  17.       public int getEnergyStored() {
  18.         return this.energy.getEnergyStored(); // 同 extractEnergy
  19.       }
  20.       @Override
  21.       public int getMaxEnergyStored(int maxReceive, boolean simulate) {
  22.         return this.energy.getMaxEnergyStored(); // 同 extractEnergy
  23.       }
  24.       @Override
  25.       public boolean canExtract() {
  26.         return this.energy.canExtract(); // 同 extractEnergy，也可以考虑无条件返回 true
  27.       }
  28.       @Override
  29.       public boolean canReceive() {
  30.         return false; // 同 receiveEnergy，拒绝接受能量
  31.       }
  32.     });
  33.   }
  34.   return super.getCapability(cap, facing);
  35. }
