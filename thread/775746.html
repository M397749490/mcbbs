改成1G后可以了，想问一下你们是怎么研究mdk里各个文件的是干什么用的？

那些文件基本都是现有工具的标准。如果之前熟悉 Java 开发中常用的工具的话，这些文件一眼就应该能看出来用途。

build.gradle 和 gradle.properties 都隶属于 Gradle，一个最初针对 Java 的自动化构建工具。其中 build.gradle 是主构建脚本，gradle.properties 则相当于是一个含有各种参数的配置文件一样的存在（请无视不准确的描述，这里的描述以简单易懂优先）

gradle 文件夹、gradlew、gradlew.bat 三个文件则是给没有预先安装 Gradle 的电脑准备的 Wrapper。可以看作是一种启动器吧... 装了 Gradle 的电脑就不需要用这个 Wrapper（比如笔者就是经常直接删掉的）

.gitignore 是默认让 git 忽略指定文件的东西。git 是一个分布式版本控制工具，在软件开发中用作版本追踪工具（打个比方，有一天发现软件出问题了，版本控制工具可以让你“坐时光机”（读作 `git checkout <commit hash>`）回去找到是什么地方开始出问题的），同时分布式的特性意味着多人协同开发更加方便。

LICENSE-new.txt、Paulscode IBXM Library License.txt、Paulscode SoundSystem CodecIBXM License.txt 三个是版权声明。LICENSE-new.txt 的正文中，除了开头的解释，剩下的都是 GNU 宽通用公共许可证第 2.1 版（的全部内容）。至于那两个 Paulscode 开头的文件，是因为直接打包了 Paulscode 的 IBXM 相关库。

CREDITS-fml.txt 和 MinecraftForge-Credits.txt 是鸣谢列表。

名字形如 forge-1.12.2-14.23.1.2598-changelog.txt 的是 Forge 自己的更新日志。如果能读懂的话，就能知道 Forge 都更新了什么。

README.txt 就是“用 MDK 前先把我，README.txt，这个文档认真读完！”。README 文件是很多程序发布时的惯例。

src 文件夹放源码。这是一种常见的 Java 项目的目录结构。

eclipse 文件夹，（如果没记错的话）是在开发环境（读作 IDE）中运行 Minecraft 时，Minecraft 的根目录。（想想平时玩 Minecraft 的根目录是 .minecraft。这个目录其实是可以自行指定的。）通常只有在用 Eclipse 的时候有效果。

以上内容基于 forge-1.12.2-14.23.1.2598-mdk.zip 的解压结果撰写。
