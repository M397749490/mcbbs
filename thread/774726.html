入门
在此页面,我们将会一步一步向您解释如何在Sponge服务端配置并使用GriefPrevention。请确认您是在 Sponge 服务端使用GriefPrevention，而不是在一个 Bukkit 服务端。

入门指南
需求
  • 一个权限管理插件(我们建议您使用 LuckPerms)。
  • 一个最新 版本 的 Sponge 服务端。

安装
请从我们 官方下载页面 下载最新版本的GriefPrevention Jar包。请下载与您的Minecraft版本相对应的版本，并且保持它处于最新！下载完成后，请将GriefPrevention-Jar包放置在您的服务器的mods文件夹下。

现在您可以启动一次您的服务器来让GriefPrevention生成所有的配置文件，您可以输入 /sponge plugins来检查GriefPrevention是否被成功的加载。接下来，您就可以关闭服务器并开始配置您的服务器了。

配置
小贴士: 仍然有一小部分配置选项需要通过您的权限管理系统进行配置，您可以在 高级选项 页了解到更多的信息.

所有的配置文件都可以在服务器的 config/griefprevention 文件夹下找到。

  1. config/
  2. └── griefprevention/
  3.     ├── GlobalPlayerData/
  4.     ├── Logs/
  5.     ├── worlds/
  6.     │   ├── minecraft/
  7.     │   │   ├── overworld/
  8.     │   │   │   ├── world/

  10.     │   │   │   │   └── world.conf
  11.     │   │   │   └── dimension.conf
  12.     │   │   └── other...

复制代码

您可以在 配置文件 中更改一些设置。这些文件都有详细的注释，十分清晰的描述的每个选项的作用。此外这里还有三种类型的配置方式:

  • Global（全球通用的配置）
  • Dimension（指定维度的配置）
  • World（指定世界的配置）
Global 配置文件能够影响服务器加载的所有世界和维度。这是配置文件的默认级别。
Dimension 配置文件用来管理某个特定的维度或者世界组（译者注：如所有的地狱维度、所有的末地维度）。在此配置文件中修改的设置将会覆盖 Global 配置文件中相关的设置。
World 配置文件仅能被用来修改指定的世界。 World 配置文件的设置内容将会覆盖在 dimension 和 global 文件下配置过的内容。为了让指定维度和世界启用您想要的设置，您需要将相关配置文件中的 config-enabled 节点值设置为 true 。

领地认领的数据可以在所在维度的 Claim 文件夹下找到，例如所有的主世界的领地认领信息都被保存在 config/griefprevention/worlds/minecraft/overworld/world/ClaimData文件里。

默认情况下，用户的领地数据会被放置在GriefPrevention配置文件根目录的 GlobalPlayerData 文件夹下。
如果您将 global.conf文件中的 use-global-storage 节点设置为 false，那么GriefPrevention将会根据不同的维度分别存储这些玩家的领地数据，如果这么做的话，GriefPrevention将会分别计算玩家在各个维度中随游戏时间增加所带来的领地块上限的增长。

权限
在您正确的安装完GriefPrevention之后，您需要给予您的玩家们认领领地的权限，因为默认情况下，玩家没有这个权限。
默认权限组所需要的基础权限都可以通过 griefprevention.user 这一个节点来赋予玩家（译者注：如果您使用LuckPerm，那么您只需要输入/lp group default permission set griefprevention.user）.对于基础的管理员权限，您可以给管理员分配 griefprevention.admin 权限。

如果您想要更多的微调权限，您可以在 这里 找到所有详细权限，如果您想查看所有指令权限和使用方法，您可以在这 这里 找到。

您可以使用下面的指令来应用以上操作：

/lp group <defaultgroup> permission set griefprevention.user
对于 <defaultgroup> 请替换为您的默认权限组，如果您还没有设置过权限组，您可以用 default替换这里。




创建领地
GriefPrevention是一款提供了自助区域保护功能的插件，为您提供了更多的选项来微调玩家（或者用户组）与门、箱子甚至建筑权限的管理方法！下面是一些领地管理的基本指令，想了解更多的关于管理选项（Flag）的微调操作方法，请查阅管理选项（Flags）页面.

所有用到的示例都是在写这篇文件的时候脑海中想到的。

领地的创建
我们提供了三种领地创建方式：管理员类型、城镇类型和基本类型，每一种类型又均可切换为2D圈地模式和3D圈地模式。
您可以使用 /adminclaims, /townclaims 和 /basicclaims 指令来在这三种类型中切换。
管理员类型的领地在范围上没有大小限制，并且有与普通玩家领地管理选项(Flag) 所不同的设置列表。
城镇类型的领地同样可以通过普通玩家建立，并且支持在城镇类型的领地中创建基础领地。
3D模式和2D模式作为两种不同的圈地模式，被用来定义领地的形状。
您可以通过 /cuboidclaims 指令在两种模式见切换:

  • 2D模式下：领地高度将会覆盖你所标记位置向下拓展5格，向上延伸到256格高度。
  • 3D模式下：领地高度将取决于你两次标记的位置（译者注：即两次右键标记方块所形成的长方体的高度）。
对于一个认领整个区块的玩家而言，他需要拥有相关权限并且拥有足够的领地块上限，这些设置可以在 设置中进行修改。

金铲子
译者注：圈地工具可以在配置文件中修改
您可以通过一个 金铲子 来创建领地(可以在配准文件中修改为其他圈地工具)，也可以通过它来重新定义领地的大小和位置。您也可也使用/adminclaims, /townclaims 和 /basicclaims指令来切换您的圈地模式和圈地类型 ！

  • 创建一个领地: 右键单击两个点，新的领地将会被定义为这两个点所在对角的矩形面积。
  • 重定义领地大小: 对着现存的领地右键一次，即可看到领地的范围标记，然后右键其中一个标记点（译者注：必须为所在矩形的对角之一），然后再右键一个新的位置来移动矩对角，从而将领地重新定义新的大小。
  • 取消正在进行的操作: 切换至除金铲子以外的任何道具（包括空手）即可取消所有仍未完成的操作行为。
铲子也可以用来给领地细分出子领地.您可以使用 /claimsubdivide 指令来切换模式。三种主要的圈地类型都支持划分子领地(细分) - 城镇类型，管理员类型和基础类型。

木棍
译者注：领地查询工具可以在配置文件中修改
基础工具，你可以使用木棍来查看所指领地的位置,也可以通过它来查看所指领地的基本信息。

  • 右键单击一个领地来查看这个领地的详细位置信息
  • 潜行状态下右键单击来查看半径100格子范围内的所有领地以及他们的领地信息
  • 左键单击来隐藏领地范围标记

领地设定
请输入 /claiminfo 来获取您所在领地的基本信息。将鼠标悬停在对应文字上可以显示更多的领地信息，通过单击对应的文字可以之久修改这些参数而不需要输入任何指令。 您仍然可以通过指令来设置领地的名字、问候语和道别语。

允许其他玩家通过你的领地
您可也通过信任指令来授予指定玩家基础的领地使用权限，例如，你可以使用 /trust Tollainmear 指令来给予一个名字叫做Tollainmear 的玩家基础的建造权限。



权限
本页Wiki仅适用于插件版本 2.3.0.207 以上, 对于旧版本请参考这里

如果你想快速上手，这里有两个基础的权限 griefprevention.user 给玩家 griefprevention.admin 给管理员 很显然这些权限相当简单，如果你需要更细化的配置，请继续阅读下列权限

强烈推荐权限插件 LuckPerms, 插件也可以搭配其它权限插件使用，例如 PermissionsEX.

重要提示
不要给自己 * 或者 griefprevention.* 权限，这可能会使插件出故障

管理员只应该拥有 griefprevention.admin 以及 griefprevention.user 权限

如果你修改了管理员权限 请务必输入 /gpreload 来重载插件

领地

别名: bc

别名: buyclaim

别名: sellclaim
以服务器货币卖出你的领地块上限。若服务器没有经济插件则此指令失效（译者注：如果配置文件中关闭了领地块买卖功能，此指令也失效）。

/inherit

/claimlist [<player> [world]]

别名: claimsetspawn
将你的当前位置设置为领地的传送点。
/claimspawn
别名: claimspawn
将你传送到指定领地的可用传送点。
/claimsubdivide
别名: subdivideclaims, sc
切换到细分模式，用于细分你的领地。
/claimtransfer [player]

配置
GriefPrevention的默认配置提供了一些拓展功能帮助您拓展你的服务器规则。下面详细描述了所有的默认变量来方便您理解和编辑。

?? 某些选项可能会导致数据不可逆的修改。请确保您已经阅读了生成的global.conf文件中注释在变量旁边的文本。所有的待修改数据都应该在备份后操作 ??

插件依赖
某些需要花费游戏币的变量 (例如城镇的' creation-cost) 需要 一个经济插件。然而, MCClans 为可选的依赖，只有您在需要城镇功能的时候需要加载。 我们 不 强制您使用GriefPrevention的城镇插件功能。

默认的领地管理标签(Flag)
所有的领地类型都可以自定义其独自的默认管理标签（Flag）。目前，GriefPrevention支持给默认类型丨管理员类型丨城镇类型丨的领地或野外分配其默认的管理标签。请检查您global.conf文件中的每一条默认管理标签（Flag）都配置正确。

模块化配置
GriefPrevention 允许进行模块化的配置。在默认生成的配置文件中，所有模块都被启用了。 禁用模块将使其所有管理标签（Flag）不可用。 只有在你不打算使用GriefPrevention管理上述管理标签的时候再禁用它们。 您可以选择禁用以下内容：
  • 方块修改相关模块: block-break, block-place
  • 碰触相关模块: collide-block, collide-entity
  • 指令相关模块: command-execute, command-execute-pvp
  • 动作相关模块: enter-claim, exit-claim
  • 生物相关模块: entity-damage, entity-riding, entity-spawn, entity-teleport-from, entity-teleport-to
  • 爆炸相关模块: explosion, explosion-surface
  • 火焰蔓延相关模块: fire-spread
  • 交互相关模块: interact-block-primary, interact-block-secondary, interact-entity-primary, interact-entity-secondary, interact-inventory, interact-inventory-click, interact-item-primary, interact-item-secondary
  • 物品相关模块: item-drop, item-pickup, item-spawn, item-use
  • 流体相关模块: liquid-flow
  • 传送门相关模块: portal-use
  • 弹射物相关模块: projectile-impact-block, projectile-impact-entity
