如题,版本:Java 1.13.2需求：
  • 雪球扔出去后对接触到的实体给予发光buff
  • 且不要把buff错误地给予投出雪球的实体
  • 要允许多个雪球同时存在并能正确将buff给予对应实体

  • 大体就是这样,用CB实现
  • 尽量不要带计分板(实在不行有也可以)
  • 要流畅点

这个问题主要的难点是过滤投出雪球的玩家，因此我们可以用一个记分板tick（dummy）来记录雪球存在的时间，因为雪球飞行到目标有一定时间，那么只要让tick大于一定阈值的雪球执行execute+effect给距离近的玩家就行了。这里以3为例（0.15秒）。发光什么的效果或是时长可以自定义，只需要修改effect命令。
start.mcfunction（初始化）
  1. scoreboard objectives add tick dummy "雪球存在的gt数"
复制代码

effect_snowball.mcfunction（包含于tick.json中，即每gt高速执行）
  1. scoreboard players add @e[type=snowball] tick 1
  2. #给雪球加分
  3. execute as @e[type=snowball,scores={tick=5..}] at @s run effect give @e[distance=..2,sort=nearest,limit=1,type=!snowball] glowing 10
  4. #让tick大于5的雪球给予1格内最近的一只生物（要过滤掉雪球本身）发光效果10秒，当然你嫌麻烦的话也可以改成@p[distance=..2]也就是只对玩家生效
复制代码

这里只是提供一个思路，算法也很粗糙也有不少BUG比如把雪球丢到很高的地方再自己接住就不符合要求了，实际应用请谨慎。
PS：亲测tick阈值最低值为3，低于3会对雪球投掷者生效
======分割线======

刚刚又想到一种新的算法，让雪球探测自己是不是离开了玩家，离开玩家（即投掷者）一定距离后给自己添加一个标签drow，再让带有drow标签的雪球去执行上面的execute+effect。同时这个方法不需要计分板。简单修改一下：
effect_snowball.mcfunction（包含于tick.json中/每gt高速执行）
  1. execute as @e[type=snowball] at @s unless entity @p[distance=..2.5] run tag @s add drow
  2. #雪球探测到自己离开玩家2.5格远后贴上标签drow
  3. execute as @e[type=snowball,tag=drow] at @s run effect give @e[distance=..2.5,sort=nearest,limit=1,type=!snowball] glowing 10
  4. #把上面的execute+effect修改一下执行对象筛选器就可以了
  5. #PS：生效对象的distance要和雪球探测玩家的distance相同，不然会误触发投掷者玩家。
  6. #而且distance的值要把握好，太低了不容易检测生效对象，太高了会导致密集玩家时产生BUG。个人认为2.5比较合适
