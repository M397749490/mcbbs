插件简介:


Description In paintball 2 teams compete against each other to bombard each other with snowballs in an arena. If a player is hit, he automatically leaves the arena and has to wait in the paintball lobby for the next paintball match. In the paintball lobby you will meet all paintball players, choose your team and wait for enough players, or for the end of the last match. If all terms are met, the countdown starts, which heralds the next match.

Basic-FeaturesPaintball has many features and is constantly expanding. And there are more and more features added, which have not much to do with the classic paintball game. But do not panic: According to your personal preferences you can modify most things and disable various fun extras in the config.yml in the paintball folder. This paintball plugin has many Features, too many to explain them all here.
No client or server modifications or extra plugins required!

  • Most stuff is configurable!
  • Multiple spawn points for each team (Red, Blue and Spectator), which change randomly on each match and makes matches more diverse.
  • Only four commands and your arena is ready and added to the automatic arena rotation!
  • Mechanism to strict seperate suvival and paintball and to prevent "cheating" in and with paintball.
  • Integrated economy, shop and rank system.
  • Various statistics: examples are points, cash, kills, deaths, hits, teamattacks, victories and defeats for each player, each arena and as a whole.
  • Many options to customize paintball on your server and according to your wishes. (Examples are customizeable: life per match, number of balls, points and cash per action, en- and disabling of certain features)
    Easy integration on every survival server! Our main target is to keep this plugin easily integratable on any standard survival server without disturbing the survival feeling. Therefore, much emphasis is placed on, for example, that paintball has no bugs that can be used to swindle items, and there are also more specific features, such as colored names over the head, that could easily be at odds with other typical plugins, which are waived or only offered as an option.

    Here you got some sort of overview, what actions are taken to prevent players doing nasty stuff while playing paintball and to protect the survival-part of the server:

    People with the paintball.admin permissions-node can bypass some of them.

    • Prevent commands that are not related to paintball.
    • Prevent breaking and placing of blocks.
    • Prevent dropping and picking up items, or dropping the armor.
    • Turned off damage and starvation.
    • On lobby join: Saves location and prevents joining in creative gamemode and with not-emptied inventory. Warns the player, so he does not automatically loose his/her inventroy.
    • On lobby leave: Inventory clearing and back-teleportation to saved location.
    • Many things can be disabled, if they create problems with your other plugins.
    • Grenade-Eggs-Explosion does no damage to blocks.
    • 1 command ("/pb") instead of many seperate commands ( "/pb red" is not as pretty as only "/red", but way more compatible to plugins, which maybe already uses this command.)


插件权限及指令：


用户指令
指令简介权限
/pb help打开帮助列表- paintball.general
/pb lobby进入游戏大厅
/pb blue加入蓝队 (*)
/pb red加入红队(*)
/pb random随机选择团队 (*)
/pb spec去围观(*)（注：坑爹呢）
/pb leave离开目前的队伍，如果你没有加入队伍，则会离开大厅！
/pb toggle切换一些彩弹消息和关闭 (例如: killfeed)
/pb shop [id]购买彩弹弹药！（需要彩弹币）- paintball.shop.not<id> 禁止购买某些物品
/pb stats显示你的统计
/pb rank显示你的彩弹排名
/pb top显示彩弹排名前10名 (according to points)
/pb cash查看你的彩弹币


(*) 这个代表如果你没有加入大厅，你会自动加入！

管理员指令
指令简介权限
/pb admin管理员帮助- paintball.admin
/pb admin reload重载插件并且T出所有在大厅里面的人！
/pb admin softreloadReloads the plugin after the current match is finished
/pb disableToggle whether new matches are allowed or not
/pb admin lobby spawn创建一个大厅重生点
/pb admin lobby remove删除一个大厅重生点
/pb admin next <arena>Tries to force the next arena
/pb admin cash <player> [amount]显示选手的排名[gives him money, negative values possible]
/pb admin rank <player> [amount]Displays the players rank [gives him the points, negative values possible]
/pb admin reset <all/player> [value]Resets all / all the players stats / some specific stats of the player
/pb admin helmet <blue/red/spec>Changes the helmet of a team to the item you are holding in hand


竞技场的管理员指令（重头戏来了）
指令简介权限
/pb arena显示帮助菜单- paintball.arena
/pb arena <name>创建一个新的竞技场
/pb arena <name> blue创建蓝队出生点
/pb arena <name> red创建红队出生点
/pb arena <name> spec创建一个观众（围观的）的出生点
/pb arena <name> remove删除一个竞技场
/pb arena <name> delblue删除蓝队出生点
/pb arena <name> delred删除红队出生点
/pb arena <name> delspec删除观众出生点
/pb arena <name> size <number>Define the size-category of the arena (Not used yet)
/pb arena info <name>Get some information on the arena
/pb arena list查看竞技场列表

更新日志和已知BUG：

更新日志：
__ (v1.0.7 Pre) __

  • Added ability to use translations.
  • Fixed teleport attempt while being in a vehicle.
  • Added ability to use admin cash and points commands in console.
  • Changed some small things with chat.
  • Using new AsyncChatEvent and different entity spawning (craftbukkit v1.3.1 R1)
  • Fixed lobby spawn rotation.
  • Added ability to use the plugin without permission plugins. (no-perm-mode)
  • Added ability to enable damage in matches and handles deaths like being dead (paintball-death, not minecraft-death)
    __ (v1.0.6) __
  • Added many checks on lobby-join to prevent many possible ways of cheating on a survival server. (Health, Food, etc.).
  • Checks (player recieving hint, that he should change something before joining the lobby) can be disabled in the config (This means ONLY the hint for the player. Inventories are cleard anyway and health, etc. is restored with and without this setting.)
  • Bug-Fix, if players hit each other at the same time (1/20 sec.): checks now if target is already dead and if match is already over.
  • DeathEvent: Then a player dies (for example by kill-command from outside the lobby), he leaves the lobby and the match, without interupting it and drops are removed (Wool-block and balls etc.)
  • Option, to save the inventories of the players. But if the player dies (for example by kill-command), he will not get it back and is not teleported back to the saved location.
  • Changed some code, like chat colors (so if you find anywhere "plugin.red" report it please).
  • Some changes with metrics graph settings. Moved the metrics configuration into the paintball-folder (metrics.yml). So everyone knows, it is related to the plugin Paintball and doesn't have to wonder why there is a metrics folder ..
  • Changed some stuff with chat colors, so it should work now for most chat-plugins by only coloring the message.
  • "only random" and "auto random" mode, which is loaded from config settings, but can changed in game via /pb admin random (until the setting is reloaded from config be reloading/startiing the plugin/server).
  • Changed the amount of items in "infinite mode" to 10. Maybe it's less "laggy" now, when it resotres the last shot ball/extra.
  • Decimals for hitquote and KD in the stats added.
  • REMAINING: The plugin "ForceField" seems to create some error when grenades / airstrikes. (Probably an bug with ForceField?)
    __ (v1.0.5) __
  • Added ability to use some admin commands also in the console (next, reload, softreload, disable).
  • Added min. players (at least 2).
  • Added max. players (at least 2).
  • Added overview on waiting players in the lobby on "match-ready"-check.
  • Break and place event are finally cancelled in the lobby and match.
  • Added some more "security" bypasses for players with the paintball.admin node
  • Some other fixes. (for ex. probably the "AbstractCollection"-Error)
  • Added some metrics custom data.
  • REMAINING: Chat-feature is not yet improved.
  • REMAINING: The plugin "ForceField" seems to create some error when grenades / airstrikes explode.
  • REMAINING: Testing.. :(

  • Fixed "player-copying" bug.
  • Fixed some listname bugs.
  • Fixed a bug in the helmet-command.
  • REMAINING: Colored chat does not work the way it should :( Better disable the chatcolor-feature in the config.yml
    __ (v1.0.4Pre) __

  • Fixed the "same listname" bug (it should now be less probable at least).

    已知BUG：
    Pest ControlIf you find some, let us know! We hate creepy-crawlies! :D

    • The plugin "ForceField" has some problems with the explosions of this plugins grenades and airstrikes and throws some error (Mostly has to do something this the "ForceField"-Plugin, but i am not sure, as I can't take a look at it's code..

    • Clones of the player are created at the location from where he joined the lobby, if he disconnects while being in the lobby. [probably found some workaround/fix for this, but this is not yet implemented] https://bukkit.atlassian.net/browse/BUKKIT-2298

    • If an arena is in a different world then the lobby, then player will get invisible until they relog. https://bukkit.atlassian.net/browse/BUKKIT-2199
    Hint: If you rename your world, then it is very likely, that the saved locations (lobby and arena spawns) are messed up in this world. You will need to reset these spawn points then.

    Hint: If the balls seem to do not hit it's very likely that the world/server the arena is in does not have pvp enabled (set to true). It needs to have pvp=true in this world to be able to detect the ball hits.

    Hint: If you have some problem/ bug you can always look into the config.yml if it is caused by a feature, that can be disabled.

    Because the plugin is rather new and there are still some issues existing, I recommend you to come around here daily to do not miss any new version with some new and important fixes!


    Some info on how to report a bug:Create a ticket (I like tickets :D ) or leave a comment (in english or german language only please) at this page or both.
    Please take care to choose the right category on ticket creation, so we don't have the effort to change it on our own.
    IMPORTANT:
    Supply a detailed description about: when the bug occurs, under which circumstances, errors on server start, errors then bug occurs, plugin list, configurations, versions of plugin, version of bukkit, more logs, screenshots, videos, etc etc etc .. ..
    The more information you provide, the better are the chances to get the bug fixed early.

    Some info on how to help us even more:

    • Check the already existing tickets and help us finding a bug with additional not yet known information (Besides: To duplicate a post is way better then to not report something..)

    • Check the existing tickets, if some bug is already fixed/ not occuring anymore in your opinion. We sometimes let tickets opend, until the fix is approved by someone for example by the ticket creator.. (so please check out at least your tickets regularly)
