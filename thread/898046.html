这东西其实很早前我就在使用了，当时懒得写使用方法就没发出来，最近有点无聊想想还是写出来吧qwq（比map好用）。

要使用Metadata，我们需要用到下面的类
Metadatable：通过doc我们可以看到有很多类实现了它（有Player等各种实体，也有Block），而Metadata的原意也是希望用这个替代map
MetadataValue：可以通过Metadatable的getMetadata方法获取。在为Metadatable添加MetadataValue时一般是用FixedMetadataValue类

使用方法：
先获取对象的MetadataValue：metadatable.getMetadata("key")，如果之前没设置过MetadataValue，还需要先使用setMetadata设置MetadataValue，如：
  1. player.setMetadata("键（类似map）", new FixedMetadataValue(plugin, 要储存的数据));
复制代码

使用getMetadata后获取到的是一个List（并不知道有什么用，是区分不同插件的？希望有大佬补充），我们使用list.get(0)来获取单个元素（MetadataValue），然后用MetadataValue的value()方法获取之前加入的数据，就像这样：
  1. Object data = player.getMetadata("key").get(0).value();
复制代码

由于获取到的对象是Object类型，还需要通过类型转换才能使用

有时要储存的数据可能比较多，所以我一般是直接在MetadataValue里塞Map（直接用Metadatable的不同键也可以）
这是我的某插件使用的代码：
  1. //为了便于区分，一个插件我只使用一个键，所以此方法直接返回保存的数据
  2. public static Map<String, Object> getMetadata(Metadatable metadatable) {
  3.         checkMetadata(metadatable);
  4.         //获取数据
  5.         Object value = metadatable.getMetadata(KEY).get(0).value();
  6.         //类型判断，以进行安全的类型转换
  7.         if(value instanceof Map) {
  8.                 return (Map<String, Object>) value;
  9.         }
  10.         
  11.         return null;
  12. }

  14. //检查Metadata是否存在，不存在则创建（值为一个空的Map）
  15. public static boolean checkMetadata(Metadatable metadatable) {
  16.         if(metadatable.hasMetadata(KEY)) {
  17.                 return true;
  18.         }
  19.         metadatable.setMetadata(KEY, new FixedMetadataValue(plugin, new HashMap<String, Object>()));
  20.         return false;
  21. }

  23. //这是玩家的pvp状态，可以看到使用Metadata储存，代码简单了很多
  24. public static boolean isPvping(Map<String, Object> metadata) {
  25.         if(!metadata.containsKey("pvp")) {
  26.                 metadata.put("pvp", false);
  27.         }
  28.         return (boolean) metadata.get("pvp");
  29. }
  30.         
  31. public static void setPvping(Map<String, Object> metadata, boolean isPvping) {
  32.         metadata.put("pvp", isPvping);
  33. }
复制代码


注意：Metadata在服务器关闭后就会消失，要保存还需要另写代码，但是它的方便之处在于数据依附的对象销毁后它也就销毁了，所以不像维护外部map那么麻烦（玩家退出重进数据还在）
