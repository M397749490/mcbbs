作者: 382792221    时间: 2020-2-4 10:05
这个和cogfig.yml下的mirrors那一栏有关
你可以设置该世界的用户或者权限组是否和world的通用。

mirrors:
        # Worlds listed here have their settings mirrored in their children.（这里列出的世界设定会反映到它的子世界上）
        # The first element 'world' is the main worlds name, and is the parent world.（第一个元素“world”是主世界，即父世界）
        # subsequent elements 'world_nether' and 'world_the_end' are worlds which will use（随后的地狱和末地会使用--        # the same user/groups files as the parent. --与“world”相同的user和group）
        # the element 'all_unnamed_worlds' specifies all worlds that aren't listed, and automatically mirrors them to it's parent.(元素“all_unnamed_worlds”指定所有未列出的世界，并自动将它们镜像到其父世界。)
        # Each child world can be configured to mirror the 'groups', 'users' or both files from its parent.（每一个子世界都可以被配置成镜像其父世界的user和groups）
        world:
          world_nether:
          - users
          - groups
          world_the_end:
          - users
          - groups
          all_unnamed_worlds:
          - users
          - groups

下面的是附带的一些例子，下面两个紫色的就是爹（父世界），其下面的是儿子（子世界）
#  world2:      (World2 would have it's own set of user and groups files)（world2有它自己的user和groups文件及其相关设定）
    #    world3:
    #    - users    (World3 would use the users.yml from world2, but it's own groups.yml)（world3会使用world2的users.yml但是有其自己的group.yml）
    #    world4:
    #    - groups   (World4 would use the groups.yml from world2, but it's own users.yml)（world4会使用world2的groups.yml，但是有自己的users.yml）
#  world5:
    #    - world6   (this would cause world6 to mirror both files from world5) (这样阔以让world6镜像world5的users.yml和groups.yml)

5楼非常清楚的解释了为什么世予的答案可以是正确的
    因为在镜像配置文件内，在world元素下有all_unnamed_worlds:
    这导致了默认的世界与多世界添加的任何世界(除了名为world2,3的世界)
    均会使用(即读取与修改)world下的数据目录，包括user和groups
    这就直接实现了所谓镜像的功能，在我看来，这还是有点精妙的

    而上面的world2,3，若存在相应的世界，则会在.../GroupManager/worlds下新建一个名为world2,3的文件夹
    他们与world文件夹(.../GroupManager/worlds/world)在同一个子目录下
    但拥有独立的users和groups文件

而既然我们说那么多个世界都是在all_unnamed_worlds:下
而且父节点都是world，也就是镜像world下每个玩家拥有的所有权限
所以世予说的的确没有问题了

但是有个槽点，她的回复下
本来就是全局的呀...你删除config重载

"全局"，容易引起误会，因为全局使用的一般是global一词，很容易联想到.../GroupManager下的globalgroups.yml
这个才是真正的全局权限所在的位置
