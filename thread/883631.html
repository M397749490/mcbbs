你开服都不把配置文件全部翻一遍么...https://github.com/IntellectualS ... duction#plot-expiry
RTFM.
插件在2017年以前就应该支持自动清理地皮了.
我在这里做一个简单的示例:
打开config/settings.yml
在47行左右能够找到这样一串东西
  1. plot-expiry: false
复制代码

把false改为true,你就启用了地皮清理计划任务.
那么接下来配置你的计划任务,你可以配置很多计划任务,满足你的不同需求.
你可以使用地皮分析来选择不同类型的地皮,如:长期不活动/完全无动作/方块数低于xxx等等等等.
参考这里:https://github.com/IntellectualS ... /wiki/Plot-analysis

这里我也简单举一个例子,要求能够14天清理一次动作数低于20的地皮,90天清理长期无活动的地皮:
在settings.yml的末尾找到clear一项.
然后这么玩:
  1. clear:
  2.   #14天清理动作数低于20的
  3.   14_empty:
  4.     #启用该任务
  5.     enabled: true
  6.     # 基准值
  7.     # 如果基准值为-1,所有地皮都会被清除
  8.     # 否则,只有低于该基准值的地皮会被清除
  9.     # 基准值用于与下面校准值相乘,然后用整块地皮对应的变量来判断
  10.     threshold: 20

  12.     # 这个校准值你可以自行配置,或者让插件自动校准
  13.     calibration:
  14.       changes_sd: 0 # 每个y轴上方块修改量的范围值
  15.       variety_sd: 0  # 每个y轴上方块种类的范围值
  16.       faces_sd: 0   # 每个y轴上能被看到的方块数量范围值
  17.       air: 0         # 每个y轴上空气数量阈值
  18.       faces: 0       # 每个y轴上能够看见的方块阈值
  19.       changes: 1     # 每个y轴上修改的方块阈值
  20.       data_sd: 0     # 每个y轴上具有数据值的方块的范围值
  21.       variety: 1     # 每个y轴上方块种类的数量
  22.       air_sd: 0      # 每个y轴上空气数量的范围值
  23.       data: 0       # 每个y轴上有数据值的方块数量
  24.    
  25.     # 清理每块地皮之间的延迟,秒为单位,越低清理速度越快,越高对tps影响越小
  26.     clear-interval-seconds: 10
  27.    
  28.     # 任何地皮超过14天未活动并满足以上条件则会被清理.
  29.     days: 14
  30. #90天未活动地皮
  31.   90_death:
  32.     enable: true
  33.     threshold: -1
  34.     calibration:
  35.       changes: 0
  36.       air: 0
  37.       faces: 0
  38.       variety: 0
  39.       data: 0
  40.     clear-interval-seconds: 10
  41.     days: 90
复制代码

名词解释:
阈值:低于此值就会被判断为符合条件
范围值:用于修正阈值,如原本changes为1,加入changes_sd范围值1后,修改数为0-2的地皮将符合条件
基准值:用于与阈值相乘,然后与整块地皮的变量比较.
如基准值为100,changes为2,changes_sd为1,则整块地皮方块修改量的数量在100-300之间都会符合条件.
