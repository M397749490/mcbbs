import java.lang.ref.Cleaner;

class Member implements Runnable {
    public Member() {
        System.out.println("实例化一个对象");
    }
    @Override
    public void run() {
        System.out.println("对象回收线程");
    }
}
class MemberCleaning implements AutoCloseable {
    private static final Cleaner cleaner = Cleaner.create();
    private Cleaner.Cleanable cleanable;
    public MemberCleaning(Member member) {
        this.cleanable = cleaner.register(this, member);
    }
    @Override
    public void close() throws Exception {
        this.cleanable.clean();
    }
}
public class JavaApiDemo {
    public static void main(String args[]) {
        Member mem = new Member();
        System.gc();
        try (MemberCleaning mc = new MemberCleaning(mem)) {
            //相关代码
        } catch (Exception e) {}
        System.out.println("正常运作");
    }
}

作者: liach    时间: 2020-4-24 01:52
1、cleaner是所有MemberCleaning都使用的，所以static。final实际上不一定，但是有final性能更好，而且这个field也没有改动必要
2、要member才能让cleaner创建cleanable，所以需要这个参数
3、closeable是处理文件读入读出这种要代码主动处理的。老版本java里面有finalize让你关闭inputstream这类的，但是这个强烈不推荐，占用硬盘影响性能等等。gc的话会读取finalize，但是gc不会丢掉文件锁这样的东西
4、try with resources 就是让代码简单点。原先 closeable 的东西别的操作出错后，如果你没有在finally里面呼叫 close 的话 close就会被跳过，很容易出错，造成资源泄漏。现在有try with resources后，close就算在try里面出错后也会自动帮你叫，如果有错误也可以更好汇报（addSuppressed）
