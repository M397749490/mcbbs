用 data modify 。
将
  1. execute store result entity @e[type=shulker_bullet,limit=1] Target.(M/L) long 1 run data get entity @p (UUIDMost/UUIDLeast)
复制代码
改成
  1. data modify entity @e[type=shulker_bullet,limit=1] Target.(M/L) set from entity @p (UUIDMost/UUIDLeast)
复制代码
计分板最大能存大小为 2^31-1 的数，而 UUIDMost/UUIDLeast 一般是超过这个数的。
把 @p 的 Motion 附到一只僵尸的 Motion：
  1. /data modify entity @e[type=minecraft:zombie,limit=1] Motion set from entity @p Motion
复制代码

印象中是data get获取的值这一节出了问题(超出最大限制)
导致store的结果不同。可自行对比bullet的uuid是否有修改为正确值。

使用data modify

倍率问题？get的时候放大几倍(确保不超出最大值)，store的时候缩小回原样以确保精度。一般放大10000倍足以。如果store的数据类型为int(即存储整数值的类型)，则没必要放大缩小。double记得保留小数点2位，所以获取时放大100倍。

中途要处理，做计算什么的，习惯放大10000倍

数据类型，int为整数值，没有后缀。double，数值后会有字母d为后缀。
byte，b。long，L。short，s。float，f
