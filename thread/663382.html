标题: BuildTools使用教程——以最直接的方式获取spigot和bukkit服务端
写在之前：为什么要写这个教程呢？现在能找到的许多完整的开服教程，发布的时间距离现在都有些年头了，可能有些东西并不适用了，其中我觉得最有问题的部分就是服务端获取这一块，大部分教程都只说“请去bukkit/spigot官网下载新版服务端”，或者自己转存一些版本的服务端给阅读者下载。但是官网早就已经不发布新版的服务端了，而作者自己转存的服务端，因为作者精力有限，也不可能实时更新。我是某个正版小服的服主，正版启动器会在更新之后自动推送新版游戏主体，实时更新最新版服务端对于纯净正版服是很有必要的，当初开服的时候这个问题困扰我许久，百度也没有答案，spigot官网的说明看得半懂不懂，花了相当一段时间才解决服务端的获取问题，所以在此分享经验，希望各位想开服的朋友少走点弯路。    搬运服务端这种行为本身违规，况且授人以鱼，不如授人以渔。
此教程从我本人的博客转发过来——原帖链接

什么是BuildTools?:
继Minecraft1.8以后，craftbukkit和spigot这两个Minecaraft非官方服务端官网就已经下载不到新版本了，这是因为这两个项目同时用到了开源的源码和不开源的源码，然而用开源的源码就需要遵守规定让这个项目开源，但是这里面又有不能开源的部分，这里就产生了一个矛盾，这曾经让craftbukkit和spigot很头疼。然后就有了BuildTools这个小程序，它能够用Git实时将开源和不开源的部分编译在一起，巧妙的解决了矛盾。

需要准备的条件：
java运行环境
git
BuildTools.jar
一台不受国内特殊网络环境影响的电脑/服务器
主要思路和步骤：安装java运行环境和git后，运行BuildTools.jar。

不同系统下步骤的举列：
Linux Centos 7：
从BuildTools构建页面下载BuildTools.jar，并存放到一个文件夹： 你可以在windows里面去https://hub.spigotmc.org/jenkins/job/BuildTools/下载好了然后再用FTP等工具传输到Centos的电脑，也可以用# wget “https://hub.spigotmc.org/jenkins ... rget/BuildTools.jar” -O BuildTools.jar 指令直接在linux系统下载BuildTools，然后再移动到某个文件夹。  yum install java（安装jdk，yum大法真的妙2333） yum install git（安装Git） java -jar BuildTools.jar –rev <版本号>  （运行BuildTools.jar，注意区分大小写，版本号两边不用加”<>”，不填版本号就是默认版本） 以上步骤如果没有用root账户操作请在指令前面加上sudo 接下来只需要等待输出的那些字闪完就可以在你存放BuildTools.jar的文件夹找到spigot和craftbukkit服务端的.jar文件啦！

Linux Ubuntu:
从BuildTools构建页面下载BuildTools.jar，并存放到一个文件夹，和Centos一样。 apt-get install default-jdk（安装jdk） apt-get install git（安装Git） java -jar BuildTools.jar –rev <版本号> （这一步和Centos一样） 以上步骤如果没有用root账户操作请在指令前面加上sudo 等待编译完成就可以在存放BuildTools.jar的文件夹找到spigot和craftbukkit服务端的.jar文件啦！

Winsows:
因为用的是自己的电脑，就算挂魔法上网也是网络很不稳定，所以一次都没有完成过，每次都会卡在一些奇怪的下载的地方，对自己网络有信心或者有在中国大陆以外的服务器的小伙伴可以尝试一下。   去Git官网下载安装包，并且运行安装包。 在开始菜单里打开或者搜索Git Bash，并运行，会看到一个git bash的类似命令行的界面 运行指令 java -jar <你存放BuildTools.jar的路径> （路径两边不用加”<>”直接将BuildTools.jar拖进git bash窗口可以快速获得路径） 等待完成之后，会在你的工作目录（如果你没有使用cd指令切换目录，则是系统的当前用户文件夹的目录，比如我的windows账户名是r_jos那么核心文件就在C:\Users\R_Jos文件夹）下找到核心文件。
2018年2月1日更新: 如果不想麻烦，可以使用这个批处理脚本，新建一个文件，改后缀名为.bat，复制下列代码将git-bash路径改为你自己的，保存后和BuildTools.jar放在一个文件夹运行，生成的所有文件都将在此文件夹。（请修改代码中的路径与版本，rem后跟的是注释）
  1. @echo off
  2. set startdir=%~dp0
  3. rem <git-bash的路径>
  4. set bashdir="C:\Program Files\Git\bin\bash.exe"
  5. rem <版本号自己修改>
  6. %bashdir% --login -i -c "java -jar ""%startdir%\BuildTools.jar"" --rev 1.12.2"
  7. pause
复制代码

一个省钱的方法：
之前说过因为国内特殊的网络环境，BuildTools.jar无法被我们直接使用，就算挂魔法上网也非常不稳定，我们很可能需要一个不再中国大陆的服务器来运行BuildTools.jar，但为了减小延迟，大部分服主的游戏服务器都在国内，然而再租用一个vps服务器即使再便宜，过得去的一个月也要大几十元，为了编译一个小程序很显然划不来，大部分服主考虑到这里也就放弃了自己获取BuildTools的想法。但是网上找的现成的大部分版本较老，对于那些喜欢更新最新版的纯净服服主来说很不方便，自己随时获取的更新才是好的。（现在spigot和craftbukkit几乎已经能和官方服务端一起更新了）接下来就说说这个省钱又方便的方法吧：
我是用腾讯云的按量计费的方法（阿里云也有，很多云服务器商都有）购买了一个临时使用的服务器，在这个计费模式下，费用按照使用时间来算，使用的时长精确到秒。以低配置来说，一小时只要零点几元，网络选择按流量计费。点击创建服务器成功时即开始计费，第一次使用时自己先按照上面的步骤配置Java环境，安装git，下载BuildTools.jar，工作完以后立即销毁这个服务器，第一次使用可以在结束工作时先制作一个镜像，下次来构建服务端可以直接俄选择上次的镜像，接着上次来。这样我第一次的花费不到一元，确实是又方便又廉价的方式。

2017.4.4日更新：其实挂魔法上网用国内网络编译也可以，之前我说不稳定可能是我用了假魔法上网。。。
