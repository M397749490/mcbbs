局限性

  • 无法处理流局满贯
  • 无法自动处理宝牌，需手动输入
  • 未检查不合理的牌形（如牌张数≠14+杠数，一张牌出现超过四个等）
  • 通常一次判定所执行的命令数会多达数千次，不过一位愿意透露姓名的素学姐曾说过：

    那大概也没什么了。

原理

如果读者之前有查过麻将和牌判定与番数计算的方法的话，那么最容易得到的方法应该是——查表法。实际上，查表法对于现代个人计算机来说，是一种相当有效的方法，但是我们面对的是 MC 命令——这对于成百上千万种麻将的可能牌型来说，就困难得多了。

不过，幸运的是，日本有一帮人通过将相似的牌型合并归类，搞出了一套将表的数量足足压缩到九千多行的麻将和牌判定方法。虽然这仍然是查表法，但已经可以以不那么占地方的方式塞进数据包里了。

表格本身是整数到整数的映射。其中每一种牌型对应的是查表法中表格的输入，而和牌的拆分方式则对应着表格的输出。需要注意的是，一种输出不仅可能对应零或一种输入，更可能对应着多种输出，考虑 22334455667788s 这一牌型：

  • 234s 234s 567s 567s 88s
  • 234s 234s 678s 678s 55s
  • 345s 345s 678s 678s 22s

不考虑七对的话，以上牌型在实际番数计算时均需考虑，这才能保证无论和牌为 2s 到 8s 这七张中的哪一张，最后番数计算时都会有平和一番。

编码输入

编码输入的方式如下：

一、将牌按是否连续拆分，连续的部分按相应位置的牌数映射，最开始与不连续处补零。考虑 111234678m11122z，由于万饼索从一到九是连续的，而字无论如何都不连续，因此最后映射的结果是：0311101110302。

二、按以下规则把数字映射到 bit 并拼凑到一起：

  • 1 => 0
  • 2 => 011
  • 3 => 01111
  • 4 => 0111111
  • 01 => 01
  • 02 => 0111
  • 03 => 011111
  • 04 => 01111111

那么最后映射到的结果应为 01111100001000111110111，也就是 4067831。

我们很容易从表中查到一个 4067831 => 26084370 的映射。

解码输出

接下来是解码过程：

一、将输出转换为 31 bit 的二进制序列，这里是 0000001100011100000010000010010。我们对该序列进行分组：0 0 0 0 0 0110 0011 1000 0001 0000 010 010，以备后续之用。

二、序列的最低三位为刻子数量（这里是二），次低三位为顺子数量（这里也是二）。

三、接下来的最低四位是雀头的位置（零）以及四个面子的位置（一，八，三，六），注意位置从右往左数，同时，按照上一步的要求，前两个为刻子，后两个为顺子。

四、最后五个 bit 代表输入是否可能满足五种特定的役，这个稍后会讲到。

额外优点

这样的处理甚至带来了几个额外的优点：

  • 它涉及的位运算较多，故很容易处理为记分板的加减乘除
  • 它可以处理七对子，也就是七个 2 或者 02 粘在一起的情况
  • 它可以处理副露的情况，因为刻子和顺子数量之和并不要求为四
  • 它可以提前判定一些役是否存在。这些役包括：七对子、九莲宝灯、一气通贯、两杯口、一杯口，实际上它们正好对应输出最高的五个 bit

那么我们的算番过程实际上分成了五步：

  • 编码
  • 映射
  • 解码
  • 算番算符
  • 统计点数

那么我们开始在 MC 里实现吧！

第五步——解码

考虑到映射表的输出最多只会有四个，我们将其分别赋值为 mahjongvalue1 到 mahjongvalue4，然后：

  • 取出 mahjongvalue1，如果有的话
    • 生成一个对应 mahjongvalue1 的 @e[tag=mahjong.agari]
    • 为 @e[tag=mahjong.agari] 算役满，要是没有役满，再算普通役
    • 计算 mahjongranking 用于事后比较和牌的拆分方式对应的番数大小
    • 取掉 mahjong.agari 标签，并标记为 mahjong.agariprev
  • 取出 mahjongvalue2 并重复上述工作，如果有的话
  • 取出 mahjongvalue3 并重复上述工作，如果有的话
  • 取出 mahjongvalue4 并重复上述工作，如果有的话
  • 取出 mahjongranking 最大的一个，标记为 mahjong.agari
  • 为 @e[tag=mahjong.agari] 把宝牌的番加上

以下是分别调用针对 mahjongvalue1 到 mahjongvalue4 的函数部分：

  1. execute if score @s mahjongvalue1 matches 0.. run function mahjong:decoding/initpart1
  2. execute if score @s mahjongvalue2 matches 0.. run function mahjong:decoding/initpart2
  3. execute if score @s mahjongvalue3 matches 0.. run function mahjong:decoding/initpart3
  4. execute if score @s mahjongvalue4 matches 0.. run function mahjong:decoding/initpart4
复制代码

乍一看上面的流程似乎没什么问题，但是实际上我们忘了一步：国士无双只能被单独处理。

  • 如果连 mahjongvalue1 都没有，考虑国士无双的可能

这里再补充一下 mahjongranking 是怎么计算的。立直麻将的要求是：

  • 如果有役满牌型，选役满数最大的
  • 如果没有役满牌型，选对应番数最多的
  • 如果有多个番数相同的，选对应符数最大的

我们完全可以搞一个基于 256 进制的公式：

  • mahjongranking = (mahjongyakuman * 256 + mahjonghan) * 256 + mahjongfu

这样我们选的就是 mahjongranking 的最大值了。实际使用的命令如下：

  1. # set ranking = (yakuman * 256 + han) * 256 + koutsu
  2. scoreboard players set @s mahjongtmpmul 256
  3. scoreboard players operation @s mahjongranking = @s mahjongyakuman
  4. scoreboard players operation @s mahjongranking *= @s mahjongtmpmul
  5. scoreboard players operation @s mahjongranking += @s mahjonghan
  6. scoreboard players operation @s mahjongranking *= @s mahjongtmpmul
  7. scoreboard players operation @s mahjongranking += @s mahjongfu
  8. # set maximum ranking value in mahjong.counter
  9. scoreboard players operation @e[tag=mahjong.counter] mahjongranking > @s mahjongranking
复制代码

这样就可以保证 @e[tag=mahjong.counter] 永远储存着 mahjongranking 的最大值了。然后：

  1. scoreboard players operation @e[tag=mahjong.agariprev] mahjongranking -= @s mahjongranking
  2. tag @e[tag=mahjong.agariprev,scores={mahjongranking=0,mahjonghan=1..},limit=1] add mahjong.agari
复制代码

就可以把 mahjongranking 为最大值，同时保证一番起和的和牌拆分方式选出来了。

第六步——番符

算番可以说是整个过程最难的一步了。麻将的各种役可以说是整个游戏中人为规定最多，亦即需要特殊处理的地方最多的规则。为方便后续输出，我们在统计役种时会为 @e[tag=mahjong.agari] 添加相应的标签，如标签 mahjong.yaku.chinitsu 代表有清一色这个役，以此类推。

在开始之前，我们首先定义“有效张数”这一概念。这一概念简而言之，就是把杠子多出来的那张去掉：

  • 一个顺子的有效张数是三张
  • 一个刻子的有效张数是三张
  • 一个杠子的有效张数是三张
  • 一个雀头的有效张数是两张

同时，为了将七对子纳入我们的统计体系，我们额外规定：

  • 七对子有七个雀头

在进行番符计算时，我们采用的是分阶段计算的方式：第一到三阶段处理役满，第四到六阶段处理普通役，第七阶段处理额外的符数。

国士无双不适用这种统计方式，因此会单独计算，在后文也会提及。

我们先从第一阶段开始。

第一阶段

第一阶段首先将番数役满倍数归零，符数设为起符 20：

  1. scoreboard players set @s mahjongfu 20
  2. scoreboard players set @s mahjonghan 0
  3. scoreboard players set @s mahjongyakuman 0
复制代码

第二阶段

在第二阶段，我们需要深入每一张牌，统计其对应的：

  • 暗刻数（0/1，存储于 mahjongankou 中）
  • 杠子数（0/1，存储于 mahjongkantsu 中）
  • 刻子数（0/1，存储于 mahjongkoutsu 中）
  • 面子数（0/1/2/3/4，存储于 mahjongmentsu 中）

同时为 @e[tag=mahjong.agari] 统计：

  • 暗刻数
  • 杠子数
  • 刻子数
  • 门清的面子数

我们有以下公式：

  • 暗刻数 = 非吃碰杠的刻子数 + 暗杠数 + 修正
  • 杠子数 = 暗杠数 + 明杠/加杠数
  • 刻子数 = 非吃碰杠的刻子数 + 暗杠数 + 明杠/加杠数 + 碰牌刻子数
  • 面子数 = 非吃碰杠的面子数 + 暗杠数 + 明杠/加杠数 + 碰牌刻子数 + 吃牌顺子数

此外还要为 @e[tag=mahjong.agari] 修正：

  • 门清的面子数 = 非吃碰杠的面子数 + 暗杠数

Well，这几个公式整体都很清楚明了，唯一一个需要注意的是那个计算暗刻数的“修正”：双碰听牌时荣和不计含荣和牌的刻子为暗刻。在考虑这一修正的时候有一个问题很关键：如果荣和的牌既可以视作刻子的听牌，也可以视作顺子的听牌，实际统计时采纳哪个呢？

实际上，只要稍作思考，就可以看出：听牌总是优先计为顺子的。

  • 暗刻多有利于三暗刻及四暗刻等役，在计符时也会占据优势
  • 听牌计为顺子有利于凑成平和，同时如果听坎张听边张也会加符

那我们判定修正的条件变成了：

  • 听牌来源为荣和
  • 听牌对应的牌有一组非暗杠的暗刻
  • 听牌对应的牌没有办法匹配成顺子

我们可以进一步简化为：

  • 听牌来源为荣和
  • 听牌对应的牌有一组刻子
  • 听牌对应的非吃碰杠的牌恰好有三张

  1. execute if entity @e[tag=mahjong.counter,scores={mahjongsaki=0..2}] run scoreboard players remove @s[scores={mahjongkoutsu=1,mahjongcount=3,mahjongtenpai=1}] mahjongankou 1

第六阶段

对于三色同刻和三色同顺，我反正是没想到什么好的办法，只能穷举：

  • 同时有 2m/5m/8m 的顺子
  • 同时有 2p/5p/8p 的顺子
  • 同时有 2s/5s/8s 的顺子

一杯口就简单多了。在门清的条件下，我们要求：

  • 存在一张牌没有对应的刻子，但对应的面子的等效牌数至少 6 张

此外，由于这些役往往需要穷举，我们在开始判定前，可以先利用已有的统计数据筛选到一些不可能存在的情况：

  • 三色同刻：刻子至少 3 个，万饼索的有效张数都至少为 3，字的有效张数不超过 5
  • 三色同顺：刻子至多 1 个，万饼索的有效张数都至少为 3，字的有效张数不超过 5
  • 一气通贯：刻子至多 1 个，带幺九的有效张数至少为 6 至多 11，同时未在第一阶段被提前判定
  • 一杯口：门前清的面子有 4 个，同时未在第一阶段被提前判定
  • 平和：没有刻子，门前清的面子有 4 个，同时没有三元牌

我们现在只剩下平和一个役没有处理了。因为立直麻将中对平和的规定最多，因此平和是所有役种中最难处理的役，甚至导致了穷举都变得很困难。除去上面的筛选条件外，平和还有以下规定：

  • 听牌不能为边张
  • 听牌不能为坎张
  • 听牌不能单骑

另外，考虑到立直麻将要求番数大者优先，因此还有一条隐藏规定：

  • 尽可能让听牌对应的顺子往平和牌型靠拢

  • 听牌的上一张有非 2m2p2s 的顺子
  • 听牌的下一张有非 8m8p8s 的顺子

第七阶段

第七阶段是算符。那么除了在第二阶段处理的外，立直麻将还有哪些需要额外算符的呢？

  • 门清点炮加 10 符
  • 如果不是平和的话
    • 门风牌/场风牌/三元牌雀头加 2 符
    • 听边张/坎张/单骑加 2 符
    • 自摸加 2 符
  • 进位到 10 符的整数倍

此外：

  • 若没有平和，但仍然是 20 符，则进位到 30 符
  • 七对子无视上面的所有规则，固定 25 符

因为立直麻将在番数相同的情况下，要求符数多者优先，因此：

  • 尽可能让听牌对应顺子，同时往听边张/坎张/单骑靠拢

门清点炮加 10 符的处理方式是显而易见的。而对听牌要求的统计和第六阶段所做的事类似：

  • 边张：听牌的上一张有 2m2p2s 的顺子或下一张有 8m8p8s 的顺子
  • 坎张：听牌的对应位置有至少一个顺子
  • 单骑：听牌的对应位置有雀头

统计门风牌/场风牌/三元牌雀头的原理不再赘述。

至于如何是进位到 10 符的整数倍的呢？实际上：

  1. scoreboard players set @s mahjongtmpinc 8
  2. scoreboard players set @s mahjongtmpmul 10
  3. scoreboard players operation @s mahjongfu += @s mahjongtmpinc
  4. scoreboard players operation @s mahjongfu /= @s mahjongtmpmul
  5. scoreboard players operation @s mahjongfu *= @s mahjongtmpmul
复制代码

  1. execute unless score @s mahjongvalue1 matches 0.. run function mahjong:decoding/initpartkokushi

第七步——点数

点数算起来就简单多了，我们先算基本点：

  • 有役满的，基本点 = 役满数 * 8000 点
  • 没役满且大于等于 13 番的，基本点 = 8000 点
  • 没役满且介于 11 和 12 番的，基本点 = 6000 点
  • 没役满且介于 8 和 10 番的，基本点 = 4000 点
  • 没役满且介于 6 和 7 番的，基本点 = 3000 点
  • 剩下的……诶剩下的呢？

剩下的：如果不超过 5 番，则基本点 = 符数 * 2 ^ (2 + 番数)，并以 2000 封顶。

对于 2 的乘方问题，这里直接使用穷举法了：

  1. execute if entity @e[tag=mahjong.agari,scores={mahjonghan=1}] run scoreboard players set @s mahjongtmpmul 8
  2. execute if entity @e[tag=mahjong.agari,scores={mahjonghan=2}] run scoreboard players set @s mahjongtmpmul 16
  3. execute if entity @e[tag=mahjong.agari,scores={mahjonghan=3}] run scoreboard players set @s mahjongtmpmul 32
  4. execute if entity @e[tag=mahjong.agari,scores={mahjonghan=4}] run scoreboard players set @s mahjongtmpmul 64
  5. execute if entity @e[tag=mahjong.agari,scores={mahjonghan=5}] run scoreboard players set @s mahjongtmpmul 128
  6. scoreboard players operation @s mahjongbasepoint = @e[tag=mahjong.agari,limit=1] mahjongfu
  7. scoreboard players operation @s mahjongbasepoint *= @s mahjongtmpmul
  8. scoreboard players set @s[scores={mahjongbasepoint=2000..}] mahjongbasepoint 2000
复制代码

接下来，亲家得点为基本点的 6 倍，子家为 4 倍（那么怎么判定和牌的到底是亲家还是子家呢：你 484 sa，门风是东风的话就是亲家，门风是南风西风北风的就是子家啊）：

  1. scoreboard players set @s mahjongtmpmul 4
  2. scoreboard players add @s[scores={mahjongmenfon=27}] mahjongtmpmul 2
  3. scoreboard players operation @s mahjongpoint = @s mahjongbasepoint
  4. scoreboard players operation @s mahjongpoint *= @s mahjongtmpmul
复制代码

最后我们向上取整到 100 的整数倍（也就是先把点数加 80 再向下取整）：

  1. scoreboard players set @s mahjongtmpinc 80
  2. scoreboard players set @s mahjongtmpmul 100
  3. scoreboard players operation @s mahjongpoint += @s mahjongtmpinc
  4. scoreboard players operation @s mahjongpoint /= @s mahjongtmpmul
