下面是代码,就两行,我也就不折叠了.
  1. execute as @p at @s run summon minecraft:area_effect_cloud ~ ~0.25 ~ {Duration:30,Tags:["temp"]}
  2. execute as @e[tag=move] at @s run tp @s ^ ^ ^0.1 facing entity @e[tag=temp,sort=nearest,limit=1,distance=1.5..]

设计思路上,利用区域效果云(area_effect_cloud,以下简称aec)进行一种拟似的玩家路径存储,然后让盔甲架沿着aec所拟定的路径前进.


使用aec的原因有很多,比如,直接使用玩家坐标作为参照时会经常出现这样的遁地现象

最后是最重要可能也是最无关紧要的一点,aec可以设置持续时间,不需要象隐形盔甲架一般额外回收,并且大量铺设也不会出现卡顿现象.实乃居家旅行杀人放火之必备良......

下面为萌新附上代码的简单解释.能看懂代码可以自行调整的大佬们,就不用戳开了,因为里头对你们来说都是废话.


execute as @p at @s run summon minecraft:area_effect_cloud ^ ^0.25 ^ {Duration:30,Tags:["temp"]}

@p修改成玩家id或者其他选择器以应对其他情况.

^ ^0.25 ^这 里的数字就是相对玩家位置生成的药水云高度,调高可以进一步避免遁地现象但是会有明显悬浮感.
Duration 该参数是aec的持续时间,加大会让实体彻底变傻跟随的延迟变长,缩小则是跟的更紧凑,数据按喜好修改.
Tags tag标签是为后续aec的操作添加的名字,可以随意取,但一定要和第二条中后半部分tag保持一致.

execute as @e[tag=move] at @s run tp @s ^ ^ ^0.1 facing entity @e[tag=temp,sort=nearest,limit=1,distance=1.5..]

@e[tag=move] 是选中所有标签为move的实体,只要有同样标签的实体都会被选中,可以随意取,如pet啊chongwu啊什么的.
    添加标签的指令:tag @e[type=armor_stand] add move
    直接召唤具有该标签的实体:summon armor_stand ~ ~ ~ {Tags:["move"]}
    其他实体同理,把armor_stand改成你要召唤的生物就好.
^ ^ ^0.1 这个数字会影响移动速度,自己调整看看效果吧,数字越大跑越快,但是移动轨迹会有一定的撕裂感.
tag=temp 就不多说了
sort=nearest 选取最近的目标
limit=1 选取数量限制为1,防止复选目标原地抽风
distance=1.5..只选取距离大于1.5的目标.这个数据可以调整跟随实体与玩家的距离,数字越大罚站的越远.改小甚至改到0会抽风.

这个是我对玩家锁头的时候使用的指令
execute as @e[tag=move] at @s run tp @s ^ ^ ^0.1 facing entity  ...

首先你要知道^^^（局部坐标）的运作原理
局部坐标是根据执行点作为基点 以面朝方向建立空间坐标系
而rotated就是更改执行点的面朝方向(类似tp中最后俩个~ ~)
而rotated ~ 0就是让执行点的y轴偏转保存原角度 而x轴偏转变为0(即与地面平行)
这时再加上^ ^ ^0.25可以保证盔甲架只会与地面平行的进行移动
而anchored是改变局部坐标基准点
命令默认执行点为实体的脚(feet) 这时facing entity eyes就是用脚看眼睛(你可以拿自己试试 命令应该是execute as @s at @s facing entity @e[type=armor_stand,tag=point,limit=1] eyes run tp @s ~ ~ ~ ~ ~ 你的记忆会非常深刻)
如果要用眼睛看向眼睛自然就要加上anchored eyes
顺便说一下 由于盔甲不会抬头 所以用其他生物的话才能做出它一直看着你的效果
然后为什么 盔甲架会漂浮？ 因为tp后生物的motion不会立刻作用于生物 至少需要1刻反应时间(只有玩家是即时运算)
