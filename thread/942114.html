概览
Magic是一款能够给你的服务器添加强大的法杖和物品的魔法插件，同时这款插件也提供了成长进度系统、自定义怪物和合成、图片地图以及大量其它特性。
有疑问? 在这里提出来吧：FAQ
想要自定义插件? 看看参考手册吧！
对于玩家
大多数施法都需要用到法杖。当你手持法杖时，左击即可施法。当你拥有多个法术时你会拥有可以用于快速切换法术并管理法术的“法杖背包”。
当你拥有了一根法杖后，你可以手持法杖右击附魔台来升级你的法杖。详情请查看进度页面。
法杖机制、进度和可用的法杖等特性取决于你的服务器管理员，所以玩家对于该插件的体验可能有所不同。
你可以到我的示例服务器内尝试不同的法杖和法术，详见示例服务器。
包括法杖背包模式的更多详细信息请查看魔法插件官网。
在官网内有所有可合成的法术的合成配方、所有法术和法杖以及各自的描述。管理员请查看下面的信息来了解如何设置独属于你的版本的插件。
对于开发者
  API  | MagicLib | EffectLib
Magic拥有简单的API，但如果你想要关联这款插件的话，本插件的API同时也很深奥。你可以施法、创建法杖或甚至加入你自己的法术和特效到本插件内。如果你想在插件中使用Magic的核心功能而不依赖Magic，你也可以在MagicLib中构建或隐藏它。
Magic也会使用EffectLib来显示粒子特效（已嵌入插件，无需额外下载），你也可以使用EffectLib！瞧瞧EffectLib吧，它很有用的。

自定义和默认
Magic可以完全自定义。插件行为、可用的法术和法杖以及游戏内的所有文本都可以自定义。
Magic 也附带了 默认示例配置 。
默认的插件体验详情：

  • 玩家没有使用Magic指令的权限
  • 玩家可以合成不同强度的法杖（默认用烈焰棒和下界之星合成法杖）
  • 玩家可能会在自然生成的箱子内找到魔法点(需使用 MagicWorlds)
  • 法杖初始等级很低，但可以用SP来在附魔台处升级法杖
  • 法杖可以在Magic或Essentials的商店内购买或放入Essentials的礼包内。
  • 法杖可以由类如ShopKeepers的插件使用。
  • 法杖绑定到玩家本人身上，其他玩家无法使用。
  • 管理员可以建立任务或其他奖励来升级或创建法杖。
  • 法杖无法摧毁。法杖会显示在卫星地图上（需安装Dynmap）来让玩家找到丢失的法杖。
  • 每根法杖都拥有可由玩家操控的独特的法术背包和材质。
  • 使用法杖需要消耗法力，法力会自动缓慢恢复。
  • 所有玩家可以使用全部的法术。

以上任何一条特性都可以关闭或修改。一些不同的选项：

  • 玩家可以选择3种不同的法杖背包模式：箱子背包（默认）、点击循环和强大的快捷栏背包模式。
  • 基于权限的法杖、法术和指令（用于分级、VIP等）
  • 不同的法杖类型、合成配方和附魔路径。
  • 玩家的法杖会在死亡后保留
  • 玩家有权限使用需要消耗原料的法术
  • 则会消耗原料而非法力
  • 用其他类型的物品显示法杖（附魔剑等）

其他有关自定义或管理员指令的详细信息请查看 管理员 页面。

关于指令与权限的提醒
Magic旨在增加原版的内容，因此该插件遵循以下Minecraft的主旋律：探索、合成和自由。本插件的所有法术和能力都与法杖有关，玩家不会受任何限制或被分类（无职业区别）。
对于玩家而言，本插件不需要用到任何指令。可以用/spells list 指令查看法术，但我不推荐你给予玩家这个指令的权限。让玩家自然地发现新的法术，如果玩家决定了要深入研究这款插件，它们可以访问 魔法插件官网 来查看所有可用的法术。 这也是Minecraft这款游戏的精髓所在！
当然，本插件的配置很灵活。你可以使用 可选配置, 如基于权限施法、自动填充法杖或其他配置来进行调整。 这在你想要特定的玩家才能使用特定的法术时而设置VIP法杖的时候很有用。或者如果你想要锁定比如聚集和回溯这样的只有管理员才能使用的法术时也很有用。
然而，如果玩家没有法杖则无法施法。法杖就是这款插件的核心。你可以尝试这样做：比如使用PowerTool来用/cast指令施法，但我不推荐你这样做。因为/Cast 指令是为管理员进行实验而准备的。你也可以在命令方块内使用 创建特殊效果和脚本事件。
/cast 指令不是给玩家用的，这个指令可能会在使用部分法术时造成毁灭性打击。请不要让你的玩家使用这个指令！大概管理员也不要使用。大概...
如果你不喜欢本插件的法杖系统，你可以告诉我来让我完善法杖系统！使用这款插件而不用法杖将会给予玩家糟糕的游戏体验。

指令和权限
指令

默认权限可以让管理员使用一些指令。尝试使用TAB补全来查看指令帮助（比如/mgive 指令）。
查看 权限 页面以获取详细的权限信息。
法杖指令
  • /wand : 创建一个新的空法杖
  • /wand <法杖名> : 创建一个在wands.yml内预设的法杖
  • /wand list : 列出在wands.yml内可以使用的法杖模板
  • /wand enchant [#等级] : 给法杖加上随机法术和附魔
  • /wand add <法术名> : 给你手持的法杖添加法术
  • /wand restore : 恢复一名玩家丢失的法杖
  • /wand organize : 重组法杖内的法术
  • /wand fill : 给法杖加上所有已知的法术（有权限使用的法术）
  • /wand remove <法术名> : 删除你手持的法杖内的法术
  • /wand configure <属性> <数值> : 配置法杖属性（详情看下面）
  • /wand upgrade <属性> <数值> : 配置法杖属性，但无法降低任何数值（详情看下面）
  • /wand override <参数> <数值> : 更改法杖施法的方式
  • /wand bind : 绑定法杖来让你可以使用该法杖
  • /wand unbind : 解绑法杖及其备份
  • /wand save <法杖名> : 保存法杖为一个新的模板
  • /wand delete <id> : 删除已保存的法杖模板
  • /wand combine <法杖> : 将一个法杖模板添加到一个法杖上（升级该法杖）
  • /wand add brush <材料名> : 给你手持的法杖添加材料
  • /wand remove brush <材料名> : 删除你手持的法杖内的材料
  • /wand name <法杖名> : 重命名法杖（你也可以用铁砧来给法杖重命名）
  • /wand describe : 列出法杖的所有属性，和configure指令一同使用
  • /wand unlock : 解锁已解锁的法杖来让你可以编辑该法杖(输入 "/wand configure locked "以解锁)
  • /wand create : 以你手持的物品为材质创建法杖
  • /wand destroy : 解除附魔 (摧毁) 你手持的法杖
  • /wand duplicate : 复制你手持的法杖
  • /wand enchant xp : 给你的法杖添加经验等级（消耗XP）可用在命令方块内以实现升级系统
  • /wandp <玩家名> <...> : 对指定的玩家使用/wand 指令
法杖配置参数：“配置”和“升级”
详细法杖配置参考
mgive指令/mgive 指令的使用方式和原版或Essentials的/give指令相似。可用于给予任何玩家任何物品，包括比如法杖、法术和升级等插件内容。也可以用于给予玩家经验值并可以作为阻止用/xp 指令获得的经验来给法杖升级的一种措施。

  • /mgive [玩家名] <物品名> [数量] : 指令的通用格式。“item”是唯一必需的参数。
  • /mgive NathanWolf elder : 给予 NathanWolf 一根远古法杖
  • /mgive NathanWolf sp 100 : 给予NathanWolf 100SP
  • /mgive NathanWolf sp:100 : 给予NathanWolf一件价值100SP的物品
  • /mgive fling 32 : 给予自己32个“投掷”法术。法术可以堆叠，也可以放在箱子里或送给其他玩家。
  • /mgive NathanWolf xp 200 : 给NathanWolf 200点经验值，在玩家拿着法杖也会生效。
  • /mgive NathanWolf gold_nugget 32 : 给NathanWolf 32个金块。物品格式必须遵循Bukkit的材料名。
  • /mgive spell:wolf : 给自己一个“狼群”法术。“spell:”、“wand:”和“upgrade:”前缀可用于区分具有相同名称的物品。
  • /mgive book:engineering : "book:<category>"物品会创建一本包含一类法术的“魔法书”。
  • /mgive book:all : 给予一本包含所有法术的“大师魔法书”，法术根据类别排序。
/mmob 指令请参阅``mmob指令Magic Mobs参考''部分！
/mitem 指令请参阅``mitem指令自定义物品参考''部分！
效用指令
  • /magic load : 重新加载配置文件并更新法术配置。
  • /magic save : 强制保存玩家数据。同时保存例如丢失的魔杖和图片等其他数据。
  • /magic commit : 提交所有更改（对所有玩家使用“commit”法术）
  • /magic cancel : 取消所有进行中的工程魔法。
  • /magic list [wands | automata | maps | tasks] <玩家名> : 列出所有丢失的法杖、地图或自动机械。“tasks”参数可用于检查在任何插件中的失控任务。
  • /magic clean <player> : 清除无人认领的丢失法杖，或特定玩家丢失的法杖。
  • /magic clean ALL : 清除所有世界的所有法杖。
  • /spells : 列出玩家已学会的所有法术。玩家可以查看其有权施放的任何法术的详细信息。给予玩家这个指令的权限很安全，尽管这个指令会消除玩家对这款插件的 神秘感。玩家可以在游戏中看到他们法杖内的法术信息（通过lore描述的提示）。

Mage法师指令
mage命令可用于检测或修改特定的玩家信息。

  • /mage check <玩家名> : 根据玩家的位置和激活的法术检测其权限
  • /mage debug <玩家名> : 开关对特定玩家的调试信息输出
  • /mage describe <玩家名> [spell/data] : 显示关于玩家施法、存储数据等内容的大量信息
  • /mage configure <玩家名> <spell/data> <数值> : 设置玩家信息、更改法术施法次数等
  • /mage reset <玩家名> : 完全重置一名玩家的所有已存储数据

Cast指令
游戏内的/cast指令非常强大。它允许你直接施法，但（更重要的是）它允许你使用“命令行参数”来使用可配置的法术系统。本插件中的许多法术都是基于同一个“积木”法术并使用不同的参数来实现的。通过自己调整这些参数，你可以创造一些有趣和强大的法术。服务器管理员可以将它们添加到spells.yml中，使它们成为“正式的”法术，这样玩家就可以在法杖上使用新法术。
例如，“boom·爆炸”、“kamikazee·神风”、“kaboom”和“nuke·核弹”都是“BoomSpell·爆炸法术”的变体，主要调整了“size”这一参数。例如“核弹”的参数是“size 20”——想看看经历10倍核弹的轰炸后的世界会是什么样子吗？尝试使用 /cast boom size 200 ... 但我要提前警告你，小心炸服！
cast指令的参数遵循在spells.yml内相同名称和格式并成对传递 - 比如 /cast<法术><参数><数值><参数><数值>。浏览默认的spells.yml是了解这些选项的最佳方式。
请参阅法术参数页面。

调试效用指令
在你尝试新法术的时候，你可以使用一些有用的指令：
/cast这个指令可以用于快捷地尝试不同参数的法术。详见上文。
/wand override这个指令可以用于修改特定法杖施法的方式。示例：
  1. # 可以让这根法杖永久地使用所有的法术 (危险操作！)
  2. /wand override bypass_undo true
  3. # 只降低闪现法术的冷却
  4. /wand override blink.cooldown 0
  5. # 减缓魔法飞弹的飞行速度
  6. /wand override missile.velocity 5

/mage check
用于检测与权限有关的问题。如果一名玩家使用一个法术时有时无法成功施法，那么你可以用这个指令来检测激活该法术的法杖。

/wand save
如果你在游戏中创建或修改了法杖，则可以用这个指令将其保存到配置文件中。比如 "/wand save 制杖" 会保存你手里的法杖为一个新的配置文件 "plugins/Magic/wands/制杖.yml"。这些法杖可以使用/wand或/mgive指令来正常地生成。

权限
插件内的大多数权限允许玩家使用特定的指令，大多数权限只应该给予服务器管理员。

快速给予
最常见的情况是，管理员应该具有以下权限才能访问所有Magic的指令和物品：
Magic.commands.*Magic.create.*给予Magic.*这个权限并不是一个好主意，有许多权限可能一直都是您不希望使用的绕过或有其他功能的权限。如果你需要绕过权限，那么你最好给自己OP权限！
玩家不需要任何特殊权限。详见下文。

玩家权限
默认所有玩家都可以使用所有的法杖和法术。
你可以给予以下否定权限来限制玩家使用法杖和法术：

  • -Magic.wand.use : 玩家无法使用法杖
  • -Magic.use.<法杖名> : 玩家无法使用特定的法杖或魔法物品
  • -Magic.wand.craft : 玩家无法合成法杖
  • -Magic.cast.*: 玩家无法使用任何法术
  • Magic.cast.<法术名> : 玩家无法使用特定的法术
默认玩家没有使用任何指令的权限。
Magic的指令和权限遵循以下格式"Magic.commands.<指令>.<子指令>"。比如：

  • Magic.commands.mskills : 玩家可以使用 /mskills skill selector
  • Magic.commands.spells : 玩家可以使用/spells
管理员权限
你也可以限制管理员不能通过/wand和/mgive指令获得特定的物品。默认如果管理员可以使用这些指令，那么管理员就可以生成任何物品。

  • Magic.commands.mgive : 玩家可以生成物品和法杖
  • Magic.commands.wand : 玩家可以生成法杖
  • -Magic.create.*: 玩家不能生成任何物品和法杖
  • Magic.create.wand : 玩家可以生成名为wand的法杖
  • Magic.create.battle : 玩家可以生成名为battle的法杖
  • Magic.create.stone : 玩家可以生成石头
  • Magic.create.hylian_shield : 玩家可以生成海拉尔之盾

绕过权限
管理员默认拥有一些可以绕过限制的权限：

  • Magic.bypass : 绕过大多数限制和检测。
  • Magic.bypass_build : 玩家可以在建筑限制区域内施法
  • Magic.bypass_break : 玩家可以在破坏限制区域内施法
  • Magic.bypass_pvp : 玩家可以在PVP限制区域内PVP
  • Magic.bypass_restricted : 玩家可以使用受限制的材料进行建筑

进度

法杖进度
玩家合成了一根法杖后就可以通过消耗SP来给法杖添加法术、法力等能力。法术可以通过手持法杖时右击附魔台购买。
每根法杖都有特定的路径，玩家只能购买属于属于或低于该路径等级的法术。当玩家获得了他们当前路径中的所有法术时，他们将“升级”到下一个路径。
默认情况下法杖遵循以下路径：初学者 -> 学者 ->学徒 -> 大师。
查看附魔路径以了解详情。
默认达到大师级为满级。当你达到大师级时，你会被告知你需要“回溯 ”法术来成为工程师。

工程魔法
如果服主选择开启这类魔法，那么玩家可以通过获得“回溯”法术来成为“工程师”。将“engineershop·工程师商店”这个法术绑定到Citizens插件的NPC身上，使用命令方块或其他可以出售法术的商店插件就可以开启工程魔法。
工程魔法是强大的永久性魔法。工程师可以使用魔法进行建筑，并永久改变世界。工程师可以使用“回溯”法术来撤销任何意外的工程魔法操作。
详情查看工程魔法这一页面。
当玩家成为工程师后，他就可以继续附魔法杖以获得更多法术。

建筑师
和工程师一样，建筑师这一等级需要“吸收”法术来解锁。“architectshop”可用于让玩家升阶为建筑师。
建筑师可以使用“吸收”法术吸收世界内的材料到法杖内。这可以让建筑师使用任何不受限制的方块进行自由建筑（默认限制使用屏障和基岩，但可在配置文件内修改限制）。
建筑师也可以继续附魔法杖以获得更多例如“填充”和“超级转换”这样能够修改大片区域内的方块的强大法术。

转变者
转变者目前只能有管理员使用，但服主可以决定是否开放这一职介。
转变者可以获得多个OP专属的法术，（最重要的是）可以不消耗方块使用工程师和建筑师的法术。这会在转变者的法杖描述上显示。
默认配置内管理员法杖就是转变者的法杖，这根法杖无法破坏，施法不消耗法力且施法没有冷却。

工程

工程魔法
Magic内的工程魔法能够建造让玩家使用法杖进行永久的建筑。
和Magic内的大多数法术不一样的是，工程魔法不会在一段时间后撤销自身对世界作出的更改。玩家可以向上或对着使用魔法造出的建筑使用“回溯”法术来撤销上一次工程魔法的操作。
工程魔法一般需要玩家拥有必要的方块才能建筑，所以就资源而言，该系统会尽可能地尝试避免作弊。工程魔法可以通过和WorldEdit指令相似的法术来让玩家快速远距离进行建筑。

笔刷选取
当玩家装备了工程魔法后可以按Shift+Q（潜行键和丢弃键）来打开笔刷选取器。玩家可以在这里选择建筑时使用的建材。玩家必须通过附魔法杖才能获得新的笔刷材料。
当玩家成为建筑师时，就可以使用吸收法术来将任何材料设置为笔刷。

特殊笔刷
玩家可以拥有这些特殊笔刷：

  • Erase·擦除 : 这个笔刷填充了空气，可以高效地摧毁方块。玩家不会获得使用该笔刷擦除的方块。
  • Copy·拷贝 : 这个笔刷自动复制玩家施法目标处的方块。
  • Clone·克隆 : 第一次选取这个笔刷时，笔刷会选区一个样本点。每次之后的施法都会从样本点处克隆方块。
  • Replicate·复制 : 和clone相似，但样本点会在每次施法时移动。这可以让玩家逐块地克隆一大片区域。移动城镇或其他大型建筑时这个笔刷非常有用。
  • Map : 玩家可以通过地图这件物品，使用羊毛、染色玻璃或粘土来进行绘制。工程魔·法使用最近查看过的地图进行建造。
  • Schematics: 玩家可以将Schematic视为笔刷。详情请查看Schematics页面 。

自动机械
自动机械是由方块构成的魔法生物。自动机械是个完全可选的特性，它可以给玩家带来全新的挑战。
Magic有一个通用的自动机械大合集， 自动机械方块可用于生成怪物、添加效果或其他特殊行为。
摧毁自动机械
你必须使用能够摧毁方块的法术才能摧毁自动机械，就比如爆裂法术。当其足够多的方块被摧毁时，自动机械就会死亡。

灵魂
「动态」法术扩展了「模拟」法术，也就是康威的生命游戏的变种。如果你熟悉生命游戏的话，那就再好不过了！如果你不熟悉的话，细胞自动机是一门非常有趣的学科，我建议你了解一下，尽管这并不必要。
你只需知道「模拟」法术将在一定半径内围绕特定类型的方块移动。如果一切顺利的话，随着自动机械的移动，这些方块会被清理。
不过，有些像病毒和蠕虫一样的自动机械会长得很大。
「模拟」法术也会做以下这些事：

  • 它会找到一个新的目标位置。不同的变种有不同的工作方式，但大多数都会以最近的玩家或自动机械为目标，并试图朝其方向移动。
  • 它可能会向自动机械移动的方向施放其他法术。

变种和方块类型
每种自动机械都绑定了特定类型的方块，并且以该方块名名，就比如“猎人-金块”一个自动机械只会模拟（修改）其原生类型的方块，所以你需要注意你创建自动机械所用的方块。很多方块类型默认是受限制的（详见materials.yml），这些限制可以避免创建出由泥土构成的病毒或类似有摧毁性的机械。

极客技术提醒
两个使用了相同方块类型但变种不同的自动机械（比如“猎人-金块”和“护卫-金块”）会模拟彼此的方块。这可能导致自动机械失控，并可能自毁，尤其是在两个不同种的自动机械的规则集不同的情况下发生的可能性更大。
两个同种方块类型和变种的自动机械很可能会在碰撞时取消各自的行动（或者合为一体）。当这种情况发生时，也会出现性能相关的故障，因为它们都是由同一个法师使用的。比如，它们会显示在单个卫星地图标记上 - 如果两个“猎人-金块”自动机械同时激活则图标会到处乱弹。
生成自动机械
每个自动机械都有对应的法术。目前玩家无法自然地获取到这些法术。狼群和康威的法杖拥有以下所有法术，或者你可以使用/wand add 指令添加这些法术：

  • hunter·猎人
  • defender·护卫
  • animate·活化
  • worm·蠕虫
  • virus·病毒
「动态」法术是一个基础法术，它可用于生成一个“魔法傀儡”。这个法术仍在制作中，完成后该法术将可以让你骑上并操控自动机械。
将任何这些法术施放在气泡方块上时会创建一个该类型的自动机械。
死亡后自动机械将施放特定法术（通常是「爆破」或「崩塌」）并掉落一些经验和特殊物品。这件特殊物品一般是法杖——一根没有法力的一次性法杖。
该法杖可用于“唤醒”自动机械，或创建一个不同类型的新的自动机械。

自然生成
你可以配置MagicWorlds 插件来使自动机械在你的世界内自然生成。只推荐在新世界内使用这款插件！
这款插件通过使用“cast”实体生成规则生成自动机械 - 插件有几率在一些类型的实体生成时施放「自动机械」法术。「动态」法术有一个可选的“seed_radius”参数，该参数可使MagicWorlds在创建自动机械前种下方块。这可以让你将自动机械配置为在特定类型的方块处自动生成。
请注意你选择用于替换的实体类型遵循原版光照等级规则。也有个可选的“allow_indoors”参数，这项参数限制自动机械不会在户内生成（在非空气方块下生成）。在下界需要关闭这个参数。
详见"otherside"MagicWorlds示例配置。

警告
一些自动机械，特别是蠕虫和病毒，可能会非常大。它们会以方块的形式侵蚀世界，但只要你选择一个不是自然存在的方块，你就可以使用「超级回溯」和「擦除」法术来恢复。
在尝试使用自动机械之前，最好使用「备份」法术或复制您的世界。推荐创建一个新世界并用于测试自动机械，如果你想要别具一格的世界，我推荐使用 MagicWorlds 。
请谨记默认情况下自动机械会在死亡时掉落其核心。这可以让玩家根据所选的方块类型重新生成自动机械。除非你用权限限制了该法术，玩家都可以获得该物品并在其他世界使用。

自定义
更新的自动机械信息，可在这里查看：
https://github.com/elBukkit/MagicPlugin/blob/master/Magic/AUTOMATA.md

自动机械方块
"mauto"指令可用于添加自动机械方块或自动机械。它们都以"方块怪物"自动机械为基础。
自动机械会在区块加载后激活，在区块卸载后停止运行。停止运行后它们会取消其效果并取消生成其生成的怪物。

添加自动机械
使用 /mautoadd <类型> 指令来在你所在位置添加新的自动机械。
Magic有一些内置的自动机械，就比如 spawner。你可以在automata.yml内添加更多自动机械。

生成怪物
自动机械可通过"spawn.mobs"属性生成怪物。

效果
自动机械拥有"effects"属性，也就是效果的列表 (或参考effects.yml内的全局效果列表)
可用于添加炫酷的粒子特效，比如内置的 fountain·喷泉 示例。

管理自动机械
/mautolist 指令可用于列出所有已激活的自动机械。使用 /mautoselect 指令可以选取已激活的自动机械。
/mautoremove 指令可以删除你已选取的自动机械
/mautodescribe 和 /mautoconfigure 可以查看并更改你选取的自动机械的属性
自动机械可以拥有覆盖配置模板的参数方块，其运行方式和法杖相似。
这意味着你可以使用 /mauto add spawner spawn.mobs creeper 指令来添加苦力怕刷怪笼，或使用 /mautoadd fountain effects earth 指令来添加不同特效。

法术
法术属性
法术的某些基本属性无法通过施法参数或法杖来覆盖。这些属性与“行动”、“效果”和“参数”一样都属于法术配置的基础。
请参阅参考手册以了解所有法术属性的完整描述！
Magic内置的进度系统可以在防止玩家快速刷怪的同时成功使用不同的法术。

收集魔法点（SP）
玩家可以通过成功施法来获得SP。“成功施法” 对于不同的法术意味也有所不同，但一般来说你施法的目标要有效才能成功施法。
当你拿着法杖的时候，你可以在法力条（通常显示在经验条处）上方的数字中看到你当前的SP值。
玩家可以右击一个附魔台来打开法术商店的GUI，在商店内他们可以用SP兑换新的法术。

升级
和附魔法杖类似，当玩家购买了他们当前法杖路径中的所有法术时，他们将“升级”到下一个路径。当玩家下次打开法术商店界面时就可以看到新的法术。

升级法术
法术需要SP才能升级。玩家可以shift+右击附魔台来查看他们的法术升级进度。

SP冷却
施法冷却系统可以使玩家不会在短时间内获得大量的SP。在你第一次施法时你可以获得最多的SP。
之后获得的SP会减少直到超过指定的时间门槛（大多数魔法默认5分钟重置门槛）如果你继续施法，那么你需要等待更长时间才能获得SP。
这个系统用于防止玩家通过刷怪在短时间获得大量的SP，并且鼓励玩家在达到法术SP获取上限时切换使用其他法术。

与Magic关联的插件
其他插件可能会使用Magic的API来关联施法、创建法杖和其它功能。

MagicWorld是一款修改世界的插件。这款插件可以让法杖随机生成在宝箱里。MagicWorlds也可以在实体生成时施法，这可用于使自动机械自然生成。
MagicArenas可以让玩家在竞技场内使用魔法进行决斗。目前该插件最主要的限制就是胜者只有一位，不支持团战。
HexRPG是一款可拓展服务器玩法的RPG插件。玩家的智力可以使玩家更高效地施法。
与其他插件的关联
虽然Magic不需要前置插件，但Magic关联了一些热门插件。
Magic会在检测到这些插件的情况下自动开启相关功能：
  • WorldGuard: Magic会遵循区域的建造和pvp权限，使玩家在区域内的施法视为建造或pvp。Magic在一般情况下不会允许玩家在区域内更改方块。Magic也添加了一些自定义标志比如blocked-spells和allowed-spells，如果你使用WorldGuard6.2或更新的版本, 或使用WGCustomFlags插件。查看区域页面了解详情。
  • dynmap:这是我最喜欢的地图插件！Magic会在卫星地图上显示你丢失的法杖所在处。Magic也会实时显示施法信息。这款插件可以给你的服务器带来一些独特的元素，比如观察玩家和丢失的法杖。Magic还会确保法术对世界所作出的更改会在卫星地图上显示，不过这会根据检测的法术类型数和玩家数而需要更高频地渲染地图。

  • Heroes: Magic添加了一个图形化技能菜单，快捷物品和基于技能施法的法杖。

  • SkillAPI: 可以在法术配置中使用SkillAPI的法力和属性。
  • Citizens: Magic提供了魔法NPC trait来做出可施法和打开内置商店以及其他机制的的NPC。Magic的法术默认忽略NPC，除非法术可指定NPC为目标（比如摄影法术）
  • Skript: Magic提供施法事件和效果。
  • MobArena: 你可以在怪物竞技场内使用魔法物品和魔法怪物。
  • Factions:Magic会遵循Factions的建造权限。
  • Towny:Magic会遵循建造和PVP权限。
  • GriefPrevention: Magic会遵循建造权限。
  • Citadel: Magic会禁止法术破坏加固方块。
  • Lockette:禁止玩家使用法术在上了牌子锁的箱子或门上方建筑。
  • PVPManager: 在关闭PVP时无法使用战斗技能。
  • CommandBook: 可以在传送路径点使用CommandBook。
  • PlaceholderAPI: 可使用这些占位符： magic_path、magic_class、magic_wand和magic_spell。
  • Multiverse: Magic会遵循 MV 的每个世界的PVP设置。
  • LightAPI: 可使用Light行动和光效法术。
  • WGCustomFlags: Magic会添加     "allowed-spells"和"blocked-spells" 标志。安装了WorldGuard     6.2+版本则不需要使用这款插件。
  • Vault:Magic会使用Vault提供的方块名称来显示笔刷材料和在商店中使用Vault的经济系统。
  • Essentials: 可通过告示牌或礼包来出售法杖模板，同时Essentials的地标也可用于传送法术。
  • Elementals: Magic的法术可以反制Elementals的元素 (试试「收缩」法术吧！)
  • MythicMobs: Magic并不直接关联MythicMobs，但你可以使怪物施法。

魔法NPC
魔法NPC可以对玩家施法，让玩家查看法术升级进度，购买法杖、物品、法术等。


入门
首先你需要Citizens的NPC。创建并选取一个NPC，然后输入以下指令：
/trait magic
添加Magic trait。Magic trait只能施法，且只能施放一种法术。在大多数情况下在NPC身上使用自定义法术很合适，不过一些法术无法由NPC施放。

mtrait指令
使用/mtrait指令来配置你的NPC。Magictrait拥有一些可配置的参数。
/mtrait <参数><数值>

Magic Trait参数

  • spell - NPC施放的法术，必须匹配spells.yml内的法术id
  • parameters - 法术的参数，用法和/cast 一样
  • caster - 如果设置为true，NPC会对与之交互的玩家施法默认是由玩家施放法术。
  • permission - 如果设置了这项参数，一名玩家需要特定的权限才能使用NPC
  • invisible - 设置为true 使NPC隐身
  • cost - 使用NPC所需费用 (通过Vault关联的金钱)
  • requires - 使用NPC所需物品 (可以是魔法物品)目前不支持多个物品。
  • hat - 将物品放到NPC头上，可显示法术图标。比如 /mtrait hat tpshop


内置NPC专用法术
以下法术是为NPC而订的：

  • upgrades - 为玩家打开可查看升级进度的GUI
  • spellshop - 打开法术商店，可替代附魔法杖的进度系统
  • magicitemshop - 出售所有魔法物品的商店
  • engineershop - 可以让玩家成为工程师的商店
  • architectshop - 可以让玩家成为建筑师的商店
  • bookshop - 可给予玩家可查看所有法术的魔法书
  • broomshop - 卖扫帚的商店
  • wandshop - 出售一些示例法杖的商店
  • tweakshop - 免费调整法杖的商店 (调整背包/箱子模式等)
  • colorshop - 出售自定义法杖颜色和效果的商店
  • mobshop - 出售自定义生物刷怪蛋的商店
  • withdrawals - 使用货币交换物品的商店
  • deposits - 使用货币交换物品的商店
  • ledgershop - 出售账本的商店
  • lootshop - 出售怪物战利品的商店
  • trinketshop - 出售皮肤头的商店
  • upgradeshop - 出售法杖升级的商店 (升级快捷栏，抗饿等)
  • fillwand - 给玩家的法杖加上所有法术
  • addspell - 可用于给予玩家特定法术
  • enchantwand - 可替换附魔台使用
  • tpshop - 消耗$1，随机传送


NPC法术参数
您可以在游戏内使用/cast 和tab补全来了解可用参数。所有商店都支持一组通用的有用的参数：

  • confirm - 是否出现确认页面
  • path - 玩家必须达到该附魔路径才能使用商店
  • path_end - 玩家必须完成该附魔路径

职业
魔法中的职业是一种以分段方式存储玩家数据的方法。
Magic最初是一个基于物品的插件，法术、法力和其他一切都存储在法杖内上。
7.0版本后，Magic可以让你选择存储一些数据到玩家身上。默认生存配置会存储法术和法力到玩家数据内，同时保留了法术背包和法杖外观。

职业配置
职业可以继承自基础职业，就像这样：
  1. base:
  2.   storage:
  3.     mana: class
  4.     mana_max: class
  5.     mana_regeneration: class
  6.     mana_regeneration: class
  7.     mana_timestamp: class
  8.     spell_levels: class
  9.     spells: class
  10.     brushes: class
  11.     path: subclass
  12.     hotbar_count: subclass
复制代码


"storage" 定义了特定数据存储在哪里。这对于使用低于7.0版本的Magic的服务器尤为重要，这会将数据从法杖物品迁移至玩家身上。
这也会使用比如 /wand 的指令更容易使用。比如你可以使用 /wand add blink 来给法杖添加「闪现」法术，但实际上这个法术添加到了玩家数据内。然而 /wand configure effect_color FF0000 仍会配置法杖物品。
独立的职业配置可能看起来会是这样：
  1. caster:
  2.   inherit: base
  3.   locked: false
  4.   mana_max: 50
  5.   mana: 50
  6.   mana_regeneration: 5
  7.   spells:
  8.   - missile

这指定了这个职业的默认值，当玩家激活这个职业时，他们的初始法力和法术。
默认情况下自动激活职业。法杖被配置为绑定到一个特定的职业上，当玩家持有法杖时将激活该职业。

未解锁的职业
一些配置（比如星战和御术）可能使用了未解锁的职业。
这些职业不会自动解锁和激活。可通过使用 /mage unlock 指令手动解锁职业，或使用职业选择菜单解锁。

自定义插件

Magic这款插件完全可以自定义。插件行为、可用的法术和法杖以及游戏内的所有文本都可以自定义。

我的编辑无效!
请在你编辑器阅读文件内的注释。文件顶部的注释会告诉你插件的功能如何运行。
最重要的是，请勿编辑位于plugins/Magic/defaults文件夹内的文件。
这些文件仅供参考且会在服务器重启后被覆盖。这些文件代表了当前设置，既包含默认配置也包含你编辑过后的配置。
你编辑的配置位于plugins/Magic，如果你还有疑问请继续阅读这个页面的内容。

默认生存配置
如果你不需要自定义Magic的特定方面，那么你最好不用动这些配置文件。默认的配置文件已经过数次优化，足以给玩家带来流畅的游戏体验。
我正在尝试使默认配置能给玩家带来一次平衡且有趣的体验。我希望能够得到你的帮助来实现这个目标 - 我很乐意更改默认配置来使其适应插件的整体愿景。但是，如果您想要真正与众不同的东西，请自行修改！
默认的插件体验详情：

  • 玩家默认没有使用Magic指令的权限
  • 玩家可以合成法杖（用烈焰棒和下界之星合成）
  • (默认禁用的配置功能): 玩家可能会在自然生成的箱子内找到法杖
  • 法杖初始等级很低，但可以用XP来在附魔台处升级法杖
  • 法杖可以用铁砧融合，可以在Magic或Essentials的商店内购买或放入Essentials的礼包内。
  • 使用铁砧名名的法杖绑定到玩家身上，其他玩家无法使用这根法杖。
  • 管理员可以建立任务或其他奖励来升级或创建法杖
  • 法杖无法摧毁。法杖会显示在卫星地图上（需安装Dynmap）来让玩家找到丢失的法杖。
  • 每根法杖都拥有可由玩家操控的独特的法术背包和材质。
  • 使用法杖需要消耗法力，法力会自动缓慢恢复。
  • 所有玩家可以使用全部的法术。
以上任何一条特性都可以关闭或修改。一些不同的选项：

  • 玩家可以选择3种不同的法杖背包模式：箱子背包（默认）、点击循环和强大的快捷栏背包模式。
  • 基于权限的法杖、法术和指令（用于分级、VIP等）
  • 玩家的法杖会在死亡后保留
  • 玩家有权限使用需要消耗原料的法术
  • 则会消耗原料而非法力
  • 使用其他类型的物品作为法杖（附魔剑等     - 也许有朝一日可以实现用弓 + 附魔箭）
另外，默认的法术和法杖目标完全可以修改。
如果你想要本地化这款插件，你只需修改messages.yml。如果你愿意分享你的语言文件的话，我很乐意将其加入到插件资源页面！

插件文件夹布局
一些文件会在你第一次运行这款插件时在plugins/Magic文件夹内生成。

  • defaults:     Magic的默认配置。
  • data:     存储数据。
剩余的文件夹对应你的配置。你可以自定义其中任何的YML文件。

  • crafting:     自定义合成配方
  • enchanting:     进度路径（曾经是自定义附魔）
  • items:     自定义非法杖的原版物品
  • materials:     自定义Magic如何及哦啊胡不同的方块和物品类型
  • messages:     游戏内显示的文本
  • mobs:     自定义怪物，包含一个会施法的怪物
  • spells:     法术、商店、Magic使用行动脚本的任何东西都在这
  • wands:     自定义可以施法的魔法物品

自定义进度
你可以自定义Magic的默认配置使用的进度系统。
Magic的进度可概述为:

  • 玩家可以制作一根法杖，玩家的初始等级是“初学者”。
  • 玩家通过施法获得法术点（SP）。
  • 玩家手持法杖与附魔台交互可以打开法术商店。
  • 法术商店出售初学者可学习的法术。
  • 玩家可以消耗SP从法术商店内购买法术。
  • 每次购买法术可能会增加法杖的法力值、保护或其他属性。
  • 当玩家学会了所有初学者法术后就会升级为学徒。
  • 升级可以提升玩家的法力上限，法杖图标也会变更，一些其他效果也会有所变化。
  • 现在玩家可以在法术商店内看到学徒级别的法术。

法术剖析
大多数法术主要用到了以下5个部分：

  • 基础属性：法术的基础属性有图标、SP消耗和获取数以及其他无法通过升级更改的信息。
  • 行动：新式的法术使用行动系统来让你构造出基于原子结构方块行动的自定义法术行为。
  • 效果：法术可使用可视效果，大多数可视效果出现在施法时。
  • 参数：行动可以拥有更改其行为的参数。参数可通过升级法术、override指令或/cast parameters更改，参数可以让你更简单地在游戏内测试法术。
  • 消耗：法术可以拥有施法消耗，一般消耗法力，但也可以消耗物品、货币或血量。

这些设置定义了SP如何运行。worth 属性是购买法术所需的SP。(或者是其他货币，这取决于法术商店的配置)。

earns_sp 属性定义了施法可获得的最大SP数。当玩家施法获得SP后，再次获得SP会有冷却。在冷却时间内，额外施法获得的SP会减少。这用于防止玩家刷怪并快速升级法术。

earns_cooldown属性定义了获得SP的冷却时间。请注意这不是一般意义上的冷却，玩家在冷却时间内还可以获得SP，不过获得的量会根据时间按比例减少。

比如，第一次施放魔法飞弹时你会获得8SP。如果你在5秒后再次施放魔法飞弹（10秒冷却的一半），你只会获得4SP。
魔法飞弹是玩家使用默认法杖时第一个学会的法术，所以这个法术的SP冷却较低。其他法术的默认冷却都是15分钟。
当魔法飞弹升级后，其SP冷却也会随之增加，直到与其他法术的冷却时间一样。

常见疑问
我怎么才能自定义法术和法杖？
请勿编辑defaults文件夹内的文件。位于"plugins/Magic"的文件将会覆盖默认文件，请将你自定义的文件放在这里。自定义包括默认的法术行为，禁用默认配置，或添加新的法术和法杖。
请谨记无论你添加了什么自定义文件，它都会添加到 defaults文件夹内。如果你想要使用自己的配置，和/或从默认配置中复制法术，你最好在config.yml内设置"load_default_spells: false" 来禁用默认配置。
详见自定义页面。


我使用自定义的配置后出现了报错！
首先请查看你的yaml配置文件内是否使用的是空格而不是按Tab键输出的长空格。
最好使用能辨析Yaml的编辑器而非使用Notepad这样的编辑器。
你也需要确保你的格式没错，example: potter为正确格式，example potter为错误格式。
在你寻求帮助前请先用Yaml验证工具来查看错误所在。

我的法杖在创造模式下显得很奇怪
法杖无法在创造模式下正常使用，对此我无能为力。

我如何本地化这款插件？
所有Magic的游戏内文本都可在plugins/Magic/messages.yml处修改。
详见消息页面。

请查看示例页面。

Potterworld这个服务器用了什么配置?
Potterworld有其基于本插件的哈利波特配置的自定义配置，以及一些订制插件。我并不管理这个服务器，所有不能提供任何细节，也不知道他们做了什么。

我怎样才能更改商店价格？
详见商店页面

我该如何制作自定义法术、法杖和合成配方？
可在这里查看生存配置：
https://github.com/elBukkit/MagicPlugin/tree/master/Magic/src/main/resources/examples/survival
这个页面对于初步了解这款插件很有用。学习制作自定义内容的最好方法就是查看一个你熟悉的法术的运行方式。
如果你对更复杂的法术感兴趣的话，我推荐你查看「地震」和「奇点」的运行方式。自定义页面也对你初步了解自定义插件内容有所帮助。

生存合成配方可在这里查看： 合成配置
你也可以在你的服务器里的plugins/Magic/defaults/crafting.defaults.yml文件处查看。

为什么合成配方里都是下界之星？
我选择下界之星作为合成材料是因为我认为这是一种游戏后期才能获得的物品，我希望法杖是能够让玩家更上一层楼的东西。当然你也可以修改合成配方。

我的法杖无法正常使用！
如果你的服务器版本是CraftBukkit/Spigot 1.7，请使CBBuild特殊版本。另外，创造模式和很多插件都会破坏法杖的特殊自定义数据。Magic在1.8以及更高的MC版本上运行更好。
如果你使用的是1.8+版本，则可能是背包备份插件保存不当而导致的。

我看不见法术图标，图标都变成了钻石斧！
你需要使用资源包才能看到法术和法杖的图标。

什么是等级进度？
法杖等级分为初学者、学者、学徒、大师、工程师、建筑师。工程师和建筑师级默认无法使用（详见下文）。我在我的生存服里使用了一份改过的enchanting.yml 来将玩家等级和法杖等级联系起来，默认情况下法杖等级只是法杖的一项属性。
如果玩家丢失法杖则会失去其所有的进度。

怎么启用工程魔法？
由于工程魔·法破坏服务器经济平衡，所以默认禁用。
当玩家达到大师级（路径最后），就可以学习「回溯」（“撤销”）。如果你想的话，你可以通过使用法术商店来让玩家学习新法术 - 内置的"engineershop·工程师商店"就是用来干这个的，你需要使用Citizens NPC trait来将商店绑定到NPC身上。
同样地，建筑师的「吸收」法术也是锁定的，也有"architectshop·建筑师"来让玩家解锁这个职业。

玩家的法杖丢了，我该怎么办？
"restore"指令可用于恢复玩家已绑定的法杖。这对已绑定的法杖有效。
/wandp <玩家名>restore
恢复玩家的法杖。每种法杖只保存了一个，所以如果玩家有多个同种类型法杖则无法全部恢复。

怎么让NPC成为施法目标？
默认NPC无法被法术选取。你可以在法术参数中加上“target_npc:true”来让该附属可对NPC使用。如果你想要对所有的法术都能选取NPC为目标，只需在spells.yml内的"default" 条目加上这个：

  2. parameters:
  3.    target_npc: true

选择器
使用选择器行动自定义GUI
选择器行动可用于创建可购买、出售或交易物品，给予玩家buff，施法，修改法杖和物品等功能的自定义GUI。
选择器可以在整个GUI或单个选项内指定多个需求。

示例
默认生存配置包含一些选择器的使用示例。玩家右击附魔台看到的GUI是进度菜单。
进度菜单内的每个选项都是不同的拥有独立文件的选择器。
星战配置也有选择职业机制的示例，位于starshop。

自定义GUI
创建一个新的GUI要先使用选择器行动来创建一个法术，就像这样：
  1. starshop:
  2.   icon: sulphur
  3.   category: shop
  4.   hidden: true
  5.   actions:
  6.       cast:
  7.       -  class: Selector

前三项属性并不是必须的，但用于测试、魔法书或显示也许很不错。

  • icon: 法术的图标。
  • category: 显示在/spells指令、网页或魔法书的哪个类别内
  • hidden: 在/spells指令中、网页和魔法书中隐藏显示。
actions部分指定了法术如何运作。在上面的示例中使用的就只有选择器行动。

参数
有一些可用于选择器的顶级参数：
  1.   parameters:
  2.     show_unavailable: true
  3.     confirm: true
  4.     confirm_filler: glass
  5.     auto_close: true
  6.     options:
  7.     - .... 详见上面的选项部分！
复制代码


  • show_unavailable: true/false，是否显示「无法使用」这个选项。
  • confirm: true/false，在选择完成时是否需要确认。
  • confirm_filler: 用于填充确认界面的材料。
  • auto_close: true/false，商店是否自动在玩家选择一个选项后自动关闭。
  • scale: 用于衡量选项中的任何价格的倍数。
  • earn_scale: 用于衡量选项汇总的任何获得物的倍数。
  • title: GUI背包所使用的标题。这也可在messages.yml内设置
  • confirm_title: 在确认选择界面使用的标题这也可在messages.yml内设置
  • unlock_confirm_title: 当玩家解锁一个选项时显示在确认选择界面的标题（购买选项）。这也可在messages.yml内设置


选项
options参数是可指定GUI内每个格子的作用的配置列表。
任何选项的属性都可以在基础选择器参数中指定。在这种情况下，它们将作为所有选项的默认值。
每个选项都可以拥有任何下列属性：

  • icon: 作为图标的物品忽略该选项将自动选择图标。
  • name: 图标标题。忽略该选项将自动决定名称。
  • lore: 图标的lore忽略该选项将自动决定名称。
  • slot: 格子序数。忽略该选项将自动使用未被占用的格子。
  • item: 需要玩家提供的物品。可以是物品名称或配置部分。详见下文。
  • items: 需要玩家提供的多个物品每个物品都可以是物品名称或配置部分。详见下文。
  • cast_spell: 强制玩家施放的法术。可用于打开另一个GUI，或让玩家执行任何法术。
  • commands: 以控制台身份运行的指令。这里可使用各种各样的参数，详见指令部分。
  • unlock_class:  玩家将解锁的职业
  • switch_class: 玩家将成为的职业。玩家当前职业将会无法解锁，新职业将解锁。
  • actions: 选择该选项时运行的行动。可用于制作自我约束的多级GUI，而非使用 cast_spell 来参阅独立的法术配置。
  • effects: 选择该选项时播放的特效。
  • earn: 选择选项时给予玩家的金钱。
  • earn_type: 获得的货币类型。
  • costs: 选择选项时的消耗物。可以是法力、金钱、物品或任何其他已注册的货币类型。(会在你开服时显示)
  • limit: 主要用于unlock_class，指定玩家可以解锁多少个职业。这用于制作"选择一个职业"     GUI。
  • unlock: 用于解锁的特殊键。如果存在则玩家第一次选择该选项时将解锁。之后该选项免费使用。这用于appearanceshop来让玩家收集特殊法杖外观并随时切换。
  • apply_to_caster: 设置为true来将物品直接应用到施放者身上，防止施放者获得作为选项的物品。
  • apply_to_wand: 设置为true可将物品直接应用于施法者的法杖，防止施法者获得作为选项的物品。
  • confirm: true/false,是否需要确认选择。
  • show_unavailable: true/false, 这个选项是否在无法使用时显示。
  • free: 设置为true则免费。可与/cast一同使用来让选择器免费。
  • selected: 当玩家选择该选项时发送给玩家的消息。
  • cost_modifiers: 用于制作基于玩家属性的动态价格。详见下文的价格调节器。
  • requirements: 玩家使用该选项需要满足的需求。

物品
选项中的items和item属性可对每个指定的物品采取两种不同的形式：

物品列表
就只是个物品列表。这里不能设定价格。
如果一件物品没有在配置内指定价值(指令：/mitem save <物品名> <价值>)，则其价值为0。
itemname@amount 格式可用于提供多个相同物品。

配置列表
对于更复杂的商店，可指定物品作为配置部分。
每件物品拥有一些属性：

  • item: 在这格内出售的物品的材料名。
  • slot: 格子序数。忽略这个选项则按顺序使用。
  • cost: 物品价格，如果忽略该选项则使用已保存的物品价值。
  • name: 自定义物品显示名。会用于图标和给予的物品。
  • lore: 物品lore。会用于图标和给予的物品。

价格调节器
价格调节器可用于根据玩家或法杖属性调节选项的价格。比如：
  1.       cost_modifiers:
  2.         - scale: "1 + 9 * (x ^ 3)"
  3.           type: wand
  4.           property: protection.overall
复制代码

根据法杖buff数量增加价格。
type 可以设置为wand·法杖、mage·法师、class·职业或attribute·属性。前三种类型使用了法杖、法师（玩家数据）或职业的属性。attribute 会使用法师职业属性
property 指定使用的属性。对于attribute调节器,你应该使用attribute。
scale 是使用特定属性作为x变量的等式。这个等式决定价格调节器调节价格的方式。
详见法杖buffs。




需求
可以在每个选项上指定一个需求列表，以确定是否允许玩家选择此选项。需求可由其他插件添加，Magic包含了各种各样的内置选项。每个需求可以指定以下任何选项：

  • permission: 玩家必须拥有的权限。
  • path: 玩家必须达到的路径。
  • path_exact: 玩家必须在该路径内。
  • path_end: 玩家必须在特定的路径上且没有可学习的新法术。
  • wand: 玩家必须手持特定法杖。
  • wands: 玩家必须持有多个特定法杖。
  • class: 玩家必须解锁特定职业。
  • active_class: 玩家必须使用特定职业。
  • holding_wand: 设置为true则需要玩家手持法杖。
  • wand_properties: 玩家必须手持有特定属性的法杖。详见下文。
  • class_properties: 玩家使用的职业必须要有特定的属性。详见下文。
  • attributes: 玩家必须拥有特定属性。详见下文。

  • property/attribute: 检测的属性
  • min: 属性下限
  • max: 属性上限
  • value: 属性的确切数值

Magic商店
Magic通过Shop行动支持不同形式的服务器GUI商店。和所有Magic里的的脚本事件一样，商店以法术的形式存在。
详见itemshop这个示例。在 elMakers开发服务器配置内也有很多示例
高级选项：Shop行动重制其参数为拓展选择器参数。

创建自定义商店
如果你继承了buyshop或sellshop法术，那么制作商店就很简单。
让我们看看trinketshop 的一部分：
  1. trinketshop:
  2.     inherit: buyshop
  3.     hidden: true
  4.     parameters:
  5.         items:
  6.         - skull_ale
  7.         - skull_apple
  8.         - skull_aquarium
  9.         - skull_arrowdown
  10.         - ...
复制代码

这个法术只有三项属性：

  • inherit 继承所有特定法术的属性。比如你想要使 buyshop 能让玩家购买物品，sellshop 能让玩家出售物品。如果你想要深入了解的话查看下面的选择器。
  • hidden 这让法术不会在/spells list的法术列表、魔法书和网站内显示。一般不需要用到这个。
  • parameters 这是设置可购买或出售的物品的地方。

参数
商店法术的参数主要使用 items 参数, 用于设置商店里的物品。
你也可以在商店内使用 scale 参数，就比如lootshop，这个参数会使物品价格升降。在出售商店的示例中，我使用了一个scale（天平）来变化物品的价值。
其他参数包括：

  • confirm: true/false,是否在购买结束前显示确认屏幕。
  • confirm_filler: 填充确认屏幕的物品材料名。
  • auto_close: true/false, 商店是否自动在购买完成后关闭。设置为false可使玩家快速交易大量物品。
  • sell: 设置为true商店只出售物品。高级选项：这重写很多选择器参数以翻转价格和结果。

物品列表
商店内的items 参数可以有两种不同的形式：

物品列表


只是一个简单的物品列表。必须为物品配置中的每个物品设定价值。可通过items.yml文件修改价值，或在游戏内输入 /mitem save<价值> 来设置物品价值。
如果一个物品没有设定价值，则其免费。
itemname@amount格式可用于提供一个格子内的多个物品。
配置列表


对于更复杂的商店，可以在配置部分设置物品。详见elMakers开发服务器的fieldshop示例。
商店内的每件物品都可以有一些属性：

  • item: 该格出售的物品的材料类型。
  • slot: 格子序数。忽略该属性则按顺序填充。
  • cost: 物品价格，将使用已保存的物品价值。
  • name: 物品显示名。该格的图标是该物品。
  • lore: 物品的自定义lore。该格的图标是该物品。
空格子

可将none放在选项列表内来代表空格子，用于给你的GUI排版。

更改价格
可以用以下两种方式更改默认内置商店的价格。

物品商店
对于简单的物品商店，最好更改物品的数值而非更改每个商店的价格。这样你的物品就可以在不同的商店之间保持一致的价格。
这可以通过在items.yml中添加如下内容实现：
emerald:  worth: 1000或在游戏内手持你想要设置数值的物品并输入 /mitem saveemerald 1000
[size=13.3333px]
法杖和其他复杂商店
对于非物品，比如法杖和法术，商店都有会内置的价格。你也可以修改相关参数来修改非物品的价格。复制默认配置到Magic/spells文件夹内并编辑。
比如magicitemshop，这个商店里有每件物品的价格。只需复制该文件到你的法术文件夹（或粘帖到spells.yml内）即可随意编辑价格。
这也是你添加和删除商店内的物品的方法。

选择器行动
Shop行动拓展了选择器，提供了一种更简单的设置商店的方法。
这意味着所有选择器行动可用的参数和其选项都可在商店和商店物品处可用。
详见选择器页面。

这个指令和其他示例一样，但这个指令禁用的是一堆法术而非一类法术。请注意这里用的是法术键名，不是在游戏内翻译过的名称。

自定义标志
Magic提供以下自定义标志：
  • allowed-spells 可使用的法术，优先度高于PVP和build·建造权限
  • blocked-spells 禁止使用的法术，优先度高于allowed-spells
  • allowed-spell-categories 可使用的一类法术
  • blocked-spell-categories 禁用的一类法术
  • allowed-wands 可使用的法杖，优先度高于wand use权限
  • blocked-wands 禁止使用的法杖，优先度高于allowed-wands
  • spell-overrides 用于"/wand override" 之类的指令，可用于使一些法术在不同区域内有不同的表现行为
  • destructible 设置破坏性法术可破坏的方块
  • reflective 设置能反弹法术的方块

通配符
"*"可用作通配符，代表 "全部"。"/region flag somewhere blocked-spells *" 则为禁止在区域内施放所有法术。
"-" 代表"无"。比如如果你有一片你想要允许施放所有法术的区域，而在该区域内有一个优先度更高的子区域，你可以输入以下指令：
  1. /region flag outer allowed-spells *
  2. /region flag inner blocked-spells blink,fling
  3. /region flag inner allowed-spells -

游戏内自定义
对于想要作出更改或测试更改后的配置的用户而言， /mconfig 指令可以让你在游戏内更改配置。

指令用法
mconfig 指令遵循以下格式：
/mconfig <行动> <类型> <key>
行动：
disable, enable, configure Types: spell, wand, recipe, mob, item, class, path, automaton, effect, attribute
在使用了任一指令后，你必须输入 /magic load 来应用新的配置。

禁用
你可以用指令快捷地禁用法术、法杖或合成配方。比如：
  1. /mconfig disable spell blink
复制代码

这个指令会禁用「闪现」法术。如果你不打算禁用法术了，你可以输入：
  1. /mconfig enable spell blink
