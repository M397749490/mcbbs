知识点：1.4.7以后的物品贴图注册，以及资源文件的搜寻

在MC1.4.7及以前版本，MC中的物品贴图使用一张大小256x256的自定贴图，并且对每一个物品，指定其中的一个16x16的区块作为一个物品的图标。这样的贴图管理方法可复用性很低，每次改一张贴图都要修改整张大贴图。在MC1.5以后，mod的贴图注册方式发生了巨变。MC引入了Icon（图标）类，用来指示一个物品/方块的图标。
Icon类一般需要在Item或者Block的registerIcons(IconRegister)函数中进行统一注册。在所有物品注册完毕以后，MC会将它们绘制到一张统一的大png图中（也就是terrains.png和items.png），并且用内部管理的坐标进行绘制。这样既保证了运行效率，又降低了美工的工作量。
在1.5和1.6时代，很多modder纠结的文件位置问题，其实非常简单：

贴图文件/资源文件的指定格式： "[名称空间]:[贴图名 or 资源名]"

其中，名称空间用来区分贴图文件所属的mod。它可以和主类中modid所指定的名称有所不同。你可以任意给你的mod贴图选择一个命名空间: "mymod", "ic2", "lambdacraft", ... 只要你觉得舒服都行。在1.6以后，MC会在以下的工作路径搜索一般的资源文件：
"[工作路径]/assets/[名称空间]/..."

其中，对于mod来说，工作路径就是mod压缩包的根目录。

对于物品的贴图加载，MC会在以下路径中搜寻相关贴图：

"[工作路径]/assets/[名称空间]/textures/items/[贴图名].png"

在上面的法杖注册代码中，我使用了setIcon("graphrevo:frozen_wand") 函数。这样，当注册Icon的时候，MC就会到 “assets/graphrevo/textures/items/frozen_wand.png” 搜寻贴图文件。

知识点：实体渲染的绑定、Render类

作为MC中渲染的重要环节，Forge毫无疑问提供了方便的为实体进行渲染的途径。通过 RenderingRegistry.registerEntityRenderer(Class <? extends Entity>, Render) 函数，我们可以为一种Entity绑定渲染器。当这类实体在Client端生成时，便会调用相应的渲染器进行渲染。
绑定的渲染器是一个Render对象，它需要实现如下方法：
    public void doRender(Entity entity, double x, double y, double z,  float f, float f1)；
    protected ResourceLocation getEntityTexture(Entity entity)；

其中，第一个doRender函数是进行渲染的关键。如果Entity出现在玩家视野内，这个函数会在每一帧被调用以进行渲染。至于具体如何编写，我们会在后文中详细阐述。
而getEntityTexture函数，字面意义是获取实体的贴图文件。不过目前意义不明，似乎Forge也没有帮你绑定贴图。return null就可以了~

知识点：相关函数和方法

Minecraft使用的图形API是OpenGL，因此所有OpenGL的图形函数在渲染器中都适用。
常见的几个渲染函数：
glTranslate ： 将坐标进行位移变换。
glRotate：将坐标进行旋转变换。
glScale：将坐标进行缩放变换。
glEnable、glDisable：打开/关闭某种特定功能。
glBlendFunc(int, int)：设置融合方法。
glColor：设置当前绘制颜色。
glPushMatrix(), glPopMatrix()：推入/弹出栈。
OpenGL是一个内容极其丰富的API，在此不作更多列举。关于具体函数的功能和使用，在之后的教程中会逐步进行说明。

对于Minecraft，它的渲染方法在OpenGL的基础上有所扩充和修改。
首先，在图形的绘制方面，Minecraft使用了一个统一的镶嵌器（Tessellator），来接管顶点和多边形的绘制工作，同时进行一些统一的光照处理，所有的图形绘制工作都要调用tessellator的实例才能完成。
对于实体、物品的渲染之类，它已经事先替Modder做好了局部坐标的变换，Modder只需要在一个相对固定的局部坐标系里进行绘制，减小了工作量。
实际上这里个人认为MCP开发组把这个类翻译为Tessellator很不恰当，毕竟只提供了一些辅助的功能嘛0w0
关于镶嵌（曲面细分）：维基百科

关于贴图绑定等动作，MC也有自己的一套机制。在MC1.6.2以后，所有的资源文件（声音，贴图）统一使用ResourceLocation进行定位，MC也为此提供了相应的绑定方法。
常见的MC渲染方法：
Tessellator t = Tessellator.instance; //获取着色器
t.startDrawingQuads(); //开始绘制 类比glBegin()
t.addVertex(); //绘制一个顶点 类比glVertex3f()
t.addVertexWithUV(); //绘制一个带UV坐标的顶点
t.draw(); //结束绘制，将信息存储到绘制缓存 类比glEnd()
t.setColorOpaque_f(R, G, B, A); //设置绘制颜色 相当于glColor4f
Minecraft.getMinecraft().renderEngine.bindTexture(ResourceLocation) //绑定贴图
OpenGlHelper.setLightMapTextureCoords(...) //设置光表面贴图坐标
......

题外话：关于ResourceLocation

ResourceLocation是MC中用来表示资源文件位置的特殊类，它在MC1.6以后被引入。从MC1.6以后，MC的文件系统发生了巨变，不过在文件结构的控制上，对Modder来说方便了很多。
ResourceLocation的定位方法：
在MC164中，和贴图文件的命名规则一样，你可以用两个字符串精确定位一个资源文件的位置——名称空间和路径。
如果我要绑定一个位于"/assets/mymod/textures/test.png"的贴图文件，我可以这么写：

  2. ResourceLocation rl = new ResourceLocation("mymod:textures/test.png");
  3. Minecraft.getMinecraft().renderEngine.bindTexture(rl);

第一个语句获取了着色器实例，方便后续绘制。

  2. GL11.glPushMatrix();
  3. //...
  4. GL11.glPopMatrix();
复制代码

注意到，在实际的绘制代码前，我调用了glPushMatrix(), 在绘制后则调用了glPopMatrix()。顾名思义，这两个函数的作用分别是“推栈”和“弹栈”。GL使用栈的机制来管理渲染管线，当你Push以后，可以当做进入了一个子渲染块。在PushMatrix()和PopMatrix()之间，你对所有坐标所做的旋转、变换、缩放，都只对在这个子渲染块中进行的绘制有用。你可以当做PushMatrix和PopMatrix函数为你的绘制构建了一个定义域，让它的坐标变换只在定义域内起作用。调用glPopMatrix之后，这个”子渲染块“从栈中弹出，和其他的世界坐标一起，进行更高层次的坐标变换。

*所有的实体、物品等的绘制代码都需要摆放在glPushMatrix()和glPopMatrix()之间。否则？自己试试看会有什么神奇的效果~\(≧▽≦)/~

然后，是对渲染内容的基本设定和预处理。
  1.         renderEngine.bindTexture(GRClientProps.TEX_FROZEN_MAGIC); //绑定贴图
  2.         GL11.glDisable(GL11.GL_LIGHTING); //关闭光照
  3.         GL11.glEnable(GL11.GL_BLEND); //开启混合
  4.         GL11.glBlendFunc(GL11.GL_SRC_ALPHA, GL11.GL_ONE_MINUS_SRC_ALPHA); //混合模式设定
  5.         GL11.glDisable(GL11.GL_CULL_FACE); //关闭面剔除
复制代码
首先，我为当先绘制操作绑定贴图，然后关闭了GL光照。（魔法当然不需要随着黑夜降临变暗不是么？！）
不过关闭GL光照还不足以让魔法一直发亮，因为MC还有一套自己的光照机制，在后文会有提到。
通过glEnable(GL_BLEND)，我开启了贴图混合。所谓混合，也就是”透明“效果。它让png中的alpha通道得以激活，并且与后层的内容混合，体现出透明效果。如果不打开它，我们便会看见一坨不透明的迷の物体飞过（你够）。

glBlendFunc(GL_SRC_ALPHA, GL_ONE_MINUS_SRC_ALPHA) 则是设置了上下层的混合模式。其中第一个参数制定了源层（也就是我们的绘制层）的透明模式，第二个参数制定了目标层（背景层）的透明模式。
这个函数有以下可用参数：

  2. GL_ONE 始终为1 （全颜色）
  3. GL_ZERO 始终为0 （无颜色）
  4. GL_SRC_COLOR 源像素的亮度值
  5. GL_SRC_ALPHA 源像素的ALPHA值
  6. GL_DST_COLOR 目标像素的亮度值
  7. GL_DST_ALPHA 目标像素的ALPHA值
  8. GL_ONE_MINUS_SRC_COLOR 1-源像素的亮度值
  9. ……
复制代码
通过将源模式设置为GL_SRC_ALPHA, 目标模式设置为GL_ONE_MINUS_SRC_ALPHA，我们让贴图呈现出标准的透明效果。
最后，我关闭了面剔除。在常见的绘制情况中，常有绘制的四边形只需要看见一面的情况（如：方块只需要看见外表面）。在这种情况，使用默认开启的面剔除，可以提高绘制效率，升高fps。在这里，因为两面都需要渲染，所以关闭了它。

  3.         GL11.glRotatef(-entity.rotationPitch, 1.0F, 0.0F, 0.0F);//上下旋转
复制代码
这三句代码，是对于绘制物体的变换函数。在后续代码的绘制中，我在（0, 0, 0）附近，绘制了两个面向Ｚ轴正方向，垂直相交的平面。通过这三个语句，两张正交贴图得以进行正常的旋转和唯一，渲染到我们需要的位置。
你可能有疑问了：为什么需要先变换再绘制呢？这不合逻辑啊！实际上在OpenGL最终的调用中，确实是先进行的绘制，再进行的变换。其原因，还是由于OpenGL的栈。

知识点：OpenGL的栈机制

在绘制代码中，我们实际需要把绘制代码倒过来读。在这里，我的绘制顺序其实是这样的：
调用着色器绘制->上下旋转->横向旋转->位移到Entity位置

其原因，在于栈的存储机制。栈使用的是一种后进先出的存储。就像往装乒乓球的盒子里顺序塞乒乓球，我们拿出来的第一个球一定是我们最后装进去的那一个。在我们调用了绘制和变换函数之后，OpenGL把它们存储在栈中。在实际的绘制之中，再把它们倒着拿出来。这样，就造成了我们需要倒序进行代码的书写。


在理解了绘制的顺序之后，剩下的工作也就水到渠成了。首先，我们使用mc的镶嵌器把贴图以矩形平面的形式绘制出来：
