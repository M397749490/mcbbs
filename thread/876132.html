简介 · Introduction

你是否想更高效地编辑YAML、 JSON & TOML 文件？

是否想要在编辑YAML文件时保留注释？

是否想要不用yml文件来存储数据？

是否想要在配置文件上节约最多90%的时间?



那么这款插件就适合你





我曾经想要不依靠bukkit或BungeeCord来存储数据。但是我其他插件库没有能做到这点的，于是我开发了这个插件库。当然有一部分插件做到了这点，但功能不能让我满意。比如ThunderBolt-2只支持JSON文件而不支持nested objects。

现在我公开发布这款插件是因为我认为该插件质量已经很高了。





目前LightningStorage支持两种文件类型：



JSON


  1. 一种简洁的文件格式。存储速度比YAML文件快，适用于存储数量较大的数据，比如玩家数据(头衔、金钱、游戏时间等.)

  2. 目前该格式暂不常见点这个格式很好用。

优点
专业:
大多数SpigotMC上专业的插件开发者使用自己的配置库来满足自己的需求- 他们不会使用bukkit提供的库。
对于LightningStorage ，我查看了很多插件开发者私人的库并与其交流来得出提效的方法。

LightningStorage结合了很多开发者的主意。

独立:
该插件不需要任何前置。
你可以用在 Bukkit 或 Proxy 的插件内 - 甚至可用在独立的Java程序上!
你可以在任何版本的 Minecraft 里使用，无论是什么平台 - LightningStorage 都可以用.


使用方便:


可自动创建所有文件夹，并且还有更多提效的方法!



灵活 - 由你决定:

你是否想尝试更多的文件格式?

效率:

讨厌为了一个配置而敲上百行的代码?

如果你想要提升开发插件的效率, 这个插件库就很适合你。

主要提效功能:

setDefault:
这可以只在文件不包含关键词时设置一个数据。


getOrSetDefault:
这可以只在文件不包含关键词时设置一个数据。
如果文件不包含关键词则返回默认数值.
如果文件包含关键词则返回自身数值 (并非默认数值)

如果你的插件支持多语言的话这十分有用。
你可以只用一行来 获取·get&set·设置 消息!
相信我，这可以节约很多时间。


setPathPrefix:

这个method 设置了一个 pathPrefix 而不需要你输入一堆东西!

这可以减少你输入

get("spawn.x")
get("spawn.y")
get("spawn.z")

你只需输入:

setPathPrefix("spawn")

然后

get("x")

这个 method 也减少了你的编程时间并让你的代码更加美观!


智能:
忘记添加 /config reload 指令!
LightningStorage 可自动重载文件。
你也可以配置LightningStorage 如何重载配置文件



保留注释!:

LightningStorage可保留所有的注释!
比如config class for example 可自动处理，你只需输入:


你文件内的所有注释都会被保留!
不需要使用其他的库!
提醒

如果你在一个YAML文件内设置了多个相同的关键词这可能会出错。
并且暂时不能保留side注释。
这是由 YamlBeans 保存方式导致的。
我将编写 YAML-解析器来修复这个问题。

安装
1. 将这串代码置入你的 repository-section:

  1. <repository>
  2.     <id>jitpack.io</id>
  3.     <url>https://jitpack.io</url>
  4. </repository>
复制代码
2.将这串代码粘帖到你的 dependency-section:

  1. <dependency>
  2.     <groupId>com.github.JavaFactoryDev</groupId>
  3.     <artifactId>LightningStorage</artifactId>
  4.     <version>2.3.4</version>
  5. </dependency>
复制代码
3. 最重要的一步! 使用一个shade 来确认本插件已嵌入你的 .jar文件内. 推荐relocation。
示例如下：

  1. <plugin>
  2.     <groupId>org.apache.maven.plugins</groupId>
  3.     <artifactId>maven-shade-plugin</artifactId>
  4.     <version>3.1.0</version>
  5.     <executions>
  6.         <execution>
  7.             <phase>package</phase>
  8.             <goals>
  9.                 <goal>shade</goal>
  10.             </goals>
  11.         </execution>
  12.     </executions>
  13.     <configuration>
  14.         <createDependencyReducedPom>false</createDependencyReducedPom>
  15.         <relocations>
  16.             <relocation>
  17.                 <pattern>de.leonhard</pattern>
  18.                 <shadedPattern>yourpackage.yourname.storage</shadedPattern>
  19.             </relocation>
  20.         </relocations>
  21.     </configuration>
  22. </plugin>
