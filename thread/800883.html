这是一款和Skript类似的，可以通过编写脚本达到不同效果的脚本引擎插件，通过这些脚本，可以做到指令触发事件，权限限制，读取配置等Bukkit插件能做到的事情，只要愿意研究，用它编写一些满足服务器需要的脚本，完全不逊色于Bukkit插件

触发型脚本的两个核心元素为“什么导致触发？”和“触发以后执行什么？”
让我们先从一个最简单的指令脚本开始讲起
  1. # 该脚本的功能是：玩家执行指令/test，显示一条提示语后获得金钱
  2. # “获得金钱”的脚本需安装Vault
  3. test:
  4.     type: world
  5.     debug: false
  6.     events:
  7.         on test command:
  8.         - determine passively fulfilled
  9.         - narrate '<&e>你刚刚执行了指令/test！你获得了 50 金币！'
  10.         - give money quantity:50
复制代码
我们可以看到，这个脚本的触发条件是“on test command”，即“执行了指令/test后会触发”
当玩家满足触发条件后，便会执行下面几个脚本“显示提示语”和“给予金钱”
脚本中的“determine fulfilled”代表告诉Bukkit：“/test”这个指令已经处理过了，如果不包含这个脚本则Bukkit会输出不存在这个指令（尽管如此但是余下的脚本还是会运行）

★数据类型
一个变量究竟是什么？是一种物品？一个坐标？一串数字？还是一只生物？
为了防止混乱，Denizen让每个变量都拥有了数据类型，你可以在Mech Search查看所有数据类型
数据类型的名称是一个小写字母d后面跟一个单词，例如dEntity代表“实体数据类型”
在某些脚本中调用变量时，必须关注其数据类型，用错数据类型的脚本通常会导致bug产生
比如使用take脚本取走玩家手中一个物品时，正确写法是：
  • - take <player.item_in_hand> quantity:1
错误写法是：
  • - take <player.item_in_hand.material.name> quantity:1
虽然上面两个脚本中使用的变量，返回值从文字上看并无区别，但是其数据类型不同，前者是dItem，后者是文字，物品可以取走，文字怎么取得走？

可以通过附加变量，直接对某类型数据进行更改：
  • <player.location> - 返回的是玩家当前坐标（dLocation）
  • <player.location.add[0,2,0]> - 返回的是玩家当前坐标Y轴向上偏移2格的坐标（dLocation）

也可以通过附加变量让变量在不同的数据类型之间转换，比如上面引用的例子

如果你给某变量指定了名字，为了防止混乱，可以在脚本调用这个变量时在前面加一个标识来指代其变量类型，例如，你创建了一个物品，名叫custom，但是这个名字没有标注变量类型（一本书可以叫custom，一只怪物也能叫custom）因此在调用此变量时可以使用i@custom来告诉Denizen：这是一个物品类型的变量（dItem）
同理：

  • b@custom代表这是一个生物群系类变量
  • w@custom代表这是一个世界类变量

1.3 脚本if
通过if来讲权限限制

if脚本只是众多脚本之中的一种，其功能是：若玩家符合条件，则执行子脚本，若不符合条件则跳过
那么我就用这个脚本来做出“给指令添加权限限制”的效果
  1. # 该脚本的功能是：有权限和无权限server.vip的玩家进服，显示不同的消息
  2. test:
  3.     type: world
  4.     debug: false
  5.     events:
  6.         on player joins:
  7.         - wait 1t
  8.         - if <player.has_permission[server.vip]> {
  9.           - narrate '<&a>亲爱的VIP玩家欢迎回到服务器！'
  10.           }
  11.         - if !<player.has_permission[server.vip]> {   
  12.           - narrate '<&a>欢迎您来到本服务器'
  13.           - queue clear
  14.           }
复制代码
该脚本被触发后执行脚本if，首先会判断其后变量是不是true（该变量可以是布尔值变量）
若变量条件符合，则执行下面的子脚本，若不符合，则跳过子脚本，继续进行下一步
在变量的前面加一个感叹号!或者加一个附加变量<[element].not>代表反向含义

当然，if脚本不一定判断的只能是布尔值变量，也可以判断两个相同数据类型变量是否相等或者谁大谁小，即 if A = B
请看例子，这里我们判断的是玩家主手的物品
  1. # 该脚本的功能是：手持石头输入/sellhand可以卖出1个石头并获得10金币
  2. test:
  3.     type: world
  4.     debug: false
  5.     events:
  6.         on sellhand command:
  7.         - determine passively fulfilled
  8.         # 如果玩家主手上是空气，即“什么都没有”，输出信息，同时终止序列，脚本不再往下运行
  9.         - if <player.item_in_hand.material.name||null> == air {
  10.           - narrate '<&a>你手上什么都没有，你必须把要出售的物品拿在手上！'
  11.           - queue clear
  12.           }
  13.         # 如果玩家手上不是石头（当然也不是空气）
  14.         # 输出信息，同时终止序列，脚本不再往下运行
  15.         - if <player.item_in_hand.material.name||null> != stone {
  16.           - narrate '<&a>目前本服务器只允许出售石头，请把石头拿在手上！'
  17.           - queue clear
  18.           }  
  19.         # 如果玩家主手上有石头，扣除主手上的一个物品，输出信息，给予玩家10金币  
  20.         - if <player.item_in_hand.material.name||null> == stone {   
  21.           - take iteminhand
  22.           - narrate '<&a>你出售了1个石头，获得10金币'
  23.           - give money quantity:10
  24.           }

1.4 脚本flag
标记 | 我已经做过这件事了？

当你给玩家加了某些效果以后，什么时候该把效果去掉？本插件该用什么来确认“这效果还在不在玩家身上？”
这时就应该使用flag标记，给玩家加上效果以后顺手给玩家加个标记，当插件想去掉效果时
首先会检测有没有标记：“哦~这家伙身上有标记，说明效果还在，移除掉！”
这种脚本大大减少了bug的发生率，很多bug产生的原因是因为：加了效果忘了移除
BUG高发提示：加了flag以后，什么时候该移除flag要考虑的非常周全，比较容易犯错误的地方有：玩家下线flag没移除，玩家死亡flag没移除，玩家转换世界flag没移除……等等

先看例子：
  1. # 该脚本的功能是：主手或者副手手持火把，可以作为光源照亮周围，并跟随玩家移动
  2. test:
  3.     type: world
  4.     debug: false
  5.     events:
  6.         on player steps on block:
  7.         # 若玩家有标记，则移除光照同时移除标记
  8.         # 因为生成的光照本身是无法“移动”的，必须消灭旧光照产生新光照来达到“移动”
  9.         - if <player.has_flag[torch_light_prev]> {
  10.           - light <context.previous_location> reset
  11.           - flag player torch_light_prev:!
  12.           }
  13.         # 若玩家主手/副手之一拿了火把，则给玩家所在位置Y轴+1的位置加上14亮度，同时给玩家加上标记  
  14.         - if <player.item_in_hand.material.name||null> == torch || <player.item_in_offhand.material.name||null> == torch {
  15.           - light <context.location.add[0,1,0]> 14
  16.           - flag player torch_light_prev
  17.           }
  18.         # 当玩家下线时，若玩家身上有标记，则移除光照并移除标记
  19.         # 这是一个好发bug的地方：玩家都下线了，效果还在        
  20.         on player quits:
  21.         - if <player.has_flag[torch_light_prev]> {
  22.           - light <context.previous_location> reset
  23.           - flag player torch_light_prev:!
  24.           }

脚本flag的格式是
- flag <player> <标记名>

1.5 脚本adjust
对变量进行“调整”

adjust字面意思翻译过来就是“调整”，其意义是对变量本身进行调整，或者对变量某一属性进行调整
该脚本的标准格式为
- adjust <变量> <属性:调整后的值> [save:临时的保存名]

同时该脚本有两个相关的变量，可调用已经调整过的保存的变量：
  • <entry[临时的保存名].result> 返回的是已经保存的单个变量
  • <entry[临时的保存名.result_list]> 返回的是已经保存的一组数据变量（dList）

需要注意的是adjust脚本并不能调整变量本身的数据类型，举个例子：你可以把“猪”调整为“幼年猪”“有鞍的猪”，而不能调整为“钻石”，因为数据类型不同

  6.         on onlinereward command:
  7.         - determine passively fulfilled

  9.           - narrate "感谢您在本服务器游玩，您收到了在线奖励 $50.00!"
  10.           - give %value% money qty:50
  11.           }

阈值上出现问题的指令经常会造成严重bug（比如：加负数金钱）需要对指令参数进行阈值的判断，来避免问题

为了理解后面的内容，首先要厘清一个重要区别：

磁盘里的配置文件和内存里的已加载配置

你在文件夹里看到的一个一个的config.yml，是磁盘里的配置文件
磁盘里的配置文件必须先加载进服务器内存，才能被读取/修改
Denizen只能对内存里的配置文件进行修改，然后把已经修改好的配置一股脑地保存进磁盘里的配置文件
为了内部方便，Denizen给每个内存里的已加载配置都赋予了一个id，这个id可以和配置文件本来的名字不同
厘清这两者的区别以后，后面的内容就很好理解了


你写的脚本到底有没有必要搞配置文件？以下是一些建议：

★如果你写脚本是为了给自己的服务器用
只是给自己用的话，添加配置文件只是徒增麻烦，我建议你不要弄配置文件，直接在脚本里修改就好

★如果你写脚本是为了发布给别人用
这种情况我建议还是添加配置文件比较好，用户可以一目了然地编辑，同时更有逼格，在MCBBS申请发布奖励时也可以更被版主看重



3.2 生成与加载配置文件 | 脚本yaml
一般插件的惯用步骤，一步一步来
首先需要介绍一个新脚本：脚本yaml
这个脚本可以用于生成配置，加载配置，卸载配置，读取并调用配置文件里的东西，保存修改到配置文件等等
前文里已经讲了内存和磁盘配置文件两种形态的区别，接下来只要不涉及保存的，我们一律以内存里的已加载配置作为介绍中心，所谓的“配置id”也都是针对内存里的配置而言的

常用的关于yaml的脚本：

★生成配置（不是直接生成配置文件，搞清楚区别！）
  • - yaml create id:<配置id>

★编辑配置（如果路径不存在则会自动创建）
  • - yaml id:<配置id> set 路径.子路径.子子路径:<值>

★保存配置至文件/从文件加载配置至内存
所谓的文件夹路径，其根目录都是你插件文件夹里的Denizen文件夹
  • - yaml savefile:/<文件夹名字>/<配置文件名>.yml id:<配置id>
  • - yaml load:/<文件夹名字>/<配置文件名>.yml id:<配置id>

★常用变量
  • <yaml[<配置id>].read[<路径>]> —— 最常用的变量：读取配置中某个设置项的值
  • <yaml[<配置id>].read[<路径>].as_list> —— 若路径下包含多个子路径以及多个值，则以dList组数据的方式输出
  • <yaml[<配置id>].contains[<路径>]> —— 布尔值变量，某配置文件中是否包含某路径
