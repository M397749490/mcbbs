Sponge服务端·优化篇
声明
        本贴所有的心得经验都是笔者多年开服的经验中学习和整理的，有些资料在网上能够找到但是本文并不会原文剽窃！
        本帖将会长期缓慢更新，计划会分多个模块讲解Sponge服务端的优化方法，欢迎各位腐竹参与讨论交流。
第一讲·tileentity-activation
原理
       Sponge通过“MIXIN”（我也不是很懂，欢迎dalao指点）对不同mod限制其TileEntity每秒获得的Tick速率，理想情况下，每一个TileEntity每秒获得20tick（你可以理解为刷新20次），但是并不是每一个TileEntity都需要每秒获得20Tick（例如炼药锅），当使用这个方法为部分TileEntity降低tick频率的时候，能够大幅度的降低服务器计算的负担。
举例
       在MC1.10.2的IC2ExpMod中，风力发电机的刷新占用大量的服务器资源，通过Timings不难发现，多个被加载的风力动能发电机往往会十分直观的增加服务器TPS丢失率，因为这些TileEntity都会不停的检测周围方块（比如周围16格是否有风电机挡住转子接风），因此带来的服务器运算资源的消耗十分可观，但是通过此方法降低风电的Tick获得效率之后，风电的检测次数将会明显下降，服务器的计算负载也会随之降低，但是我们会面临一个问题，以前100EU/Tick的发电量将会因为Tick获得次数的减少导致风电产能的减少，此时我们需要协同修改IC2.ini(工业配置文件)。
用法说明
使用此功能大概需要以下几步：
  • 找到并打开Config/Sponge/Globle.cfg文件
  • 在“modules”模块下找到“tileentity-activation=false”，将对应的值改为true
    1. <b>modules</b> {
    2.         block-capturing-control=true
    3.         bungeecord=false
    4.         entity-activation-range=true
    5.         entity-collisions=true
    6.         exploits=true
    7.         game-fixes=false
    8.         optimizations=true
    9.         # Use real (wall) time instead of ticks as much as possible
    10.         realtime=false
    11.         # Controls block range and tick rate of tileentities.
    12.         # Use with caution as this can break intended functionality.
    13. <b>        tileentity-activation=true</b>
    14.         timings=true
    15.         tracking=true
    16.     }
    复制代码

  • 找到“tileentity-activation”模块，将“auto-populate”对应的值设置为true
    1. tileentity-activation {
    2.         # If enabled, newly discovered tileentities will be added to this config with default settings.
    3.         auto-populate=true（笔者注：自动获取可修改的TileEntity并记录在下面）
    4.         # Default activation block range used for all tileentities unless overidden.
    5.         default-block-range=256（笔者注：只有在此范围内有玩家时才为对应的方块激活，否则不会更新）
    6.         # Default tick rate used for all tileentities unless overidden.
    7.         default-tick-rate=1（笔者注：若将默认tick率设为X，获得的Tick为20/X，即当x=10，实际获得2tick/秒）
    8.         # Per-mod overrides. Refer to the minecraft default mod for example.
    9.         mods {}
    10. }
    复制代码

  • 保存文件并重启服务端 （注意：此处必须重启服务端侧能生效，亲测重载指令无效）
  • 重启后，再次打开Global.cfg，修改对应的TileEntity的Tick值（此处以量子太阳能举例）
    1. tileentity-activation {
    2. # If enabled, newly discovered tileentities will be added to this config with default settings.
    3. auto-populate=true
    4. # Default activation block range used for all tileentities unless overidden.
    5. default-block-range=256
    6. # Default tick rate used for all tileentities unless overidden.
    7. default-tick-rate=1
    8. # Per-mod overrides. Refer to the minecraft default mod for example.
    9. mods {
    10. "advanced_solar_panels" {
    11. block-range {
    12. [b]"advanced_solar_panels:quantum_solar_panel"=512[/b]
    13. }
    14. # Set to false if you want mod to ignore tileentity activation rules and always tick.
    15. enabled=true
    16. tick-rate {
    17. [b]"advanced_solar_panels:quantum_solar_panel"=20[/b]
    18. }
    19. }
    20. }
    复制代码
    此处的量子太阳能将仅在512格内有玩家时才会获得tick，默认每秒获得1tick（每秒产一次电，神特么优化有木有）
  • 将你认为卡服并且无需获取过多Tick的TileEntity设置完成后，保存文件，在游戏中输入"/Sponge -g reload"
  • 大功告成。
名词解释
  • auto-populate —— 自动检测可修改的tileEntity并记录在下面的mod块内
  • Block-Range —— 方块范围，当指定范围内没有玩家的时候，对应的TileEntity将不会获得tick
  • enable=true —— 你可以将此项设置为false，代表对指定mod都不监听不限制tick。
  • Tick-Rate ——对应方块获取的tick率，默认tick数除以此数值，例如输入2，实际表达式为:默认tick数 /2(即原有tick的一半)。
已知问题
  • 在加载AEmod的服务端，请关闭此功能对AEmod的限制，丢失tick可能会导致与输出总线连接的箱子卡出双倍的道具。
  • 在加载末影接口的服务端，请在调低导管术Tick的同时提高导管术的流体携带量，不然可能导致IC2的热核冷却液加载不够而炸核。
  • 在调低风力动能发电机的同时请调高风力产能，不然会导致发电量大减。
  • sponge配置文件只会读取世界已出现的可以调整tick的方块，也就是说这方法最好是等玩家发展到一定程度再去调，不然一开始配置文件读取的方块就只有几个
    如上所述，开启自动计算之后不会立马出现所有方块数量，没有记录过的方块只有在出现在世界终止后才会记录在“Global.conf”文件中，所以请定期检查这一优化方法。

BB弹的优化教程

目前我所知道的优化方式就只有以下四种
①、增加优化相关的MOD         
②、修改Sponge端的配置文件   
③、修改启动参数                    
④、修改玩法                          

第①点，增加优化MOD
推荐服务端安装以下MOD
Clumps
FoamFix
BetterFps
AI Improvements
Lag Goggles

其中，前三个对玩家的影响几乎没有，却能降低服务器的负担
第一个 Clumps 是用来缓解经验球过多导致卡服的问题， FoamFix 和 BetterFps 则是通过优化算法来降低延迟
第四个 AI Improvements 是通过优化怪物与动物的AI算法来降低对CPU的负担，或许会对游戏难度有微量的降低，但也能降低CPU占用
第五个 Lag Goggles 就是靠腐竹和管理们在游戏中找出卡服原因用的，通常在比较多科技MOD的情况下较为管用

第②点，修改配置文件
forgeChunkLoading.cfg 文件
该文件在config文件夹内

asyncChunkLoading ，这是异步区块加载的开关，如果是 false 请改为true

forge.cfg 文件
该文件在config文件夹内

鉴于我国有强大的防火墙，建议将检查更新全部关闭。分别是forge检查 disableVersionCheck=false 将 false 改为 true；以及mod检查 Global=true 将 true 改为 false 。

removeErroringEntities ; removeErroringTileEntities ，这两个选项是用来自动移除出错的实体。假设有MOD的实体出错了导致蹦服，如果将该选项打开的话就能避免实体问题导致蹦服，建议这两项都改为 true 。

server.properties 文件
该文件在根目录下

max-world-size ，该选项用于设定世界边界，可通过设置该数值来减少玩家跑图导致卡服的现象，该选项设置的数值为中心点到边界的距离，例如设置为2000，则世界边界为4000*4000。

network-compression-threshold ，此选项是用于设置数据的封包，默认为256，如果想节省带宽量可以降低该数值，但是可能会增加对CPU的开销，强烈不建议低于64。

generate-structures ，定义是否在生成世界时生成结构（例如村庄）不影响地牢及要塞，设置为false可以减少这些特殊环境生成和周期性检查带来的开销。但是会导致一些常见的玩法不能用，例如刷铁机。

view-distance ，视距，即以玩家为中心加载区块的半径。默认是10，通过修改该选项可以大幅度的提升服务器性能，建议改为4~6。

global.conf 文件
该文件在config\sponge文件夹内
