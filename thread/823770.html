*插件简介

简单来说, 这是一款自定义多数据表, 多字段的基于Mysql的关系数据储存插件.

说人话.

用人话说, 这个插件可以让你使用命令为玩家写入数据, 使用Papi读取数据.


*一通乱吹

体积不足15Kb, 代码轻量, 开源.使用体验友好, 对预料中的爆炸有红色中文报错提示.



*如何使用

- 让我们来举一个简单(划掉)的栗子.

假设你的服务器举行一个活动, 免费给玩家发福利.

每个玩家可以免费领取5次100点券, 使用Dm(杜蕾斯)菜单制作GUI.

- 那么问题来了:

你怎么限制玩家只能领取5次而不是无限点击呢?

- 一般的解决方案是通过类似Pex插件酱紫的权限组.

但很明显Pex和其他类似插件开发的初衷不是为了让你存玩家领了多少礼包.

这将导致一些弊端:

例如, 权限组混乱, 性能较低, 且配置非常麻烦, 需要一个权限一个权限地加.

- 这就是我写这个插件的初衷

每个玩家对应储存的数据都不同. 你可以自定义储存哪些数据, 并通过简单的命令实现储存. 这大大地降低了配置类似机制的繁琐程度.

- 那么接下来, 通过这个简单的栗子, 我向大家展示如何使用这个插件.

回到上文所述的栗子中,

接下来, 我们需要创建一个数据, 用于储存玩家领取福利的次数, 确保玩家不能领取超过5次的奖励.

本插件的命令是 /kd. 直接键入/kd你就可以看到一个简短的使用说明.

命令权限: kd.cmd / 控制台 / OP

这个使用说明需要一定智商才能看懂, 因此我建议你还是继续看教程吧.

我们假设这次活动的代号是 activity1, 这个福利的代号叫做 kit1, 并且这个活动还有其他的福利, 所以我们最好单独创建一个表来储存这次活动的所有数据.

我们执行一个命令来创建它.

/kd new activity1 kit1 INT 0

不难看出, 创建数据的命令看起来像这样:

/kd new [数据表] [数据名称] [数据类型] [默认值]

如果数据表不存在, 插件会自动创建数据表并后台重载数据库连接.

默认值指的是你还没有/kd set 时一个玩家获取变量的默认返回值.


而修改数据的命令看起来像是这样的

/kd set [数据表] [数据名称] [操作符] [值] [玩家名]


慢着, 数据类型是什么魔鬼东西?

截至目前, 插件支持两种数据类型:

分别是 INT(整数) 和 STRING(文本)

他们的区别主要在于能否支持加减操作符和替换符.


...Wait, 操作符又是什么窒息操作?

截至目前, 插件支持3种操作符:

分别是 +(加法) -(减法)和 >(直接设置)

只有INT类型的数据支持+/-操作符.

显而易见, +/- 的意思就是给数据做加减.

例如, /kd set a b + 100 c

就是给a数据表中类型为INT且对应玩家为b的c数据 + 100

假设c原本是200, 那么执行这个命令之后c的值就会为300.

同理可得减法(-)则反之.

而>(直接设置)很明显就是把某个数据直接设置为你想要的值.

例如, /kd set a b > 666 c

就是把a数据表中类型为INT且对应玩家为b的c数据设置为666

假设c刚才是300, 那么执行这个命令之后c的值就会为666.

>还有一个特性, 就是支持替换符.


Ojbk, 那替换符又是什么奇妙魔法?

替换符只有在你同时使用>和STRING类型的数据时才有用.

替换符目前有3种: 它们分别是 [空格] [换行] 和 &

回到正题, 在栗子中, 你只需要在Dm配置中的领取奖励按钮点击事件的给予点券命令后面加上一条 /kd set activity1 kit1 + 1 {player_name} 即可.

没有图片, 我懒得截了.


那么允许显示这个按钮的条件很显然就是

kit1 < 5 , 也就是点击了5次后就不能再点击了

怎么获取kit1呢?

获取一个数据的Papi变量看起来是这样的:

%kd_数据表:数据名称%

即, 允许显示这个按钮的条件应该这样写:

%kd_activity1:kit1% < 5


至此, 你学会了如何使用这个奇妙的插件.




建议用本插件储存一些小数据, 不过只要你愿意, 你也可以把它当成一个经济插件使用, 创建多种货币, 例如 金币/硬币/信誉值 等等...
