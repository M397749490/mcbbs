功能
支持NPC模组,Flan模组！
支持SkillApi与大部分RPG插件造成的伤害
支持无限增加奖励
支持自定义Gui
支持奖励翻页预览
支持VIP更多奖励
支持PAPI变量
支持指定时间清除所有玩家战令信息(赛季机制)
更多的配置（每天最大获取点数，RES支持，生物黑名单等）
命令
/daward open -开启奖励界面
/daward give <玩家> <点数> -给予玩家伤害点数
/daward vip <玩家> -将玩家设置为VIP组
/daward close vip <玩家> -取消玩家的VIP状态
/daward setdp <玩家> <点数> -设置玩家点数为特定值
/daward clear  -设置当前日期为更新日，所有今日以及以后登录的玩家战令数据清空一次
/daward reload -重载插件

【1.14.4新增指令】  
/daward save <唯一标示ID> -将主手物品保存在Gui文件夹中，用于显示Gui显示。
/daward save item/vip <标示ID> -将主手物品保存在AwardItem.yml（item）中和AwardVipItem.yml（Vip）中，用于奖励显示。

插件教程[1.7.10-1.12.2]:
鉴于近期很多的人加我问一些配置方面的问题，现在出个简单的配置教程吧~
Q: 如何配置更多的奖励?
A:
配置更多的奖励需要我们配置AwardItem下的文件。
以AwardItem.yml和AwardSetting.yml举例
AwardItem.yml：
  1. item1:
  2.   id: 1
  3.   sid: 0
  4.   display: "&d&l测试物品1"
  5.   lore: []
复制代码
这是插件自带的一个物品，id为物品的数字ID，sid为子ID，例如: 388:1   id就是388，sid就是1，同样也适用于mod物品。
给出一个例子:
  1. item1:
  2.   #砂石 24:1
  3.   id: 24
  4.   sid: 1
  5.   #display随便取
  6.   display: "&d&l砂石"
  7.   #颜色符号&
  8.   lore:
  9.   - '&a一行测试Lore'
复制代码
插件本身配置仅给出了10个样例物品，若想继续添加，遵循: "item"+数字 的方式，不断添加即可
item1：
  ……
item10: ...
item11: ...
AwardSetting.yml:
  1. AwardLevel:
  2.   #无需更改，请依次递增
  3.   1:
  4.   #领取该奖励需要的点数
  5.   Point: 1
  6.   #领取后执行的命令
  7.   Command:
  8.   - 'say hello-1'
  9.   #Gui中展示的物品，对应AwardItem.yml中的物品
  10.   Item: item1
  11.   #是否开启，用于区分VIP和普通奖励，普通奖励可以多设置几个false
  12.   Open: true
复制代码
“1”即为 第几个奖励，若需要添加，请依次递增就好了，第11个奖励就写11
“Point”为 领取这个奖励需要多少点数
“Command”为 领取之后执行的奖励 %player%为玩家变量
“Item”为 显示在Gui中的物品，这个物品不会被当做奖励给玩家，仅在Gui中显示用，代号对应AwardItem.yml中的物品
“Open”为 是否开启这个奖励，非Vip设置多些false，vip将此项全部设置为true （逃）
举例第23个奖励:
  1.   23:
  2.     Point: 1000
  3.     Command:
  4.     - 'eco give %player% 100000'
  5.     Item: item23
  6.     Open: true
复制代码
Item项可以多个奖励共用一个AwardItem物品。
VIP的照葫芦画瓢就可以了！

Q：Gui里的物品可以改吗？
A：当然可以
打开Gui/AwardGui.yml，内容分为两个部分:物品属性 和 位置信息
物品属性:
  1. item1:
  2.   id: 397
  3.   sid: 3
  4.   display: ""
  5.   lore: []
复制代码
与AwardItem的配置相同，自行更改。
位置信息:
  1. SetItem1: 0,1,2,3,4,5,6,7,8
  2. SetItem2: 45,46,47,49,51,52,53
  3. SetItem3: 18,26,27,35
  4. SetItem4: 9,10,11,12,13,14,15,16,17,37,38,39,40,41,42,43
  5. SetItem5: 50
  6. SetItem6: 48
  7. SetItem7: 36
  8. SetItem8: 44
复制代码
意为：Gui中0,1,2,3,4,5,6,7,8格子设置为Item1，以此类推，第一个格子为 0 。
理论来讲，Gui是完全可以自定义的，包括任何按钮：
config.yml中:
  1. AwardSet:
  2.   Normal: 19,20,21,22,23,24,25
  3.   Vip: 28,29,30,31,32,33,34
  4. Button:
  5.   Up: 36
  6.   Down: 44
  7.   Info: 48
  8.   Get: 50
  9.   Normal: 19
  10.   Vip: 28
复制代码
AwardSet下的 Normal指显示普通奖励的位置 ，vip为vip奖励
Button即为按钮位置，Up上一页按钮，Down下一页按钮，Info玩家信息按钮，Get领取奖励按钮，Normal和VIP对应两个奖励的起始位置即可。

Q: 配置文件中的Clear是什么？需要设置吗？
A：不需要手动设置
这是设置为当前日期为清空所有玩家战令状态的设置项。
需要在游戏中使用/daward clear指令设置
比如战令开放了一个月了，可以使用/daward clear设置本日清空；
所有的玩家战令状态都会在上线后被清空一次，包括VIP状态。
