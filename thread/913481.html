TRMobAPI —— 自定义怪物API


这是什么？
这是一套给开发者准备的自定义怪物API，
通过这套API，你可以高效而方便地随心所欲地发挥你的设计，
并且该API官方自带几个附属插件，例如世界刷新，
使得你不必关注于设计没有意义的轮子。
（其实是过中秋，发点福利，把我一直自己用的怪物框架给公开了）

特性：
· 快速高效：只需新建一个类，一个怪物类便产生了
· 方便设计：无需关注于注册监听器和写很多轮子
· 等级系统：无需自己设计怪物等级，已为你准备好
· 可持续性：即使服务器重启，怪物也不会失效或丢失
· 提供接口：附属插件可以来回协调工作使得拓展性更大
· 限制近无：API并不会限制你的设计，可随心所欲发挥
· Boss血条：仅需实现TRBossBar接口便可自动产生Boss条
· 自带配置：仅需implements TRJsonConfigurable，无需自己设计
· 自带命令：调试怪物远比你想的方便得多，不再繁琐
· 可热拔插：你甚至无需重启服务器便可动态修改怪物
· 自动更新：尽量不必关心用户版本错位导致的各种报错
· 官方附属：无需反复设计一些已有的附属内容
- 未来计划：内置独立数据接口
- 未来计划：提供更多操作NMS的接口

第二章 —— 插件的安装，生成第一只怪物，基础命令
Load,Spawn,Command

插件的安装：
只需要去发布帖地址下载插件本体，然后放入服务器plugins即可
不过你只安装一个本体是没有任何作用的，你需要安装一个附属
这里有一个示范用附属：https://gitee.com/vlvxingze/TRMExample
把两个插件都下载完毕后丢入plugins 后重启就算是完成了

生成第一只怪物：
TRMExample 附属插件提供了四个示范怪物，
com.relatev.minecraft.TRMExample.TestZombie 这只僵尸具有等级，最大生命值为20+等级x5，伤害为等级x2，掉落经验为等级x2，若等级大于5级，死亡时还会掉一颗钻石。但它出生时，只有1滴血，每过5五秒会恢复5点生命值直至满血
com.relatev.minecraft.TRMExample.GiantBoss 巨人僵尸拥有血条，不具有等级，每过5秒便会在脚下召唤一只等级为5的TestZombie僵尸，Boss血条显示距离为32M
com.relatev.minecraft.TRMExample.TestSkeleton不具有等级，该小白射出的弓箭会在着落点引发半径为1.5M的爆炸
com.relatev.minecraft.TRMExample.FeiSheep 沸羊羊是一只羊，具有等级，其出生生命值为20+等级x5，但它有三条命，每次死亡时都会立即满血，另外，其拥有Boss血条，距离为32M

输入/trm spawn <怪物ID> 就可以生成一只指定的怪物了
/trm spawn com.relatev.minecraft.TRMExample.GiantBoss

由于太长，所以你没有必要打那么完整，插件会模糊匹配名字
/trm spawn giantboss

而某些怪物具有等级，输入/trm spawn <怪物ID> <等级> 刷出指定等级的怪物
/trm spawn testzombie 5

基础命令：
插件本身提供的命令并不多，不过附属插件可能会提供更多命令给你
/trm spawn <ID> (Level) 生成指定等级的怪物
/trm killall <ID> 清理该ID存活的所有怪物
/trm list 列表当前服务器已加载的怪物类

刷新点刷新指定怪物：

/trms spawnpoint removepoint <半径> 删除周围多少米内的所有刷怪点
/trms listpoint (距离) 列表附近多少米内所有刷怪点，不填半径为全部刷怪点

/trms spawnpoint removepoint 5

/trms spawnpoint listpoint 5

第四章 —— 对怪物进行常见的配置讲解
TRJsonConfigurable

如果你有看过开发者教程，你应该知道TRMobAPI自带了一套非常简单好用的配置生成和读取器，
使用的是Json搭配Yaml格式，使用极其方便，编辑起来还是比较人性化的。
不同的附属插件其怪物配置文件也不尽相同，但这里讲解了常见的几个参数：
  1. TRJsonConfig: |-
  2.   {
  3.     "DisplayName": "&a小绿 &bLv.%Level%", #怪物的名字，%Level%代表等级替换符
  4.     "BukkitEntityType": "ZOMBIE", #怪物类型，有些附属插件可能不支持修改类型，或会报错
  5.     "ID": "com.relatev.minecraft.TRMExample.TestZombie", #怪物ID，不建议乱改，ID重合会导致插件冲突
  6.     "Mobs": [], #不要动
  7.     "Tasks": [] #不要动
  8.   }

第三章 —— 设置僵尸的各项属性

TRLevelMob、spawn

TRMob类从你激活的那一刻起，就自动被注册了监听器
不需要你自己去注册{:4_119:}

TRLevelMob 是 TRMob 的一个子类，TRMob是没有等级系统的
但如果你的类继承的是TRLevelMob，那么怪物就有等级了{:4_119:}
因此把你的
  1. public class TestZombie extends TRMob
复制代码
改为
  1. public class TestZombie extends TRLevelMob
复制代码


那么你需要覆写spawn(Location loc,int level)方法
loc 指的是刷新位置，level 指的是刷新等级

这里以修改初始生命值为例
  1.     @Override
  2.     public LivingEntity spawn(Location loc, int level) {
  3.         Zombie zombie = (Zombie) super.spawn(loc, level);
  4.         zombie.getAttribute(Attribute.GENERIC_MAX_HEALTH).setBaseValue(20 + level * 5); //设定怪物出生最大生命值为 20+等级x5
  5.         zombie.setHealth(zombie.getAttribute(Attribute.GENERIC_MAX_HEALTH).getValue()); //让怪物满血
  6.         return zombie;
  7.     }

第八章 —— 调控另一个附属插件的怪物
TRMobSpawnEvent、TRMobManager

TRMobAPI 提供了监听器，
比如TRMobSpawnOverEvent
然而很遗憾的是，并不支持Cancelled，只能监听信息和获得实体
原因在于这是一套API插件，天知道另一个插件的怪物生成的时候
对怪物做了什么，如果撤销生成就要返回null，很可能会报错
但你仍然给对其他插件生成的TR怪物进行操作
不能Cancelled，你可以在生成监听器触发后立即remove掉它

注意！
原版自带的CreatureSpawnEvent 仍然对TRMobAPI生效
若你对CreatureSpawnEvent 生成的怪物进行操作，有可能是不会生效的
因为插件工作机理如下：
CreatureSpawnEvent --> TRMobAPI --> 附属插件 --> TRMobSpawnOverEvent

因此如果你用CreatureSpawnEvent 修改了TRMobAPI生成的怪物，
TRMobAPI随后就会改回去....
TRMobSpawnOverEvent 监听器会在TRMobAPI怪物生成完毕后才触发
这样你对怪物的后续修改便会生效了

需求：隔壁附属插件有个怪物ID为 com.relatev.minecraft.TRMExample.TestZombie
我要对其后续修改，如果它的生成Y高度高于12，则让它只有一滴血
