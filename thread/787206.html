很久没看依赖高频来做循环的命令了...
你这命令有几个重要问题
1. 没立即删除map_tools-click，导致不停生成marker
2. searcher在多于1个玩家点击的时候会多于一个，但#minecraft:tick函数内第三条命令只让一个searcher使用，这代表逻辑有问题。
3. armor_stand的朝向其实和生成它的玩家不同，所以map_tools:tick/searcher不能如预期的运作。
4. map_tools:tick/find那里的execute store错了，你不应该储存在所有玩家的记分板内，应该分辨玩家
5. map_tools:tick/find那里execute store之后的data get也是错了，没指定获取哪个NBT的分数，需要指定Pos[0] Pos[1] Pos[2]

简单来说就是你这不能用，解决方案:
我是用的是1gt内完成的嵌套。
  1. function map_tools:_main (tag: #minecraft:tick)
  2.     execute as @a[tag=map_tools-click] at @s positioned ~ ~1.62 ~ run function map_tools:raycast
  3.     tag @a[tag=map_tools-click] remove map_tools-click

  5. function map_tools:raycast
  6.     execute if entity @s[distance=..50] if block ~ ~ ~ air positioned ^ ^ ^0.3 run function map_tools:raycast
  7.     execute if entity @s[distance=..50] unless block ~ ~ ~ air run function map_tools:store_result
  8.     execute as @s[distance=..50] unless block ~ ~ ~ air run tellraw @s ["","x: ",{"score":{"name":"@s","objective":"map_tools-x"}},"y: ",{"score":{"name":"@s","objective":"map_tools-y"}},"z: ",{"score":{"name":"@s","objective":"map_tools-z"}}]

  10. function map_tools:store_result
  11.     summon minecraft:armor_stand ~ ~ ~ {NoGravity:1b,Tags:["map_tools-searcher"],Invisible:1b,Invulnerable:1b}
  12.     execute store result score @s map_tools-x run data get entity @e[limit=1,tag=map_tools-searcher] Pos[0]
  13.     execute store result score @s map_tools-y run data get entity @e[limit=1,tag=map_tools-searcher] Pos[1]
  14.     execute store result score @s map_tools-z run data get entity @e[limit=1,tag=map_tools-searcher] Pos[2]
  15.     kill @e[tag=map_tools-searcher]

pca的raycast中 有更简便的防止超过65535的方法，不需要新建counter记分板。那太麻烦了。
function map_tools:raycast
    execute if entity @s[distance=..65535] at @s if block ~ ~ ~ air positioned ^ ^ ^1 run function map_tools:raycast
    execute if entity @s[distance=..65535] at @s unless block ~ ~ ~ air run function map_tools:store_result

删掉以后没有反应，因为不能删。execute store的scale值不是可省值。
而data get的scale值可选，因此命令末尾没有加上1。
