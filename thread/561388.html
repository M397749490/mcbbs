另外提几个建议，不知道你是否已经实现或准备实现：
1.客户端文件使用SHA-256或更长的消息摘要算法来验证，因为MD5已经可以实现碰撞了(据说还出了碰撞MD5的软件)
2.发包的数据要进行加密和验证，而且即使是相同数据每次发送到服务器都应该加一个[状态信息]供服务端验证，否则抓一下包很容易破解掉。
   发包的数据大体要保证三点：
1)保证即使抓了包也无法分析出实际数据(虽然不可能绝对无法，但是做到分析时间超过几年应该不难)
2)保证只有正常客户端向服务端发的包有效(简单来说就是抓包数据重发是无效的)
3)保证当数据不完整时(如缺失某信息或某信息明显不符合常理等)服务端能够判断出并判定该数据包无效

向高产帝致敬，另外给一个自动获取版本的代码，直接调用getCraftClass，第一个参数是版本号(如1_8_R3)后面的包名+类名，第二个参数是标识版本号前面的是org.bukkit.craftbukkit还是net.minecraft.server

  1.     private static Class<?> getCraftClass(String name, boolean isbukkit) {
  2.         String version = getVersion() + ".";
  3.         String className = "";
  4.         if (isbukkit) {
  5.             className = "org.bukkit.craftbukkit." + version + name;
  6.         } else {
  7.             className = "net.minecraft.server." + version + name;
  8.         }
  9.         Class<?> clazz = null;
  10.         try {
  11.             clazz = Class.forName(className);
  12.         } catch (ClassNotFoundException e) {
  13.             e.printStackTrace();
  14.         }
  15.         return clazz;
  16.     }
  17.    
  18.     private static String getVersion() {
  19.         return org.bukkit.Bukkit.getServer().getClass().getPackage().getName().replace(".", ",").split(",")[3];
  20.     }
