原帖地址：https://minecraft.curseforge.com/projects/boxlin
我们可以使用kotlin（锅特灵）进行MCMOD的开发，常用的前置是forgelin，直到我在去年12月发现了一个叫boxlin的新前置——年幼无知的我生出了一个问题：这么做岂不是无用功？
作者笑着摸了摸我的狗头：不是啊，既然kotlin和Java高度兼容，是Java最好用的第三方库（划掉），那你为什么还要安装一个前置（forgelin）来完成MC和kt mod之间的通信呢？boxlin就是立足于这样一点（不需要boxlin本身）制作出来的，不过在此之前，你需要对你的主类做出一点修改：
原主类：
  1. @Mod(
  2.     modid = Mod.ID,
  3.     name = Mod.NAME,
  4.     version = Mod.VERSION
  5. )
  6. class Mod {
  7.     companion object {
  8.         const val ID = "mod"
  9.         const val NAME = "Mod"
  10.         const val VERSION = "1.0.0"
  11.     }
  12.    
  13.     @EventHandler
  14.     fun preInit(event: FMLPreInitializationEvent) {
  15.         // code...
  16.     }
  17. }
复制代码
改主类：
  1. @Mod(
  2.     modid = Mod.ID,
  3.     name = Mod.NAME,
  4.     version = Mod.VERSION,
  5.     modLanguage = "Kotlin",
  6.     modLanguageAdapter = Boxlin.ADAPTER
  7. )
  8. object Mod {
  9.     const val ID = "mod"
  10.     const val NAME = "Mod"
  11.     const val VERSION = "1.0.0"
  12.    
  13.     @EventHandler
  14.     fun preInit(event: FMLPreInitializationEvent) {
  15.         // code...
  16.     }
  17. }
复制代码
然后是安装过程：
Make sure that in the repositories closure the jcenter is called（在你的代码库声明一个如下所示的jcenter闭包）
  1. repositories
  2. {jcenter()   
  3. // ...}
复制代码
And then paste this in the dependencies closure（然后将如下信息粘贴到dependencies闭包中）
  1. compile "io.opencubes.boxlin:boxlin:1.3.0"
复制代码

然后你就可以用锅特灵这个JVM上的C#去开发啦。

楼主你删帖吧。

如果你这么做了：
  1.     modLanguageAdapter = Boxlin.ADAPTER
复制代码

然后没装 Boxlin，那么有两种可能：
  • 编译器没有优化这个引用，仍然指向 Boxlin 下的对应字段。然后你没有装 Boxlin。运行时找不到字段，FieldNotFoundException。这样的编译器存在吗？？？我自己都不信。
  • 编译器把这个引用的值直接写进了 Annotation 里。然后你没有装 Boxlin，此时 Forge 会因此炸掉（被 RuntimeException 包装后的某个 Exception，在这里所提到的情况下应该是 ClassNotFoundException）。


更何况用 Kotlin 写的 Mod 还是需要依赖 Kotlin 的标准库及运行时的。Forgelin 和 Boxlin 两者都做了这件事。不装当然也会让你的 Mod 无法运行。

说起来... 我记得有三个让 Modder 用 Kotlin 写 Mod 的 Lib Mod 啊——Forgelin、YukariLib 和 Boxlin。https://minecraft.curseforge.com/search?search=kotlin
