从上面可以看见这个我们的启动参数都是从这个JSO上面获取，那么我们现在需要做的就是处理这些参数。
仔细看我下面的示例代码可以很容易发现libraies里面的所有name属性是以（例：）xxx:xxx:xxx命名的，而对应一下我们在-cp所需要的参数是地址，**，觉得name属性和这个地址像就对了，所以我们可以从libraries里面读取到所有name的内容并进行处理。
那具体要怎么处理呢？请看一下的地址和name属性：
  • com.mojang:authlib:1.3
  • C:\Users\xxx\xxx\172F\.minecraft\libraries\com\mojang\authlib\1.3\authlib-1.3.jar
这时一对比，又发现了冒号“：”将name属性分成了三部分-> com.mojang 与 authlib 和 1.3
好了，分割出来这三个部分我们在看看libraries后面部分的路径com\mojang\authlib\1.3\authlib-1.3.jar
分析到这里，我们就要处理他的规律了，用对象语言的思想处理一下这俩
定义一个数组为 nameSpilt[3]
那么按照刚才分割出来的name属性作出以下处理
nameSpilt[0] = com.mojang
nameSpilt[1] = authlib
nameSpilt[2] = 1.3
这时你又发现com.mojang也要处理一下才能变成com\mojang
所以再次定义一个数组 为dirSpilt[2]并作出以下处理
dirSpilt[0] = com
dirSpilt[1] = mojang
要把这两个数组的元素格式化成路径：com\mojang\authlib\1.3\authlib-1.3.jar
dirSpilt[0] +@"\"+ dirSpilt[1] +@"\"+ nameSpilt[1] +@"\"+ nameSpilt[2] +@"\"+ ( nameSpilt[1] + namespilt[2] + ".jar")
如果继续仔细观察json,你又会发现有类似org.apache.logging.log4j:log4j-api:2.0-beta9这样的属性(第一个元素有很多点，代表文件夹有很多层)，不过由于本节不讲代码实现部分，仅作原理解析，所以不予讲解。
