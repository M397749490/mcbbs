本人高中狗，没什么时间去管本帖和进阶版本，很抱歉

===========

玩过TE4的朋友会发现能源是一个很大的问题，尤其是再装了应用能源模组之后，大型ME网络能量消耗简直是逆天。所以说TE现有的5种最高功率只有80RF/t的能源炉就根本不够用。
大型反应堆（Big reactors)模组很好的解决了这个问题，此模组提供了两种多方块的组合式发电机（反应堆 and 涡轮）。
相对于其它如反应堆工艺、模块化发电机等的模组，大型反应堆发电量有可能不及它们高，但比它们更安全、更便宜、更实用。

7.反应堆工作总开关。左边为开，右边为关
8.燃料表。将鼠标移上去会显示7行字
├第一行：燃料棒中的液体所占百分比（包括液态黄铀和液态蓝晶）
├第二行：燃料棒中的液态蓝晶所占百分比
├第三行：燃料棒数量
├第四行：燃料棒液体总容量
├第五行：当前液态黄铀容量
├第六行：当前液态蓝晶容量
└第七行：当前液体总量
9.反应堆外壳温度（高热的外壳可以提高能源输出和加快冷却液的转换）
10.反应堆燃料温度（过高的热量会加快燃料的使用速度。堆芯的热量会向外壳传输，传输速率基于反应堆的内部设计）

更新日志

0.4.3A
Another bugfix release! This one fixes a pretty serious, long-standing issue which caused server crashes (and occasionally corrupted worlds) when active reactors were broken with Tinker's Construct hammers. It also fixes a nasty problem which caused any changes to the powerProductionMultiplier config to be applied twice, so power output was out-of-whack with non-standard config settings.

0.4.2A2
Minor bugfix release for a ComputerCraft issue - exceptions encountered when calls are coming in via ComputerCraft Lua code will now be rethrown as LuaExceptions, and therefore appear as errors in the user's lua program instead of bloating up your server logs.

0.4.2A
Another bugfix release while 0.5 development continues. Also, thanks to DragonsLover, we now have French Canadian language support.
A few fixes for relatively important issues - turbines no longer count metal blocks surrounding their exteriors as coil blocks, and reactors now properly save their waste-ejection settings.
I've also added setControlRodName and getControlRodLocation methods to the Computer port.
A couple other minor fixes as well - turbine rotor bearings have proper collision geometry now, and picks/wrenches can properly break a cyanite reprocessor without losing the block.

0.4.1A2
Just a quick bugfix - the previous version didn't properly include the reactor & turbine power production config settings changes. This has been fixed. Sorry about that!

0.4.1A1
This update upgrades to the latest version of CoFHCore, which fixes crashes which may occur when using BR with certain other mods.
Also, I've added two new config options, which allow server operators and modpack curators to alter the power production of turbines and reactors separately. These new settings stack with the overall power production multiplier. The Mekanism combiner recipe for yellorite has also been fixed, and SoerenKK contributed a Danish translation. (Thanks!)

0.4.0A
A stable alpha release at last! This update primarily just bumps the mod up to requiring CoFHCore 3.0.0B8, which resolves the “turbines don't assemble right” issue once and for all.
It also fixes a small bug with power taps erroneously showing up as green/connected even when they weren't actually allowed to connect to an RF cable. This mostly only happened with AE2, but it's fixed now.
0.5 development has been slow due to my hectic work schedule, but hopefully I'll have some good news on the 0.5 front sooner rather than later.

0.4.0rc11
This is primarily a compatibility update, as most of my focus is now on coding 0.5. This update upgrades OpenComputers support to 1.4; note that OpenComputers 1.3 will likely no longer work with Big Reactors.
I've also added some compatibility updates for mods which do automatic generation of recipes, like AOBD. Several translations have been updated, and a Czech translation is now available.

0.4.0rc10
Another minor bugfix release; we're still awaiting the next version of CoFHCore to resolve the turbine/reactor assembly bug, unfortunately. As soon as that's released, 0.4.0 will be marked stable.
In this release, I've fixed a bug whereby cyanite/blutonium could be duped via cyanite reprocessors, fixed some recipe bugs such as TE hardened glass recipes not working, and fixed the API calls to Mekanism. This means that Big Reactors should now be compatible with Mekanism 7.1.1.

0.4.0rc9
Hey folks, this is a minor bugfix release that's long, long overdue. However, the good news is that things appear to be approaching stability - the last major bug I'm aware of is an external bug in CoFHCore which should be resolved in the next CoFHCore release. I've been avoiding declaring BR 0.4 stable explicitly due to it.
In this release, I've added a new setting, dimensionWhitelist for those of you using the ExtraUtils underdark. You can add negative dimensions to the dimensionWhitelist and BR worldgen will run in them as normal.
I've also fixed some graphical bugs, integrated updated translations for Chinese and Russian, and fixed some cases where data was not being saved properly.
Also, as a workaround for the annoying issue where turbines don't properly appear assembled (which is the oredict issue in CoFHCore I mentioned above), I've added a new block: ludicrite. It's designed to be ludicrously expensive, but slightly “better” than enderium and other mod blocks, and I've hardcoded a check for it, so it won't suffer from the oredict issue.

0.4.0rc8
This is a single-line-of-code emergency update, as rc7 more or less broke the entire mod. (Oops.) Power taps, fluid ports and access ports will now properly recognize and connect to the appropriate other blocks - energy conduits, pipes, etc.

0.4.0rc7
A number of bugfixes in this version - primarily, this version moves up to requiring the newest CoFHCore, which fixes the problem where reactors and turbines (on some servers) do not appear to assemble when using non-Vanilla blocks inside them. Unfortunately, the problem is only resolved for new worlds. I apologize for the inconvenience.
Also fixed are a nasty crash bug which occurred when entering view of a very very very large reactor or turbine (16x16x48 or so), a texture corruption problem, and a bug which made turbine/reactor glass uncraftable in some modpacks.
In nicer news, there's now 4 new turbine configuration options for modpack curators wishing to balance turbines, and I've added Version Checker integration.
Oh yes, and the website seems a little different.

0.4.0rc5
This version primarily bumps the Forge requirement to 1205 (or newer) and fixes compatibility with CoFHCore, upgrading to the newest version as of this writing (3.0.0B5). Thanks to everyone who tweeted or filed issues about the problem, and special thanks to mysticdrew for submitting a pull request with the necessary fixes.
A slew of bugfixes in this release, as well. Various problems with cyanite reprocessors, textures and recipes have been fixed. See the Changelog for details.

0.4.0rc3
Another bugfix release. Cyanite reprocessors will no longer spontaneously dismantle themselves when you look at them with NEI enabled. (Seriously, that was a weird one to track down.)
Also, plain-vanilla Forge servers should no longer have weird networking issues with turbine GUIs not updating or multiblock textures not updating on assembly.

0.4.0rc2
A minor bugfix - cyanite reprocessors were not properly accepting inputs when their input slot was exposed (i.e. you toggled one of its sides to red and attached a pipe, hopper or similar thing). This has been fixed.
