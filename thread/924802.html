GroupManager 中 addp 与 delp 的使用误区


首先，我们来看一下一个事件



有一位服主, 他想要某位OP不能使用彩色字, 于是他找到需要删除这位OP两个权限


essentials.chat.color 和 essentials.chat.colour


于是他就去用delp删除权限了, 但是...



然后这位服主心想: 既然del不了我add一次不就能del了吗(笑),于是



此时这位OP上线并给了这位服主一棒子



此时他想到好像可以用add加负权限, 然后




这位服主终于把这位OP的权限删除了, 可喜可贺!


启示(滑稽)


我们需要给玩家/权限组删除权限的时候, 应该用 addp 添加负权限而不是用 delp


原因分析(不想看的可以走了)


首先，这部分是以原版的 OP 命令进行解析的


首先 原版的op命令所需要的权限是 minecraft.command.op (不信的可以自己去查去验证)


然后, 我们需要知道这些概念



  • 默认值

    • 以 minecraft.command.op 为例, 当玩家是 OP 和 不是 OP 时有两种情况

    • 是 OP: 有权限

    • 不是 OP: 没有权限

    • 注意, 默认值什么的是这个权限所属的插件设置的, 目前主流的权限组插件都没有修改默认值的功能

    • 如果所属插件不是通过代码批量注册的话可以在 <插件.jar>!/plugin.yml 找到默认权限注册信息


  • 插件权限覆盖 (请注意, 这是我个人的术语, 实际上是PermissionAttachment 权限附属, 覆盖比较好理解)

    • 直接看下面的权限检测流程就OK

    • 实际就是一个池子

    • 一个 HashMap<String, Boolean>



然后我们需要了解一下权限系统是怎么工作的



  • 首先查询是否需要检测的权限已经被覆盖设置了

  • 如果没有被覆盖的话就返回默认值


GM 的权限系统是怎么工作的


Tips: 如果你想要了解GM的内核是怎么工作的, 可以去翻GM源码, 这里只给出GM的工作流程


首先, GroupManager是由一个个Node信息组成的, 这里不怎么说, 主要说addp和delp的工作原理



  • addp [Target] [permissions]

    • 把 [permission] 添加到 [Target]的 插件权限覆盖区 的记录中


  • delp [Target] [permissions]

    • 把 [permission] 从 [Target] 的 插件权限覆盖区 的记录中移除



是的, 相信大家都看到我划出重点的内容: 插件权限覆盖区, 这就是 GM 中最容易误导人的地方,
甚至中文翻译的Wiki都是有误导的 Group Manager/命令


> /manudelp: 从玩家直接移除权限。


直接, 是的, 这也就是误导服主们的因素, 应该是


> /manudelp: 从GroupManager的记录中移除玩家的记录


Addp / Delp 的具体分析


首先, 我们在这里定义玩家是 Default 组


Default组有以下权限



  • perm.group.default

  • -perm.group.default.del


玩家(Player)还有这些权限



  • user.perm

  • -user.perm.del

  • perm.group.default.del


Tips: 这些都可以在GM的存储文件中看到, 也就是 记录 内容, GM真正记下来的


然后, 以 - 开头的就是真正移除的权限, 下面给出这些Node的插件覆盖区的值



  • Default

    • perm.group.default -> true

    • perm.group.default.del -> false


  • Player

    • user.perm -> true

    • user.perm.del -> false

    • perm.group.default.del -> true



然后在权限出现重复设置的时候,
由最高层把底层的权限情况给覆盖掉, 也就是 Player 的会把 Default组 的给覆盖掉


此时 GM 传给服务器的实际权限覆盖区的情况是这样的



  • user.perm -> true

  • user.perm.del -> false

  • perm.group.default.del -> true

  • perm.group.default


其中 perm.group.default.del 被Player的值给覆盖掉了


如果你认真看到这里的话, 你就会很容易理解 addp 和 delp 做了什么



  • addp 负责把权限加入到 Target

  • delp 负责把记录从 Target 中移除
