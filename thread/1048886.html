标题: 10条命令实现实体分数排序
我们有时遇到这样的问题：在竞技类小游戏中如何获取某位玩家分数的排名？为了解决这种问题，写一个排序函数是很有用的。

摘自小豆数学库56号函数：
  1. scoreboard players add @e[tag=sort] scb 0
  2. scoreboard players set @e[tag=sort] sort 0
  3. execute as @e[tag=sort] run summon area_effect_cloud ~ ~ ~ {Tags:["stmp"]}
  4. scoreboard players set @e[tag=stmp] int -2147483648
  5. execute as @e[tag=sort] run scoreboard players operation @e[tag=stmp,scores={int=-2147483648},limit=1] int = @s scb
  6. execute as @e[tag=stmp] store result entity @s Pos[1] double 0.0000001 run scoreboard players get @s int
  7. scoreboard players set stemp int 0
  8. execute positioned ~ -220 ~ as @e[tag=stmp,sort=nearest] store result score @s int run scoreboard players add stemp int 1
  9. execute as @e[tag=stmp] run scoreboard players operation @e[tag=sort,scores={sort=0},limit=1] sort = @s int
  10. kill @e[tag=stmp]
复制代码

其中@e[tag=sort]为被排序实体，scb为储存实体分数的记分板，int是用法十分特殊的一个记分板（已被小豆用烂），这里可看作临时处理
局限性：被排序分数不能有-2147483648

基本原理：1.目标选择器若不加入sort参数，按实体出现时间顺序选择
                2.利用execute store可将分数转为实体坐标
                3.利用目标选择器sort=nearest，可按照实体坐标远近选择实体



分步做法：1.分数初始化，add 0，序号初始化,  set 0

                2.召唤一批临时药水云，与被排序实体分数逐一对应，临时药水云将分数转为自己y轴坐标

                3.临时分数赋值为0，按远近选择实体执行命令，每次执行利用add把临时分数累加，利用store存为自己的分数

                4.所有的临时药水云按时间顺序，把未得到序号的实体（sort分数为0）的序号赋值为自己的分数
                   依据原理1，此步骤的顺序与步骤2顺序相同，分数逐一对应关系保留。

                5.清除所有临时药水云

这种做法的本质是调用了目标选择器的sort参数内部排序算法，性能未知，但很方便。

有大佬说他用加分法就ok了，然后我写了一下，缺点是检测的实体坐标不能完全重合，当然多加几条命令可以解决

scoreboard players set @e[scores={credit=-2147483648..2147483647}] rank 1

execute as @e[scores={credit=-2147483648..2147483647}] at @s at @e[distance=0.01..,scores={credit=-2147483648..2147483647}] if score @s credit > @e[scores={credit=-2147483648..2147483647},sort=nearest,limit=1] credit run scoreboard players add @e[scores={credit=-2147483648..2147483647},sort=nearest,limit=1] rank 1
基本原理：
1。让所有对象对比自己菜的对象顶一下
2。被顶得最高的就是最菜对象
3。由于最强的没人敢顶，因此开头(或结尾也可以)给所有对象顶一下。
