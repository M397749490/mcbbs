标题: 让我们一起复活MCPC+吧
本帖最后由 dogeop 于 2017-8-28 17:15 编辑

由于Sponge两年不出正式版并且插件少，我有了这个复活mcpc+的想法，现在和大家分享一下。
       Minecraft Port Central(MCPC) 是一个实现了Bukkit API的mod，诞生于我还没入坑的古老年代，它给了喜欢mod的玩家一道曙光，腐竹们也可以不那么担心服务器难于管理，为minecraft社区增加了不少活力。
       可惜好景不长，由于DMCA事件，MCPC+整个被 take down，无法访问，后续续命的Cauldron(实现了spigot API的mcpc)，KCauldron（由某个姓K的人制作，大雾），Thermos也都停在了1.7.10版，mcpc的主力开发人员出走了sponge，而sponge2年没个正式版，bug一堆并且插件不够多，导致正经开服没几个人用它。那么问题来了，为什么就不能复活这个大锅呢？
       其实大锅这个东西的实现，说难？还真不难，至少原理懂了的话还是很简单的。
       首先，从MC插件和mod的历史说起吧。
       MC从一开始就不是一个开源项目，玩家要想体验一些不一样的什么东西，就要考虑对游戏本体进行修改了，本来天不亡人，这东西是个java程序，由于JAVA字节码标准是开放的，因此随便搞个什么反编译器就可以吧源码搞出来，自己修改，听起来很好可是～这代码是混淆过的！你就算反编译出来你也是-----看不懂的！因此最早要想修改MC实现自己的小功能是极其困难的。当然这个看不懂是对大多数人而言，总有那么几个脑子偏门的，就能看懂这代码！他们不止看懂了代码，还将代码做了反混淆，变成了人可以看懂的东西(hMod,https://github.com/traitor/Minecraft-Server-Mod)，开启了minecraft的插件时代！后来这个东西就走向了两个分支，一个叫MCP，它的反混淆从服务器到客户端都覆盖了，基于它的代表作品叫Forge，是mod领域的事实标准，另一支叫bukkit(craftbukkit)，是插件界的领头者，其使用的反混淆名是另一套，反混淆的类和方法数也比较少。这两兄弟几乎是对半分江山，其他的小众服务端基本是看不到影子的。
      Forge和Bukkit这两兄弟，两个都很好，但是它们都专精一方面，而另一方面不是那么精通，其中forge注重“修改”，从服务器到客户端改出新天地，而bukkit作为纯服务器端的东西经常用作管理，偶尔也可以用来在mc ”贫乏“ 而 ”有限“的元素上挖掘玩法。但是这两兄弟以前一直是不能在一起的！为什么呢？
      前面说到，这两兄弟虽说基于一份mc，但是用的反混淆名字都是完全不同的，包和类的分布也完全不一样。bukkit用的服务端api都位于 net.minecraft.server（插件开发者俗称NMS）包，而forge的mc本体则有很多很多包，如 net.minecraft.world.*, net.minecraft.entity.* ,等等，并且运行时的类，方法，字段也完全不一样，forge运行时使用searge半混淆名，如(func_xxxxx_xx,field_xxxxx_xx),而bukkit直接使用了反混淆名，就算你开发的是个纯服务器端插件，你尝试把插件丢进forge也是完全没用的！就算forge接受了你的jar，并且加载，等待你的也只会是找不到类的错误。那么为什么后来有了mod插件同服呢？
      还记得我提到，他们都是基于同一份mc么？很好，我只要基于mc原来混淆过的名字，为字段，方法，类由bukkit到mcp做一一映射，重新实现craftbukkit，并且对forge打补丁使得forge向bukkit发送事件，不就行了？事实上，mcpc+就是这个工作原理。通过处理mcp和bukkit的混淆映射，将craftbukkit变成用mcp实现，并且对forge和craftbukkit做一些适配（比如让插件识别mod的方块，实体等），让forge将世界内的事件送给bukkit（插件就能用了）。此时bukkit是作为一个mod跑在forge上面的，虽然说，由于mod这个东西的行为很多都会脱离bukkit之外，他们只遵循forge的法则，导致有很多类似于什么扳手拆领地，挖矿机挖领地等一系列蛋疼事情的出现，但是，瑕不掩瑜啊！mod多好玩！
      后来14年的时候，mcpc被dmca，mod服的发展陷入低谷，再也没有1.7以上的bukkit + forge了。
      再后来由于sponge进度的缓慢，我决定开这个坑，作为练习（大雾）。
      经过2天左右的奋战，拿到了spigot映射到mcp的源代码，目前代码很干净，只剩下适配工作（某些字段，原版mcp/forge没有，craft/spigot可能往服务器核心里面打了补丁，导致编译出错，需要对forge进行修改，实现这些功能来消除，同时还需要让bukkit适应forge的实体/方块/多世界等元素），万里长城走出了第一步，剩下的就是抄了！没错，就是抄，cauldron和mcpc+的前人成果是可以抄过来移植的，当然craftbukkit对服务器的修改也要抄，并适配1.8以后的服务端。
      使用工具: SpecialSource, Srg2source, forge MDK, MCP，以及可以直接生成spigot到mcp的映射的 MinecraftMappings(https://github.com/Techcable/MinecraftMappings)
      映射思路就是用MinecraftMappings生成的东西来做到从spigot到mcp
      步骤：1. 前期准备：Mac／linux环境（讲解都是基于这个），JDK,apache Maven,kotlin,eclipse/IDEA
，            2. git clone https://github.com/md-5/SpecialSource, 进入克隆的代码库根目录，执行mvn package,取出target/SpecialSource-xxx-shaded.jar备用
               3.git clone https://github.com/Techcable/MinecraftMappings, 进入代码库根目录，执行./genmappings.sh <版本> <mcp版本>之后会出现一大堆版本(1.8-1.10)的映射，你可以选择喜欢的去用（我自己改了个1.11.2，通过改那个kt文件添加新的版本）。
               4.去https://hub.spigotmc.org/jenkins ... rget/BuildTools.jar下载buildTools.jar, 在工作目录执行 java -jar BuildTools.jar --rev 你要的版本，生成craftbukkit和spigot的最终jar，这里我取craftbukkit为例子。如果buildTools.jar成功执行并编译了（为此你的网络要好一些否则下载就把你卡住了），你应该可以在CraftBukkit/target 找到 craftBukkit-版本-SNAPSHOT.jar,不要选择带orginal的，有血坑！
               5.将craftbukkit拷贝到你的工作目录，这里假定 MinecraftMappings/1.10.2/ 将之前的SpecialSource拷贝到这里。用记事本编辑以下内容：
               PK: net/minecraft/server/v1_11_R1 net/minecraft/server
               PK: org/bukkit/craftbukkit/v1_11_R1 org/bukkit/craftbukkit
               PK: org/bukkit/craftbukkit/libs/joptsimple joptsimple
               PK: org/bukkit/craftbukkit/libs/joptsimple/internal joptsimple/internal
               PK: org/bukkit/craftbukkit/libs/joptsimple/util joptsimple/util
               PK: org/bukkit/craftbukkit/libs/jline jline
               PK: org/bukkit/craftbukkit/libs/jline/console jline/console
               PK: org/bukkit/craftbukkit/libs/jline/console/compeleter jline/console/completer
               PK: org/bukkit/craftbukkit/libs/jline/console/history jline/console/history
               PK: org/bukkit/craftbukkit/libs/jline/internal jline/internal
               PK: org/bukkit/craftbukkit/libs/jline/org/ org
               PK: org/bukkit/craftbukkit/libs/jline/org/gjt org/gjt
               PK: org/bukkit/craftbukkit/libs/jline/org/gjt/mm org/gjt/mm
               PK: org/bukkit/craftbukkit/libs/jline/org/gjt/mm/mysql org/gjt/mm/mysql
               根据实际情况你可能要把v1_11_R1替换成v1_10_R1,v1_9_R2等字符，并且把org/bukkit/craftbukkit/libs/下面所有的包都映射到根目录，如org/bukkit/craftbukkit/libs/jline jline,具体要查看jar包内容操作，大概就是这样。将调整好的内容存到工作目录取名packages.srg

               6.重映射jar：执行 java -jar SpecialSource-xxx-shade.jar -i craftbukkit-xxx.jar -o remap.jar -m packages.srg, 就可以得到重映射的craftbukkit
               7.从Spigot目录/CraftBukkit/ 下面把src拷贝到工作目录（MinecraftMapping/你的版本，下面叫PWD), 备用
               8.git clone https://github.com/MinecraftForge/Srg2Source 用IDEA/Eclipse 打开这个工程，新建2个运行选项，其中一个设定为这样

           --srcRoot 仍然是craftbukkit源码 --SrcRangeMap 为你上一个生成的映射文件,srgFiles选择同一目录下的spigot2mcp.srg,--lvRangemap选择同一个映射，--excFiles 的来源另讲  --outDir为输出源码目录。其中exc File最简单的生成方式是：MDK(https://files.minecraftforge.net ... e/index_1.11.2.html)，在forge下载页面选择MDK并解压，进入解压的mdk目录执行 ./gradlew setupDecompWorkSpace，执行完后到 ~/.gradle/caches/de/oceanlabs/mcp/mcp_snapshot/20xx_xxxx/x.x.x/srgs/ 拷贝出mcp.exc到工作目录里面，然后将excFiles指定为它即可。

              10. 应用 Access TransFormer，下载附件 spigot2mcp_at.cfg (9.97 KB, 下载次数: 9)

，此附件适用1.11.2版本，如果需要其他版本请在spigot的buildData找到bukkit-x.x.x.at,并将它转化为forge的searge半混淆名字（可以自己写小脚本转化），将它放在src/main/resources/META-INF下面，不这么做的话你会发现多出一堆访问权限不对的错误。具体说明在这里：https://docs.spongepowered.org/5 ... s-transformers.html
              11.一切就位后，打开IDE，导入这个mdk为gradle工程，再次运行setupDecompWorkSpace任务（应用access Transformer），之后你可能需要处理一大堆错误，比如错误的import（最常见的是很多类mcp名字和bukkit名字一样导致了混乱，这可能花费你2-3个小时手动处理错误，但不得不说这已经是最好的结果了），处理完后，错误还会剩下一些，基本是找不到对应的方法和字段的错误，这是因为，craftbukkit修改了mc本体，打了补丁，forge自带的mcp没有这些改变，就会报错，当然这也是你要去适配的地方！
              12.这么一大套做下来，也累了，泡杯茶，思考一下后面怎么抄怎么改，来复活mcpc吧～
