[ 反起床战争隔空偷床外挂 ]
-ImpossibleBreak-

作者：andylizi

插件介绍：
   一句话，防止玩家使用外挂进行隔空偷床，插件已在百人小游戏服务器测试过几个月，没有接到过任何误报反馈，应该是很安全的

安装方法：
   丢到服务端里面运行即可，注意服务器必须要使用java8或者以上
展示图片：


（烟雾是调试时使用的，用来标明密封检查遍历到了哪些方块）

配置文件：
  1. checkImpossibleBreak:
  2.     checkTypes:   # 方块被破坏时，检查哪些类型。默认只有床。支持数字id，不支持副id
  3.         - BED_BLOCK
  4.    
  5.     # 判定床是否处于封闭空间检测时的最大范围, 强烈建议不了解用途的情况下不要修改
  6.     maxDistance: 9
  7.    # 搜索的最大深度(方块数), 强烈建议不了解用途的情况下不要修改
  8.     searchDepth: 16
  9. checkBreakSpeed:
  10.     # 是否检查拆床的速度过快的情况
  11.     enable: true
  12.     # 如果同一个玩家拆除两个床方块之间的时间间隔小于此值（毫秒）, 就判定为作弊
  13.     maxBreakSpeed: 200
  14. messages:
  15.     broadcast:
  16.         # 检测到隔空拆床外挂时，全服广播信息，支持彩色，%s 替换玩家名字
  17.         impossibleBreak: "&7玩家 %s &7因使用隔空拆床作弊被踢出游戏"
  18.         # 检测到拆床速度过快时的广播信息，同上
  19.         fastBreak: "&7玩家 %s &7因使用自动拆床被踢出游戏"
  20.     kick:
  21.         # 踢出信息同上。
  22.         impossibleBreak: "&c检测到隔空拆床作弊"
  23.         fastBreak: "&c检测到自动拆床作弊"

一些补充说明：

此插件的密封检测原理只能防止外挂直接隔空拆除“周围被堵死的床”。
如果外挂玩家所处的位置可以从任何一个角度（不管是什么角度，合理或不合理的角度）通过任何大小的缝隙“够到”床的话，此插件不会将其判定为外挂（至少 impossiblebreak 检测不会，但 breakspeed 检测说不定，它工作原理不同）。

不过鉴于正常玩家玩起床时都会把床包的死死的，这应该不是什么大问题啦。

此插件不会阻止玩家在正常游戏逻辑支持的情况下，比如通过台阶之间的缝隙来拆床。仅会在完全不正常的行为（床6个面都被包的好好的，可玩家却把成功它拆了）下才会触发 impossiblebreak 机制。因此理论上来说不可能误报，理论上来说外挂是没有办法绕过的。

不过，像世界上所有的反作弊系统一样，在延迟极高的情况下，什么都是有可能且无可避免的会发生的，这种误报不被考虑在内。

关于开源：免费发布此插件只是为了对中国小游戏服的环境做一点微小的工作，github上的源码里注释非常的非常的全面（全面到写完后我这辈子再也不想写注释和文档），热烈欢迎各种pull request及不通知本人的再修改。

由于使用到了一些（好吧，是大量） Java 8 的新特性，因此你可能需要学会一些 Lambda 、函数式接口与 SteamAPI 的基础知识才能正常理解与修改源码。

如果想知道此插件的工作原理，可以参考 BlockChecker类的文档 和 主类的相关注释。

同样，欢迎各位借用此插件的想法开发新的相关反作弊插件（不过放个Credit最好啦）。在明显位置注明了作者的情况下，也欢迎各位不加询问的使用此插件的源码。

游戏生物的AI检查能不能看见玩家吗？

如果能准确的检查“能不能看见玩家”那可以解决近一半的作弊手段了。特别是最令人头疼的，危害极大、误报率极高、对延迟要求极高的的，检测对资源的消耗高且算法难度大的杀人光环系列外挂。

这个不是能不能直线够到床，而是“有没有可能直线够到床”。比如，如果床四周都被包裹了，那么玩家无论在哪个角度都不可能够到床，不管是不是直线。
因此，当玩家尝试破坏一个被包的死死的床时，那肯定是外挂了。

夺旗这个比喻恰当的不能再恰当了。
