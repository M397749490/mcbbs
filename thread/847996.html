文本过滤/重塑



本插件可用于对发送给玩家的文本内容进行强制替换，并支持以正则表达式的方式匹配文本中可变化的字段，应用在替换后的文本上。

支持的范围包括

- 聊天信息

- actionbar

- 物品栏标题

- 物品名字/lore

- bossbar

- scoreboard objective/score



替换文本的原理是修改数据包，所以不会对服务器进行逻辑处理及存储的信息造成任何影响。

配置方法

在配置文件中添加一系列替换条目来设定替换规则。一个替换条目包含
- pattern （正则匹配规则）
- replace （替换成什么）
- sources （所有可能出现的地方）

以下为默认配置文件中包含的示例替换条目：
  1. - pattern: "my name is (?<name>.*?), I am (?<age>.*?) years old."
  2.   replace: "我 $(age) 岁，叫 $(name)。" # 如果置空则撤销信息
  3.   sources:
  4.   - 'chat' # 聊天栏信息，或action bar
  5.   - 'title' # 标题信息
  6.   - 'inv' # 物品栏标题
  7.   - 'item' # 物品
  8.   - 'bossbar'
  9.   - 'scoreboard' # objective 的显示名字或 score 的名字
复制代码
sources用于减少不必要的处理量，请在配置一个替换条目中添加这个替换条目可能出现的所有位置。
如果不添加任何出现位置，则这个替换条目不会生效。

需要注意的是，文本匹配是使用正则表达式进行的，正则表达式中下列符号具有特殊含义：\, *, +, ?, |, {, [, (,), ^, $, ., #
如果你需要匹配的原文本中包含列出的符号，请对其进行转义。转义方法参考上面给出的第二个示例。
一些废话：
上面的示例中使用了两个反斜杠（\）来对 $ 符号进行转义，因为bukkit在读取配置文件的过程中也会处理一次转义，所以配置文件中填写的两个反斜杠，实际上是对反斜杠再进行一次转义，输入到正则表达式解释器时就只有一个反斜杠，这是我们想要的结果。


对文本中可变字段的匹配是依赖正则表达式的named capture功能实现的，使用方法也请参考上面第二个示例。
上面示例中value是可以随意定义的，例如改为money，xiaoqianqian均可。
一个句子中可以包含多个这样的capture group，但是capture group的名字不能冲突。

关于嗅探功能
如果你不知道想要匹配的文本的具体内容，如不可见的颜色符号等，可以通过设置配置文件中
  1. sniffer: true
复制代码
然后重载插件来打开嗅探功能。
(本插件未设置重载指令，请使用第三方插件管理器，如plugman来重载插件)
嗅探功能开启的情况下，插件会把所有可能会被处理的文本输出到控制台，所以请不要在服务器正式运行的时候打开这个功能。
