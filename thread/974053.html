什么是钩子？

钩子是关联两个对象的手段。钩子是一种有效性绑定，对于一个勾入其他对象的对象而言，被勾对象失效（或更改）时将得到通知。

为什么要使用钩子？

假设你要做这样一个插件：延迟中毒。一个简单的思路是设定一个定时 (Server#runTaskLater(.)). 但如果玩家在定时结束前下线，那么这个定时器要操作的对象就失效了。如果我们只监听玩家下线时间并取消定时，那么必然会有人意识到只要通过下线重登就能无限延长延迟从而永不中毒。要解决这个问题，我们就必须暂停定时器并在玩家上线后恢复。传统地，我们将不得不监听玩家的上线和下线事件，并手动挂起和恢复计时器。

但现在通过钩子，可以将上下线事件和对定时的挂起和恢复托管到这个插件。

如何使用？

（由于服务器负载原因，暂时不提供 maven 仓库，请下载 jar 文件并作为本地依赖。）

这是一个插件例子：

  1. public class Main extends JavaPlugin implements Listener {
  2.         @Override
  3.         public void onEnable() {
  4.                 getServer().getPluginManager().registerEvents(this, this);
  5.         }

  7.         @EventHandler(priority = EventPriority.MONITOR)
  8.         public void onPlayerJoin(PlayerJoinEvent event) {
  9.                 Player player = event.getPlayer();
  10.                 UUID uuid = player.getUniqueId();
  11.                 if (!tracking.contains(uuid)) {
  12.                         // Setting an task
  13.                         PlayerTaskHookApi.runTaskTimer(this, player, () -> {
  14.                                 getLogger().info("tick"); // <-
  15.                         }, 0L, 20L);
  16.                         tracking.add(uuid);
  17.                 }
  18.         }

  20.         private Set<UUID> tracking = ConcurrentHashMap.newKeySet();
  21. }
复制代码


插件提供两个方法创建定时任务：

  1. // 创建延迟任务
  2. TaskDescriptor PlayerTaskHookApi.runTaskLater(Plugin, Player, Runnable, long delay);
  3. // 创建定时任务
  4. TaskDescriptor PlayerTaskHookApi.runTaskTimer(Plugin, Player, Runnable, long delay, long interval);

除 Player 参数外和 Bukkit 参数一致。TaskDescriptor 提供以下方法：

  1. // 恢复挂起的任务
  2. void resume();
  3. // 挂起任务
  4. void suspend();
  5. // 取消任务
  6. void cancel();

关于线程安全
默认情况下，可以在异步线程中添加任务而无需额外加锁。所有任务都运行在同步线程中，可以安全地更改游戏内容。


关于性能

这个插件单独维护一个任务队列，且运行在主线程内。如果安排过多任务可能会产生显著的性能问题。
玩家的加入在不为玩家安排任何定时的情况下不产生额外的性能开销。

由于暂时没有序列化 Runnable 的方案，所有的任务都保存在内存中，且会随重启丢失。在后续版本可能添加任务休眠。

关于兼容性

理论上，这个 API 可以在 1.6 以及以上版本使用。但仅测试到 1.12.
由于 Concurrent* 的使用，需要至少 Java 8 的支持。（你为什么还在用 Java 6?）
