[一、开始的开始]
插件下载：关于目前服务器插件来源的一点点看法
现在很多服务器的腐竹在寻找服务端插件时都在插件板块直接下载楼主的网盘链接或者是下载服务端懒人包在插件文件夹里复制粘贴插件，其实有的插件更新以后楼主并没有更新到最新版本，这样就造成老版本插件泛滥，每次插件的更新都意味着新功能的加入和原先bug的修复，有的插件不更新后台还会咔咔刷码，所以在转载插件贴中下载前还是先去看看原帖的最新版本是多少，差的太多了就去下载最新的吧。

【一，默认组的设置】
       在默认状态下每个玩家进入服务器时都被安排在[Builder]用户组中这个用户组默认配置好了所有玩家可能用到的权限，可能有的人会问不是有个[Default]组吗？的确在英文中Default是“默认”的意思，但是这个组一般不在服务器中使用，大家可以看到【范例代码-1】中第16行代码中的
  1. default: true
复制代码
       对比这个选项不难发现其他的组都是false，实际上这个值是控制着玩家加入服务器时默认分配的用户组。你把这个true赋值给其他的组就可以将该组设置为默认组，但是推荐不要修改，Builder组很实用，其他的组权限不是多了就是少了的.....
【二，升级式用户组和并列式用户组】
       首先说明一下，这俩名字都是我自己起的，如果他们有专业的名字麻烦回帖告诉我一下，谢谢。
       同时，这一节也是我这篇帖子的核心内容。
       ————{顾名思义，升级式用户组的特点就是等级制度严，高等级不但具有低等级所有的权限而且拥有低等级所没有的权限。升级式用户组体现了一个词，那就是“继承”，高等级继承并获得低等级的所有权限并且随着低等级权限的改变而改变，也就是说，在低等级获得一个新权限时，所有从他那里继承权限的分组都将获得这一权限，【范例代码-1】就是一个升级式用户组的例子。
       ————{与之相反的，并列式用户组就像是一个平级的等级制度，除了Default组之外的组都是从D组继承权限，即所有用户组之间平等。【范例代码-2】就是一个并列式用户组的例子：
  1. groups:
  2.   Default:
  3.     default: false
  4.     permissions:
  5.     - -bukkit.command.kill
  6.     inheritance:
  7.     - g:groupmanager_default
  8.     - g:bukkit_default
  9.     - g:essentials_default
  10.     - g:towny_default
  11.     info:
  12.       prefix: ''
  13.       build: false
  14.       suffix: '
  15.   Builder:
  16.     default: true
  17.     permissions: []
  18.     inheritance:
  19.     - default
  20.     - g:essentials_builder
  21.     - g:towny_builder
  22.     info:
  23.       prefix: '
  24.       build: true
  25.       suffix: ''
  26.   VIP:
  27.     default: false
  28.     permissions: []
  29.     inheritance:
  30.     - Default
  31.     info:
  32.       prefix: '
  33.       build: true
  34.       suffix: ''
复制代码
       在并列式用户组中除了一个母用户的权限等级较低之外，其他的组之间平等而且相互独立，要给全体用户组添加权限可以直接给母用户组添加权限（因为全部其他的组都是从母用户组继承的权限），也可以给他们单独添加权限。

【三、我自己对这两种用户组模式的理解】
升级式用户组添加权限方便，可以用给低级用户组添加权限的方式给全部的高级组添加同一权限，缺点是控制不够精确。打个小比方，kit礼包，不同的等级（比如vip等级这类的）之间需要不同的用户组权限领取礼包，如果给低级用户组权限，那就意味着全部用户组等级比它高的组都能领取这一礼包，就导致了高级用户组玩家一天领取还几个礼包，还有地皮的数量权限(plotme.limit.x)，给低级用户组1个地皮的权限，那么高级组就没办法设置多个了。并列式用户组虽然设置上有点麻烦，但是话说回来开服的有几个怕麻烦？并列式用户组还可以，设置各种特殊组，当权限较多时，使用起来反而比分级式用户组方便的多.........

更新一下全体用户组的内容

       全体用户组又叫全球用户组
储存的位置就是在GM插件的配置文件夹下的“
globalgroups”文件内。由于配置文件过长这里就不在转载（建议读者找一个配置文件比对着往下读）

全体用户组实际上是一个权限组的集合，插件作者将一批权限集中放在这样的一个组里。打个比方，在一间学校里校长要3年2班全体同学到校门口集合，不需要将三年二班所有学生的名字喊一遍，而只是需要说“三年二班”就可以了。全体用户组和单个权限之间的关系就像单个学生和一个班级的关系一样。
【全体用户组的作用】
1、首先个人认为全体用户组的存在使每个组的配置文件更加简洁。因为大都数用户组都要包含几十条权限，都写在用户组配置文件下...画面自行脑补。
2、全体用户组为我们管理服务器权限提供了一种新的思路。一般来说我们在全体用户组中删除一条权限时就意味着所有使用到这个全体用户组的用户组都失去了这一权限。当然，它所对应的指令在本服就失去了作用（因为没有人有权限执行它）。
3、全体用户组使精确的权限控制更加方便。假如我只想让新手组可以使用“help”指令，那我就可以在全体用户组中删掉对应的权限，然后在新手组的权限列表中单独加上它。而不用全体用户组的话我们就要在游戏中反复输入指令取消其他组的help权限。
4、运用全体用户组可以更方便的管理服务器内VIP特权。除了配置文件本身自带的全体用户组，我们还可以自己新建我们所需要的全体用户组。在新组中加入各种vip特权，可以方便的在groups文件里添加权限，不用一遍遍的复制权限。
