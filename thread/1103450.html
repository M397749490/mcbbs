前言：
当我在某服务器玩耍的时候，遇上了一个搞事的玩家。她自己制作了个客户端，并购买了不少非法帐号，在服务器内一直刷屏，内容就是类似于“哼哼哼啊啊啊啊啊”之类的（homo确认）或者大声复读各种奇怪的东西且管理员屡禁不止。虽有ignore忽略功能和管理员积极的封禁但搞事情的能换号所以依旧能够影响游戏体验。


提示：请从本帖给出的github链接进行下载或构建，其他网站提供的插件本体安全性未知且可能会将你和你的服务器的正版玩家的帐号置于风险之中。因从其他网站下载产生的帐号问题本鱼一概不负责！同时对索要密码的插件也请保持高度警惕

原理：
检测玩家是否拥有她所使用正版的邮箱（据本人观察大多数黑卡所使用的邮箱使用者并没有办法访问）（就这

特性：
    自带http服务端（超级简陋）和api服务端（可以用来自定义验证页面）
    能够发送邮件以验证玩家是否拥有她所使用的账户的邮箱
    支持bungeecord跨服
    不主动向用户索要账户密码以保证安全性
    支持正版盗版同服，同时盗版玩家不受其影响
    - 其他版本兼容性未知且未对其他版本的服务端进行测试


如何使用：
氟竹：
1.将插件丢进服务端中的plugins
2.如果是群组服的话，建议也将插件丢进bungeecord的plugins中
3. 启动，让插件生成配置文件及网页（如果开启内置网页服务端的话）
3.打开配置文件，针对机器进行配置（如何配置看下面）
3.1 插件配置编码为UTF-8，请考虑使用vscode进行编辑
3.2 可选打开success.html和fail.html进行编辑以自定义自己的页面
3.3 可选打开message.yml进行对玩家发送的消息的编辑

4.开服

正版玩家：
1.点击金色字体复制密码
2.去minecraft.net将密码修改为从游戏里复制出来的那一份
3.在游戏内输入“.check 你的邮箱”以完成第一步验证
4.去邮箱访问所提供的链接以完成验证
5.将你的密码改回你想要的密码

盗版玩家：
无需操作，这个插件是针对正版玩家的

（网页？）开发者：
1.根据配置中所提供的api配置，确认/调整插件所监听的端口
1.1 不建议将插件所监听的端口填写到开放的端口上
2.验证成功时，应发送玩家使用的UUID（带横杠）和session id（一般为不带横杠的UUID），通知插件验证完成
2.1 无需针对bungee作相关的处理，插件自己会向其他子服同步验证信息

指令&权限：
    .check 邮箱（也不知道算不算指令）
    alawhitelist指令 权限节点：antileakaccount.whitelist（通用） 用法：
        alawhitelist add 玩家名 将一个玩家加入白名单，这个玩家将不用进行验证 对应权限节点 antileakaccount.whitelist.add （权限节点仅限spigot/paper端）
        alawhitelist remove 玩家名 将一个玩家移除白名单，这个玩家将需要进行验证 对应权限节点 antileakaccount.whitelist.remove （权限节点仅限spigot/paper端）
        alawhitelist list 列出白名单中的玩家和她们的uuid 对应权限节点 antileakaccount.whitelist.list （权限节点仅限spigot/paper端）
        alawhitelist import 文件 从一个yaml文档中导入白名单列表 对应权限节点 antileakaccount.whitelist.reload（权限节点仅限spigot/paper端）
