什么个原理这么神奇？
执行set_point时，使用记分板保存玩家传送点的三维坐标；
  1. execute store result score @s telepX run data get entity @s Pos[0]
  2. execute store result score @s telepY run data get entity @s Pos[1]
  3. execute store result score @s telepZ run data get entity @s Pos[2]
复制代码

执行tp_point时，获取玩家当前的坐标并和传送点的坐标进行比较，再利用穷举来使玩家的对应轴坐标向传送点的坐标偏移1；接着判断玩家是否到达了传送点，若到达则修正坐标至方块中心并结束，若未达到则继续递归。
  1. scoreboard players set @s ok 0
  2. execute store result score @s posX run data get entity @s Pos[0]
  3. execute store result score @s posY run data get entity @s Pos[1]
  4. execute store result score @s posZ run data get entity @s Pos[2]
  5. execute as @s at @s if score @s posX > @s telepX run tp @s ~-1 ~ ~
  6. execute as @s at @s if score @s posX < @s telepX run tp @s ~1 ~ ~
  7. execute as @s at @s if score @s posY > @s telepY run tp @s ~ ~-1 ~
  8. execute as @s at @s if score @s posY < @s telepY run tp @s ~ ~1 ~
  9. execute as @s at @s if score @s posZ > @s telepZ run tp @s ~ ~ ~-1
  10. execute as @s at @s if score @s posZ < @s telepZ run tp @s ~ ~ ~1
  11. execute as @s at @s if score @s posX = @s telepX if score @s posY = @s telepY if score @s posZ = @s telepZ run scoreboard players set @s ok 1
  12. execute if score @s ok matches 0 run function telepoint:tp_point
  13. execute as @s at @s if score @s ok matches 1 run execute align xyz run tp ~0.5 ~ ~0.5
复制代码



因为使用了递归，再加上maxCommandChainLength，所以在离传送点过远时（大约16000格外）会导致命令执行失败并把你传送到某些奇怪的地方。
同时离传送点越远，命令执行所需的时间就越长，且会带来严重的MSPT上升问题。多个玩家同时传送也可能会导致卡顿。
