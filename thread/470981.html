Json在Minecraft的命令大类中有着特别重要的作用。因为有了Json，玩家便可以使用Json格式来写出许多玩家需要的功能，无论是实体、方块，还是希望能提供一个在游戏中就实现的游戏所没有的可视化操作界面，这都可以办得到。
现在，Json格式在minecraft中主要有3个用途：
1.NBT标签
2./tellraw指令
3./title指令其他还包括牌子、书本也使用Json编辑，但不在这里一一列举了，如果要了解请点击主页中的链接。
是的，这个其他人已经发过了，但我再发一遍的目的并不是要与他们的攻略抗衡，而是为了通过这里的实例来概述Json的基本用途以及稍微了解下Json的格式。后面的项目中，我们将要讲Json的实际用途。后面讲Json的内容可能版全部发错了，但是为了整理在一起，也因为Json的主阵营在这里，所以我只能冒险在这里发。后面，我可能会在“编程开发”一版再发个指引贴。（“编程开发”版几乎没人看，这也是个比较重要的原因）
Json除了用在游戏的指令中，而且在游戏启动、游戏开发也带来了一些帮助。
为什么下载好了游戏还需要启动器？为什么下载好的jar不能和其他java程序一样直接正常运行？为什么其他开发启动器的人总说jar启动需要json文件的帮助？
接下来，我们就来解答这些问题……

Json的文件格式相信大家也见过了吧，除了minecraft里所用的json，网页中、脚本读取器等等，json也一样会出现。接下来，将讲解json在程序员眼里是什么样子的。

/tellraw，自定义提示信息，用来在玩家的聊天栏中发送带有各种奇妙颜色、各种书写格式、甚至是可以和网页一样点击一下能帮你执行命令、移到哪里显示什么的文字。它的语法格式如下：
/tellraw <玩家/选择器> [信息]
其中的[信息]便是要我们写Json的地方。它的格式和NBT类似，只不过内容几乎不同。

英文名中文名用途
text文字显示其后面定义的文字，其颜色、特殊效果等可以通过下面的参数来决定。
color颜色定义颜色，可以定义的颜色有：
black（黑），dark_blue（深蓝色），dark_aqua（深绿），dark_red（深红），
dark_purple（深紫），gold（金色），gray（灰色），blue（蓝色），
green（绿色），aqua（水绿色），red（红色），light_purple（亮紫），
yellow（黄色），while（白色）和reset（还原颜色，在extra中可以起到取消原text中设定的文字颜色的功能）。
bold设置粗体是否让文字变为粗体，设置true为是（变为粗体），flase为否（不变为粗体），默认为false。
underlined设置下划线是否让文字带有下划线，设置true为是（带下划线），false为否（不带下划线），默认为false。
italic设置斜体是否让文字变为斜体 ，设置true为是（变为斜体），false为否（不变为斜体），默认为false。
strikethrough设置删除线 是否让文字带有删除线，设置true为是（带删除线），false为否（不带删除线），默认为false。
obfuscated设置为随机字符 是否让文字变得随机（文字乱码，还不停变化），设置true为是（变得随机），false为否（不变得随机），默认为false。注意，此效果只能在语言包选中为English(US) 时才能使用，而且只能变换英文字符（中文或者日文等等那种一个字占2个小写字母的字符是没办法变的）。
insertion复制操作 设置是否能让玩家通过按住shift 再点击文字就能将文字复制到聊天栏，设置true为是（可以复制），false为否（不可以复制），默认为false。用这个来指定是不会将聊天栏已经输入的字符给覆盖掉的，而是直接从光标处插入。
translate语言翻译包 使用的翻译语言包。如果你想把你的提示消息发给外国人，那么用这个你就省了翻译了，因为你只要给它指定这个参数一个游戏文件里有的lang语言包，那么它就能将with里的内容翻译并照格式发出！不过这实在是不常用，因为翻译语言包不多（不是游戏语言包）。而且，只有不指定text时with和translate才能正常使用，因为text的显示优先级比with大。（具体待研究）
with要翻译的语言对应translate指定语言包而要翻译并显示的内容，可以包括其上面除了translate的所有内容，不过需要一个花括号全部括起来。（具体待研究）
score要显示的分数 显示一个指定玩家在记分板中定义好的分数。但是如果给出的参数返回无结果，那么有可能会出bug把text和translate给忽略掉。格式如下：
……,score:{name:玩家名/选择器/*符号 ,objective:分数名 ,value:分数 },……
（1.如果name后为*，那么所有玩家看到的是自己的分数    2.如果有value，那么显示的分数将改为此分，不过不会修改原来的值）（具体待研究）
selector选择器 显示由选择器指定的玩家/实体的名字，格式：（明明和指令一开始的那个一样= =）
……,selector:@a/@p/@r/@e[......]  ,……
clickEvent点击动作 设置如果玩家在聊天信息中点下这些文字，那么就会根据参数来执行相应的动作，格式：
……,clickEvent:{action:"open_url/run_command/suggest_command/change_page ",value:"与前面action对应的要执行的文本 "},……
其中，open_url是指打开某一个网址，value的内容就应该是一个网址；run_command是指如果玩家点了那就以玩家的身份执行在value中设置的指令，注意要加上“/”，而且执行的指令因为是以这个玩家的身份执行的所以要想好他的权限；suggest_command是指点击之后会将聊天输入框内的内容全部替换成value的内容（注意是替换而不是插入）；change_page是在书中用的，在/tellraw和/title中不能使用，这是用来换页码的，value应该指定存在的页码（整数）。
hoverEvent提示动作 设置如果玩家的鼠标指针移到了这些文字，那么就会根据参数来在鼠标旁边显示不同的说明信息，格式：
……,hoverEvent:{action:"show_text/show_item/show_achievement/show_entity ",value:"要显示在鼠标旁边的内容，如果是show_entity、show_text或show_item则不需要双引号而改成'{……}'这样的数据标签 "},……
其中，show_text显示Json信息（只能纯文本），而表示信息的复合标签（参数）写在跟在value后的'{}'里；show_item显示物品信息，表示物品属性的复合标签（参数）写在跟在value后的'{}'里；show_achievement显示成就，value后面跟着用双引号引起来的成就名称；show_entity显示生物信息，表示生物属性的符合标签（参数）写在跟在value后的'{}'里。
extra子标签列表用于将希望显示不同颜色、样式、功能的文本用列表表示，格式：
……,extra:[{你要设定的子文本信息 },{你要设定的子文本信息 },……],……
其中，在子文本信息的花括号里可以使用上面的任意参数，但是不能再包括extra。另外，如果里头有的参数没有指定但是外面指定了，那么就使用外面所定义的文本格式。比如在extra外定义了红色但是extra里的第一项没定义颜色，那么第一项的文本颜色就和外面一样是红色；如果定义了是绿色，那么颜色将不和extra外面的定义颜色统一，而是显示绿色。
以下是一些例子。
注意，加粗的地方是重点，最容易错的地方！
①
举例：显示给最近的一个人，文本叫“MCBBS”，其颜色是红色，则
/tellraw @p {text:"MCBBS",color:red}
效果：
MCBBS
②
举例：
显示给最近的一个人，文本叫“点我拿钻石”，其颜色是蓝色，加下划线，点它就能自杀（注意是原版指令），则
/tellraw @p {text:"点我拿钻石",color:blue,underlined:true,clickEvent:{action:"run_command",value:"/kill"}}

效果：
点我拿钻石
（点了之后……）
（被HIM杀死……）
（：55555……我的钻石掉光了啊………………）
③
举例：
显示给所有人，文本叫“MCBBS欢迎你，你的金粒个数是：”加上名字叫jinli的分数（已经提前定义好），而且看的是自己的金粒，颜色“MCBBS”是间隔的红和黄色，“官服欢迎你”是蓝色，“，”和“：”是绿色，“你的金粒个数是”是黑色，则（答案不唯一，这是其中一个最让人能看得懂的，请不要吐槽= =）
/tellraw @p {text:"",extra:[{text:"M",color:red},{text:"C",color:yellow},{text:"B",color:red},{text:"B",color:yellow},{text:"S",color:red},{text:"官服欢迎你",color:blue},{text:"，",color:green},{text:"你的金粒个数是"},{text:"：",color:green},{score:{name:"*",objective:"jinli"}}]}
效果：（假设条件：玩家A的jinli分数为233，玩家B的jinli分数为998）
——玩家A：MCBBS官服欢迎你，你的金粒个数是：233
——玩家B：MCBBS官服欢迎你，你的金粒个数是：998

/title，自定义显示标题，用来在玩家游戏屏幕的中央显示已经定义好的Json信息。它比/testfor的使用方法还要多，因为它不仅分为主标题（在正中央，字稍微大些）和副标题（紧靠主标题，在主标题下面，字稍微小些），而且还能调整淡入淡出的效果！这在单机RPG中显示一些提示或警告信息是很有用的。它的语法格式如下：
/title <玩家/选择器> clear
//用来立即清除玩家屏幕上用title生成的信息
/title <玩家/选择器> reset
//撤销上次用title做的设置（相当于还原上一次用title做的关于subtitle或time的设置）
/title <玩家/选择器> title <Json信息>
//设置主标题的文本内容，Json格式参见 Json与/tellraw
/title <玩家/选择器> subtitle <Json信息>
//设置副标题的文本内容，Json格式参见 Json与/tellraw
/title <玩家/选择器> times <淡入时间> <显示时间> <淡出时间>
//设置显示标题的淡入时间、停留时间和淡出时间，单位为游戏刻（1秒=20游戏刻）
如果想要看到执行的效果，请点击这里，将跳转到@sylqiuyifeng 的视频演示。

Dos指令中，除了有打开、查询目录、对目录进行一些基本操作等等的功能，它启动程序时有个在Windows一类的可视化系统中启动exe没有的功能：给定几个参数启动这个程序，
格式是这样的：XXX.exe -参数名 参数 -参数名 参数 ………………………………
其中 -参数名 中的参数名需要你先知道这个程序给了你什么参数可以用，你才能调用。参数也必须对应，才能正常使用这个程序。
早期Dos指令通常就是用这种方式来执行多功能的程序的。因为你想使用程序的某些特殊功能而想指定这个程序的运行模式（比如指定1就打开1网页，2就是2网页，等等），但是Dos并没有可视化界面，不能给你编辑框来操作，就只能以这样的格式来告诉这个程序：我要你做什么，怎么做，对谁做，用什么方法做，什么时候该做完等等。这就是-…… …… -…… ……格式的用途。
java程序同样也支持这样的调用方法，只不过前面加了一个java，扩展名也变成了jar：
java XXX.jar -XXX xxx -XXX xxx ………………

所以，minecraftArguments是用来启动游戏的jar程序的参数列表，因此json文件就必须要了。

然后，libraries中的文件以及其附带的URL、指定参数也是需要的，因为这些文件将支持minecraft游戏的如3D模拟功能、光线特效、平滑光照甚至是Forge、Skinme这样的内置Mod需要的支持库。如果没有它们，游戏将因为没有其能实现3D效果的事先写好的程序而出错。jar、json并不是就独立两个文件就可以运行的，否则为什么.minecraft文件夹里除了存档、材质包、Mod等等，还有一大堆的jar附加程序来配合游戏一起运行？

所以，Json文件对于游戏的jar启动是很重要的。

JSON(Java Script Object Notation) 是一种轻量级的数据交换格式。它基于JavaScrip的一个子集。 JSON采用完全独立于语言的文本格式，但是也使用了类似于C语言家族的习惯(包括C, C++,Java等)。这些特性使JSON成为了理想的数据交换脚本语言，不仅易于人阅读和编写，同时也易于机器解析和生成(网络传输速度)。
（json准确的说应该归类于脚本语言，而且通常只要有文本编辑器人就能读懂它，几乎所有编程语言都可以使用此语言，通用性很强（不过还是没有太多人用……毕竟它虽然可读性高但是写出来后文件比xml要大一些））
所以，它实质上是一门编程语言。

我们在书写NBT指令时，就已经知道，要表示一个大项就用{}，一个列表就用[]，而其他的都统统用赋值的方式来定义我们要的参数。百科里说了这样5种基本格式：
1、对象是一个无序的“‘名称/值’对”集合。一个对象以“{”（左括号）开始，“}”（右括号）结束。每个“名称”后跟一个“:”（冒号）；“‘名称/值’ 对”之间使用“,”（逗号）分隔。（如图所示，图中表示数据的方式是类似非确定性自动机的形式，没学过编译原理的人，可能理解起来困难点，实际上也是正则表达式的形式。下同）

2、数组是值（value）的有序集合。一个数组以“[”（左中括号）开始，“]”（右中括号）结束。值之间使用“,”（逗号）分隔。

3、值（value）可以是双引号括起来的字符串（string）、数值(number)、true、false、 null、对象（object）或者数组（array）。这些结构可以嵌套。

4、字符串（string）是由双引号包围的任意数量Unicode字符的集合，使用反斜线转义。一个字符（character）即一个单独的字符串（character string）。 字符串（string）与C或者Java的字符串非常相似。

5、数值（number）也与C或者Java的数值非常相似。除去未曾使用的八进制与十六进制格式。除去一些编码细节。


那么，基本的格式就是这样的了：
1的表达方式：{objective:{subject1,subject2……} }
2的表达方式：{objective:[{subject1……},{subject2……}]}（也就是wiki里所说的Tag-List，列表，你可以理解为数学中的集合）
3的表达方式：{body:"body"}
4的表达方式："body"
5的表达方式：-subject1 ${any_body}-subject2 ${any_body}……


实际上和我们之前所介绍的NBT指令里所讲内容差不多，只是多了一个数值（第五个）。

几乎每一种高级编程语言都有大大小小专门支持脚本语言的模块/dll。如果你是前台管理服务器的（比如你在发帖时）就肯定希望能让[XXX][/XXX]的代码能更简洁一些，因为这样子就易读、易写，甚至不用编辑框上方的工具帮忙。不过，如果你是程序猿的话，还是用xml比较合适，因为json的花括号嵌套还不如xml的子标签方便。
json仍然有不可比拟的优点，具体和其他语言比一下就知道了。即使它只是一个标识状态的语言。

首先注意，我讲的是语法比较。

xml与json不分上下，因为xml的代码json可以实现，json的代码xml也可以实现（如果不调用javaScript的话）。
那究竟是谁最简便？如果你只是要发帖回帖，希望能给自己的文字多一些特殊效果，你绝对会喜欢json，因为他很容易读懂；但是如果你需要开发软件，请最好不用json，因为xml才是真正用于网页数据传递的结构。（不过，在JavaScript里用json的话xml当然比不上它）

注明：论坛里用的回帖的不是xml格式。
注明2:xml的优点是利于传输数据而不是表达数据，所以比起json来讲，xml在数据大小方面更好些……

json与java是在一个平台下生成的文件格式（java），而json和java的分部也不同（JavaScript/JDK），所以几乎扯不上关系。在minecraft的代码说明中，json其中一个用途是用来给jar文件找到入口class文件以便于启动游戏，而class又是被java编译而来。所以，关系就只有这个。

有兴趣的朋友，可以多研究下java的相关书籍。

前面说了，json的书写格式和c语言家族的书写格式很像（cpp是c++/#出来的文件格式）。只有这个关系，但是我们可以把它们两个拿来做比较：
1.表达式：这个一样
2.数据结构：都是大括号小括号的= =
3.函数调用：json没有可用函数，但是cpp可以通过调用函数（name(body);）来调用子程序或执行命令

NBT是minecraft中保存世界的一种基本格式。它的功能是改变世界数据，仅此而已。不过，其他高人就利用这个功能，创造出了许多奇妙的地图。它的格式如下：

{
list:
  [
    {subname1:body,subname2:body},
    {subname3:body,subname4:body}
  ]
name1:
  {
  subname5:body,
  subname6:body
  }
name2:body
name3:body
……
}

从上面可以看出，这里的NBT指令中，有以下3种部分：
1.带有"...:..."格式的项"nameX"，它可以定义某个变量为某个值
2.带有"{}"的项，该项可以包含任意个"...:...""{}""[]"，不限制
3.带有"[]"的项"list"，内部可以包含多个"{}"项，相当于给"{}"项一个列表（可以把它理解为数学中的集合，而整式就是"{}"）


这便是NBT的基本格式。
