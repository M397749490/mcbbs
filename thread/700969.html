以前见过些sethome原版模组,原理归类成这样的:

计分板:除sethome,home,delhome是trigger计分板,其余都是dummy

高频enable玩家可以使用sethome,home,delhome这三个变量,如果有玩家/trigger sethome set 1,检测了trigger判据计分板sethome上为一分的玩家,然后execut @e[score_sethome_min=1,score_sethome=1] summon area_effect_cloud/armor_stand ~ ~ ~ {Tags:["home"]}就是让玩家原地放置marker,当玩家使用/trigger home set 1时,利用teleport玩家到marker那边,如果marker多于一个,则杀死之前的marker,/trigger delhome set 1就是移除之前放置的marker

但是这样,仅仅支持单人模式,多人模式会导致marker无法识别自己是哪个玩家放置的marker.

而我觉得可以让每个marker都绑定自己的那个玩家就可以了,如果所有的marker在一个计分板上和一个使用了trigger home的玩家的分数相减,分数为0的marker,就是那个玩家放置的mark,但是怎么保证每个玩家的分数都不同呢,就要利用上面的不等式性质了,假如已经存在一个HomeID计分板上为3分的玩家,现在有另一个玩家使用了trigger sethome,就利用scoreboard players operation xx xx > xx xx让使用了trigger sethome的那个玩家取整个HomeID里的最大值,这里就是3,这样如果再让这个玩家加一分,就一定变成了整个计分板里HomeID的唯一最高分了,以后每个使用sethome的玩家都会成为唯一的最高分,保证了所有玩家的分数都不相等,之后让所有的marker在HomeID里和绑定自己的那个玩家分数相等,待玩家使用trigger home时,就可以准确tp了,为了防止多玩家同gt执行sethome,所以先execute marker ~ ~ ~ scoreboard players tag @p[score_sethome_min=1,score_sethome=1] add sethome后,所有命令都对tag=sethome的玩家执行,保证每次执行只会存在一名玩家,然后另一个玩家将在下一gt成功sethome.

这里是1.12版的sethome_main.mcfunction文件,这个每条比ooc要清晰很多,所以我就用function来解释一下这个伪插件

复制代码
#tell部分就是让每个在加载这个伪插件之后第一次进入世界的人得知这个东西的用法

#Age部分是让marker保持存在状态

#gamerule和#scoreboard部分是为了方便,直接放在高频模块里执行了

剩余的分为三大部分:#sethome,#home和#delhome

这三个注释取自trriger后的三个变量名sethome/home/delhome

看的出就是/trigger sethome set 1部分,/trigger home set 1部分和/trigger delhome set 1部分

1.sethome部分:在放置marker之前,要清除多余的marker,所以把sethome计分板为一分的玩家的HomeID的分数复制到removehome计分板上,marker的分数也复制到removehome计分板上,让marker的分数=玩家-marker的分数,杀死removehome里分数为0的marker,即可清除之前的marker,然后重新放置一个marker,先让玩家变为HomeID里唯一的最高分之后,让marker在HomeID里的分数=玩家在HomeID里的分数,这样marker和玩家的分数在HomeID里就是唯一相等的一对分数,相减=0的一定就是互相绑定的玩家和marker

2.home部分:把home分数=1的玩家HomeID里分数和所有marker分数复制到gohome里,marker分数-玩家分数=0的marker把相应的home分数=1的玩家teleport到自己旁边,原理基本和sethome一样,就是换了个计分板和主要动作换为了teleport,然后如果玩家没有设置家的情况,nohome里的分数会为1,相减后分数=0的marker会把绑定的玩家的nohome设置为0,执行trigger home的时候tellraw @a[score_nohome_min=1] {"text":"没有设置家."}

3.delhome部分:原理同sethome部分的removehome

从上面可以看出,如果玩家切换了世界,就无法正常执行命令,如果marker所在区块被卸载了,也无法正常执行命令,如果玩家想避免区块问题,或许把那个GPS给改一下就成了[滑稽哭.jpg]

当然这玩意也是可以做成支持多个home的,原理大致就是在另一个计分板上把玩家的trigger判据sethome计分板上的分数复制到另一个计分板上,然后marker和在HomeID绑定的玩家的分数相等,trigger home的时候相减=0的marker执行命令就好了,然而我已经懒得去弄支持多个家的玩意了=_=
