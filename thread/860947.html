問題：以下原本1.13.2能用的指令哪裡出問題了？具體上應該怎麼修正？

問題描述：

請教一下各位dalao，我在1.13.2用data做了一個傳送的系統，利用召喚AEC、更改AEC的POS到傳送點、再把玩家傳送到AEC
前陣子更新到1.14就失效了。
指令是這樣的－－

==================================

1. functionA

偵測左手拿物品A →被加上tagA →以下四條指令儲存"當下位置" 到 3個記分板 (x, y, z)  →清除tagA →清除物品A
execute as @a[tag=A] store result score @s x run data get entity @s Pos[0]
execute as @a[tag=A] store result score @s y run data get entity @s Pos[1]
execute as @a[tag=A] run scoreboard players add @s y 1
execute as @a[tag=A] store result score @s z run data get entity @s Pos[2]

2. functionB
偵測左手拿物品B  →被加上tagB →以下指令 召喚 藥水雲 於位置x, y, z 對應於 tagB者的記分板xyz分數

→傳送tagB者 到 藥水雲位置  →清除tagB →清除物品B
execute at @a[nbt] run summon minecraft:area_effect_cloud ~ ~ ~ {Tags:["aecPosA"],NoGravity:1,Invisible:1,Duration:20}
execute as @a[nbt] store result entity @e[type=area_effect_cloud,tag=aecPosA,limit=1] Pos[0] double 1 run scoreboard players get 玩家名稱 x
execute as @a[nbt] store result entity @e[type=area_effect_cloud,tag=aecPosA,limit=1] Pos[1] double 1 run scoreboard players get 玩家名稱 y
execute as @a[nbt] store result entity @e[type=area_effect_cloud,tag=aecPosA,limit=1] Pos[2] double 1 run scoreboard players get 玩家名稱 z
execute at @a[nbt] run tp @p @e[type=area_effect_cloud,tag=aecPosA,limit=1]

==================================
以上(nbt恕刪)

更新1.14後的出錯時的狀況是：近處的地點依然能夠傳送，但遠處(沒有被加載的區塊?) 就無法傳送了 (但傳送以外的功能有正常運作)。雖然理論上遠處的實體會因為區塊沒被加載而不能傳送，但不知為何1.13.2還是可以先把AEC傳過去，再把人傳到AEC上。
然而1.14之後貌似就不行了？，請問應該如何修正？

查了很久，發現1.14貌似有個data modify的功能 (不知道能不能用？)
從別人的指令中(1.14)，也有一條：execute store result entity @s Pos[0] double 1 run data get entity @s Item.tag.Pos[0] 好像能用？(這條裡面的"Item.tag."這個路徑是從哪裡來的？要去哪裡查看？)

问题略多...

首先是你贴出来的部分命令，一个问题是Tags:["aecPosA"]
但是，如果不是你实际的命令，且原本是能用的话，就没什么好看的了

另外一个是优化的地方，data get储存分数时可以把分数往上放大，在store时在缩小以保留精度。
这样也就不用y+1了（y+1有被玩家利用的可能...）

“利用召喚AEC、更改AEC的POS到傳送點、再把玩家傳送到AEC”
如果是在同一tick下先生成后传送玩家过去的话，
这个逻辑完全没问题。而且还是标准的做法...
记得当初1.14还是前一个快照出来时有个部分实体不能被选取的严重BUG。

那么我的对策是...放到最后一个快照版本下测试（非pre），如果没问题的话，估计就是bug了，可能下个版本就修。
如果最新快照下也有问题的话就真的是哪里出问题了，先打开gameoutput查看是否有error
不行的话，再来把命令贴过来...

哦对了...data modify的路径
Item.tag.Pos[0]
Item是当物品为实体形式时拥有的nbt，tag后面的pos是玩家自己创的路径。
大概应该就长这样...{Item:{tag:{Pos:[0,1,2]}}}

不过使用这个的话方法或许会更麻烦（除非方法改为丢出物品记录坐标，或记录在一个实体上）
物品a记录坐标，物品b执行传送对吧？
那么，原因则会是data modify无法直接修改玩家的背包物品，虽然还是有其他办法可以把坐标储存到手持物上，但对比你现在的方法，麻烦太多...
