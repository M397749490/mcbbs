一、groups.yml组文件 文件组设置一般格式（注意空格！）： groups: # 这个要保持在文件最上处 XXX: # XXX的含义是你可以自行增减用户组，名称任意，只要保持各设置格式相同即可 default: false # 该项设置玩家第一次进入游戏时，是否自动归入改组，true是，false否，下同 permissions: # 该项设置玩家的权限，在下一行之后添加，该项请看完后面的设置再更改 - essentials.* # *代表ESS插件某一权限，例如“sethome”为设置家等，如果保持*，该组则拥有Essentials插件的所有权限 - &#039;*&#039; # 仅仅为&#039;*&#039;（注意引号）则是指该组拥有所有的权限（包括上面的） - XXX.XXX # 这是其他插件的权限格式，长短，点数量不定，作者应该会在帖子中作说明，ESS的详细权限在3楼中可以找到（目前未完成） inheritance: # 意为继承，在下一行之后添加其它某一组（级别相邻或相同即可），之后XXX组就拥有所添加的组的所有权限，没有则改为“inheritance: []”，下方组也不添加 - default # 例如该项设置了默认组，则XXX组就拥有默认组所有权限（你不用再在“permissions”中添加命令了） info: # 用户组属性 prefix: &#039;&e&#039; # 前缀，若将引号中的内容改为“&c[VIP]&2”，该组所有玩家名则会显示为：[VIP]绿名，输入“/list”查看在线人数时就可以看到。颜色设置在这里看 build: true # 该组是否能修改地形（注：刚安装插件时，默认组此项为false） suffix: &#039;&#039; # 尾缀，好吧，这项我没用过，应该和“prefix”一样功能，不过在昵称尾部 二、users.yml玩家文件 该项设置很简单，一般格式： users: # 该项固定在文件顶部 123: # 我们以一个名叫“123”的玩家举例吧 subgroups: [] # 子用户组，类似于上面的“继承”，单独对该玩家有效（上面的“继承”同样有效），冒号后接“空格[]”表示“无”，下同 permissions: [] # 权限，仅该玩家拥有（添加方法同groups.yml），该两项设置一般不需更改 group: XXX # 玩家所在用户组 接下来就是领地了，领地这个就不方便直接删除，直接进入plugins\Residence\Save，全选删除即可。 最重要的就是玩家登录信息了，这个不同的登录插件都不一样但大同小异，下面以Authme为例。 大部分服务器一般以SQLite为数据介质，这个大家用help命令可以看到，但是也会有例外，有些大服用的是MySQL数据库。如果你使用的是SQLite，请直接删除plugins\AuthMe下的auths.db文件，如果想完全重置可以只保留config.yml其他的全部删除，这样登陆的时候就不会出现一些奇奇怪怪的问题了。使用MySQL的可以自行清空数据库，如果租用服务器的给你的数据库可以让服务商帮忙删除一下，一般花不了多少时间的。 然后是Ess插件的数据，plugins\Essentials\userdata下所有文件都删除，这里面都是以玩家ID为文件名的yml文件，当然类似warps文件夹也要删掉的。 如果你使用了Quickshop之类的商店插件，请删除这类插件配置文件夹下所有db文件，这些记录了商店的坐标但是如果换周目了这些就会阻碍新商店的生成还会出现一些兼容性问题。注意不只是这类插件，mcjobs职业插件、各类签到插件、AntiX-Ray插件的玩家数据都要删掉的，不然会出现一些奇怪的问题。 最后处理，请用批处理文件删除所有目录中的log、tmp文件以减小文件夹大小，这些日志、缓存对我们来说已经没有用了，留你何用？
