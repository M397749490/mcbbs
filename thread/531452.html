                           Bukkit                  静态方法的使用
本教程说明: 类  包  方法
Bukkit作为一个重要类 提供各种静态的方法 在插件开发中十分重要



Bukkit位于 org.bukkit 包下
所谓静态方法:
由static修饰的方法
在调用时无需实例化该类



提供的方法实在太多 不能一一叙述 这里抽重要的方法讲

addRecipe(Recipe recipe) 添加合成的方法 具体的使用方法请看 http://www.mcbbs.net/thread-504576-1-1.html
同系列的方法有 clearRecipes()      getRecipesFor(ItemStack result)         recipeIterator()        resetRecipes()
clearRecipes()   清理所有的合成 将会移除所有的合成表 包括原版的 如果仅仅是想移除插件添加的合成请使用 resetRecipes()
getRecipesFor(ItemStack result)  返回是 List<Recipe>  将返回可以生成目标物品的合成
recipeIterator()  返回是  Iterator<Recipe>  将返回所有注册在服务器的合成的 迭代器

broadcastMessage(String message) 以及 broadcast(String message, String permission)
对全服进行广播 同时显示在后台 注意的是 broadcast(String message, String permission)  将只对拥有权限的玩家进行显示


dispatchCommand(CommandSender sender, String commandLine)  使CommandSender 发出一条命令(不无视权限) 命令不带/
                                                                                                            任何继承了CommandSender 的类比如Player同样适用


get系列:
getConsoleSender() 将返回ConsoleCommandSender 也就是控制台 需要搭配方法 dispatchCommand(CommandSender sender, String commandLine)
getPlayer(String name)  getPlayer(UUID id)  使用名字或UUID查找玩家 若不存在返回null
getPluginManager()  返回PluginManagerl类
getServer()  返回Server类
getWorld(String name)  getWorld(UUID uid)  通过名字或UUID查找世界 若不存在返回null
getWorlds()  返回List<World>  包括这个服务器所有世界的List


                                         HandlerList           监听器的注册与注销

HandlerList位于 org.bukkit.event 包下
是在卸载监听器时会用到的类 并且这个类会储存所有的监听器

方法:
unregister(Listener listener)  unregisterAll(Listener listener) 卸载指定监听器内的所有方法 通常用在一些偶尔才需要的监听器注销时
unregister(Plugin plugin)  unregisterAll(Plugin plugin)    卸载某一插件上的所有的监听器   通常用在OnDisable()时
unregisterAll()                     卸载所有的监听器  通常不使用



FileConfiguration   Bukkit自带的配置类使用
本教程说明: 类  包  方法


FileConfiguration 位于 bukkit.configuration.file 包下是Bukkit提供的一个简单的配置文件读取的类
因为简单懒人所以也有些小问题
比如: 在不同系统环境下config的读取格式不同Windos使用ansi  Linux下却是使用UTF-8
所以,很多插件会遇到转码问题
首先这个类 通过JavaPlugin的getConfig()方法获得  这个方法将读取 plugins/插件名/config.yml 文件
当然 首先你的yml文件必须是正确的 否则就会抛出异常


FileConfiguration 提供了大量的get方法 比如 getString() getInt() getStringList()    实际这些方法都是其完成的接口ConfigurationSection的
可以方便的获取config.yml中的数据
具体演示:   变量config已经是通过getConfig()方法获得的
config.yml:
  1. Plugin:
  2.   version: 1
  3. #惩罚
  4.   punish:
  5.     enable: true
  6.     damage: 1.0
复制代码

如果我要获取ml中的version项就应该要
  1. int version = config.getInt("Plugin.version");
复制代码
这时version变量值就为1
比如这个enable和damage:
  1. boolean enable  = Boolean.valueOf(config.getBoolean("Plugin.punish.enable"));
  2. double damage = config.getDouble("Plugin.punish.damage");
