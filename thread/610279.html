插件地址：bukkit  下载地址本帖仅适用于插件版本v2.0之前的版本（不包括v2.0），即游戏版本1.8之前的版本（不包括1.8）。
原因是v2.0之后的版本更新了指令的格式，以及在实际测试时出现了或大或小的bug。




简单介绍


    这个插件可以说是ScriptBlock的更加灵活的版本，增加了更多的触发方式、判定和脚本。当然相对来说使用难度也提升了很多。
    也就是通过创建一些触发器来执行脚本。我这里只做一些简单的介绍，以及对实例中用到的东西做稍微详细的介绍。更详细的内容请查阅插件的bukkit页面


    触发器的触发方式包括
        敲击某个方块(click)【/vtc [脚本行]】来创建
        经过某个方块(walk)【/vtw [脚本行]】来创建
       进入或离开某个区域(area)【/vta [区域名] [enter或exit] [脚本行]】来创建（已创建vt区域的前提下）
       输入一条自定义的指令(command)【/vtcmd  [指令] [脚本行]】来创建
        发生了某个事件(event) --包括玩家进入游戏 离开游戏 死亡 重生 破坏方块 放置方块 生物死亡等【/vte [事件] [脚本行]】来创建

    脚本的种类就非常多了，比如
        传送到坐标0 65 5，并且面朝北仰角45°（@TP 0,65,5 180 -45），
        在坐标0 64 0设置一个岩浆（@SETBLOCK 11 0,64,0），
        在触发该脚本的玩家的公屏上显示一行字（@PLAYER &e这个破服一点意思都没有对吧？），
        公告一条信息（@BROADCAST &6这个世界需要更多英雄！所以本破服即将永久关闭，各位小王八蛋们再见！），
        以OP的权限执行一条指令（@CMDOP save-all）
        以控制台执行一条指令（@CMDCON stop）
        最为强大的条件判断脚本（@IF @OR @AND,@ELSE, @ENDIF）
        十分方便的执行后台编辑的脚本文件中的脚本（@CALL ）后台yml文件建议使用notepad++打开

    占位符可以在脚本里面用于
        代替一串字符str（比如玩家名<playername>所在世界名<worldname>），例：创建了一个脚本【@PLAYER 你叫<playername>，你在<worldname>】 一个叫magicbear的玩家，在主世界触发了这个脚本的话，他就会得到一条【你叫magicbear，你在world】这样的信息。
        或者代替数字int（比如玩家血量<health:>，从0到114中随机一个数字<random0to:114>，从1到514中随机一个数字<random1to:514>），
        或者代替位置数（也是属于一串字符str）（比如玩家所在的坐标<playerloc>，触发器的坐标<triggerloc>），
        或者代替真假判断的结果，也叫bool值（比如玩家触发这个脚本时是不是按住shift行走<issneaking:>，触发这个脚本的玩家身上够不够四百五并拿走
<takemoney:<playername>:450>）

    自定义变量  格式为$obj.var
        一个变量也是包含三种格式的值（str int bool），主要配合一些控制变量的脚本使用在条件判断脚本中。
        当一个变量的值没有被设定的时候，str默认为null，int默认为0，bool默认为false。   





实例介绍：深受bilicraft玩家喜爱的(并不)  玩梗系统


功能介绍：没有什么实际用途，仅仅是让玩家输入一条由管理自定义的指令，来播放一条恶搞公告的娱乐功能。
        虽然比较简单，不过为了方便管理，设置了各种各样的使用条件
        【设置了一个总开关，设置了仅在主世界(world)才能使用的判定，设置了带有提示的冷却(插件自身的@COOLDOWN脚本是不带有提示的)】
        所以也用到了简单的条件判定语句，以及后台编辑脚本文件的方法。这两点是本帖主要想介绍的功能
        除了玩梗的指令以外，还设置了一些便于管理和查阅梗的指令。


用到的创建触发器的指令：
    /vtcmd [指令] [脚本行]   
    创建一个指令触发器  
    例：/vtcmd test @PLAYER 这是一条测试指令。
    创建一个指令为test的指令触发器，触发后执行的内容是给触发者一条“这是一条测试指令”的信息
    再输入/test就能看到
   
    上面会出现一条Unknown command.的原因是，vt创建的指令，默认是与服务器原有指令共同存在的，当然我们也可以用下面一条指令把它去掉。

    /vtcmdo [指令] [true或false]
    设置一个已创建的指令是否覆盖服务器原有指令  
    例：/vtcmdo test true
    把服务器原有指令覆盖掉，再输入/test就能看到上面一条指令就能看到已经不会再出现未知指令的提示了。    后面的讲解中不在赘述。
   

    /vtcmdv [指令]
    查看一条创建的指令执行的所有脚本行

    /vtcmde [指令] [序号] [脚本行]    修改一条创建的指令中的某一条脚本行

    /vtcmdr [指令]
    删除一个指令触发器  
    例：/vtcmdr test  删除test指令

    /vtcmdp [指令] [节点]
    设置一个已创建的指令所需要的权限节点 （名字也是随便起），不设置的话默认为所有人都可以使用该指令。
    例：/vtcmdp test bilicraft.test
    为test指令设置一个权限节点 bilicraft.test 。配合groupmanager【/manuaddp 玩家id bilicraft.test】或者pex【/pex user add bilicraft.test】都可以进行管理。当然这个节点也被【bilicraft.*】节点以及【*】节点所包含。


用到的脚本
    【@PLAYER [文本内容]】----------给触发者一条信息。
    【@BROADCAST [文本内容]】----公告一条信息。
    【@PAUSE [秒数]】----------------暂停一定时间后再继续执行脚本
    【@IF、@ELSE、@ENDIF】-------条件判定脚本
    【@CMD [指令内容]】-------------以触发者自身现有的权限执行一条指令
    【@SETBOOL】---------------------设置一个变量的bool值 （用法：@SETBOOL [$obj.var] [true或false]）
    【@CALL】 -------------------------读取脚本文件中的脚本（用法：@CALL [文件名:脚本名]）
    【@PRINT [文本内容]】---------可以在控制台上写上一行内容，主要用于记录。


用到的占位符
    <playername>   代替触发者的名字 str值
    <worldname>    代替所在世界的名字 str值
    <cmdarg:1>      仅用于指令触发器 str值  代替一条复数的指令中紧跟着第一个指令的指令(绕)，例：/res tp a2这条指令中，<cmdarg:1>=tp，<cmdarg:2>=a2
    <cmdargcount> 仅用于指令触发器 int值 代替一条复数指令中后面跟了几条指令，用上面的例子来说tp是1个，a2是1个，所以这里的<cmdargcount>=2
    <var:$obj.var>  在条件判定脚本和控制变量脚本中可以直接使$obj.var，除此以外的脚本中，需要给变量套一个<var:>的马甲才能代替里面的值。str值或int值

条件判断
我们仍然先讲在游戏内直接输入指令来创建触发器添加脚本的方法。如果要使用一个完整的条件判断的话，一个触发器将会最少拥有5个脚本行。在讲这个之前，如果你跟着上面的讲解一起试着做了一遍也创建了一个dmxs的指令的话，就要先把这个指令移除
  1. /vtcmdr dmxs
复制代码
因为触发器执行脚本是按顺序进行的，而且这个【顺序】是与输入指令添加脚本的顺序相同的。
所以如果要使用带有条件判断的脚本的话，基本上都是先给触发器添加一个@IF的脚本作为开头。

拿一个完整的条件判断脚本【触发时玩家所在的世界是否为主世界world】作为示例来讲，创一个这样的脚本需要5条指令：/vtcmd dmxs @IF s <worldname> = world
/vtcmd dmxs @BROADCAST &2<playername>&e「我即使是死了，钉在棺材里了，也要在墓里，用这腐朽的声带喊出：冬马小三！！！」
/vtcmd dmxs @ELSE
/vtcmd dmxs @PLAYER 玩梗只能在主世界使用。
/vtcmd dmxs @ENDIF

查看dmxs这个指令包含了哪些脚本
  1. /vtcmdv dmxs
复制代码



一个完整的条件判断脚本，需要包含@IF @ELSE @ENDIF
@IF的格式为 @IF [s/i/b] [一个值] [>/</=/>=/<=/><] [另一个值]
其中  [s/i/b]是指要判断的值的属性 s=str值 i=int值 b=bool值
         [>/</=/>=/<=/><] 两个值的关系(不是颜文字)，除了大于小于等于以外也可以用【不小于(大于等于)】【不大于(小于等于)】【不等于】
也可以简单的理解为 @IF [要判断的值的属性] [一个式子]
当这个式子成立的时候，将会执行【@IF】与【@ELSE】之间的脚本(可以是多个脚本行)，如上图的【2】
当这个式子不成立的时候，将会执行【@ELSE】与【@ENDIF】之间的脚本(可以是多个脚本行)，如上图的【4】


在这个示例中就是：判断所在的世界是不是world，是就执行公告，不是的话就提示玩家这里不可以。(感觉好色情)

对于一些比较简单的不需要经常修改的脚本，完全可以在游戏内使用指令完成。
但是对于一些比较复杂的，条件判断用的比较多导致脚本行非常多的脚本，一旦出现漏打一行脚本的失误，可能就要修改大部分脚本行甚至重新输入。
而且mc本身输入栏的长度有限，万一需要输入超过输入栏长度的脚本行的话，就不能通过在游戏内直接输入指令的方法来添加脚本。
这时候就要用到后台编辑脚本文件的方法。



编辑脚本文件
v1版本的vt插件在安装之后生成的VariableTriggers文件夹中，会生成一个example.script.yml文件，（使用notepad++打开)
这是一个脚本文件的示例。里面有2个示例脚本，以及说明文字和一些注意事项。建议看一下里面的注意事项。

要创建一个自己的脚本文件的话，推荐的方法是复制example.script.yml这个文件，并把它重命名为[脚本名.script.yml]。
这里我们拿玩梗系统来做示例，重命名为 geng.script.yml  。
再把里面【#】开头的说明文字全部删除，修改脚本并保留带有最低限度的脚本和脚本内容
完成之后可以将其保存，再复制一份更名为sample.script.yml作为样本，这样以后创建新的脚本文件时直接复制样本就可以了。

当然也可以创建一个txt文件，将其改名为xxx.script.yml，再把上面的内容严格按照相同的格式输入到里。
但是如果这个框架部分输入的格式有一点微小的偏差的话，就会导致整个脚本文件无法被服务器读取。
所以比较推荐上面的复制example.script.yml的方法。

注意事项：在要增加脚本行的时候，由于notepad++默认是有一个自动缩进的功能，然而自动缩进会导致格式出错。解决方法是要么在设置里把自动缩进功能关闭，要么每次换行之后按一下退格键把自动缩进的那段给删掉再敲4个空格到与上一行对齐。

最上面的【nianshi】是脚本名，为了方便观察和管理操作，建议把脚本名直接命名为指令名称。（游戏内想用/nianshi的话，这里就取名nianshi）
在这个脚本中的红色框框标示的部分可以看出，一个完整的条件判断脚本是可以插入到别的条件判断脚本中的，
而且这个被插入的脚本还可以再插入别的脚本中。（百！人！连！体！）
前提是，必须是一个完整的条件判断脚本，要注意如果漏掉了@ELSE或者@ENDIF，就会导致关系错乱，达不到想要的效果。
每个脚本行开头的【-】和【'】之间的空格数量是没有要求的，这里使用空格调整缩进距离是为了方便观察。


nianshi脚本中，最内的红色框框内是一个冷却时间的脚本。这里有个小技巧，使用的自定义变量是$gengcd.<playername>以玩家名来创建的变量。
这样每个玩家计算冷却用的变量都是这个玩家特有的，也就是说每个玩家各自计算自己的冷却时间。
【@PAUSE <var:$geng.cd>】这一行其实完全可以直接写一个数字上去【@PAUSE 10】，
    但是为了方便在游戏内就可以随时管理，就使用了变量。游戏内可以使用指令【/vt setint [obj] [var] [数字]】来管理，这里我们用
  1. /vt setint geng cd 10

这是通过vt自带的指令去修改变量，而不是通过脚本来控制。
同理，也可以直接使用指令来修改$geng.jinyong的bool值，【/vt setbool [obj] [var] [true或false]】
如果觉得指令长输入起来很麻烦，也可以创建一个简化操作的脚本。这里就是使用脚本来控制变量了。

设置了权限节点的指令，op以及*权限都是默认拥有这些权限的。
另外，由于这些脚本本身不会在控制台做出记录，所以使用@PRINT来记录谁在什么时候使用了这些指令。也是为了避免不必要的麻烦。



脚本文件编辑完成后，保存，输入/vt reloadscripts（简化：/vt rs）可以重载脚本文件，让新更改的脚本生效。
如果顺利加载，服务器控制台会提示xx Scripts from xx files loaded.
如果你编辑的脚本格式有误的话，会提示你某某文件第几行出现了错误，认真排查修正保存再尝试重载就可以了。

顺利重载之后，在游戏内只需要一个【@CALL [文件名:脚本名]】就可以读取这个脚本了。
这个实例中，文件名只需要取其中的【geng】，脚本名【nianshi】即可
  1. /vtcmd nianshi @CALL geng:nianshi

比如一个迷宫的终点有一个门，进去之后需要判断条件是否满足才能传送到下一关的区域，不满足就传送到起点。
这个条件可以是在迷宫某处触发一个按钮，或者获得了某个物品……
还可以在迷宫内随便找几个点做一些概率的定向传送，或者随机往某几个点中的一个点传送……
以后有时间有心情可能会更新别的详细点的实例。
