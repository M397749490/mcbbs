顺序是激活顺序，不要弄错了
壹（以防出生点错误）
  1. tp @a[team=team1] x y z
复制代码
贰（这里考虑到一些只让参观的服务器，可加可不加）
  1. gamemode spectator @a[team=wanjia1]
复制代码
叁（过渡）
  1. team join team2 @a[team=team1]
复制代码
肆（记录实体）
  1. scoreboard players add @a[team=team2] scb1 1
复制代码
伍（对所有玩家发出信息）
  1. tellraw @a [{"text":"欢迎新玩家，"},{"selector":"@p[scores={scb1=1}]"},{"text":"。"}]
复制代码
陆（记录完毕，恢复状态）
  1. scoreboard players set @a[team=team2] scb1 0
复制代码
柒（将玩家移入其他team，以免出现错误）
  1. team join team3 @a[team=team2]
复制代码
分支电路（将所有新玩家移入team1，在后面老玩家依赖里面以免出现bug）
  1. team join team1 @a[team=]
复制代码

同样，也是按照激活顺序写

壹（给予一个多次登录的玩家特征，可以让选择器寻找到）
  1. xp set @a[team=!team1,team=!team2,level=0] 1 levels
复制代码
贰（记录实体）
  1. scoreboard players add @a[level=1] scb2 1
复制代码
叁（对所有玩家发出信息）
  1. tellraw @a [{"text":"欢迎回来，"},{"selector":"@p[scores={scb2=1}]"},{"text":"。"}]
复制代码
肆（将玩家的特征进行更改，但选择器里的不会变）
  1. xp set @a[scores={scb2=1}] 2 levels
复制代码
伍（记录完毕，恢复状态）
  1. scoreboard players set @a[scores={scb2=1}] scb2 0

点进来之前光看你这线路我还以为是四五年前的1.7 1.8教程。
首先是真的不建议使用红石元件，三色CB+条件制约+可控保持开启不香吗。
其次是这个问题完全没必要复杂化，可以做得简单很多。
1.创建两个记分板，都是退出游戏准则。
2.玩家登陆后，记分板QuitA记录玩家累计退出游戏的次数，QuitB在tellraw后清零。
3.QuitA=0的玩家即为新玩家，QuitA=1..的玩家则是老玩家，直接通过目标选择器参数选定即可。
目测只需要三个命令方块。一个rcb，俩ccb就行。两个tellraw，一个scb reset QuitB。
哦不对，没有分数的时候似乎检测不出来，那就是要四个。
execute if score matches似乎是可以检测的，总之就是三四个，远不用那么麻烦。

另外我自己做的话习惯创建一个在线时间的记分板，用rcb每刻超频加分。
为0的时候就是新玩家，可以给予玩家新手装备啥的，不为0的都是老玩家。
