在水桶插件中，Bukkit给出了一个默认的配置文件:config.yml
关于这货的方法，比较常用的有reloadConfig(); 重新读取config.yml  还有一个saveDefaultConfig(); 其作用为保存并读取config.yml  当config.yml不存在时将jar中自带的config拉到工作目录下。
所以我们经常这样加载config:
  1. if(!getDataFolder().exists()) {
  2.   getDataFolder().mkdir();
  3. }
  4. File file=new File(getDataFolder(),"config.yml");
  5. if (!(file.exists())) {saveDefaultConfig();}
  6. reloadConfig();
复制代码
getDataFolder()为获取工作目录 就是\plugins\插件名 这个文件夹
当工作目录不存在时，先新建工作目录，当config不存在时,saveDefaultConfig,然后再reloadConfig();

那么这样写又有什么用呢？
小栗子
在上节课的pluginname插件的onEnable方法中添加加载config的那一段 (下面是做好了的，能不看就不看)
  1. public void onEnable() {
  2.   if(!getDataFolder().exists()) {
  3.     getDataFolder().mkdir();
  4.   }
  5.   File file=new File(getDataFolder(),"config.yml");
  6.   if (!(file.exists())) {saveDefaultConfig();}
  7.   reloadConfig();
  8.   getLogger().info("启用完毕！");
  9. }
复制代码
才发现saveDefaultConfig()还有点问题 要是config不存在时会从jar里吧默认的config拉出来，我们先把默认的config.yml创建好,跟plugin.yml的创建方法相同,但不用把编码改成UTF-8！
然后在里面写上:
Message: §aHello!
§的打法是alt按住+1+6+7+松开alt 在插件中也要用这个当做颜色代码的&，记得冒号后的空格
好了这是默认的config创建/加载方法，接下来我们假如要创建其他的配置文件怎么办呢？
好好看，很有用的
在主类中创建一个方法:  (这方法记一下，以后就不用写了)
  1. public FileConfiguration load(File file){
  2.                 if (!(file.exists())) { //假如文件不存在
  3.                  Try   //捕捉异常，因为有可能创建不成功

  6.                   }
  7.                  catch(IOException   e)
  8.                    {

  10.                    }

  12.                 return YamlConfiguration.loadConfiguration(file);
  13.         }
复制代码
然后想调用的时候就声明一下下面这两个变量， 当然你声明成员变量也是可以的，让整个主类都可以调用，不过要注意是先执行成员变量声明再执行启用方法 也就是说有可能工作目录不存在！
File file=new File(getDataFolder(),"otherconfig.yml");
FileConfiguration other = load(file);
成员变量的话要加private 私有修饰符，表示不能在此类外修改 有点封包的含义了吧?
这时就定义好了一个工作目录下叫做otherconfig.yml的配置文件。
与config的差别是他是完全空白的 要是想多弄点config一样会从jar中复制过来的的文件 就该这样写：
saveResource(“config.yml”, false); 保存复写xxx文件
就等于saveDefaultConfig()方法了
第二个参数为布尔值,true代表复写,false代表不复写

读写配置文件基本的方法：
假如我要读取默认config.yml中的Message栏 然后写入另外的内容
读
getConfig().get(“Message”) 参数就是路径字符串，这样的话得到的当然就是obj类了，我们还有更细的分支: getInt以及getString 还有一些关于List， 自己摸索吧。
注意判断需要取的内容的路径存在与否，使用getConfig().contains(路径)来判断路径是否存在，存在返回true 不存在返回false
自定义的配置文件这样写
other.get(路径) 直接用那个FileConfiguration类型的成员变量代替getConfig()即可
写
getConfig().set(路径, 内容)
内容可以为String int List什么的
自定义配置文件照葫芦画瓢吧！
set为null表示删除此节点以及他的所有子节点
记得要保存 保存方法:
File file=new File(getDataFolder(),"config.yml");
try{getConfig().save(file);}
