概念 第一部分 了解什么是MC服务端、
当大家谈到开服的时候 指的是什么
——————————————————————————

（解释各类常用的名词/概念）

一般有服务端/客户端概念

通俗的讲 服务端本身是一个没有界面的游戏程序

大家都玩过各种联机游戏/网游

比如CF/CS/求生之路 想要和朋友一起玩游戏

一般得新建房间 然后邀请朋友 然后大家就可以一起玩了

开服指的就是新建房间这个过程 只不过在MC的环境下 通常更为专业化 更为复杂化

一般开服有两种方式 一种直接通过联机平台 建立虚拟局域网 然后点击游戏内的联机按钮

朋友只要按照提示连接进来即可 非常简单 非常便捷

但相信看到此文的人肯定不仅仅满足于联机这么简单的目的

毕竟想要开服的一般已经花费了金钱 简单的联机是不能满足各位的需求的

也许要安装插件 也许要更高的流畅度 也许想要修改各种设置 也许想要装模组

总之各种各样的需求都促使着我们使用第二种开服方式

专用服务端（dedicated server）

专用服务端一般和游戏内直接联机的最主要的区别

就是没有游戏画面 是单独的程序 不是游戏和服务器一起的

能满足一个最基本的需求 房主不在/不玩的时候其他人也能玩

同时因为没有游戏画面 不需要显卡 也就可以在租用的无显卡服务器（指专用计算机）

开服这里一般指使用专用服务端架设可以游玩的服务器



概念 第二部分 MC服务端的各种类型
——————————————————————————————

众所周知 MC在2020年 分两个版本

基岩版/Java版

那么首先就有两个大类 基岩版服务端/Java版服务端

这里先讲Java版服务端 Java版服务端顾名思义 是可以供架设Java版游戏可游玩的服务器的专用程序

Java版服务端目前主流分为三种（根据主流分类方式 是否有插件API 是哪种插件API划分）



1.官方服务端

2.Bukkit API服务端

3.Sponge API服务端

————————————————————————————————————

先讲官方服务端

官方服务端 顾名思义 由Mojang官方发布的服务端

一般文件名为:minecraft_server.jar

其包含完整的和单人游戏完全没有区别的内容

可以修改默认难度 村民是否生成 等等设置 具体参考

https://minecraft-zh.gamepedia.com/Server.properties

但一个完全没有经过修改的官方服务端 是无法安装任何插件/MOD的

但是MCBBS服务端整合版中 很多标题为官服端的服务端整合包 是带有MOD的

这是怎么回事呢？ 就像客户端可以打Forge API装MOD一样 官方服务端也可以装MOD

这里我们把没有安装Sponge 无论安装不安装Forge的官方服务端 都叫做官方服务端

其优点是随游戏更新而更新 不会出现已经可以玩到新版本游戏却不能玩到新版本服务器的情况

———————————————————————————————————————————————



再讲Bukkit API服务端

Bukkit API服务端是支持Bukkit API插件的服务端

全部都由第三方开发 因此可能游戏更新了但没有对应的服务端

讲Bukkit API服务端 就不得不讲大家熟知的概念 插件（Plugin）

这里我们对本篇教程内的插件这一词汇下个定义

安装在服务端 不需要安装在客户端的修改内容 不修改客户端内容的 称之为插件（Plugin）

那么什么是Bukkit API呢

就像手机会有安卓系统和IOS系统一样

你想要装APP 如果你用的是IOS 那么装的就是IOS APP

你用的是安卓 那么装的就是安卓APP

无论安卓APP还是IOSAPP 都叫APP

无论Bukkit API插件 还是Sponge API插件 都叫插件

Bukkit API相当于能让你装插件的特殊系统

常见的服务端 比如 Spigot CraftBukkit PaperSpigot 都属于Bukkit API服务端

Bukkit服务端只能安装Bukkit API的插件 就像苹果手机只能装苹果程序不能装安卓程序一样

我们常见的 Authme 登录插件 Essentials 基础插件 GroupManager权限插件 都属于Bukkit API插件

纯粹的Bukkit API服务端是不能安装MOD的 无论是什么MOD都不能安装

但同时具有Bukkit API和Forge API的服务端 可以同时安装MOD和Bukkit插件

比如CatServer PFServer Mohist等等

截止2020 3月 任何Bukkit API服务端都是非官方的

也就意味着可能有些版本没有 是正常现象

————————————————————————————————————————————————————

再讲Sponge服务端

和上文一样 Sponge服务端是支持Sponge API插件的服务端

是支持另一种插件系统的服务端

现在以官服端的MOD形式实现

说白了 安装有SpongeMod的Forge API官方服务端 就是Sponge服务端

可以装Sponge API插件的 就是Sponge服务端

————————————————————————————————————————

三种服务端 到底选哪种好呢？

我们这里只对三大类进行阐述

想要玩最新的快照版本 就选官方服务端 因为其他两种属于第三方服务端 很可能没有快照版本

不需要加Mod的话 推荐使用Bukkit API服务端

因为Bukkit API服务端性能更好 插件更多 教程也更多

能实现的功能更多 BUG更少 更稳定

————————————————————————————————

需要加MOD的话  首先取决于游戏版本

目前 能够同时加Bukkit API插件和Forge API MOD的服务端

只有1.4.7~1.7.10 1.12.2这几个版本（147之前的很难解释 不讲）

Sponge服务端只有1.10.2及以上的版本基础功能正常 低版本不推荐使用



首先应该根据版本选择

然后取决于你加多少MOD 加什么样的MOD

如果你加的都是很热门 很常见的MOD 比如工业2 神秘时代 神奇宝贝等等的

并且你还有装Bukkit API插件的需求 比如做商业服 做VIP 做菜单 做游戏内自助充值

你应该选择Bukkit API服务端

如果你加的都是冷门Mod 比如冰与火之歌 或者MOD数量特别多 一两百个

比如RLCraft 比如各种FTB包 各种国外的多MOD整合包

由于国外作者基本使用Sponge 所以建议你选择Sponge服务端

他对模组的兼容性更好 几乎是百分百兼容



概念 第三部分 什么是服务端核心 选择什么样的服务端核心
——————————————————————————————————

服务端核心 一般指具体的服务端程序 而不是某一类

比如CraftBukkit Spigot PaperSpigot CatServer等

一般是服务端整合包根目录里后缀为.jar的文件

第二部 右键 编辑该文件

那么选择什么样的服务端核心呢 首先介绍常用服务端核心的不同


CraftBukkit/Spigot 最原始的Bukkit API服务端 百分百支持Bukkit API所有插件

PaperSpigot（Paper）基于Spigot修改的优化版服务端 兼容大部分Bukkit API插件 性能更好

CatServer服务端 目前最好的1.12.2 可以同时装Forge API MOD和Bukkit API插件的服务端

Cauldron/MCPC-Plus（本质上一样）
1.4.7——1.7.10可以同时装ForgeAPI MOD和Bukkit API插件的服务端

KCauldron 1.7.10可以同时装ForgeAPI MOD和Bukkit API插件的服务端 Forge版本更新到了 1664

thermos KCauldron 的修改版本 修复一些Bug Mod兼容性更差 据说是性能更好

uranium 国人开发的KCauldron修改版 主要目的是兼容高版本特性（十分不稳定）

（作者自己都承认不稳定 作者自己表示没有修复拔刀）

Forge官服端 打了ForgeAPI的官方服务端 可以装Mod 不能装插件

Sponge服务端 在Forge官服端的基础上安装SpongeMOD 可以装Sponge插件和ForgeMOD



那么怎么选择呢 当然是看各位的需求了

个人建议 不玩模组 不装奇怪插件的 首选PaperSpigot

个人建议 不玩模组 装奇怪插件的 首选Spigot

1.4.7~1.6.4 玩主流模组+插件的 选择 Cauldron /MCPC-Plus

1.7.10 玩主流模组+插件的 可以选择KCauldron / thermos

1.7.10 玩非主流模组/FTB包+插件的 可以选择KCauldron / Forge官方服务端

1.7.10 玩非主流模组/FTB包不要插件的 可以选择 Forge官方服务端

1.10.2~1.12.2 玩模组的 不需要插件的 可以选择Forge官服端/Sponge服务端

1.12.2 玩模组的 需要装模组和BukkitAPI插件的 选CatServer

其他版本 需要玩模组的或者需要玩冷门模组的 选择Forge官方服务端

Farbic/其他MOD api 过于冷门 在此不表 有兴趣的自己研究

实战 开始开服
————————————————————
有了以上知识的你 现在可以开始正式学习如何开服了

1.首先 需要安装Java
展开折叠查看
Java分大版本号/系统位数的区别
32位Java只能分配1GB内存 不适合专业开服 不能利用内存
64位Java则可以使用更多内存 适合专业开服

大版本号这里只讲两个
Java7/Java8
1.7.10及以上版本 使用Java8
（Java8推荐使用191版本 191版本使用unsafe操作内存的延迟比后续版本低
说人话就是 191版本一般情况下比其他版本开服性能更好）
1.7.10/1.6.4以下版本 使用Java7
因为这是最简单直接分辨兼容性的办法

推荐Java8下载地址:https://pc.qq.com/detail/1/detail_21141.html（点击普通下载）
Java官网上现在很难下载到离线包 下载速度很慢 而且下载到的是32位的


个人对网上一些用其他版本Java运行服务端的看法：
网传OpenJ9可以减少内存占用 性能还会更好
我简单讲 这是假的 不可能

安装完Java后 下载服务端核心/服务端整合包

2.然后用记事本编辑/新建开服脚本文件（比如开服.bat 建议用英文 run.bat 能避免不必要的问题）

最基本的开服脚本的内容为
java -Xms1G -Xmx1G -jar xxx.jar

其中xxx.jar为服务端核心文件名 在上文概念篇有提到如何获取
-Xms1G 最小内存1G（还可以使用比如5000M这样的）
-Xmx1G 最大内存1G （还可以使用比如5000M这样的）
一般来讲 我们推荐内存充裕 只开一个服务端的用户 有多少内存 分配多少内存 最小和最大分配成一样的
可以避免因为重复回收内存导致的性能损失
如果开很多个服务端 而且人数不多 一会这个服务端人数多 一会那个服务端人数多
可以设置不同的最小内存 一般最常玩人最多的服务器设置最多的最小内存
这样便会动态分配内存 以小内存开更多服务端

高级优化参数
例如Java7的开服参数可以是（大型插件非常多，MaxPermSize可以设置得更高）：
java -Xms最小内存 -Xmx最大内存 -XX:MaxPermSize=128M -XX:+AggressiveOpts -jar xxx.jar

Java8的参数可以是：
java -Xms最小内存 -Xmx最大内存 -XX:+AggressiveOpts -jar xxx.jar
* 如果分配的内存大于等于4GB，建议使用 -XX:+UseG1GC 使用G1GC，并且把最小和最大内存设置为相同的大小
java -Xms最小内存 -Xmx最大内存 -XX:+AggressiveOpts -jar xxx.jar


这里讲一些个人经验 一般情况下 都可以不加任何高级优化参数 本人实测
1.15.2原版服务端 不加任何优化参数的效果 比其他情况好
建议大家自行对比测试 效果因人而异

这里强烈建议新手按本文说明 新建开服脚本 而不是使用整合包内自带的
原因：很多整合包作者水平很差 甚至使用Java6时代的-xingc参数 十分影响性能

这里讲一下常见错误:
'java' 不是内部或外部命令，也不是可运行的程序
或批处理文件。

该错误的原因是因为java没有安装好
简单的方法是卸载java重装

最简单最可靠的办法 输入 help tps list

特此备注
加MOD/插件 以及常见问题解决方法

1.加插件

非常简单 Sponge插件放到服务端的mods文件夹里

Bukkit插件放到服务端的plugins文件夹里

2.加模组

把模组放到服务端的mods文件夹里 完事了



加插件常见简单问题：

1.加完插件后卡住动不了

一般为插件使用主线程自动更新 但连不上更新服务器

在配置文件里关闭自动更新即可

2.中文乱码

Windows平台下 1.8.8及以下版本服务端 使用ANSI编码

1.8.8以上版本服务端 使用UTF-8无BOM编码



加模组常见简单问题



1.加完模组后卡住动不了
一般为模组使用主线程自动更新 但连不上更新服务器
解决方案：安装禁止更新MOD 非常有效
下载地址:https://minecraft.curseforge.com/projects/non-update
随便下载 全版本通用

1.删完模组后卡住动不了

一般为FML保护存档机制
输入/fml confirm （要带/）
等待服务端备份旧存档即可
等待时间视存档大小而决定


优化 服务器卡怎么办？（前提 服务器性能足够）


首先必须了解的：


1.不要安装多个优化插件
多个优化插件可能都拥有区块卸载功能
频繁卸载/加载区块会消耗大量CPU资源 导致服务器卡顿


2.CatServer不要安装任何区块卸载插件
CatServer的特殊性 导致其会超高频率卸载 吃满你的CPU
