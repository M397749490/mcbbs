首页

欢迎来到 Glowstone Wiki！ Glowstone 是一个的开源 Minecraft 服务端，以 Java 写成，并且速度快、可高度自定义、兼容性强、支持 Bukkit 插件。当然 Spigot 和 Paper 的兼容工作也在继续。Glowstone 的代码完全自主重构，所以有些使用了 Mojang 代码的 Bukkit 插件不能运行。

这个 Glowstone wiki 上的文档是给服主和开发人员的。如果你是游玩由 Glowstone 驱动的服务器的玩家，也许你会发现更适合切有趣的官网。

如果你需要某方面的帮助，或是本 wiki 无法解答你的困惑，你可以通过 我们的 Discord 服务器 与我们交流；或者如果你更喜欢 IRC 的话，可在 Espernet 上的 glowstone 找到我们。

所有目录可点击！



入门

您将会在这里了解选择 Glowstone 的理由，学习到如何安装 Glowstone，还有 Glowstone 已支持的特性和常见的问题！





安装

安装 Glowstone 与其它软件一样简单。

安装 Java

推荐安装 Oracle Java 8 。如果你运行的是 Linux 发行版，请在使用这些下载之前，先通过包管理器来安装 Oracle Java。 但是，如果你真的不想用 Oracle Java，你可以选择 OpenJDK。谨记：我们需要 Java 8 Update 101 及以上的版本。 我们的 Maven 存储库使用了 Let's Encrypt 证书，并且 Let's Encrypt 在 Update 101 被加进 Java 信任库。如没有此信任库，由于 SSL 安全错误，我们的库管理器将无法从服务器中提取依赖项。
通过在你的系统的命令提示符/终端中运行 java -version  确认你拥有的是 Java 8。你应当在顶部看到类似 java version "1.8.0_121" 的东西。只要它包含 1.8，并且 _ 后的数字超过 101 即可。

如果你在 MacOS 上安装了 Java 8，但是 java -version 仍在显示旧版本，请运行

  1. sudo mv /usr/bin/java /usr/bin/java-1.6
  2. sudo ln -s '/Library/Internet Plug-Ins/JavaAppletPlugin.plugin/Contents/Home/bin/java' /usr/bin/java
复制代码

详情参见本指南。

安装 Glowstone

  • 下载 Glowstone 的最新构建版。
  • 将 jar 文件拖至你的服务器文件夹。如果你将 jar 拖动并运行于正确的地方，它将自动迁移大多数设置至 Glowstone。

Windows
使用记事本类的文本编辑器，创建一个名为 start.bat 的简单脚本来启动 jar 文件：

  1. [url=home.php?mod=space&uid=39305]@echo[/url] off  
  2. java -Xms768M -XX:+UseG1GC -jar glowstone.jar
  3. pause
复制代码

确保你在保存窗口中选择了全部文件作为文件类型。

最后，双击 start.bat。

使用一款 gedit、mousepad、Atom、Sublime Text、nano、(Neo)vi(m)、Kate、emacs 之类的文本编辑器，以创建一个名为 start.sh 的简单脚本来启动 jar 文件：

  1. #!/bin/sh  
  2. BINDIR=$(dirname "$(readlink -fn "$0")")  
  3. cd "$BINDIR"  
  4. java -Xms768M -XX:+UseG1GC -jar glowstone.jar
复制代码

打开终端，进入你的 Glowstone 文件夹，执行此命令以给予脚本运行权限：

  1. chmod +x start.sh

将这些命令输入到服务器终端当中：

  1. ./start.sh

Drag start.command into the Terminal window. Confirm there is a space between chmod a+x and the start.command path, and then enter. Finally, double click the start.command file to start the server.

想法之后

如果你在设置过程中遇到任何困难，请在论坛，Discord 或者 IRC (ensper 上的 #glowstone)寻求帮助。如果没什么意外，大功告成，你已经将 Glowstone 安装完毕！

插件
绝大多数 Bukkit，Spigot 和 Paper 插件可在 Glowstone 正常工作。 Only plugins that use Paper-Server, Spigot-Server, CraftBukkit or Minecraft code will not work, unless they are designed to fail gracefully. 只有那些使用 Paper-Server，Spigot-Server，CraftBukkit 或 Minecraft 代码的插件不会工作，除非它们设计得优雅地失败。



为什么选择 Glowstone

为什么从 Spigot/CraftBukkit/PaperSpigot 转到 Glowstone？
在我们说明转移至 Glowstone 的好处之前，我们得声明一下：Glowstone 并未完全开发完，因此一些基于 CraftBukkit 的服务器的特性仍然缺失。尽管 Linkstone 正致力于此，但我们并不支持 nms 或 obc 的代码。换句话说， Glowstone 不提供 org.bukkit.craftbukkit.* 与 net.minecraft.server.* 的包，因此使用这些包的插件将无法工作。

Glowstone 完全开源。我们不依靠 Minecraft 内部代码，此软件一切皆原创。这也意味着我们的代码在大多数地方都比 CraftBukkit 和 Minecraft 更简单、更自定义化。

Just because Glowstone is written from scratch doesn't mean you'll sacrifice plugin compatibility. Glowstone 原生地支持 Bukkit，Spigot-API 和 PaperSpigot-API 的插件 , 并且第一个提供为 Bukkit2Sponge 的 可以提供 Sponge 插件支持的 class support。

如果你是一名开发者，你会发现做出贡献比 CraftBucket 简单许多, 因为 Glowstone 并没有难懂的代码，或是有什么微小的差异。你甚至可以修改 Glowstone 来私用，比如增删、修改 Glowstone 以满足你服务器的特殊需求。

Glowstone 是一个 Minecraft 服务器——这也就是说，它实现了 Minecraft 协议，它与 Minecraft 客户端共运行， 并允许用户与其它用户共同游玩。任何以任何身份使用 Minecraft 或者运行一项与 Minecraft 玩家工作的服务的人都必须遵循 Minecraft EULA。 参见 Blizzard v bnetd。

报错
无法绑定地址。 地址是否已经使用？
  1. 22:24:15 [SEVERE] Error during server startup.
  2. java.lang.RuntimeException: Failed to bind to address. Maybe it is already in use?
  3.         at net.glowstone.GlowServer.bind(GlowServer.java:438)
  4.         at net.glowstone.GlowServer.main(GlowServer.java:93)
复制代码

This error means that you've already got a server running on the port that you've configured. When starting the server, please make sure you do so by following the methods in [[the installation instructions|Installation]], instead of double-clicking the JAR. If you do double-click the JAR, the server will start up, but you won't have any console, so you'll have to kill it using the task manager or whatever process management tools are relevant to your system.

  • If you're converting from Bukkit, make sure you've stopped the old Bukkit server, if you plan to use the same port.
  • Make sure you're not running more than one copy of Glowstone on the same port.
  • Check that you have no extra Java processes running. If you're on Windows, use the Task Manager. You might not want to kill some of them, such as the minecraft client.
  • If this still isn't working, please check whether you have an ip set in the server section of your config/glowstone.yml file.
    • If you do, please consider that most people will not need this entry - it's only useful for people running large servers with multiple network cards. In the majority of cases, you can simply remove this line from your file.
    • If you're convinced that you need it, it should contain only an IP address - usually of the form a.b.c.d, from 0.0.0.0 up to 255.255.255.255 for IPv4.

这个报错代表着你正运行低于 Java 8 的版本，你需要升级 Java。在 Windows 与 Linux 上，是否升级了版本相当明显；但 MacOS 用户可能发现他们已经升级过 Java （却仍然报错）。 如果你是 MacOS 用户，请阅读这个优秀的指南。

java.lang.ClassNotFoundException: net.minecraft.server or org.bukkit.craftbukkit

  1. 17:25:12 [SEVERE] Could not load 'plugins/MassiveCore.jar' in folder 'plugins'
  2. org.bukkit.plugin.InvalidPluginException: java.lang.NoClassDefFoundError: net/minecraft/server/v1_7_R4/PlayerInventory
复制代码

This error is caused by plugins whose developers refused or were unable to use pure Bukkit classes when writing their plugins, and instead used CraftBukkit or internal Minecraft classes to achieve the functionality they needed.

These plugins are often called "impure" plugins, and aren't technically Bukkit plugins at all. They will not work with Glowstone, unless Linkstone supports them. You will have to ask the developer of the plugin to add Glowstone support, or fix the plugin yourself, if you're able to.

Plugins that rely on ProtocolLib will also have the same issue, as it uses internal Minecraft classes.

You can find more information on the supported plugins at [[Plugin Compatibility]].

特性与 bug
某一特性不运行！

Glowstone 是一个完全自定义的服务器端，这意味着它不用一点 Minecraft 代码。CraftBukkit（更为熟知的名字是 Bukkit）则大量地使用 Minecraft 内部代码来实现功能。

As Glowstone doesn't, and can't, use the relevant Minecraft code for anything it implements, all of the features you'd expect from a Minecraft server must be rewritten from scratch.

因此，Glowstone 的开发可能在有些人看来有些慢，并让新用户感到困惑。然我们正在努力成为完全开发完毕的 Minecreaft 服务端的又一选择，但这些工作需要花费时间，因此我们建议查询当前特性。
我与在另外的某一平台上用的是一个种子，但 Glowstone 生成的世界看上去并不一样

因为我们的地形生成器是从头开始制作的，所以使用与另一个平台相同的种子将不会生成相同的地形（甚至完全不同）。 鉴于伪随机数的生成原理，而地形随机器又是从头开始构建的，因此这种情况并不意外。

FAF（常问功能）

有些功能经常有人问，而有些功能则是我们正式决定可能永不添加的。

对旧版本的支持

我们已经决定不再支持旧版本的 Minecraft。只要 BukkitAPI 一更新，我们就更新至最新版本的 Minecraft。However, you may be able to achieve this by using third-party tools and plugins like BungeeCord. We have also worked with ProtocolSupport's team to make it possible to host older Minecraft versions on the latest version of Glowstone.

对 Sponge 插件的支持

以前我们曾与 Sponge 的团队共同开发来在 Glowstone 上支持 Sponge API。不幸的是，我们已经放弃了此，我们可能永远不会正式支持我们平台上的Sponge 插件。不幸的是，我们已经放弃了这个目标，我们可能永远不会正式支持我们平台上的Sponge插件。这可以找到更多相关的帖子与主题.

对移动版的支持


我们现在根本没有时间与精力去做对移动版的支持，我们的工作重心更多放在 PC 版本上。Some third-party projects (like ProtocolSupport) are currently working on this kind of support on Bukkit platforms.

Packet API / ProtocolLib support

Because packets are not part of the scope of the Bukkit API, there is no Packet API implementation in Glowstone. We are faced with a decision between making our own API, or supporting an API designed by the community. ProtocolLib has been around for quite a while and has become the de-facto community standard API for packet manipulation. ProtocolLib is designed to work on multiple versions of the Vanilla server using reflection, but it does not support Glowstone networking internals. This feature has been discussed here, but it may take a while before anything is functional.

插件兼容性



Opening Tickets
首先，感谢你花费时间想要帮助改进 Glowstone 服务器。每一次你发布一个可以被修复的 bug 或者特性，这就会帮助发展和改进这个项目，所以对你花费的时间感激不尽。

请在一个不同的 issue 开启一个 bug 或者特性请求。这可以让项目的管理变得简单很多。

Bugs

开始

在你还没点击 “new issue” 按钮的时候，请确认...

  • 你可以重现这个问题。
  • 你正在使用最新版本的 Glowstone。
  • 没有已经被举报的相似的问题。

Opening your issue

检查了一遍之后并且你已经满足了所有条件，现在你就可以 open a new issue 了。

使用一个好的标题！ 确认你给这个问题一个好的名字，请不要使用“坏掉了”作为标题。而是用“木门打不开”这样的标题，这样开发者可以更快的修复你的问题。这同时可以清理 issue tracker，重复的问题不会被经常打开。

描述细节！ 如果你需要，给我们一本小说来讲清楚这个问题。请确认描述好这个 bug ，你是怎么遇到这个 bug ，和一些相关的信息或者错误。请给我们你的操作系统名称和版本，以及你的java版本。

预览你的问题！ 有时候 markdown 会非常烦人。这就是你为什么需要在发布问题之前预览一下，这样可以避免尴尬的格式问题。如果想要更好的可读性，熟悉一下 markdown 。

确认你的问题是最新的

确认你注意你发布的问题，别人可能会询问更多信息，所以如果可能，最少一天检查一次。这对我们都有帮助。

如果你发现一些和 bug 相关不幸的是，我们已经放弃了这个目标，我们可能永远不会正式支持我们平台上的Sponge插件的新信息，请在原问题上发布一套评论。

关闭你的问题

如果你发现这个 bug 是你自己造成的，你可以关闭你的问题，但是请确认你完全地描述了你的失误，因为别人可能也会做出同样的错误。

如果你看见一些关于 commit 的信息，那可能是因为有人修复了你的 bug。它会链接到 commit ，上面会写着开发者为了修复这个 bug 干的事情。如果你的问题还是没有被解决，重新打开你的问题，并为我们填写更多细节。

建议新的特性

特性是你想要加入 Glowstone 的东西。他们和 bug 类似，但是他们的步骤不同。

开始

在你还没点击 “new issue” 按钮的时候，请确认...

  • 是否已经有人建议了相似的特性？
  • 你的建议是否满足 Glowstone 项目的目标或者需求？
  • 你的建议是否可以被所有 Glowstone 用户使用？

只要你满足了这几个条件，你就可以继续了！

Opening your issue

检查并且满足所有条件之后，你就可以 open a new issue 了。

  • 确认你给这个问题起一个好名字。 像“我想要一个东西”或者“有些东西需要立刻被加入”会让开发者更难发现并且决定是否深入了解，如果开发者根本不看你的问题，那它可能不会被加入！
  • 细节！ 当你在填写你问题的内容时，请不要直接复制你的标题之后就这么走，这样一点用都没有。能写多少细节就写多少细节。描述这个细节并且讲解这个细节会怎么工作，会加入什么命令，有什么作用... 如果可以，请把上面的内容以及你觉得可以帮助的内容全都讲解一下。
  • 在发布之前预览你的问题！ 所有人都不希望阅读一个根本读不了的 markdown，点击 preview 并且确认你的内容看着和你想要的一样。

确认更新你的问题

关注你自己发布的问题是非常重要的。开发者可能需要你提供更多细节，或者可能需要和你确认一些事情。检查你的问题并且注意每一个 GitHub 页面右上角提醒标志上的蓝点。根据你的设置，你可能会收到关于你的问题的邮件。

如果你的特性更改了或者你想查看更多信息，请确认你在同样的问题上和我们更新信息。

关闭你的问题

一般情况下你不需要关闭你的问题，一般都会被开发者关闭。你只需要在你发现 Glowstone 已经包含这个特性或者已经有人发布这个问题的情况下关闭你的问题。

一般来说，开发者会关闭你的问题，通过 commit 或者手动关闭。当一个 commit 关闭一个问题的时候，你通常会收到一条像这样的信息：“mastercoms closed this issue from a commit 22 days ago: 'Added Amazing new feature to create random rainbows. Resolves #322'”。如果已经有解决办法，开发者也会关闭你的问题。如果一个开发者关闭了你的问题但是你感觉你的问题没有被解决，请对开发者说出来。如果已经解决了，你的任务已经完成了！




库管理
本页面包含如何使用依赖外部资源库的插件的教程。

Glowstone 有一个资源库管理器，不需要额外配置就可以自动下载 MySQL 和 SQLite 资源库。我们还在努力制作用于自定义资源库的额外配置。目前来说，有一个解决在 Glowstone 内使用外部资源库的办法。

基本上，你需要把 jar 添加到 classpath 里面。格式通常是这样。

  1. java -cp glowstone.jar:library1.jar:library2.jar net.glowstone.GlowServer

在 Windows 内, 使用 ; 来代替 : 用来分开文件名。

  1. java -cp glowstone.jar;library1.jar;library2.jar net.glowstone.GlowServer
复制代码

"Glowstone.jar" 应该处在所有jar之前，library1.jar / library2.jar 是可选的资源库。你想要加多少资源库就加多少资源库，只需要把他们的文件名用冒号或者分号分开即可（根据系统而定）。

log4j2

有一些插件可能会使用 Log4j，一个被 CraftBukkit 从1.7就开始使用的 logging 资源库。Glowstone 不使用 Log4j，所以本应该可以使用的插件可能不能使用。解决办法： Log4j 的 jar 可以被在运行的时候使用，但是不会有 Log 过滤功能（比如过滤掉密码）或者其他通过 Log4j 的功能。

文件:

  • log4j-core-2.0-rc2.jar
  • log4j-api-2.0-rc2.jar

启动代码:

  1. java -cp glowstone.jar:log4j-core-2.0-rc2.jar:log4j-api-2.0-rc2.jar net.glowstone.GlowServer
