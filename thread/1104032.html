此问题由于ProtocolSupport与ViaVersion冲突而引起，全部删除后一切正常



服务端版本
Paper-211 1.15.2，处于BungeeCord内



经过
自己写了一个插件，后来插件出了问题，会不断在主城周围召唤烟花即使区块并未加载。这导致大量烟花囤积，此后（此前从未发生）第一个到达主城的玩家是我，我看到了成千上万个（当时大约有6000个）烟花同时释放，后来掉线（此时的掉线原因是平时经常见到的原因），后来每次上线都将出现Unknown dimension network id: 13后弹出服务器。
结合这段文字与实际分析得出13与世界一一对应。在其他世界也发生过几次，但数量远少于主城世界。




描述
在成功连接服务器到弹出的几个tick内（大于1tick），输入的指令与聊天信息无法发出，但可以触发PlayerJoinEvent（即玩家加入游戏）事件并被其他插件成功监听。
此后，大部分玩家进入主城世界后会发生以下情况：
  • 无法发送聊天信息，发送后显示Cannot send chat message
  • 无法发送指令，没有任何提示但无法发出
  • 无法对世界进行修改，无法创建/移除实体（例子是扔出物品与拾取物品）
  • 无法被命令方块识别到
  • 可以被/list或Tab识别到
  • 掉线后再次上线即以Unknown dimension network id: 13的理由弹出游戏
并且，有大约1/8玩家不会遇到此问题，且这类玩家在不断的变动，即原来无效的一段时间后也可能会出现此问题，反之亦然。
发现此问题后，目前唯一的解决方法是使用高频命令方块进行跨世界传送，理论上编写插件监听PlayerJoinEvent后传送玩家也可以做到但未尝试。还有，玩家掉线后后台没有任何的报错信息，和往常一样

经过检查，此问题还会导致玩家被bug踢出后玩家实体仍然存在，导致Bukkit.getOnlinePlayers()正常，但World#getPlayers()存在多余玩家实体，并导致其他插件工作错误、某些玩家无法被看到等问题。
从而得出，是此问题引发了烟花堆积，而不是烟花堆积引发此问题。




排查
遇到这个问题后，我首先就修复了那个bug，之后发现仍然发生此问题。
于是我进行了更严格的测试，我把除了多世界以外的所有插件全部禁用（Disable）后，仍然有此问题，且没有任何改变。
猜测和烟花并无关联，只是巧合，但没有依据。还有一种可能性是看到烟花后客户端或服务端“记住”了某些信息导致此问题。



问题：如何彻底解决此问题？
已经严重影响到正常游戏，希望解决，感激不尽！




解决方式
魔改服务端，在玩家因为异常被踢出后面加上打印异常堆栈轨迹
然后获得包名protocolsupport，经检查是ProtocolSupport插件工作异常
后来得知ProtocolSupport与ViaVersion冲突（上次检查时为防止出现未知错误，没有关闭这两个插件；ViaVersion是为了向高版本支持（其实对于1.15.2的服务器来说没什么用，不知道为什么当时要安装），ProtocolSupport是为了支持低版本），删除后恢复正常。
