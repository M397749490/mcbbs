前言

这是我在问答版回答关于崩溃报告所积累下的小技巧，希望对大家有所启发。
本人写作能力较低 内容可能较为枯燥与硬核 还请见谅。

以下提到的方法皆不深入到源代码 所以是源代码出问题的话 推荐直接删插件或mod


一.快速定位崩溃
1.实体或方块错误引起的崩溃引用
这种要看最开始那部分有没有Description: Ticking block entity
如果有的话 就接着看到(里面的<>是我写的注释)
-- Block entity being ticked --
Details:
        Name: ic2:crop // ic2.core.crop.TileEntityCrop                <方块名称>
        Block type: ID #303 (ic2.te // ic2.core.block.BlockTileEntity // ic2:te)        <方块数字ID>
        Block data value: 11 / 0xB / 0b1011
        Block location: World: (31,55,308), Chunk: (at 15,3,4 in 1,19; contains blocks 16,0,304 to 31,255,319), Region: (0,0; contains chunks 0,0 to 31,31, blocks 0,0,0 to 511,255,511)                <方块所在的坐标与区块>
        Actual block type: ID #303 (ic2.te // ic2.core.block.BlockTileEntity // ic2:te)
        Actual block data value: 11 / 0xB / 0b1011
Stacktrace:
        at net.minecraft.world.World.func_72939_s(World.java:2133)
        at net.minecraft.world.WorldServer.func_72939_s(WorldServer.java:756)

这部分内容说明了引发崩溃的方块所在的位置 及其方块ID
我们知道了坐标与区块以后呢
我们有两种方法
①.用一些软件去删掉这个方块（或其所在的小区块）或者直接删区块文件
②.找到服务端的config\forge.cfg
将以下两项改为true
    B:removeErroringEntities=false
    B:removeErroringTileEntities=false

2.缺失前置
缺失前置一般有两种情况
第一种是直接显示misses mod（我很久没看到过了 好像是这样显示的吧...）
第二种是出现java.lang.NoClassDefFoundError:xxx
这种情况就要注意:后面的包名了 一般来说某个包名是对应缺失mod的名字的
在java.lang.NoClassDefFoundError下面几行一般也可以看包名来定位是哪个mod缺失了前置
在你去curseforge也找不到前置的情况下 一般我是推荐直接删mod
也有可能这个包是引发崩溃的那个mod自己的 这时就要推荐楼主更新或降级mod（还是不行就直接删mod吧）

3.内存不足（内容具有争议）
在崩溃报告中一般可以找到关键字样Caused by: java.lang.OutOfMemoryError
但有时候不一定会出现
这时就会出现一些其他的字样 但会有一些明显特征 比如点一下背包就崩溃了 按一下E就崩溃了 其他人不能复现该崩溃
同时结合楼主的内存大小 一般可以知道这种是因为电脑不行而导致的崩溃（电脑不行还加什么暮色和虚无的是真的够了 ）
这时就应该推荐楼主删一些大型mod 加一些优化mod（最好的方法是换电脑）

4.数组越位
这类崩溃有个明显的特征
java.lang.ArrayIndexOutOfBoundsException:xxx

但是想要真正定位到是哪个mod是很有难度的
要像上面一样看java.lang.xxx下面几行 大致猜一下是因为什么而崩溃的

5.空指针
有明显特征
java.lang.nullpointerexception

也可以在java.lang.nullpointerexception下面几行找到相关的mod
然后推荐其更新或删除
