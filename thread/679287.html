（1）Entity的渲染及Techne的使用：
Techne导出的模型是Model类。在RenderLiving的构造方法中就可以作为一个参数输入。这很方便。
但是要是继承的是其他的Render（如投射物）就没有这个参数，那怎么办呢？
我得出的结论是：
Model类的render()其实就是发送了一组OpenGL命令。在参考了http://www.mcbbs.net/thread-204115-1-1.html这篇教程之后。我将我用Techne做出的Model类生成了一个实例，在这个Render的doRender（）方法中调用model.render（）。就成功了。

（2）Entity的附加属性（如技能，蓝条）的制作
感谢@[size=1em]Jackiecrazy告诉我的IEEP
使用方法详情参考http://mcforge-cn.readthedocs.io ... edentityproperties/
看了Entity的FormNBT()的代码之后你就会发现IEEP是在
  1. for (String identifier : this.extendedProperties.keySet())
  2.             {
  3.                 try
  4.                 {
  5.                     IExtendedEntityProperties props = this.extendedProperties.get(identifier);
  6.                     props.loadNBTData(p_70020_1_);
  7.                 }
  8.                 catch (Throwable t)
  9.                 {
  10.                     FMLLog.severe("Failed to load extended properties for %s.  This is a mod issue.", identifier);
  11.                     t.printStackTrace();
  12.                 }
  13.             }
复制代码

那么问题就来了，当玩家刚刚生成的时候，没有你注册的这个Key，也就是就是String identifier : this.extendedProperties.keySet()这里没有获取到你的IEEP的Key，那么他是不会读取到你保存的数据的（我使用的时候老是只saveNBT没有loadNBT就是这个原理）。
怎么解决呢？
事件EntityConstructing在FormNBT()之前调用，所以说你要在这里给Entity加上这个Key的IEEP（里面的数据什么样无所谓），如果你不是奇葩的话，在这里面调用你的IEEP的init()即可。

针对服务器编程的玄学：

要mod支持服务器主要就是要分开服务端代码（尤其是这货）和客户端代码。只能在客户端出现的代码千万不能在服务端运行。比如
MinecraftForgeClient.registerItemRenderer();

玄学1、NetWork：
如果你要向服务器发一个IMessage，很简单 客户端 和 服务器 都注册它就好了
registerMessage(SlashMsg.Handler.class, SlashMsg.class, Side.SERVER);
但是如果你要向客户端发送一个IMessage！
你的IMessage的处理中如果有只能在客户端执行的代码。
那么你直接
registerMessage(SkillMsg.Handler.class, SkillMsg.class, Side.CLIENT);
服务端会崩溃！
那么如果我只在客户端注册它呢？
if(event.getSide().isClient())
                registerMessage(SkillMsg.Handler.class, SkillMsg.class, Side.CLIENT);
OK？
服务端 和 客户端 都开启而且看似正常的运行了。
但是如果服务端会发送一个SkillMsg。那么由于没有在它这边注册，那么它不会发送这个msg，客户端也不会收到一个SkillMsg。
所以你要在服务端也注册一个SkillMsg
if(event.getSide().isClient())
        {
                registerMessage(SkillMsg.Handler.class, SkillMsg.class, Side.CLIENT);
        }
        else
        {
                registerMessage(SkillMsg.SerHandler.class, SkillMsg.class, Side.SERVER);
        }

哪怕这个SerHandler什么也不做。
这样才能正常的运行（当然如果你不进行这些奇葩的行为的话，mod在单人游戏和多人联机的时候也不会有什么问题）
