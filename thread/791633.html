前言
什么是海绵服务端？
      海绵服务端是新一代的高版本服务端，是由原Cauldron、spigot、bukkit的部分开发者组建的开发团队开发运维的新生代服务端，其内核“SpongeForge”/“SpongeVanilla”是基于Forge运行在服务器上的服务端插件前置，因此，其不同于传统的Cauldron服务端，Sponge插件对模组的高兼容性是以Bukkit微内核的Cauldron无法企及的，而其搭载的Mixin技术更是为模组服的优化提供了强大的保证！而Sponge服务端作为一个开源项目，具有相当快的版本迭代周期，很多反馈问题都会在最快的时间内得到官方支持的解决。
为什么选择海绵服务端？
      海绵服务端的稳定性是Cauldron难以达到的，了解Cauldron运行原理的腐竹都知道，Cauldron内核是Bukkit管理的，如果为Bukkit打上Forge，那将会在触发任何事件的时候激活两次监听，一次bukkit的，一次Forge的，这样一来，在一些由forge注册的非原版事件是Bukkit无法识别的，这时候就会出现后台刷报错的问题，而Sponge服务端全部运行于Forge之下，用统一的触发机制接收事件的监听并统一调用，实现了插件和模组的统一（实际上，我们可以将Sponge插件看做是Sponge内核的附属mod）。
      此外，Sponge服务端有非常多的优势，简单梳理如下：
  • 强兼容性；
  • 多线程优化（api7较为明显）
  • 插件跨版本兼容（针对部分）
  • 高度自定义的优化方案
  • 高版本
  • 最新的模组支持

关于模组
      同Cauldron端不同，Sponge服务端的所有插件均为mod，为了同服务端的插件区分，本整合包将所有的游戏性mod放置在mods/1.10.2文件夹下。

      服务端搭载了海螺的AntiCheat4mod，可以有效的防止玩家使用作弊mod，这里给大家简单做一个反作弊的教程：
  • 第一步：删除客户端的config/anticheat4.cfg文件
  • 第二部：启动客户端，让客户端重新生成mod的md5
  • 第三部：打开客户端的config/anticheat4.cfg文件，将其中所有md5码拷贝到服务端的config/anticheat4.cfg中

  • 注意：服务端的anticheat4.cfg有“required”和“select”两个选项，如果你希望玩家必须加载指定mod，那请将相关mod的md5放置在“required”下，如果你认为某些mod是玩家可选的，请将对应的mod的md5放置在“select”下。
  • 注意：请注意以下容易导致配置错误并导致客户端无法连入服务器的问题：
  • 误将八个空格设置为Tab制表符
  • required下留了一行或多行空行（*重要，常见）

当导入的世界（如主城建筑一般都是创造模式）为创造模式时，服务器导入后的世界也是创造模式（这设定有点蛋疼）。。

并且在sponge配置中有一项：

    commands {
        # A mapping from unqualified command alias to plugin id of the plugin that should handle a certain command
        aliases {}
        # Patches the specified commands to respect the world of the sender instead of applying the changes on the all worlds.
        multi-world-patches {
            defaultgamemode=true
            difficulty=true
            gamerule=true
            seed=true
            setdefaultspawnpoint=true
            time=true
            toggledownfall=true
            weather=true
            worldborder=true
这样的话所有的世界就成了创造模式。。
