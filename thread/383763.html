简介
Citizens2是一款先进的基于CraftBukkit的NPC插件。与原来的Citizens不同，Citizens2允许开发人员扩展基本的NPC提供不同的玩法和功能。它继承了simple NPCs的全部功能，并加入了生动的语言，好动的居民，哨兵，贸易商和以及其他更多特性。Citizens含有多种可切换字符和无限可能性、扩展性与新的易于使用的API。凭借先进的功能，如脚本，人工智能和乐于助人的开发团队，Citizens将继续扩展，让您的服务器可以更好！

基本功能
  • 基本的NPC - 右键点击消息，物品，环顾四周，路径点，等等。
  • 可切换的NPC角色，API地址 - http://wiki.citizensnpcs.co/Characters
  • 兼容Essentials，BOSEconomy，MultiCurrency和iConomy4，5，6。前置插件为Vault（必需）。

主要特点




  • NPC可以行走，站立，自然地与玩家对话。
  • 有易于使用的API可以进行开发。这使得全新的角色能够增强你的NPC体验。
  • 怪物和动物的NPC。您可以在地狱门周围创建恐怖的烈焰人，出生点附近创建受人欢迎的羊，还可以在您的村庄里创建一些有用的村民。可以查看命令页面了解如何创建一个生物NPC。
  • 可以骑乘与控制的NPC。
  • 强大的文字编辑能力。新文本编辑界面允许添加，删除和编辑NPC文本。
  • 服务器拥有的NPC可以被任何拥有citizens.admin权限的玩家进行编辑。
  • 管理员可以自定义创建NPC所需的费用以及每个玩家最多拥有的NPC的数量。

如何安装
安装Citizens 2.0非常容易。像许多其他的Bukkit插件一样，如果你不知道怎么做，请往下看。




  • 首先下载Citizens 2.0。
  • 将Citizens 2.0.jar 放进你服务器的/ plugins目录里。
  • 下载任何你需要的特性（Trait）插件，然后都放进/ plugins目录里。
  • 重启你的服务器。Citizens 2将创建一个plugins/Citizens文件夹和一个config.yml文件。
  • 根据自己的喜好配置好config.yml文件。可以查看配置页面获得更多帮助。
    • reload或者重启你的服务器。
    • 开始创建和编辑NPC！
    • 一定要设置权限，以便您的玩家可以与NPC的互动。
    需要注意的是玩家需要citizens.npc.talk权限才能听到的NPC的对话！

编辑器
编辑器可以通过简单的方法对NPC进行进一步的编辑。很多情况下只用命令来实现一系列功能太过复杂，在所有的编辑器中，你可以一次性将所有相关的命令键入编辑器，然后退出编辑。你同一时间只能在一个编辑器里。
文本编辑器（指令: /npc text）
编辑NPC的文本很简单。可以按照游戏中的指示添加，编辑和删除NPC的文本。一个"random-talker"NPC意味着它会不断地从文本列表中随机抽取语句来说话。如果"random"是false的话，它会按文本列表顺序不断循环抽取语句。通过输入"close"设置close-talker可以切换当玩家接近NPC5个方块距离时，NPC是否说话。如果值为false，该NPC只会在设置了相应的点击行为时才会说话。如果值为true，则该NPC只会在玩家接近时才会说话。
需要注意的是玩家需要citizens.npc.talk权限才能听到的NPC的对话！
重要提示：在输入框中输入’exit’来关闭编辑器！
详见“文本语法”页面（稍后翻译）

装备编辑器（指令：/npc equip）
“装备”是一些类似装甲、手上拿着的物品，以及NPC身上一些可见的特征。只有一部分类型的NPC可以编辑它们特有的“装备”。
一般的：随着1.4.5版本生物“装备”的更新，所有没有在这里列出的生物将默认使用人类的装备风格。需要注意的是装备可能无法在所有的生物上正确显示，特别是一些不支持它的生物。
人类 (标准NPC)：人类NPC可以修改自己的装甲和手持物品。你可以通过手持一个装甲右击一个NPC来将这个装甲给予它，这个装甲将会穿着在NPC身上，而之前在NPC上的物品或装甲将会被移除或掉在地上。你还可以通过按住潜行键右击NPC将你手上的装甲放置到NPC的手中。当你空手右击NPC时将会清空它身上的所有物品。
末影人：末影人NPC可以修改它们手中搬运的物品。末影人只能持有“方块” - 大多数的物品不会出现在客户端上。需要注意的是某些实体方块，如公告牌,蠹虫方块等等也不会出现在客户端上。空手点击末影人NPC将移除它手中的方块。
羊：羊NPC可以修改它们的毛色或者剪毛之后的样子。手拿着剪刀，像你平时剪羊毛那样右键它，可以设置该NPC为剪毛后的样子。拿着剪刀再次右键，则会恢复成剪毛前的样子。拿着染料点击NPC，可以修改它们的毛色。拿着任何一个不是染料的物品点击NPC，将会使它变回白色，并且染料会掉到地上。
猪：猪NPC可以添加和删除他们的马鞍。手拿马鞍右键NPC就可以添加马鞍，拿着其他任意东西点击则会移除它的马鞍。
兼容性
已知的与Citizens2.0.4的兼容问题：
  • Citizens需要CraftBukkit 1.4.5以上版本
  • 设置pvp=false可能会与左键功能冲突，因为这被视为攻击NPC，因此事件将不会触发。
  • 敌对生物类型的NPC的生成可能会在以下情况下被阻止：
  • 有一些插件会以最高优先级阻止生成，插件列表：
                        Essentials会阻止NPC生成
                        WorldGuard不会阻止NPC生成
                        MultiVerse不会阻止NPC生成
  • Authme可能会在连接到Citizens2时引发控制台错误。
  • PvPToggle可能会在连接到Citizens2时引发控制台错误。
  • TeleportSuite在寻找NPC时可能会引发控制台错误。
  • HomeSpawnPlus可能会在使用木棍时阻止右键选择。
  • APIPlus可能会阻止所有右键点击。
  • PopulationDensity/GriefPrevention可能会在服务器启动的时候干扰NPC的生成，并且可能会在执行/reload命令时复制他们。
  • heros已知与玩家类型的NPC存在问题。请不要给他们门票(没用过这个插件，不明白什么意思)，我们正试图与Kainzo合作来解决这个问题。
  • CityScape也使用/npc指令，如果你同时装了这两个插件请使用/npc2来执行citizens2的指令。

配置文件
Citizens的配置文件路径为/plugins/Citizens/config.yml。每个设置的具体信息请参阅下方示例。对于文本节点的详细信息，如<npc>节点，请参看“文本编辑器”语法页面。
默认配置文件
# Citizens Configuration
npc:
  chat:
    options:
      bystandersheartargetedchat: true
      maxnumberoftargetstoshow: 2
      multipletargetsformat: <target>|, <target>| & <target>| & others
      range: 5
    format:
      notargets: '[<npc>]: <text>'
      withtargettobystanders: '[<npc>] -> [<target>]: <text>'
      totarget: '[<npc>] -> You: <text>'
      withtargetstobystanders: '[<npc>] -> [<targets>]: <text>'
  default:
    lookclose: # NPC的头转向玩家的设置
      enabled: false # 是否在靠近玩家时看向玩家
      range: 5 # 玩家靠近时转头的检测范围
    pathfinding:
      range: 25.0 # 在放弃之前的最大寻路范围
    randomtalker: true # 设置NPC说的话是否是随机抽取的
realisticlooking: false # 设置NPC在不被墙遮挡的时能让潜在（隐身？）的玩家看到对话（不是很理解什么意思，需要测试一下）。
    stationaryticks: -1 # 设置NPC在寻路过程中被卡住时尝试多长时间后放弃（-1应该是无限久）。
    talkclose:
      enabled: false # 是否在玩家靠近时说话
      range: 5 # 检测范围
    text:
      '0': Hi, I'm <npc>! # 默认文本
  limits:
    defaultlimit: 10 # 每个玩家可拥有的NPC上限
    maxpermissionchecks: 100 # 一个玩家可以领取的NPC任务的最大数量的（原文是the maximum number of per-player NPCs a player can have，但是我看这个标签的意思应该和这个注释有出入，所以我按自己的意思翻译了，仅供参考）
    maxspeed: 100 # NPC可以设置的最大速度
  chunks:
    alwayskeeploaded: false # 设置在区块中没有玩家只有NPC时是否保持区块加载。

炼金术士
炼金术士是Citizens 2.0的一个角色特性，它赋予NPC以下的能力：
  • 根据预先定义的配方制作药水。
  • 收费提供服务。
下载地址：http://ci.citizensnpcs.co/view/Add-ons/job/Alchemist/

如何使用
基本信息
炼金术士提供创造药水配方的能力。你可以在配置文件中自定义这些配方。一个默认的配方已经提供给您做为参考。
请记住，没有方法可以使用这个插件来查看一个炼金术士当前配方的成分。这是故意这么设置的，因为你，做为服务器的管理员，应该可以完全自由地来决定如何显示配方，你可以使用告示牌、其他插件，或者根本不显示成分。
互动
手持适当的成分右键炼金术士将会把成分递给他，一旦配方的成分集齐了，炼金术士会将药水掉落在他周围。如果玩家走得太远，炼金术士会停止炼药，并且给予他的物品也会消失。
指令
在只用指令之前，您应该先选中一个NPC，并且是它的拥有者。这些指令不需要任何权限。
指令
描述
/alchemist help
显示帮助菜单
/alchemist recipe
显示这个炼金术士当前的配方（只是名称？）
/alchemist recipe [name]
设置这个炼金术士当前的配方
权限
要使用炼金术士，你只需要一个权限：alchemist.interact，用来允许玩家与炼金术士互动。
配置文件

价格
价格是通过一个物品的损坏程度、附魔的种类和数量、以及在配置文件中设置的价格来决定的。一般说来，制造一个物品的价格 = 基础价格 + 回复的耐久度 + 附魔。

基础价格
制造一个物品的默认基础价格是定义在配置文件中的base-prices.default字段的值。要为每个单独的物品添加新的基础价格，你需要添加这个物品到配置文件的base-prices下。

耐久度
耐久度是一个物品损坏的情况。 通常制造一个损坏度越高的物品就越便宜。如果你试图制造一个没有任何损坏的物品，那将会更加得昂贵。每一点耐久度需要的费用定义在配置文件的price-per-durability-point.default字段中。每个物品的价值可以通过添加进这个部分来设置。

指令
以下所有的指令可以在选中一个NPC时（/npc select [NPC的ID]）直接执行（/builder [指令]），或者通过/builder [NPC的ID] [指令] 来对指定的某个NPC执行。
/builder list - 列出在配置的schematics文件夹下所有可用的.schematic文件。此命令不需要选中NPC。
/builder load [schematic] - 加载一个.schematic文件。只要简单地使用schematic文件的名称即可。例如：
/builder load house
/builder origin - 设置建造者工程的原点为建造者当前所在的位置。允许你在相同的点重建。如果没有设置的话建造者将总是从当前所在的位置开始建造。
/builder origin clear - 清除已保存的建造原点。
/builder origin schematic - 设置建造者工程的原点为当前加载的schematic文件的原点。最适用于从建造者的世界中使用WorldEdit创建的schematics。（不是很明白，需测试）
/builder origin me - 设置建造者工程的原点为玩家所在的位置。该命令无法从控制台输入。
/builder origin current - 设置建造者工程的原点为当前正在建设的工程的原点。用于在开始建造之前你忘记设置原点，又需要取消工程稍后重建的。（需测试才好理解）
/builder origin x,y,z - 设置建造者工程的原点为建造者当前所在的世界的x,y,z坐标。
/builder mark (item)- 在工程的覆盖区域的四个角各放置一个方块，然后回到原点，这样你就可以知道将会建造在什么位置上。你可以指定使用一个定义在config.yml中的物品（大概是指MarkMaterials）。如果没有指定物品的话，将使用config.yml中定义的第一个物品。如果config.yml中没有定义的话将使用玻璃。
/builder timeout [value] - 设置在方块中的最大时间（秒）。有效值在0.1 - 2000000.0之间。默认是2.0。默认值可以在config.yml中修改（就是那个不明白什么意思的MoveTimeoutSeconds吧）。
/builder build (option1) (option2) ... etc - 开始根据schematic文件建造。这个指令有几个可选的参数。没有顺序要求。你可以添加如下参数：
·  linear - 从北向南建造。
·  reverselinear - 从南向北建造。
·  sprial - 由内向外建造（这是默认选项所以不用特别指定）。
·  reversespiral - 由外向内建造。
·  excavate - 建造者在开始建造之前会先把这个区域的方块清理掉。
·  layers:# - 建造者一次会建造#层，这个值默认是1。
·  yoffset:# - y坐标上的偏移量（就是在原来的位置向上或向下移#格）。
·  groupall - 建造者将会一次性将一组材料建造完成，而不是一层一层地建。
·  ignoreair - 建造者将不会放置空气方块。（用于在现有的结构中建造，如果和excavate模式一起将会没有意义）
·  ignoreliquid - 建造者将不会放置岩浆或水方块。（用于在这个图纸（schematic）的底部有流动的水）
·  onstart:Task - 建造者将会在开始建造之前（收集材料之后）执行居民的任务脚本，详见“进阶用法页面”（Advanced Usage）。
·  oncomplete:Task - 建造者将会在建造结束之后执行居民的任务脚本，详见“进阶用法页面”（Advanced Usage）。
·  oncancel:Task - 建造者将会在取消建造的时候执行居民的任务脚本，详见“进阶用法页面”（Advanced Usage）。
·  silent - 建造者将不会发送完成或者错误的消息。
以下是例子：
/builder build
/builder build excavate reverselinear yoffset:-3
/builder build ignoreair ignoreliquid oncomplete:Celebrate
/builder build groupall layers:3

/builder cancel - 取消当前的建造工作。
/builder info - 查看一个建造者已加载的schematic的名称和大小，同时查看建造者的选项（option）和状态。
/builder survey (excavate) - 显示在当前位置上建造需要的方块类型和数量。加上excavate参数的话显示如果使用excavate模式需要的材料。不会显示水和岩浆。
/builder supply true|false 设置建造者在开始建造之前是否需要给予材料详见“供给模式”（Supply Mode）。
/builder hold true|false 设置建造者在放置时手上是否要拿着对应的方块。（设置为false只有在需要兼容别的插件的情况下，如哨兵插件）
/builder reload - 重新加载config.yml里的选项。
/builder help - 显示帮助。

使用方法
·  .schematic文件应该被放入/plugins/Builder/schematics/文件夹。这个文件夹可以在config.yml里配置。
·  在你执行build指令之前，放置好建造者的位置，或者设置好它的原点，最好位于你要建造的覆盖面的中心。图纸（schematic）的大小在加载时会显示。
·  当你设置了原点之后，你可以取消一个建造过程并在之后可以继续它。如果你忘记设置原点，可以在建造开始之后使用/builder origin current指令来设置它。
·  不要试图恢复一个使用了excavate参数的建造过程！（估计会把之前造的都清空了）
·  建造者将会忽略图纸（schematic）下方的任何空的空间，所以它总是会停留在开始时的地面上。如果你希望建造在原点上面或者下面的话，在执行build指令时使用yoffset:参数。
·  建造者不会视图去替换一个摆放正确的方块，这意味着你可以使用建造者快速地“恢复”一个它之前建造过的东西。
要让一个建造者来维护一个现有的建筑可以按照以下步骤：
使用Worldedit来选择一个建筑物然后将它保存成schematic文件。
将该schematic文件复制到建造者的schematics文件夹。
将这个schematic加载到一个建造者上然后执行/builder origin schematic指令。
执行/builder build指令，建造者将会放置所有缺失的方块或者摧毁新放置的方块。
·  铁轨和发射器可能无法被正确放置。（嘿，这是个建筑物，而不是一个工程）
·  默认情况下，NPC会在他们所在的区块unload时despawn。这个行为可以在Citizens2的config.yml文件中修改。如果你希望建造者在无人看管的情况下继续建造的话推荐你这么做。

供应模式（Supply Mode）
    如果建造者被设置为需要材料进行建设（/builder supply true），那么当/builder build指令被执行的时候，它将会使用供应模式。当供应模式启动的时候，建造者会调查并列出需要的材料清单。玩家必须提供这些材料建造者才会开始建造。
在供应模式中：
    空手右键建造者可以查看还需要哪些材料。
    手持任意方块或者物品右键建造者可以知道它是否需要。如果需要，它会告诉你还需要多少个。
    当手持所需材料点击过建造者之后，再次按住右键几秒可以把材料递给它。
    在收到材料后建造者会说它总共还需要多少方块才能开始建造，如果材料已经收集全了他将会开始建造。
需要什么材料：
    默认情况下所有的方块都需要它们的普通掉落形态（比如蜘蛛网需要的是线）。
    这个行为可以通过\Builder文件夹里的'supply.txt'文件来覆盖。
        每一行包含在schematic中定义的物品ID和实际需要的物品ID。
        您还可以指定每一个所需的建筑方块需要的物品数量。
        设置需要的物品ID为0的话，这个建筑方块就不会出现在需要的材料列表里了。
    （简单总结一下就是说你可以自定义盖房子的某个材料要由哪些物品组成，并且需要多少，比如你可以设置要建造者放置一个蜘蛛网，你必须给它2个线这样的规则）

进阶用法
建造者可以在建造过程的开始时、完成时或者取消时执行居民任务脚本。
该NPC必须同时具有建造者及居民特性。
在执行/builder build指令时带上以下选项。
    onstart:任务名称
    oncomplete:任务名称
    oncancel:任务名称
举个栗子：
/builder build oncomplete:DespawnTask oncancel:AnnounceTask
建造者同样可以运行居民的行动（Actions）事件（居民部分还没有看，看完之后再修正翻译）。添加以下文字到该NPC的actions中：
"Build Start"
"Build Complete"
"Build Cancel"
举个栗子：
BuilderAssignment:
  type: assignment
  actions:
    on Build Start:
      - ANNOUNCE "Let's do this!"
    on Build Complete:
      - ANNOUNCE "I have finished!"

继续重建
如果你希望让一个建造者看起来很忙碌，按照图纸不断地重建与破坏，你可以像下面这样设置。
在居民的脚本文件夹里用任意一个yml文件创建如下的一个任务脚本。
---- script.yml ----
Rebuild:
  Type: Task
  Script:
    - execute as_npc "builder <npc.id> build excavate oncomplete:Rebuild"
现在创建一个建造者，加载一个你想要的schematic文件，设置一个原点，然后执行如下指令：/builder build oncomplete:Rebuild。
这个建造者将会建造这个schematic文件，然后执行这个任务，又继续重新建造，在excavate这个的选项下，它将会先把造好的建筑拆掉，这样就会永远循环下去。
你可以使用这个脚本来创建尽可能多的建造者和图纸，但是不会改变任何东西。

FAQ
Q: 如何能让多个建造者一起建造一个东西？
A: 你通过给最多4个建造者同样的schematic和原点，但是不同的建造模板来让他们共同建造（不太清楚建造模板是什么）。你同样可以用WorldEdit或者MCEdit将schematic文件手工分割成多个部分。
Q: 怎样才能让建造者盖得快一些？
A: 使用/builder timeout指令来设置他在方块间的最大时间。你同样可以使用"/npc speed"指令来让它走得快一点。
