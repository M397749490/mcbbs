使用命令的地图制作者或玩家们：
我正考虑添加 /modifyitem 命令，但我需要你们的反馈
https://www.reddit.com/user/Dinnerbone/comments/6wjeai/possible_new_113_command_modifyitem/



/modifyitem
  • 这是替换 /enchant 的新命令
  • 格式分为3部分，首先选中容器或背包：
    • /modifyitem block <pos> 选中方块容器
    • /modifyitem entity <entity> 选中实体背包
  • 然后选择物品槽位：
    • slot <name> 选择指定物品槽位
    • item <item> <count> 是任何匹配本物品的物品槽位（查看物品参数类型来获得更多信息），最大会匹配 <count> 个物品槽位（-1即匹配所有）
  • 最终指定行动：
  • enchantment add <enchantment> [rank] 为物品增加或升级 <enchantment> 附魔等级 <rank> （默认是1）
    • 与旧的 /enchant 命令不同的是，我们不会强制实施生存模式下的附魔规则，你可以在木棍上附锋利附魔！
    • 如果物品已有 <enchantment> 附魔的话，会增加其附魔等级 <rank> 级
    • 如果物品没有 <enchantment> 附魔的话，会为其附上 <rank> 等级的附魔
  • enchantment remove <enchantment> [rank] 为物品降低 <enchantment> 附魔等级 <rank> （默认值为-1，即解除附魔）
    • 如果物品没有 <enchantment> 附魔的话，本命令会运行失败
    • 如果执行后最终等级为0或更低的话，会自动移除附魔
  • enchantment clear
    • 如果物品没有任何附魔的话，本命令会运行失败
    • 会移除物品上的所有附魔
  • damage add <amount> 减少物品 <amount> 耐久度
    • 如果物品无法减少损伤值的话，本命令会运行失败
    • 损伤值与耐久对立 - 一把普通的木剑耐久值为60，损伤值为0，如果你使用了一次的话，耐久值剩余59，损伤值为1
    • 如果最终损伤值比物品最大耐久大的话，会移除物品
  • damage remove <amount> 恢复物品 <amount> 剩余耐久
    • 如果物品不能增加损伤值的话，本命令会运行失败
    • 如果最终的损伤值比0小的话，会设置为0，因为物品的损伤值为负数是无意义的
  • damage set <amount>
    • 如果物品不能设置损伤值的话，本命令会失败
    • 将物品的损伤值设置为 <amount>
    • 如果最终损伤值比物品最大耐久大的话，会移除物品
  • nbt add <nbt> 为物品NBT增加 <nbt>
    • 这和 /entitydata ,/blockdata 和其他增加NBT的操作的工作方式相同
  • nbt set <nbt> 将物品的NBT设置为 <nbt>
    • 在设置新NBT之前会清除已存在的NBT
  • nbt clear 移除物品所有的NBT属性
    • 会移除所有属性
    • 包括附魔和损伤值
  • count add <count> 物品数目增加 <count>
    • 如果最终物品数目比一组多的话，本命令会运行失败
    • 也就是说不能堆叠的物品使用本命令会永远失败
  • count remove <count> 物品数目减少 <count>
    • 如果最终物品数目小于等于0的话，物品会被直接移除
  • count set <count> 将物品的数目设置为 <count>
    • 如果设置的最终物品数目比一组多的话，本命令会运行失败

注释
  • 本命令对堆叠的物品工作，而不是单个物品
  • 关于损伤值我不是很高兴去弄，但是如果让我去弄耐久度的话我会更不开心的
    • 0 耐久度的意思是“坏掉了”，0 损伤值的意思是“完好无缺”
  • 未来我也可以增加对属性（attribute）修改的支持，但是我不知道最终看起来会怎样，因为属性标签现在看起来有点乱
  • 我也可以增加 nbt remove <tag> 但是我不知道它是否能正常工作，因为之前没有先例
  • 我们也考虑使用本命令替换 /replaceitem 然后增加 replace <item> 作为可指定的行动
