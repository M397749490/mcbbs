如果加这个阐述-XX:+UseG1GC会启动不了bat是空白的

我之前复制的cpw推荐的参数
oracle的文档
https://docs.oracle.com/javase/8 ... s/windows/java.html
你的脚本是设置使用 CMS GC
-XX:+UseConcMarkSweepGC
-XX:ParallelGCThreads=16 (设置GC的线程 我个人觉得这个是没有必要改的
Java8之后 我个人更推荐使用G1GC
-XX:+UseG1GC
G1GC相关的参数可以参考
https://www.oracle.com/technetwo ... a/g1gc-1984535.html
-XX:MaxGCPauseMillis=50 (我个人觉得使用G1GC添加这个就足够了

其它的参数
-Xms5120M -Xmx10240M 设置堆的最小和最大内存 (如果你是10G的机器我觉得还是预留出足够的部分给系统比较好 比如最大设置成8G

-XX:+AggressiveOpts 激进的优化策略
    Enables the use of aggressive performance optimization features, which are expected to become default in upcoming releases. By default, this option is disabled and experimental performance features are not used.

-XX:+UseCompressedOops 在Java8中 这个默认是开启的 压缩内存

-XX:+UseFastAccessorMethods 在Java7的文档中有提到这个是使用更快的方法Get基础类型的域,在java8的文档中没有看到
-XX:MaxPermSize 这个在Java8是过时的,推荐使用-XX:MaxMetaspaceSize

-XX:+DisableExplicitGC 禁止显示的调用System.gc() 可以阻止v乐乐或者各种声称能够减少内存的插件 显示调用gc造成性能波动

总结一下就是
-Xms6G -Xmx8G -XX:+UseG1GC -XX:MaxGCPauseMillis=50 -XX:+AggressiveOpts -XX:MaxMetaspaceSize=1024M -XX:+DisableExplicitGC

最大内存设置为10240M 最小内存最好是最大内存的一半 所以就是5120M  加上一些优化代码 和加速代码就是：

java -Xms5120M -Xmx10240M -server -XX:+AggressiveOpts  -XX:+UseCompressedOops -Xss256k  -XX:ParallelGCThreads=16 -XX:+UseG1GC -XX:MaxGCPauseMillis=50 -XX:+UseFastAccessorMethods -d64 -jar 服务端名称.jar

-server 启动服务器模式

-Xms5120M -Xmx10240M 设置最大和最小内存

-XX:+AggressiveOpts  -XX:+UseCompressedOops 优化和压缩内存指针

-Xss16m  -XX:ParallelGCThreads=16 使用16个线程 一个线程使用16M内存运行服务器 1核=2个线程

-XX:+UseG1GC -XX:MaxGCPauseMillis=50 自动清理java产生的垃圾

-XX:+UseFastAccessorMethods  原始类型的JAVA自带的快速优化

-d64 使用64位数据模型
