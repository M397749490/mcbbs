前言
这是一款功能全面，短小精悍的绑定插件，没有花里胡哨的功能，是一款市面上的绑定插件的精简版
小，意味着实现功能更加容易，不需要什么配置，装入服务器就可以使用
如果出现任何问题，请加本人qq1131271403，只要与此插件有关，就可以迅速解决

本插件与本人定制插件BoundSoul非同一插件，不接受任何辩驳


功能
  • 更加自由，绑定物品，但可以丢出
  • 语言全可自行修改，带重载指令
  • 实现简单，只需要给物品加上一条lore
  • 新手礼包等等，直接发放到背包的一样可以使用
  • 带有绑定特效，如果你想要玩家买到氪金物品或者捡到了神器的时候给予一个特效显示，也可以使用本插件。20号前将会推出3款主流绑定插件转换功能。23号前推出菜单绑定与强化修正(物品放入强化菜单时，自动修改绑定为统一内容，取出物品后再恢复原样)
  • 3/14 支持去除玩家名称(%player%)变量，并可指定可放入的容器，使其可以用于NPCMOD交换强化，支持设置指定容器名称可放置！
  • 3/14 支持绑定物品死亡不掉落

一些关于绑定插件普遍存在的bug说明：
已经解决了的

①盔甲架交易，使用玩家变量%player%即可绝对禁止玩家之间交易物品。
②背包满时点击绑定物品会使物品丢失
③绑定物品在开启死亡不掉落设置时，服务器开启死亡掉落，玩家死亡还没复活就意外掉线物品会丢失
还没解决：
①绑定物品在开启死亡不掉落设置时，服务器开启死亡掉落，玩家死亡服务器崩溃物品会丢失（17号前解决）



指令与权限（感谢nono云大力支持）
  • /bs 显示所有指令 —— SoulBound.used
  • /bs bind 绑定手上的物品 —— SoulBound.used
  • /bs unbind 给手上物品解除绑定 —— SoulBound.admin
  • /bs reload 重载指令 —— SoulBound.admin
  • /bs checking [on/off] 开启或关闭容器debug模式，后台输出容器类型，把容器的类型给写在AllowInventory项上，是以 - xxx的形式，同时去掉认主的%player%变量，这项功能就会启用，你便可以在npcmod中交换绑定物品了

提示：插件其他指令前缀 bs、bsoul、sb 或者插件全称soulbound
默认给予SoulBound.used权限，请注意

配置文件
  1. Version: 1.4

  3. Plugin_Prefix: "§CSoulBound §e>> "
  4. AutoBindLore_Before: "§a拾取绑定"
  5. #AutoBindLore_later: "§c认主: §a%player_name%"
  6. AutoBindLore_later: "§c认主: §a%player_name%"
  7. IllegalItems: "§c非法物品"

  9. Censor-freq: 500
  10. #扫描间隔，单位毫秒，推荐1000-100
  11. allowThrowItem: true
  12. #允许丢出自己的物品
  13. useInteraction: true
  14. #允许不属于自己的物品交互，仅适用于手持武器...左键或者右键
  15. #不建议禁止修改后需要重启才能生效
  16. useBindNotDrop: true
  17. #绑定物品死亡不掉落
  18. useEffect: true
  19. useSound: true
  20. useFireworks: true
  21. #背包内有别人物品时会被丢出
  22. throwOutItem: true

  24. #允许使用的容器类型
  25. AllowInventory: []

  27. BindSuccess: "§f物品 %s% §f被绑定了!"
  28. Lang:
  29.   ClickCancelled: "操作不合法，试图取出没有处置权的物品"
  30.   ClickCancelled2: "背包已满的时候禁止点击绑定物品！"
  31.   DropItemCancelled: "丢出自己已绑物品非法行为"
  32.   InteractCancelled: "此物品不属于你"
  33.   PlayerPickupItemCancelled: "拾起物品已经被别人绑定"

更新预判
  • 拾取后一段时间后绑定
  • 装备后绑定
  • 另外菜单绑定我个人觉得是没意义的，因为这样徒废操作，绑定物品又不意味着不会丢失，还是可能卡掉，除非和找回操作配合着一起用才可能有用，否则就是脱裤子放屁嘛，据我所知绑定物品只是用于妨碍付费/难得物品流通罢了。通过菜单绑定收费绑定倒行，如果有很多人需要我可以添加此功能

除非你去更改抽奖插件本身，不然绑定插件经常会致使抽奖券作废（因为判定ItemStack#isSimilar时会判定lore这样的nbt），如果插件本身检测的是物品名或ModelData之类的不牵扯lore的nbt就自然不会有所影响。这兼容自己写其实不好搞，即使自己写了对面一个版本更新都怕是要出bug
所以解决的办法我还是建议不要给抽奖券来个绑定，或者直接改一改抽奖插件的源代码让他别判定lore
