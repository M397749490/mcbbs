/execute at @e run tp @p x y z

execute as ... 仅改变执行者，不改变执行坐标与朝向
execute at ... 仅改变执行坐标和执行朝向，不改变执行者
如
execute as @a run summon pig会让每个玩家在命令执行的地方生成猪
execute at @a run summon pig会在每个玩家所处的位置生成猪
execute as @a run say 1 每个玩家say 1
execute at @a run say 1 命令执行者自己到各个玩家所在的位置say 1（执行者say 1的次数与当前玩家总数相同）

这么说吧，1.13之前的execute相当于1.13以后的 execute as @a at @s run ...

就比如说，我在A地，B地有个实体（假设可以用@e[tag=B]选中）

那就可以用/execute at @e[tag=B] run say 1
这样就相当于我在B第执行了say 1，当然，say 1的人还是我，不是这个@e[tag=B]

那怎么说明这个say 1确实是在B地执行的呢？
将say 1换成其他命令，如
/execute at @e[tag=B] run setblock ~ ~ ~ stone
这个石头确实是在B地生成的，而不是在A地生成的。那么可以说明这个say 1也确实是在B地执行的（虽然我依然在A地）

作者: ⊙u⊙    时间: 2020-4-28 15:20
testfor @e "等价"于 execute if entity @e
if/unless只判断是否，不改变后续命令的执行对象和位置

execute @e ~ ~ ~  "等价"于 execute as @e at @s
以前的execute把as at于一身，现在的把as和at细分了出来
as将以选择器中的对象处理后续命令，改变对象，不改变位置
at将获取一个坐标或一个对象所在的坐标处理后续命令，改变位置，不改变对象

as @e at @s 则为以@e这些对象，且使用这些对象的坐标
@s 只选择唯一一个实体：该命令的执行者



为什么是"等价"而不是等价，只是一些极端情况而已，不必较真
