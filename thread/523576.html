这里是没营养的前言....
在两年前我因为好奇开了我的第一个Minecraft服务器，时间一晃已经这么长时间了。在那个时候没有人教我，只有自己在不断的碰壁中摸索着往上爬，希望有一天能看到阳光...这几天在论坛里的问答区发现有很多坛友因为一些很简单的问题提问，还有很多有开服梦想的坛友在到处找技术人员的帮助。论坛中当然有很多比我专业的多的大角虫发的教程贴，然而...有的地方小白腐竹并不能看得明白，而且很多作者已经弃坑。在看了两遍版规后作为萌新的我决定发这样一个完备的、各种腐竹都能看得懂的MCPC开服教程。版主和管理手下留情啊喂........

需要大家注意以下几点，要不看了贴也没啥用。
       1、本教程是根据1.7.2和1.7.10两个版本的Cauldron(也就是大家常说的MCPC)，对于其他的服务端可能并不适用

       3、一些常用的软件和插件在贴中会有下载链接，但是请大家尽量去官网下载最新版的。原因主要是每次软件的更新都意味着BUG的修复和新功能的加入；其次点击有的下载链接还能为作者创造一点微薄的点击收入，也是对他们创作的一种鼓励

第一章:服务器硬件准备

一点点自己的见解
可能是受到“某宝”上的面板服的影响，很多腐竹陷入了这样一种误区：内存越大，服务器乘载人数越多，越稳定。首先我们要理解内存在服务器中扮演了什么角色：正在游戏的玩家的背包等信息需要内存来储存、正在载入的地图区块需要内存、各种插件的运行也需要用到内存。如果内存不够用，那么当用到这些东西的话CPU就要从外存中将这些数据调入内存(CPU只能处理内存中的数据这都知道吧...)，所以...服务器就会卡了...但是！一个服务器能否流畅运行并不是内存多少决定的！原因请往下看！
一、CPU
       CPU是服务器最核心的部分没有之一，分为计算器和控制器...(扯远了)，CPU的性能直接影响到了开服后游戏的流畅程度。以下内容引用自这篇帖子：
  • 如果 真核数 <= 8 则 基数 = CPU 真核数 x 最高睿频
  • 如果 真核数 > 8 则 基数 = CPU 真核数 x 默认主频
  • 如果手动超频则 基数 = CPU 真核数 x 全核心最高同步主频（不过超频的玩家基本都不会需要看这一节吧）
  • 如果为 Intel CPU 则 基数 x 1.7
  • 如果支持并开启超线程则 基数 x 1.5
  • 如果默认主频 < 2GHz 则 基数 x 0.9
  • 自己CPU的各种参数，百度一下便有，不用问我。如果最终结果 > 18 的话，开一个二十人以下小型服务器问题不大； > 30 的开六十人以下的中型服务器无压力。大型服务器？你确定你有在认真读？

附：最高睿频就是CPU超频后的最大主频。具体查看方法就是下载一个CPU-Z，下载地址百度有很多，当然这个网盘也有(论伸手党的胜利。密码：f2h3)，按照上面的公式(就好像初中学的分段函数)计算完成后比对第七条，计算自己的服务器的CPU能带多少玩家。
另外总觉得CPU实际的承载力始终比计算值要低一些，可能是MC服务端本身对多核心CPU的利用就不好，但是群组服却能很好地利用多核心。
二、带宽
       带宽是租用服务器(或VPS)最贵的项目之一。一般来说都是以5M、10M或者是20M为主(上次还看见有50M的，不过贵的要死)，VPS        VPS可以自己分配带宽。注意，不要因为带宽很贵就降低标准。
       在服务器中上传带宽更重要，而家用机正好相反(这也是不提倡用家用机开服的原因之一)
       在这里讲一下MBps和Mbps的区别：我们平时说的“20M宽带”中的“M”是“Mbps”。不要忽略了这个大小写，Mbps和MBps是两个不同的单位，比率是【8bps = 1Bps】也就是说，20M宽带的理论速度只有20 / 8 = 2.5M每秒。服务器中的每个玩家需要大概12KBps的上行带宽。按照单位换算一下，20M带宽能带动 ((20÷8)*1024)/12 = 213 个玩家(关于你服务器带宽承载力的算法：（[(X / 8) * 1024] / 12，将X换为你的购买的带宽就行。当然如果你计算器都懒得开，就用这个小程序吧,37KB。密码：i8pw，输入带宽就能计算人数。C++编写，安全无毒
       ps：看到这里大家就能发现某宝上的只用内存大小决定人数的方法是不负责任的。况且很多供应商的接入带宽只有可怜的5M，但是只因为分配高内存就把人数定为100人，实际上这样还是会很卡。
三、内存
（本节部分文本由 @zlzchuyue 协助编写）
       关于内存的所用在前面已经说明，这里就不再赘述。
       关于服务器内存大小的建议：一般来说，在纯净服为每8到9个玩家分配1G内存可以不卡。MOD服中安装的各种MOD（特别是像暮色或者是神奇宝贝这类的MOD）要吃掉不少内存，MOD服内存自己估计着分配，安装的MOD不同额外消耗的内存也不同。
       安装内存和分配内存的区别：安装内存是指服务器实际安装的内存，在上面那个CPU-Z软件可以查看，各种检测软件也可以查看，在“我的电脑”上右击点开“属性”也可以查看。分配内存就是你分配给你的服务端的内存。分配内存需要在比如我的服务器安装内存是32G，假如我分配1G内存就意味着服务端只能利用1G的安装内存，对这个服来说剩下的31G就是浪费掉了(因为没有被利用)。所以一般来说在只有一个服务端的情况下分配内存占用整个系统的安装内存96%比较合适，当安装内存很大时可以设置为98%左右(原因是java本身还有其他的一些电脑的系统应用还要消耗一部分内存)
       关于分配内存的设置在启动脚本那里也不会写到，因为大家都知道怎么设置
(有的服务器安装内存能达到128G，快赶上我电脑上的一块硬盘了...真吓人...)
四、外存
       这里的外存是指服务器搭载的硬盘的容量。如果一台服务器上只搭载一个服务端，那就除了系统盘之外再有一个盘就够。如果是搭载多个服务端的话最好是每个盘放一个服务端(当然这只是为了方便管理方便)
       外存的大小其实无所谓。外存容量很便宜，1块钱能买好多好多的容量。就照多了买吧(少吃一包辣条就能买十几个G)。但是我认为对外存空间的利用却是一个服能长久运行下去的保障
       井井有条的风格可以使开服更加顺畅，当出了问题也容易找到问题文件的地址。如果是自己存的东西自己都找不到，那开服就比较难受了。当然，有大神喜欢乱糟糟那就当我没说。另外楼主的强迫症八成治不好了.....233
五、java环境
       众所周知的，Minecraft是用java编写的。和其他的高级语言不同，java既是解释性语言，又是编译性语言。源文件在编译后不会生成机器码文件，而会生成“中间文件”，中间文件由解释器解读然后执行。所以安装java环境是开服不可或缺的一步。
       java版本的选择：推荐使用64位的java8，原因... 不说也罢，官网就有下载(当然，如果你懒得上官网，那就在这里下载.论伸手党的胜利)。
总结
       就好像“木桶效应”一样，服务器的承载力是由最弱的部分决定的。任何一项的单方面提升都不会使服务器性能有大的改善，根据自己服务器的规模选择合适的配置才能最大限度的利用服务器资源。

第三章:安装模组
       一、模组的安装倒是没什么好讲的。只要注意以下几点：
          1：注意版本，版本不符合就不要安装了
          2：注意是不是服务端mod。你要是在服务端装上小地图，不蹦服才怪
          3：注意API类型。一般都是Forge，这个倒是没什么好说的
       二、另外还有自己的一点经验
          模组最好一个一个安装，如果崩服了方便找出是哪个mod的问题
          在服务端安装之前先在自己的客户端上试一试，看看模组是不是已经损坏
          在安装模组之前最好把原来的服务端备份，防止不可逆的错误
       三、模组的配置
模组也有配置文件，就存在那个config文件夹里，有很多有用的配置，比如NPC的防止作弊和工业的防核爆。由于楼主玩的模组实在有限，在这里就不说太多了，只是跟大家说明有这么个东西...

第四章:安装插件
       插件种类繁多，数不胜数。也正是因为有了插件服务器才变得更好玩。楼主在这里只讲解几种最最最基础的。其实我想传达的还是一种思维方式，因为一个插件一个插件的学是永远学不完的。插件的安装在这里就不讲了。
一、插件的配置
       在很多的插件帖中帖主都建议“先运行插件，然后修改插件生成的配置文件”。但是在很多插件的jar里本身就有配置文件，这个时候最好在jar里修改，具体原因我也说不上来，可能是强迫症没救了吧...但是这种方法真的很好。在插件第一次运行结束以后你去看看它生成的配置文件是不是你配置的就能轻松确定插件是不是正确加载~
       关于UTF-8和ANSI：windows的配置文件需要使用ANSI格式，但是win本身的记事本却是以UTF-8的格式编辑的，所以用NOTEPAD++编写配置文件是一个不错的实践方法(下载地址：点我。密码：okoc)。当然如果插件本身自带的配置文件就是UTF-8，那就需要转换成ANSI。具体怎么转换，请娘度之。

       2、登陆插件
          登陆插件推荐使用AuthMe插件(下载地址：点我；密码：r4ax。论伸手党的大获全胜)。
         3、多世界插件
             多世界插件有两个，Multiverse-Core(简称MV)和MultiWorld(简称MW)。推荐使用MV多世界(惯例，下载地址：点我；密码：wnx0)，因为很多像地皮这类插件需要多世界作为前置的插件大部分是以MV作为范例的。当然也有例外，但是例外毕竟是少数。由于多世界出的问题比较多，我来列举几个。
     1：怎么创建多世界？多世界的创建方法、创建的类型在这里不做介绍(大家都会)。
     2：怎么卸载世界？
         答：首先在主世界文件夹下删除对应世界的子文件夹，然后再多世界的world文件下将该世界的配置删掉。
     3：玩家在新的世界没有权限怎么办？
         答：首先说明一下，我本人从来没遇到这个问题。搬运作者的解决办法是权限覆盖，把主世界的权限覆盖给新生成的世界。操作方法：
当你生成新世界后，plugins\GroupManager\worlds下会生成一个名为新世界名的文件夹，里面包含的东西就不介绍了，把普通世界的groups.yml user.yml丢进去覆盖之，/manload重载一下即可，当然，你也可以给不同的世界设置不同的权限。

           如果你对这种方法看不明白，请去MV的搬运贴提问搬运作者，我没遇到这个问题没有发言权。
     4：在服务器聊天栏怎么修改世界名城？
         答：在多世界的worlds.yml文件中的“alias”后面修改世界名，注意编码格式！同理，名称颜色在下面的“color”修改
       5：某个世界进不去了怎么办？
         答：首先输入/mv list查看多世界列表，如过世界的名称变成了灰色，那就说明这个世界被卸载了。如果不是被管理员卸载的那就是世界出现错误，多世界把它卸掉了。建议重新生成那个世界。
       6：注意，在删除某个世界之前，先把所有玩家(不管是在线的还是没在线的)都从那个世界挪出来，否则删除世界后那个玩家将不能登陆游戏
总结
       实际上这一章基本就是水，确实没什么好讲的...因为各种插件的用法在插件原帖或者是搬运贴中都有详细的介绍。只要看明白适用版本就基本没有什么问题。但是不管怎么说插件也是一个服务端出彩的地方，与其说玩家玩的是模组不如说玩的是服务器种的插件和各种设定。如何善用插件是每个腐竹的必修课。=，创建自己的、有特色的服务器。因为只有这样才能吸引玩家、留住玩家...另外刚才发现表格居然这么长...
