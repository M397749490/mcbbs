版本判断器

    顾名思义，它是一个用来判断minecraft版本的前置原版模组。

    下载提取码：rjai

这个原版模组怎么用？

    首先安装该原版模组，然后打开游戏，在version计分板的$version假名下存储了当前游玩的minecraft游戏版本，您可以随时调用之
    将该数据包载入后，请输入/reload（需要作弊)。
    版本对应计分板分数对照：

    支持1.13-1.16快照，以后会同步更新（如果我还活着）

这个原版模组有什么用？
从1.13到1.16，命令系统都有一定的改动。为了让我这样的想用一个原版模组适配所有版本的开发者更好地将不同版本的命令糅合到一个原版模组中去，我开发了这个前置。
   如果您和我一样，那么您可以借助它来作为启用适配不同版本的命令模块的判断条件；
   如果您是个正常的原版模组开发者，那么这个原版模组并没有什么用。哦，有可能可以给没有使用正确版本安装数据包的玩家发出警告。仅此而已。
它的原理是什么？
玩家有个nbt是DataVersion，存储着数据版本，可转换为实际版本

旧版本原理：
每个版本都有其命令改动的地方，而这就是用来判断的依据。
   1.13起，新版本的命令系统大多兼容旧版本，因此需要从高版本向低版本探测。
具体地：
因为在同一个函数中，包含不合法的命令会使整个函数失效，所以必须把不同版本的命令分开。
在load函数中：
  1. scoreboard objectives add version dummy
  2. scoreboard players set $version version 0
  3. #1.16
  4. function ver:ver_check/116
  5. #1.15
  6. function ver:ver_check/115
  7. #1.14
  8. function ver:ver_check/114
  9. #1.13-
  10. function ver:ver_check/113
复制代码
最开头的两个命令为初始化，
1.16中：
  1. #1.16
  2. summon minecraft:bat ~ ~ ~ {Tags:["ver"]}
  3. attribute @e[type=bat,limit=1,tag=ver] minecraft:generic.max_health base set 16
  4. execute store result score $version version run data get entity @e[type=bat,limit=1,tag=ver] Attributes[{Name:"minecraft:generic.max_health"}].Base
  5. kill @e[tag=ver]
复制代码
借助/attribute命令，将版本号暂存在实体中，再储存至计分板。
若版本为低版本，则无法储存，下同。
1.15中：
  1. #1.15
  2. execute unless score $version version matches 16.. run data modify storage cam:ver ver set value 15
  3. execute unless score $version version matches 15.. run execute store result score $version version run data get storage cam:ver ver
