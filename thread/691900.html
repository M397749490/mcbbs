◆ 使用方法&指令 ◆
  • 本插件与ScriptBlock并不冲突，若是使用不习惯的话可以两个插件都保留
  • 本插件适用的服务端：CraftBukkit、Spigot、Paper、CatServer及其它基于BukkitAPI的服务端（此处仅列举官宣支持的服务端）
  • 使用本插件之前请安装Vault前置（MC1.8-1.12推荐安装Vault1.5.6，MC1.13-1.15推荐安装Vault1.7.2，点击此处下载Vault）

与ScriptBlock不同的是，本插件的创建/修改脚本方块方法为“先输入指令，再点击相应方块”

小窍门：制作消耗PlayerPoints点券的脚本方块商店
必备原料：ScriptBlockPlus脚本方块，PlayerPoints点券插件，PlaceholderAPI
首先，要下载适合PlaceholderAPI的点券变量拓展包，游戏内输入指令
  • /papi ecloud download playerpoints
  • /papi reload

至此，你便可以任意调用有关点券PlayerPoints的变量了，变量是
  • %playerpoints_points%

回到脚本方块的创建上，假设我们要创建一个“脚本方块商店”，玩家点击脚本方块，就可以花费100点券购买64个钻石，但是，脚本大全里没有关于消耗点券的脚本啊！该怎么办呢？

我们用来创建这个“商店”的方块脚本包括了三个部分：判断部分，扣费部分，给物部分

/sbp interact create [@calc:%playerpoints_points% >= 100 &c点券不够！][@bypass /points take <player> 100][@bypass /give <player> diamond 64]

看懂了没？当玩家的点券不够100时，该脚本会在判断部分拦下，使得脚本执行失败，只有满足100点券的条件，才会继续执行后面的脚本（扣费100点券，获得64个钻石）

小窍门：用红石驱动脚本方块
本特性旨在把脚本方块变成一个真正的“命令方块”，可以使用红石驱动。
安全警告：由于红石有诸多不确定性，例如高频红石的问题等等，因此是否使用本插件这一特性请各位仔细考量。

★★★设置一个脚本方块可以使用红石触发的基本指令是
/sbp <交互方式> redstone true [限制条件] [目标选择]
输入这个指令后点击相关脚本方块即可生效。

★★★[限制条件]是对目标选择玩家条件的进一步限制。基本格式：filter{设置项=值}，可选择的设置项有：
  • op=true/false  触发该方块的玩家是否是OP
  • perm=xxxx  触发该方块的玩家是否有相关权限
  • limit=x  该方块只能被执行的次数
可用英文逗号隔开多个限制条件，例如filter{设置项=值,设置项=值}


★★★[目标选择]指的是该脚本方块针对的目标。
关于[目标选择]这一部分的详细格式请参阅MinecraftWiki命令方块-目标选择器这一部分内容→链接，在这里仅举几个常见的例子。
  • @p→指距离该方块最近的玩家
  • @a→指全部玩家

可以添加更多参数，比如@p[level=30]会选择距离该脚本方块最近的等级大于30的玩家
插件搬运者并非命令方块大神，因此这部分介绍写的不详细，请至Wiki查看更多详细信息


举例：
使用以下指令完成了一个脚本方块制作，即“触发后令玩家suicide”
  • /sbp interact create [@bypass /suicide]

并使用以下指令将其设置为使用红石驱动，由一个陷阱压力板触发
  • /sbp interact redstone true filter{limit=1} @p

如果一个不幸的玩家踩中了这个陷阱压力板，触发了脚本方块，则距离该脚本方块最近的玩家将suicide。
