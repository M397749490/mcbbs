最近，我在这个Yamler插件的一些想法下，写了一个小类然后写进了我的Regions插件（依然在制作中）。这个插件（在早期的版本）就已经发布在我们的俄语社区了。
在一些小的更改下我发现如果把这个类做进 Nukkit，那将是极好的。现在我把它加入了然后你就可以使用这个类。你会发现这个 SimpleConfig 类允许你非常简单的生成配置文件，你依然可以使用旧的 Config 类 - 那里的代码没有被破坏。
然后我要告诉你...

如何使用 SimpleConfig
首先你需要创建你自己的配置类，这个类要继承 SimpleConfig：
  1. package ru.nukkit.regions.config;

  3. import cn.nukkit.plugin.PluginBase;
  4. import cn.nukkit.utils.SimpleConfig;

  6. import java.util.List;

  8. public class RegionsConfig extends SimpleConfig {

  10.     @Path (value = "claim.max-regions-per-player")
  11.     public int maxRegionPerPlayer=5;

  13.     @Path (value = "claim.max-claim-volume")
  14.     public int maxClaimVolume=10000;

  16.     @Path (value = "claim.claim-only-existing-regions")
  17.     public boolean claimOnlyExisting = false;

  19.     @Path (value = "claim.allow-to-claim-another-regions")
  20.     public boolean intersectionsAllowed = false;

  22.     public RegionsConfig(PluginBase plugin) {
  23.         super(plugin);
  24.     }
  25. }
复制代码
然后我们在插件主类的 onEnable 下创建一个类的实例：
  1.     private RegionsConfig cfg;

  3.     @Override
  4.     public void onEnable(){
  5.         // 如果你的jar打包了默认的配置文件，你可以添加 this.saveResource("config.yml");
  6.         this.cfg = new RegionsConfig(this); // 创建配置类
  7.         this.cfg.load(); // 从文件中读取值到配置类
  8.         this.cfg.save(); // 保存配置类中的值到文件
  9.         // 然后可以干其它在 onEnable 中干的事情
  10.     }
复制代码
在 cfg.load() 加载所有配置文件中的项的时候，所有的项目会被绑定到这个类的变量中。如果你需要获得这个变量的值，你可以直接拿出来（不需要 getBoolean，getString 这样麻烦的玩意）：
  1.     player.sendMessage ("You cannot claim more than "+ cfg.maxClaimVolume + " blocks!");
复制代码
如果你需要改变这个类的某个值，直接更改这个变量然后使用方法 save 来保存即可：
  1.     cfg.intersectionsAllowed=true;
  2.     cfg.save();
复制代码
保存后，如果你在插件的配置文件中寻找，你会发现 config.yml 中包含这样的内容：(感谢群友勘误）
  1. claim:
  2.   max-regions-per-player: 5
  3.   max-claim-volume: 10000
  4.   claim-only-existing-regions: false
  5.   allow-to-claim-another-regions: false

就这些了。然后我在这里需要补充一些说明：

说明1: 使用别的文件名
如果你需要使用别的文件名，你需要修改你的配置类的构造函数。看下面的例子：
  1. public RegionsConfig(PluginBase plugin) {
  2.         super(plugin,"data.yml");
  3.     }
复制代码

这个类依然在插件的数据文件夹保存配置文件，但保存的是 data.yml 而不是 config.yml。

说明2: 关于 @Path 注解
这个注解定义的是配置文件中这个值的键名。如果没有这个注解，SimpleConfig 将会使用变量的名字作为键名（名字中 "_" 会被替换成 "."）。所以以下的两段代码保存的文件是一样的：
  1.     @Path (value = "claim.volume")
  2.     public int maxClaimVolume=10000;
复制代码
  1.     public int claim_volume=10000;
复制代码

说明3: 关于类型
SimpleConfig 配置类会自动适配数据的类型。也就是说，如果你在配置文件中这么写：
  1. claim:
  2.   max-regions-per-player: 5
复制代码
这时候claim.max-regions-per-player类型应该为int。如果在配置类中写成了String：
  1.     @Path (value = "claim.max-regions-per-player")
  2.     public String maxRegionPerPlayer;
复制代码
那么在读取后这个变量的值会自动适配成字符串"5"，而不会报错。
