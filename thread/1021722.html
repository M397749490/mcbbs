WARN: Establishing SSL connection without server's identity verification is not recommended. According to MySQL 5.5.45+, 5.6.26+ and 5.7.6+ requirements SSL connection must be established by default if explicit option isn't set. For compliance with existing applications not using SSL the verifyServerCertificate property is set to 'false'. You need either to explicitly disable SSL by setting useSSL=false, or set useSSL=true and provide truststore for server certificate verification.

以上文字，各位新手服主再使用MySQL数据库时候，可能都会遇到。根据官方文章和前辈的指导，我们知道，在构建连接语句时候要在语句中添加“useSSL=false”来解决。那么形如“jdbc:mysql://127.0.0.1:3306/base”的连接语句添加后就编程了
“jdbc:mysql://127.0.0.1:3306/base?useSSL=false”
其实今天文本并不是教大家这些。
如果你看到下面这种数据库配置，你是否还会添加呢？
data:
  address: 127.0.0.1:3306
  database: base
  username: root
  password: root

你可能问过一些前辈，这种数据库配置，怎么办？他们也许会回答你。这样配置没办法。
那么，今天的重点来了。我今天就来教你如何在这样的配置文件中进行添加。


首先，我们来对比这两种连接方式
第一种，使用的是连接语句。构造为 连接协议+地址+端口+数据库
第二种，使用的是配置信息。
其实，不管是哪种方式，在与数据库通信时候，均采用的是第一种类似网址的代码。
也就是说，使用第二种配置方式的插件，只不过将同参数，单独拿出来，然后后台构造成连接语句的。
我们同样也可以利用这种方式添加“useSSL=false”，
说到这里，你是不是想到答案了？
没错，就是在数据库配置中直接添加"?useSSL=false"就行了。
data:
address: 127.0.0.1:3306
database: base?useSSL=false
username: root
password: root


重启插件试一试？怎么样？如果好用，给个回应可好？


如果上面方法造成数据库无法连接点开下面
试试在后面添加“&”符号。
本人测试过，MultiInv插件可行。又或者试试加单引号或者双引号。
