1.2  编程语言简史&java简史

语言简史
既然我们要学习java,那什么是java呢？
那就要从编程语言的历史说起了

第一代语言就是传说中的打孔机了，相信大家都应该知道吧。
那么问题就来了：你给我一排孔，叫我拿来编程，你这是在逗我么？

于是人们就发明了真正意义上的编程语言，也就是第二代语言-汇编了。这是第一代编程猿主要使用的语言，也可以理解为cpu指令集。

可是问题又来了，每个cpu都有它自己的指令集，那我岂不是每个cpu都要定制一个系统了吗？另外，这些汇编语句都是最底层的，涉及到了很多cpu的底层原理。要用它来写一个大游戏，你先去准备一车键盘~

于是第三代语言就是现在的主流语言就出现了，一般是划分为面向过程和面向对象两种。面向过程跟汇编有些类似，就是一句一句命令来写。面向对象则是对现实的一种抽象。比如你写个开车的程序，用面向过程思维就是打火、挂挡、踩油门…；而面向对象思维就是：有一辆车，这辆车有什么属性（贵的破的长的矮的等）可以做什么（可以跑、可以停、可以锁等）

很明显，每一代都是朝着更接近自然语言(人话)的方向发展。而面向对象的思维比起面向过程更接近人的思维。
那第四代语言呢？现在大多数人认为就是像目前功能最强大的数据查询语言SQL一样的语言–你只要告诉它你要什么，无须告诉它怎么做，它就能把答案给你，但第四代语言仍处于起步阶段==

而java的定位就是面向对象语言，而且是纯的面向对象。（c++和c#这些都不是）

1.4 Java三件套&JDK的安装与配置


Java三件套
上节课我们粗略地讲了Java的语言特点和基本体系。这节课我们先来看Java的三件套。首先二话不说就贴图↓ （自己做的图有点毁三观）



没错，就是它！
JDK（JavaDevelopment Kit JAVA开发工具包）涵盖了JRE和一些java开发的工具。
JRE（Java Runtime Environment JAVA运行时系统）涵盖了JVM和一些必要的库（不是裤）。
JVM（Java Virtual Machine JAVA虚拟机）是Java的一种核心机制，下一节我们会详细讲解。
开发Java程序就必须要有这JDK,但运行普通的java程序只要JRE就够了。（玩我的世界装的一般就是JRE。）


JDK的安装既然我们要写程序那么装的肯定是JDK。首先把JDK下载下来,地址：

小D java基础系列1.5 Java的两大核心机制

如果没有意外的话，这应该是这一章的最后一节。
上一节我们初步了解JDK、JRE和JVM的作用和它们之间的关系。这节课我们再继续学习Java的两大核心机制—Java虚拟机（也就是JVM了）和自动内存回收


Java虚拟机

前面我们提及到了Java是一种与平台无关的语言。那什么是平台呢，你可以粗略地理解它为一个系统如Windows平台、Linux平台。（但严格来说就不能这样理解）。当然Java也可以理解为一个平台。与平台无关说白了就是跨平台，比如说一程序编译完后不修改，放Windows系统里能跑，放Android里能跑，放Mac OS里也能跑，这就叫跨平台。实际上，MC虽然在不同系统里启动的方法不一样，但所有启动器归根到底就是把核心Jar给启动了，而核心Jar在各个系统里是可以通用的(不信你可以把你的MC核心换一个同版本的不同系统的核心试试)。而这个跨平台的特性正是Java虚拟机机制所带来的。


根据这种图就能很好的理解了。
就好比如你去参加一个国际舞会，里面说什么的都有，就是没有说汉语的，运气就是这么好，你
就只会说汉语，你该怎么办？
其实办法很简单，请个翻译不就得了？那么问题又来了，你又想和所有人都能交谈无阻，怎么办？那就请个啥都会说的翻译呗—JVM就是那个啥都会说的翻译。
我们来看看Java从写代码到运行的全过程：
首先，我们要先把代码写到一个后缀为java的文本文档里（相当于你说的汉语），然后告诉翻译，然后这个翻译会先把你说的汉语翻译为所有翻译都听得懂的英语，就相当于编译了。编译出来的.class文件就是所有翻译员通用的英语了。然后，见到法国人法国人的翻译把英语翻译为法语，见到德国人德国人的翻译就把英语翻译为德语……
单在执行的过程中，JVM究竟是如何转换为各个系统的程序的呢？
其实，每一个支持Java平台都会有一个自己的JVM,它们在自己的平台里各自为政，但是它们之间有着一种共同语言—-就是class字节码文件。
比如说我在Windows下写了一个服务器插件，然后把它编译成.class文件（事实上还把class文件集中在以前打包起来就变成了.jar文件）。我先在Windows下进行测试，这时我电脑里的JVM For Windows 就把class文件转换为Windows程序来运行。测试完后，我吧插件发布了出去。一服主张三很喜欢我的插件，于是就把我的插件放进了他在Linux系统下的服务器，此时他的服务器里的JVM for Linux会吧.class文件转换为Linux程序在运行。
注：在实际操作中，每一个java程序都会启动一个JVM,并由JVM根据class里的命令代替我的程序执行
GC内存回收机制
在c++等语言中，程序申请完内存后要手动回收内存空间，如果写的时候一不小心出错了，轻则导致内存占用过多或内存溢出程序奔溃，重则导致系统蹦馈。针对此问题，Java引用了GC内存自动回收机制，也就是在java编程中我们只管申请变量不需要手动回收，而是java虚拟机自动为你回收（当然可以手动催促回收某个对象）。 贴图↓
