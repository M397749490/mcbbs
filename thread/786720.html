Authme与Flarum互联

什么是Flarum:
    Flarum是一个新生代的PHP论坛系统 以简洁 轻量闻名,本贴将带您跳进无法自拔的深坑(不
    您可以查看几个使用Flarum论坛系统搭建的站点
    [Flarum官方] [Flarum中文] [阳光之城社区] [喵窝社区] [毛线社区]
需要准备的材料:
  • Notepad++
  • Authme或支持Bcrypt加密算法的登陆插件
  • 一个支持外网访问的Flarum数据库
开始动手:
    Flarum是使用的PHP的Bcrypt加密算法，非常巧，Authme恰恰也支持这个算法，现在 让我们开始编辑Authme的配置文件
   将Authme配置文件(config.yml)改为如下内容 请不要复制粘贴:
第一部分:
  1. DataSource:
  2.     # What type of database do you want to use?
  3.     # Valid values: SQLITE, MYSQL
  4.     backend: 'mysql' #这里我们选择mysql
  5.     # Enable database caching, should improve database performance
  6.     caching: false #设置为false 不使用数据库缓存机制
  7.     # Database host address
  8.     mySQLHost: '123.123.123.123' #这里改成你自己的数据库服务器IP地址 必须支持外网访问
  9.     # Database port
  10.     mySQLPort: '23333' #这里改成你自己的数据库服务器端口
  11.     # Connect to MySQL database over SSL
  12.     mySQLUseSSL: false #如果你的数据库支持SSL安全链接 可以打开
  13.     # Username to connect to the MySQL database
  14.     mySQLUsername: 'root' #这里是你的数据库的用户名 必须拥有访问Flarum数据库的权限
  15.     # Password to connect to the MySQL database
  16.     mySQLPassword: '12345678' #数据库密码
  17.     # Database Name, use with converters or as SQLITE database name
  18.     mySQLDatabase: 'flarum' #这个是你安装Flarum的数据库的数据库名
  19.     # Table of the database
  20.     mySQLTablename: 'flarum_users' #默认flarum_users
  21.     # Column of IDs to sort data
  22.     mySQLColumnId: 'id' #我们使用id作为索引列 这也是Flarum默认值
  23.     # Column for storing or checking players nickname
  24.     mySQLColumnName: 'username' #识别玩家的名称的列 默认username
  25.     # Column for storing or checking players RealName
  26.     mySQLRealName: 'username' #Flarum不存在昵称这种东西 所以也用username就好了

第二部分:
  1. ExternalBoardOptions:
  2.     # Column for storing players passwords salts
  3.     mySQLColumnSalt: '' #保持为空
  4.     # Column for storing players groups
  5.     mySQLColumnGroup: '' #保持为空
  6.     # -1 means disabled. If you want that only activated players
  7.     # can log into your server, you can set here the group number
  8.     # of unactivated users, needed for some forum/CMS support
  9.     nonActivedUserGroup: -1 #设置为-1
  10.     # Other MySQL columns where we need to put the username (case-sensitive)
  11.     mySQLOtherUsernameColumns: [] #保持默认
  12.     # How much log2 rounds needed in BCrypt (do not change if you do not know what it does)
  13.     bCryptLog2Round: 10 #这里一定要设置为10
  14.     # phpBB table prefix defined during the phpBB installation process
  15.     phpbbTablePrefix: 'phpbb_'#保持默认
  16.     # phpBB activated group ID; 2 is the default registered group defined by phpBB
  17.     phpbbActivatedGroupId: 2 #保持默认
  18.     # IP Board table prefix defined during the IP Board installation process
  19.     IPBTablePrefix: 'ipb_' #保持默认
  20.     # IP Board default group ID; 3 is the default registered group defined by IP Board
  21.     IPBActivatedGroupId: 3 #保持默认
  22.     # XenForo default group ID; 2 is the default registered group defined by Xenforo
  23.     XFActivatedGroupId: 2 #保持默认
  24.     # Wordpress prefix defined during WordPress installation
  25.     wordpressTablePrefix: 'wp_' #保持默认

第三部分:
  1. security:
  2.         # Minimum length of password
  3.         minPasswordLength: 5 #设为5
  4.         # Maximum length of password
  5.         passwordMaxLength: 30 #设为30
  6.         # Possible values: SHA256, BCRYPT, BCRYPT2Y, PBKDF2, SALTEDSHA512, WHIRLPOOL,
  7.         # MYBB, IPB3, PHPBB, PHPFUSION, SMF, XENFORO, XAUTH, JOOMLA, WBB3, WBB4, MD5VB,
  8.         # PBKDF2DJANGO, WORDPRESS, ROYALAUTH, CUSTOM (for developers only). See full list at
  9.         # https://github.com/AuthMe/AuthMeReloaded/blob/master/docs/hash_algorithms.md
  10.         passwordHash: 'BCRYPT' #这里一定要设置为BCRYPT
  11.         # If a password check fails, AuthMe will also try to check with the following hash methods.
  12.         # Use this setting when you change from one hash method to another.
  13.         # AuthMe will update the password to the new hash. Example:
  14.         # legacyHashes:
  15.         # - 'SHA1'
  16.         legacyHashes: []
  17.         # Salt length for the SALTED2MD5 MD5(MD5(password)+salt)
  18.         doubleMD5SaltLength: 1 #保持默认
  19.         # Number of rounds to use if passwordHash is set to PBKDF2. Default is 10000
  20.         pbkdf2Rounds: 10000 #保持默认
  21.         # Prevent unsafe passwords from being used; put them in lowercase!
  22.         # You should always set 'help' as unsafePassword due to possible conflicts.
  23.         # unsafePasswords:
  24.         # - '123456'
  25.         # - 'password'
  26.         # - 'help'
  27.         unsafePasswords:
  28.         - '123456'
  29.         - 'password'
  30.         - 'qwerty'
  31.         - '12345'
  32.         - '54321'
  33.         - '123456789'
  34.         - 'help'
复制代码
     现在，你的Authme已与Flarum连接
     如需关闭注册请按以下步骤禁用注册功能:
  1. registration:
  2.         # Enable registration on the server?
  3.         enabled: false #设置为false
  4.         # Send every X seconds a message to a player to
  5.         # remind him that he has to login/register
  6.         messageInterval: 5
  7.         # Only registered and logged in players can play.
  8.         # See restrictions for exceptions
  9.         force: true #设置为true
  10.         # Type of registration: PASSWORD or EMAIL
  11.         # PASSWORD = account is registered with a password supplied by the user;
  12.         # EMAIL = password is generated and sent to the email provided by the user.
  13.         # More info at https://github.com/AuthMe/AuthMeReloaded/wiki/Registration
  14.         type: 'PASSWORD'
  15.         # Second argument the /register command should take: NONE = no 2nd argument
  16.         # CONFIRMATION = must repeat first argument (pass or email)
  17.         # EMAIL_OPTIONAL = for password register: 2nd argument can be empty or have email address
  18.         # EMAIL_MANDATORY = for password register: 2nd argument MUST be an email address
  19.         secondArg: 'CONFIRMATION'
  20.         # Do we force kick a player after a successful registration?
  21.         # Do not use with login feature below
  22.         forceKickAfterRegister: false
  23.         # Does AuthMe need to enforce a /login after a successful registration?
  24.         forceLoginAfterRegister: false
