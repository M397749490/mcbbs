一想到低版本没有生物保护，于是我去外站找了一个协助保护动物的插件

但我不死心   仔qiang细xing阅fan读yi了英文说明后装上去试了试

如插件说明中写了：
butcher = Animal Protection.
哦。。。这个应该是动物保护的权限节点吧。

于是我游戏内:
/res set butcher false

然后【领地插件】提示我没有权限
excuse me???
我是op权限哎？？？
于是我使用
/resadmin set butcher false
结果成功了！动物也确实可以被正常保护了

那么说明这个resprotect插件提供的支持其实是有效的，但我又不可能让玩家去使用resadmin命令
于是我就想，到底是什么原因造成了即使是OP权限也无法操作这个权限节点呢？
我忽然想到了提示我权限不足的是【领地插件】
于是我去领地的config，看到以下字眼

    # This gives permission to change certain flags to all groups, unless specifically denied to the group.
    FlagPermission:
        move: true
        build: true
        place: true
        destroy: true
.....

以及

    # These are default flags applied to all residences from any user group.
    ResidenceDefault:
        build: false
        use: false
        container: false
        pvp: false
        tnt: false
        creeper: false
        flow: false
        piston: false
        ignite: false
        firespread: false
    # These are default flags applied to the residence creator of any group.
    CreatorDefault:
        build: true
        move: true
        use: true
        ignite: true
        container: true
....

也就是说领地插件其实为每一个权限节点提供了一个独立的控制选项
通过配置config.yml可以实现
1.玩家对特定权限节点的操作权限
2.领地默认是否允许该权限（行为）    如在ResidenceDefault:   中build:false 则说明领地被建立后就不允许任何人对领地内的方块进行操作
3.那么领地主人呢？  CreatorDefault里面就指定了主人默认拥有的权限，比如build   
也就是说
1.Flagpermission中 build:true 说明玩家可以对领地的build权限进行true或者false的设定
2.领地的build权限默认是禁止的
3.领地主人拥有build权限

于是我在这些项目里面添加了

如FlagPermission里
butcher: true     (允许玩家编辑butcher权限)
ResidenceDefault 中
butcher:false    (玩家默认没有butcher权限)
CreatorDefault中
butcher:true    (主人拥有butcher权限)

到此，第一个问题就解决了。
