  • tab补全命令

制作一个菜单
打开menus.yml文件,这是菜单文件，所有菜单都可以添加在里面。
你需要了解菜单添加的格式与图标格式,动作,条件。我在这里放出菜单的添加格式
  1. menus:
  2.   #每添加一个菜单需要在menus的子配置下,比如这个主菜单
  3.   #是空了2格的和主菜单一样以此类推在menus下面添加即可
  4.   #这是菜单的id
  5.   主菜单:
  6.     # 设置打开菜单的命令
  7.     commands:
  8.       - '主菜单'
  9.     # 图标之间的距离
  10.     distances:
  11.       x1: 4
  12.       x2: 2
  13.       x4: 2
  14.       x5: 4
  15.     # 打开菜单时触发
  16.     open-actions:
  17.       # 打开菜单的条件
  18.       requirements:
  19.         # 权限条件。可删除
  20.         permissions:
  21.           fallback: '&c&l打开该菜单需要(%permissions%)权限'
  22.           value:
  23.             - 'tdg.open.example'
  24.         # 经济条件，支持 Vault 和 Economy插件。可删除
  25.         money:
  26.           fallback: '&c你没有足够的钱来打开菜单，你需要 (%money%)元打开该菜单'
  27.           value: 1000
  28.         # 冷却时间
  29.         cooldown:
  30.           fallback: '&c你不能在 %cooldown%秒内多次打开菜单'
  31.           value: 10
  32.       # 需要Vault 或 Economy 插件
  33.       # 来扣除玩家的钱
  34.       take-money-action:
  35.         action: TAKE_MONEY
  36.         value: 1000
  37.       # 发出音效
  38.       sound-action-1:
  39.         requirements:
  40.           #权限控制
  41.           perms:
  42.             - 'tdg.openeffect'
  43.         action: SOUND
  44.         value: 'ENTITY_ENDERMAN_TELEPORT'
  45.         volume: 1.0
  46.         pitch: 0
  47.       # 打开菜单发送消息
  48.       message-action-1:
  49.         action: MESSAGE
  50.         value:
  51.           - '&6你打开了菜单'
  52.     # 关闭菜单触发
  53.     close-actions:
  54.       # 控制台执行命令
  55.       command-action-1:
  56.         action: COMMANDS
  57.         #如果开启，将是作为玩家执行命令
  58.         as-player: false
  59.         value:
  60.           - 'give %player_name% apple 1'
  61.       # 粒子效果
  62.       particle-action-1:
  63.         action: PARTICLES
  64.         #类型
  65.         value: 'cloud'
  66.         #数量
  67.         amount: 10
  68.         #速度
  69.         speed: 1

图标和菜单的子配置项介绍

每个菜单和图标下都有子配置项，来运行这个菜单和图标按钮

这是菜单配置下的子配置项介绍
  1.   #打开菜单的动作项
  2.   open-actions:
  3.   #打开菜单可以设置打开菜单的需求条件
  4.   #有以下条件和动作
  5.     requirements: #(这是条件项目集)
  6.       permissions: #(这是权限条件)，有很多条件我会在下面列举出来
  7.         #这里我会将条件的基本格式用权限条件为基础介绍出来
  8.         #以免各位不明白这是什么意思，
  9.         #
  10.         #这是条件不足所提示的消息
  11.         #%permissions%是所需权限的变量
  12.         #目前条件变量有许多,我会在下面列举出来
  13.         fallback: '&c&l打开该菜单需要(%permissions%)权限'
  14.         #这是条件的需求例如我的条件是money
  15.         #检测钱,那么我就要写成 value: 1000(检测是否拥有1000)
  16.         #这只是数值的介绍，这个权限可以添加多个，可以用
  17.         #value:
  18.         #  -'权限1'
  19.         #  -'权限2'        
  20.         value:
  21.           - 'tdg.open.example'

  23.         fallback: '&c你没有足够的钱来打开菜单，你需要 (%money%)元打开该菜单'
  24.         value: 1000
  25.       cooldown:
  26.         fallback: '&c你不能在 %cooldown%秒内多次打开菜单'
  27.         value: 10
  28.     #接下来介绍的是动作，打开菜单时的动作
  29.     #添加需要在open-actions:的下面空2格写
  30.     #这是动作id,可以随便写不是固定的
  31.     #只需要修改下面的action就可以
  32.     take-money-action:
  33.       #动作类型（动作类型有很多，我会在下面列举出来)

  36.       value: 1000
  37.     #这是带有条件的动作,在动作内也可以添加条件来判断
  38.     #下面的是判断文件是否有tdg.openeffect条件
  39.     #如果有就执行 SOUND音效动作
  40.     sound-action-1:

  53.   # 这需要对其open-actions:
  54.   # 这属于菜单下的动作，id是固定的
  55.   # 在菜单id下空2格添加
  56.   # close-actions是关闭菜单动作
  57.   close-actions:
  58.       # 控制台执行命令动作
  59.       # id可以随意填,子动作id都可以随便写
  60.       # 只要修改action就可以
