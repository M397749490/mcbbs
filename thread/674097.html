如何向核心中插入自己的事件 - 以PlayerOPEvent举例

这不是基础教程，函数详细用法参考百度，这里只提供思路和源码

我们知道Bukkit在添加用户为OP的时候是没有对应事件给插件的，这可不方便管理，所以我们自己给他加一个

本文涉及如下内容 :
JavaAgent -  如果知道是啥就不用点开了


javaagent的主要功能如下：
  • 可以在加载class文件之前做拦截，对字节码做修改
  • 可以在运行期对已加载类的字节码做变更，但是这种情况下会有很多的限制，后面会详细说
  • 还有其他一些小众的功能
    • 获取所有已经加载过的类
    • 获取所有已经初始化过的类（执行过clinit方法，是上面的一个子集）
    • 获取某个对象的大小
    • 将某个jar加入到bootstrap classpath里作为高优先级被bootstrapClassloader加载
    • 将某个jar加入到classpath里供AppClassloard去加载
    • 设置某些native方法的前缀，主要在查找native方法的时候做规则匹配



Javassist -  如果知道是啥就不用点开了

Javassist是一个开源的分析、编辑和创建Java字节码的类库。是由东京工业大学的数学和计算机科学系的 Shigeru Chiba 所创建的。它已加入了开放源代码JBoss 应用服务器项目,通过使用Javassist对字节码操作为JBoss实现动态"AOP"框架。

Step 2 - 构建我们自己的PlayerList

目标 - 在真正进行添加OP操作前进行判断
先上代码，再解释功能，函数功能请查看JavaDoc
  1. public class ABDClassPatcher {
  2.     private ClassPool pool;
  3.     public ABDClassPatcher(){
  4.         try {
  5.             pool = ClassPool.getDefault();
  6.             pool.appendClassPath(ABDClassHelper.getJarFilePathFromClass(ABDClassHelper.getCraftClassAsName("PlayerList",false)));
  7.             pool.appendClassPath(ABDClassHelper.getJarFilePathFromClass(this.getClass()));
  8.         } catch (NotFoundException e) {
  9.             e.printStackTrace();
  10.         }
  11.     }
  12.    
  13.     public byte[] PatchPlayerList(){
  14.         try {
  15.             CtClass classplayerlist = pool.get(ABDClassHelper.getCraftClassAsName("PlayerList",false));
  16.             CtMethod addopmenthod = classplayerlist.getDeclaredMethod("addOp");
  17.             addopmenthod.insertBefore("{com.verofess.abdapi.patcher.SetOpPatcher#CallEvent($1);}");
  18.             return classplayerlist.toBytecode();
  19.         } catch (NotFoundException | CannotCompileException | IOException e) {
  20.             e.printStackTrace();
  21.             return new byte[0];
  22.         }
  23.     }
  24. }
复制代码
这是我之前发布的某个插件中的源码，
在构造函数中向ClassPool中添加了核心和自身的路径，
PatchPlayerList()大概的意思就是向addOP()的前面插入了一行

com.verofess.abdapi.patcher.SetOpPatcher#CallEvent($1);

那么SetOpPatcher的内容是什么呢？
  1. public class  SetOpPatcher {
  2.     static public void CallEvent(GameProfile gp){
  3.         Player player = Bukkit.getServer().getPlayer(gp.getId());
  4.         StackTraceElement stack[] = Thread.currentThread().getStackTrace();  
  5.         if(ABDClassHelper.isFromPlugins(stack)){
  6.             PlayerSetOPEvent event = new PlayerSetOPEvent(player);
  7.             Bukkit.getServer().getPluginManager().callEvent(event);
  8.         }
  9.     }
  10. }

判断了一下这个事件是不是来自插件的，如果是就new 一个PlayerSetOPEvent()出来


getCraftClassAsName是用来取类名的，不用管它


step - 3  替换原始的PlayerList

我们为了完成替换，应当在原始的PlayerList类加载前对其进行处理
所以只需要实现JavaAgent的premain就好，代码如下

  1. public class ABDAgent {
  2.     private static String Ver;
  3.     public static void premain(String agentArgs, Instrumentation inst){
  4.         Ver = agentArgs;
  5.         ABDClassPatcher patcher = new ABDClassPatcher();
  6.         try {
  7.             inst.redefineClasses(new ClassDefinition(Class.forName(ABDClassHelper.getCraftClassAsName("PlayerList",false)),patcher.PatchPlayerList()));
  8.         } catch (ClassNotFoundException | UnmodifiableClassException e) {
  9.             e.printStackTrace();
  10.         }
  11.     }
  12.     public static String getVer() {
  13.         return Ver;
  14.     }
  15. }
复制代码
这里就是调用了刚才的函数对PlayerList类进行了重定义，为了让java知道我们要用这个功能，还需要修改下MANIFEST.MF文件
  1. Manifest-Version: 1.0
  2. Premain-Class: com.verofess.abdapi.ABDAgent
  3. Can-Redefine-Classes: true
