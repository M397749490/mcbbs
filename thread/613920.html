插件简介

CustomGo是一款非常自由的自定义房间插件,其最大的特点就是能够为你的服务器提供任意自定义的房间。而这个房间可以是是RPG副本,小游戏,竞技场,以及你想象力触及的一切。本插件自定义程度十——分——高,插件内带有40+个任务、30+个触发器、条件、流程控制语句等，完全足够让你能做到以下功能:

1.小游戏：能够设置陷阱|宝箱|各种各样的通过条件！
2.PVP：由你来决定战斗规则，时间，装备，特殊效果...等等一切！
3.RPG：小队挑战副本设定的精度高达到每一个房间的每一个环节的每一个指定的怪物!
4.使用附属插件SpRoom，完成独立副本效果（让玩家同步游戏互不干扰，告别密室副本）！

配置&教程（简略版）

安装:
将插件直接丢入plugins重启服务器即可
如需安装插件内自带新手教程，请在安装插件后输入 /fw teach

文件:
itemtask———— "物品执行器"文件夹(相当于就是放入玩家手里的脚本触发器)
lobby————"游戏房间"文件夹(副本/小游戏整体的文件夹,存放所有房间的配置！)
sign ————"告示牌"文件夹（游戏告示牌的文件夹...你可以在游戏内配置，所以不用动~）


Data.yml ————储存插件数据（不了解插件者无需动它）
Option.yml————插件基本配置（插件基础配置，基本没有2333）

基础概念：
配置文件内容:
在插件附件中带有配置文件示例。lobby文件夹内就是所有游戏房间。
文件夹名即为游戏名字(即/fw xx join中XX填写内容)，
而游戏文件夹里每个配置文件即为游戏中的队列名。

声明，游戏房间 与 队列 的关系：
游戏内的队列是游戏内容的核心，而游戏文件夹能够起到代理加入作用。
就如同：PVP是一个用来加入游戏，但真正打起来的是红蓝两队！


读取你的游戏：
在后台启动插件时，可以看到队列读取情况。
在修改队列配置后，可以使用/fw XX load或/fw reload进行读取。
如果读取成功，在输入/fw list时，该名字是绿色的(失败是红色)。
当然，读取成功就意味着可以加入了~
另外，输入/fw xx statu可看到一个游戏的状态哦

itemtask物品执行器:
物品执行器能让你在游戏中右键指定物品达到特殊目的。
你可以让给予的指定物品无法在背包里移动，让它成为一个"菜单按钮"！

只需要适当的编辑，不同队列可以是游戏中的不同阵营/不同房间等。

CustomGO详细教程
指令
管理员指令：
/fw help                            插件帮助
/fw reload                         重载插件（自动结束所有游戏）
/fw list                              列出所有游戏
/fw <游戏名> statu           查看游戏状态
/fw <游戏名> load             加载游戏文件/重载游戏
/fw <游戏名> unload         卸载游戏
/fw give <Task物品名>      获得一个编辑好的Task物品(ItemTask)
/fw give <Task物品名> <玩家>  给予玩家一个编辑好的Task物品

/fw leave <玩家>              使玩家离开当前所在游戏
/fw <游戏名> join <玩家>    使一个玩家加入一个游戏


玩家指令：
/fw leave                          离开当前所在游戏
/fw <游戏名> join              加入一个游戏

权限
-管理员权限
fw.admin               插件所有权

-玩家权限：
fw.join.<游戏>       加入指定游戏权限
fw.leave.<游戏>     退出指定游戏权限

PAPI变量
%fw游戏名_playeramount%       当前游戏内人数(无论玩家在哪个队列)
%fw游戏名_statu%                    当前游戏状态(等待中/游戏中)
%fw游戏名_minplayer%             游戏的最小人数
%fw游戏名_maxplayer%            游戏的最大人数

强大的任务（由于任务过多，这里仅列举部分主要的）
任务是一种特殊的插件内部逐条进行的命令格式，就像在MC中使用指令与命令方块一样发挥极其强大的效果！

统一格式：  <命令>{<参数>}  <目标>    其中<目标>在下文目标指代器会进行详细介绍。

一. 玩家互动类：
command{指令}  <目标>
令目标无视权限执行指令。(指令无需带"/")

consolecommand{指令}  <目标>
令后台执行指令(这里<目标>仅用于获取<striker>相关变量)。(指令无需带"/")

damage{伤害量}  <目标>
对目标造成一定量伤害。

heal{治疗量}  <目标>
给目标回复一定量生命值。

say{一段话}  <目标>
让目标在聊天栏说一段话。

teleport{x,y,z,world}  <目标>
将目标传送到指定地点。

spawnmob{MM怪物ID,数量,x,y,z,世界名}
在指定位置生成MythicMobs的怪物。


二. 消息提示类：

title{标题,副标题}  <目标>
给目标发送3秒标题。（注意，必须1.8.1+才能使用，1.8或以下都无法使用。）

notice消息提示系列

    notice{消息}
    给本队列内的玩家发送一个消息，出现在聊天栏。

   globalnotice{消息}
    给全游戏中的玩家发送一个消息，出现在聊天栏。

    tell{文本}  <目标>
    给目标发送一个消息，出现在聊天栏。
   tell{xx} @a 与notice{xx} 效果一样，tell{xx} @e 与globalnotice{xx} 效果一样。


三. 流程控制类：
delay{延迟时间}
以tick为单位(20tick=1秒)。令执行器等待一段时间再往下执行。

end{判断器}  <目标>  或  end{ }
直接结束本次Task任务进程，无论进行到了哪里。
如果有判断器，判断器为<否>则跳过本命令。其中<目标>会作为判断器的触发者。
(注：判断器在下文会有专门的介绍。)

goto{标记名,判断器}  <目标>   或   goto{标记}
  以及对应的mark{标记名}
你可以在Task的任何地方用 mark{标记名} 在Task内做一个标记。
标记后用goto{标记名} 则可以跳跃到task内指定的标记继续执行（可以往回跳）！
如果有判断器，判断器为<否>则跳过本命令。其中<目标>会作为判断器的触发者。
(注：判断器在下文会有专门的介绍。)

skip{行数,判断器}  <目标>
如果满足条件判断，让Task执行时往下跳过<行数>行Task继续执行。
如果有判断器，<目标>会作为判断器的触发者。

respond响应器系列

    respond{触发密码}  <目标>
   respond{触发密码,判断器}  <目标>

    globalrespond{触发密码}  <目标>
    globalrespond{触发密码,判断器}  <目标>

    对外发送一个密码。所有对应密码的Respond触发器(详情看触发器教程)将被触发。
    若用respond，密码会发送到队列内。若用globalrespond，密码会发送到全游戏。

    其中<目标>会被传递到Respond触发器中作为触发器的触发者。
    如果有判断器，<目标>也会作为判断器(在下文会有专门的介绍)的触发者。


四. 数据处理类：

value 变量系列 (注意，所有value必须为数字！)

    playervalue{变量名,值}  <目标>
    给一个玩家的一个队列变量赋值。该玩家变量在队列内通用。

    globalplayervalue{变量名,值}  <目标>
    给一个玩家的一个游戏变量赋值。该变量在全游戏中通用。

    value{变量名,值}
    给一个队列变量赋值。该变量在队列内通用。

    globalvalue{变量名,值}
    给一个队列变量赋值。该变量在在全游戏中通用。


五. 队列控制类：

divide{队列1,队列2,队列3.....}
令当前队列内所有玩家平均分配到每一个填写的队列。
可以填写相同队列以做到按比例分配，
例如divide{A,B,B,B}可以使玩家大致按照1:3的比例分到A,B两个队列。

join{队列名} <目标>
令一个玩家从当前队列跳转到 本游戏的其他的队列。
跳转时不触发原队列的任何离开触发器，不受到任何新队列的加入限制（除了满人）。

leave{参数}  <目标>
令目标离开队列。效果等同于执行一次指令/fw leave。

stopgame{}
清空游戏内玩家，结束本场游戏。
结束一场游戏有两种方法：1.队列内已经没有玩家。2.在任何地方执行了stopgame{}。

taskitem{物品执行器名}  <目标>  或  taskitem{物品执行器名,位置}  <目标>
给予目标一个物品执行器，直接放入它的背包。
如果填写了位置(0-35)，该ItemTask会强制发送到玩家背包该位置，若该位置原来有东西将被自动放到其他空格，若背包已满则会销毁原有物品。
如果未填位置或填写数字无效，物品将自动找空格发送给玩家，如果背包已满将取消发送。
(注:这里的物品执行器名，是文件的名字！)



补充-上文提到的判断器：
判断器会在goto{}，end{}，respond{}等这些流程性Task中有特别作用。
如果判断器的判断结果是<否>，则该流程Task不会执行。
判断过程可以使用玩家类变量,代指玩家名字。
A=B            判断是否相等。
A!=B           判断是否不等。
ABIGB          判断A是否大于B（需要是两个数字）
ASMALLB        判断A是否小于B（需要是两个数字）



流程控制器
当前版本所有TaskController：
标签含义：
[含触发者]       - 在这个Task中可以使用@p,<striker>等指向触发者的变量。
[限非自由加入]   - 这个TaskController仅能在非自由加入队列中使用，否则失效。
[含变量]        - 这个TaskController会有一个括号后缀，内含一个变量辅助判定。


onGroupStart
[限非自由加入
在队列开始(即等待结束)时执行。

onPlayerJoin
[含触发者]
在一名玩家加入队伍时执行。

onPlayerLeave
[含触发者
在一名玩家离开队伍时执行。

onPlayerRest(剩余数量)
[含变量] [限非自由加入
在队伍中仅剩余一定玩家时执行。
如果是onPlayerRest(0) 可以直接等价为"当队列结束时执行"。

onEverySecond
在游戏进行中每秒执行一次。

onTimePast(剩余时间)
[含变量] [限非自由加入
在游戏时间剩余一定秒数时执行。

onLobbyTimePast(剩余时间)
[含变量] [限非自由加入
在等待厅中，等待时间剩余一定秒数时执行。

onPlayerEnough
[限非自由加入
在等待厅时，玩家达到最大人数时触发。

onGroupLoaded
当一个队伍加载时执行。
如果不进行额外重载，则在服务器启动时(启动时加载插件)执行。
一般地，这个执行器用于初始化队列，例如调用一下enabletrigger{all}。



触发器介绍（由于触发器过多，这里仅列举部分主要的）
触发器是插件监听游戏过程并执行对应任务的功能哦！有了它，游戏才能变得无比丰富~

BreakBlock

                           例如：|[dcal=<playeramount>*3]|   代指玩家数量的三倍
                          运算符号：
                              +-*/        四则运算
                              a^b        次方运算(a的b次方)

                               ln[a]       对数运算

                          + reward  (+数字)                设置该强退条件触发时的金钱奖励。
    pickupitem     + id (+id,id.... 或者all)            设置触发强退要求捡起的id,支持附加值。
