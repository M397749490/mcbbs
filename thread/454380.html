有木有这样的经历
  • 编写mod的时候，不得不修改不在net.minecraft.src包中的文件，却不能打包
  • 发现mcp源码里面目录、文件有条有理，一大堆又一大堆，实际上用压缩软件打开1.6.2(或者其他版本号).jar最后发现net文件夹文件极其少，都到哪里去了？
  • 想要用自己修改的class替换原来的，自带混淆编译以后（reobf或者gradlew.build）居然发现那个文件夹里面的都是什么a.class,**.class什么的几个字母组成的琐碎文件，自己修改的那个文件找不到了
解决办法来了！
步骤：1、在你的直接替换jar包class的mod里面像平常写mod一样在net.minecraft.src新建一个mod主类
类似下面的代码
  1. package net.minecraft.src;
  2. import net.minecraft.client.gui.GuiMultiplayer;
  3. import net.minecraft.client.gui.GuiScreen;
  4. import cpw.mods.fml.common.Mod;
  5. import cpw.mods.fml.common.Mod.EventHandler;
  6. import cpw.mods.fml.common.event.FMLInitializationEvent;
  7. import cpw.mods.fml.common.event.FMLPostInitializationEvent;
  8. import cpw.mods.fml.common.event.FMLPreInitializationEvent;

  10. @Mod(modid="ceshi", name="ce", version="1.0.0")
  11. public class mod_ceshi {
  12.         @EventHandler
  13.         public void preLoad(FMLPreInitializationEvent event)
  14.         {
  15.                 GuiScreen news = new GuiScreen();
  16.                 GuiMultiplayer gui = new GuiMultiplayer(news);
  17.         }

  19.         @EventHandler
  20.         public void load(FMLInitializationEvent event)
  21.         {
  22.         }

  24.         @EventHandler
  25.         public void postLoad(FMLPostInitializationEvent event)
  26.         {
  27.         }
  28. }

复制代码
一下就是mod主类中我采用的代码，做个分析，net.minecraft.client.gui.GuiMultiplayer.java是被我修改的java文件，我就将它导入进来，并且实例化，同时实例化时要传入一个GuiScreen对象，所以再把它实例化传进去，实际上这个对象是不需要包含任何信息的。
2、正常地混淆编译
3、下载文件点我链接其他下载站的下载地址
4、运行，打开mod主类(混淆编译后的class文件)，如果修改的和我是同一文件，很快发现实例化的一行是这样的：
avk gui = new avk(news);
秒懂，文件名变成了在第一个目录下的avk.class(import也没了就说明在同一目录)
5、把avk.class(你可能是其他的)果断地提取出来，它就是拖进jar里面要替换掉的你的文件了！接下来，安装时直接拖进jar我就不说了哦。
