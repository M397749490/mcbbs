1  命令UI


如图所示，命令现在有颜色了，如果一个参数有误，则这个参数在输入框里会显示红色。



涂上颜色的命令参数仅限当前的子命令。

应当指出，这些命令提示的背景还是全黑的，未来很可能改为透明背景。

另外，Tab补全有了微小的变化——只有在你输入了单词前缀才可以进行补全了（填自己名称例外）。

2 新的命令，以及新旧对应

啊，一些像as，at这样显而易见的就不试了，尝试了改变比较大的。

2.1
/execute (if|unless) score <target> <targetObjective> (<|<=|=|>=|>) <source> <sourceObjective> <chained command>

比较两个分数是否满足条件，满足则执行命令。由于score是execute子命令的一个，所以如果chained command要直接写普通命令，还必须加run哦。

说起来，这个比较关系相较于记分板的operation，还缺少了“><”，也就是不等于……（请连续使用两个score？原来是unless =，不过既然如此完全可以只设置3个比较符嘛）

2.2
/execute store (result|success) <name> <objective> <chained command>

以前/stats的运作方式是将一个记分板变量通过某种关系与方块或实体绑定。当命令方块或实体执行命令时，就会根据对应关系改变记分板变量的分数。

/stats操作是会保持的，如果不使用clear，绑定的关系就会一直存在。

在新的store命令中，五种对应关系简化成了两种。除了SuccessCount，其它四种都归在了result上。而具体是哪种关系，则由chained command的性质来自动确定。

总之就不再那么繁琐啦！

/function foo if @e[tag=bar] -> /execute if entity @e[tag=bar] run function foo

mcbbs新闻贴没写那个run，恐怕是晚餐骨发现事情不妙补上去的XD

提到了function，就顺便说一下，如果某个function的命令出现问题了，将会被更严厉地解析出来，并显示在log中


图中的function写了一条命令，gamemode 1。这在以前当然是能成功执行的，而且你甚至可以写gamemode deepdarkfantasy都没问题，游戏照样会提示执行成功。1.13真的很严格。

3 参数格式

3.1 选择器
终于可以复用参数啦！为了选择几类生物而要写几条type=...的日子一去不复返啦！

另外，一个最显著的更新，就是加入了区间系统。所以score_name, score_name_min这样臃肿的参数理所当然地被删除了。

鉴于小于1的小数可以省略0，于是我们可以写出这样一个参数：distance=.1...2，也就是0.1到0.2……XD

3.2 方块参数
这里我遇到了一个很尴尬的问题。

根据扁平化的说法，1.13应该把红色羊毛，花岗岩这样的东西改成minecraft:red_wool，minecraft:granite这样的东西了

然而事实上，游戏中还是只能用1.13的格式，按1.12的规则来进行，也就是minecraft:wool，minecraft:stone[varient=granite]



这个东西应该会在之后的更新中修改掉。

3.3 物品参数
这个比方块参数更加尴尬一些。red_wool自然是不能用了，然而wool[...]这样的格式只适用于描述方块状态，所以也不能像上面那样获得羊毛。

而wool{...}是用来修改nbt标签（tag）的，不能拿来修改Damage。

所以这个版本暂时无法give红色羊毛了？如果有办法的话请告知一下，非常感谢……
