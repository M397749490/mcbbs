仔细看插件帖

  1. BanItem.*:
  2.     BanItem所有权限
  3.     权限默认所有者: 管理员
  4.     子权限:
  5.         BanItem.bypass: true
  6.         BanItem.cmdcomplete: true
  7.         BanItem.cmd: true
  8. # 对于BanItem.bypass权限,配置文件中启用相应的配置
  9. # 例如一个子id为0的箱子的use权限被禁了
  10. # 启用Permission.CheckItemId,权限检查会检查BanItem.bypass.use.54这样的权限
  11. # 启用Permission.CheckItemDamage,权限检查会检查BanItem.bypass.use.54@0这样的权限
  12. # 两者都未启用,只会检查BanItem.bypass.use这样的权限
  13. BanItem.bypass:
  14.     跳过禁用物品检查的权限
  15.     权限默认所有者: 管理员
  16.     子权限:
  17.         # 破坏方块的权限
  18.         BanItem.bypass.break: true
  19.         # 合成物品的权限
  20.         # 此权限仅在玩家点击结果格子的物品时才会触发检查,例如工作台,炉子
  21.         BanItem.bypass.craft: true
  22.         # 拿着该物品的权限,此权限处理有缺点
  23.         # 如果玩家快捷栏全是没有hold权限的物品,那么就没有意义了
  24.         BanItem.bypass.hold: true
  25.         # 与方块交互的权限
  26.         BanItem.bypass.interact: true
  27.         # 基本所有的权限,检查玩家背包,放置,点击,丢弃,切换,基本所有事件都需要检查该权限
  28.         BanItem.bypass.inv: true
  29.         # 放置方块的权限
  30.         BanItem.bypass.place: true
  31.         # 使用物品的权限
  32.         BanItem.bypass.use: true
  33. BanItem.bypass.*.物品id
  34.     此权限3.0.31及以后的版本才存在
  35.     跳过某个物品所有禁用Flag检查的权限
  36.     物品id支持数字id和文字id
  37.     例如,以前版本,如果你禁了箱子的use和hold权限,这时候想给某个玩家用
  38.     那么你必须同时给该玩家BanItem.bypass.use.54和BanItem.bypass.hold.54两个权限
  39.     非常的繁琐,所以这时候就可以改用给该权限BanItem.bypass.*.54直接给所有Flag的权限
  40.     不要忘记将配置中Permission.CheckItemId设置为true,否则此权限无效
  41. BanItem.bypass.useintnbt
  42.     在nbt中使用物品的权限,例如法杖核心,枪械mod的子弹
  43.     权限默认所有者: 管理员
  44. BanItem.cmdcomplete:

  46.     权限默认所有者: 管理员
