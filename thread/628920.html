0. 前言
插件程序员想起了那些年被插件支配的恐怖。
创建一个Java工程，多痛苦。
添加依赖库，多痛苦。
创建一个继承自JavaPlugin的类，多痛苦。
写plugin.yml，多痛苦。
导出一个jar，多痛苦。
如果中间还要debug，更痛苦了。
打开IDE，多痛苦。

于是，脚本语言创造了懒惰。
而一个号称最懒惰的程序员，创造这个插件。

本插件开源（GPLv3）：https://github.com/aegistudio/Scriptful

1. 程序员怎么使用？
1.1. 一个最简单的插件
如何安装插件就不说了，咱们来进入正题。
打开Scriptful文件夹，下面空空如也，我们创建一个hello.js。里面写入
  1. print("hello world");
复制代码
保存，启动服务器。
服务器控制台是不是输出了hello world？
经过多年的编码已经成为老司机的你，是不是找到初次写代码的感觉？

1.2 需要监听器？
写插件没有监听器，怎么行？
创建chat.js，里面写入
  1. self.registerListener({
  2.           event: "PlayerChatEvent",
  3.           priority: priority.normal,
  4.           handle: function(chatEvent) {
  5.                     print("Somebody chat!");
  6.                     chatEvent.getPlayer().sendMessage("You speak!");
  7.           }
  8. });
复制代码
于是你说的每一句，老大哥，啊不，插件，都在听。
这里出现了“self”，这是一个非常重要的东西，有了它，我们可以做和java插件一样的事情，我们以后继续讨论。
那个priority.normal其实是偷懒用的，一共有priority.lowest, priority.low, priority.normal, priority.high, priority.highest, priority.monitor。
更懒的境界是不写priority项，默认normal。不过event和handle还是一定要写的。

1.3 接受指令
没有指令也不行，接下来接受指令。
创建cmd.js，里面写入
  1. self.registerCommand({
  2.           name: "testcmd",
  3.           description: "example for command.",
  4.           usage: "/testcmd [args]",
  5.           permission: "testcmd.use",
  6.           executor: function(sender) {
  7.                     sender.sendMessage("Respond to you!");
  8.                     return true;
  9.           }
  10. });
复制代码
你可能会问，为什么executor只有一个参数？
ok，那是因为我懒，executor有四个参数，并返回一个布尔值（和bukkit原来的一样）
别的一看就懂了，懒人都是聪明人。
其实除了name以外。。其他变量都可以不assign。。

1.4 多个文件？
有人可能觉得，把所有东西放一个文件里可能太降san值了，需要更多文件方便arrange代码。
行，满足你这个愿望。通过观察，你可以发现，我们一个插件对应一个文件，脚本后缀决定类型，要怎么搞？

我们知道，java文件编译得到一个class文件， 但我们可以把它们放进一个jar文件中。
同理，我们把脚本放进压缩包里（目前支持.zip，.gzip，.gz）。

比如，创建一个multiple.zip，先把1.2（chat.js）与1.3（cmd.js）的代码放进去。
如果你Scriptful目录下没删除chat.js与cmd.js，那请先把他们删了，以免影响结果。
现在multiple.zip里有两个js文件，但是如果我们这时运行，他们将不会被加载（你可以运行服务端试试）。

为了让他们加载，你需要再往multiple.zip添加一个文件，名为main.js（或者multiple.js也可以），内容如下：
  1. self.include("chat.js");
  2. self.include("cmd.js");
复制代码
再运行看看？没错，self.include的作用就是加载包里其他脚本文件。
注意self.include只有压缩包类插件可以调用，脚本文件类插件不行。

1.5 支持其他脚本语言
你认为只可以用js来写插件？当然不是！
你可以用一切有java引擎支持的脚本语言来写，比如python。
就拿python举例吧，首先我们需要一个叫jython的东西：https://sourceforge.net/projects/jython。
把里面的jython.jar解压出来，然后你可以：
  • 把jar文件拖进<jre_home>/lib下。
  • 把jar文件解压，把里面内容拖进服务端jar。
  • 把jar文件拖进服务端根目录，运行参数加上-cp jython.jar。（比如java -cp jython.jar -jar spigot-1.8.7-R0.1-SNAPSHOT.jar）
我知道你会嫌麻烦，其实把jar文件拖进Scriptful文件夹（插件目录）下就可以了，哈哈哈哈哈哈哈哈哈哈哈哈~

运行服务端，你会看到本插件输出“Supported languages:”，比如“Supported languages: .lua, js, lua, py”
输出内容为支持的脚本类型，比如上面输出代表支持lua，javascript与python。

创建commandpy.py，里面写入：
  1. print('Hello! Im py!');

  3. class CommandSender(dict):
  4.           def __init__(this):
  5.                     this['name'] = "testcmdpy"
  6.                     this['description'] = 'example for command (python).'
  7.                     this['usage'] = "/testcmdpy [args]"
  8.                     this['executor'] = True

  10.           def executor(this, sender, cmd, label, args):
  11.                     sender.sendMessage("Py respond to you!")
  12.                     return True

  14. self.registerCommand(CommandSender());
复制代码
你会发现，现在多了一条testcmdpy指令，更重要的是，你可以用python写插件啦！{:10_521:}

1.7 Scheduler
想必写插件的各位对Scheduler不会感到陌生。
在Java插件中，我们getServer().getScheduler()并Scheduler用的方法注册任务。
在脚本插件中，我们用self.schedule()注册任务。请看以下代码：
  1. self.schedule({
  2.           async: false,
  3.           period: 20, delay: 0,
  4.           counter: 0,
  5.           run: function() {
  6.                     print('Count: ' + this.counter);
  7.                     this.counter ++;
  8.           }
  9. });
复制代码

3. 权限与指令
/script: 列出所有script下的指令及用法。（执行script指令均需要script.command权限！）
/script unload <name>: 卸载指定的插件（插件必须已经加载）。
/script reload <name>: 重新加载指定的插件（插件必须已经加载）。
/script load <name>: 加载指定的插件（插件刚被卸载，或刚被拖进Scriptful目录下）。
/script exec <name> <code>: 在某一插件环境下执行语句（debug福利！）。
