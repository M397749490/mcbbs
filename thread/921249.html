前言
随着版本的更新和论坛整合包区块的改革，越来越多的模组玩家加入了制作魔改整合包的大坑。但是，整合包版块还是没有足够的作者来产出源源不断的优质内容。本贴旨在浅析一些制作整合包的技巧和心得，全面阐述了一个大型整合包是怎样制成的，希望论坛能越做越好，精品整合包越来愈多。

这个帖子并不是一个魔改整合包的入门教程，若有需要可以参阅以下帖子：

制作整合包的那些事——从整合新手到整合大神 -最后更新于2017-6-10
整合包制作&魔改教程 -最后更新于2018-7-25
从零开始学魔改（适用于1.12.2CraftTweaker）-最后更新于2019-10-12

这个帖子的一些部分可能会比较系统化，希望读者能够自行变通

关于制作

1.构思

首先，在制作整合包之前，你需要确定一点：我的整合包需要围绕着什么来发展？

这个东西下文使用 主题 来代替，

主题可以是一个类型的模组：科技？魔法？冒险？维度？生存？空岛？
你也可以将不同类型的主题糅合在一起，比如最常见的科技和魔法，生存和空岛，冒险和维度
某坛最盛行的不就是空岛，以及生存下面的子类型：迫降嘛（bu

主题也可以是一个特定的模组：余烬？神秘时代？核电工艺？僵尸意志？甚至生活调味料（这个太硬核了）
抛砖引玉：强行修改生活调味料的数值来迫使玩家在不同的维度中寻找不同的食物，每种食物只能食用一次，食用了整合包中所有的食物后解锁终极食物，并视作通关。

主题更甚可以是一个物品：余烬中的灰烬？神秘时代中的傀儡？原版圆石？
抛砖引玉：在只有一棵树的空岛上开局赠送两组灰烬，使用一组半灰烬来制造用燃料来产生余烬能量的机器/无限产生余烬晶体和一个灰烬炉，然后使用灰烬来展开科技线。

有了主题之后，便可以着手开始制作整合包了。

在真正开始制作整合包之前，我强烈建议大家先想好自己需要一条怎样的线路，需要什么模组才能实现这条构思出来的线路，如果没有现成的模组可以实现的话，需要自己添加哪些 材料/方块/物品/机器 来实现。

如果可以的话，最好可以将这些构思整理为一个文档来保存你的脑洞，好的点子转瞬即逝。

当然，你也可以为你的整合包添加剧情，虽然我本人并不是很喜欢拥有剧情的整合包（大部分原因是坛里的剧情都大多残缺不全且不能自圆），但是一条优质剧情线是可以为你的整合包带来热度和人气的。

大家最好也把它整理在一个文档里保存下来。
推荐使用MarkDown语法来归档脑洞，
关于MD的教程：https://www.runoob.com/markdown/md-tutorial.html
推荐使用Typora（WINDOS）作为MD文档编辑器，读者可以自行搜索软件资源下载，Typora是免费软件。

2.制作的环境

·启动器的选择

制作整合包的第一步，就是挑选一个合适的，趁手的启动器了，
这里有几个选择推荐给大家，各有利弊：

HMCL（国内老牌启动器，最适合新手的选择，除了频繁崩服外值得信赖，无需正版账号）
HMCL不用多说了，估计论坛里的各位也都用过，特点是可以导入/导出通用格式的整合包压缩包

MultiMC（轻量级别的多版本管理软件/启动器，需要正版账号）
多版本启动器的集大成者，除了不能启动器内安装模组外十项全能，标准的制定者

Twitch（集成的高效启动器，需要正版账号，墙内使用略麻烦）
两个字：方便。可以便捷的直接在启动器内 安装/更新 模组/整合包

个人推荐使用Twitch进行模组安装和更新，并用MMC作为主要启动器，因为Twitch屎一样的UI和启动手感令人作呕。

·文本编辑器的选择

若要制作一个魔改整合包，不可避免的会遇到自定义内容
（魔改脚本，进度JSON，原版数据包，模组Config，自定义机器JSON等等）
那么，一个使用体验绝佳的文本编辑器就必不可少了，
这里推荐微软家的VS Code，轻量，集成，支持插件
可以极大的增加脚本和JSON文件的可读性（高亮语法，括号等）
软件可以百度到资源，这里就不贴链接了
ZenScript插件可以在这里或是在插件中心搜索ZenScript安装：https://www.mcbbs.net/thread-846423-1-1.html

·版本的选择

虽说是版本的选择，但也基本是CT/MT（魔改）模组的版本选择了，一般来说有下面四个大版本

1.7.10（MT3）
1.10.2（CT1）
1.12.2（CT2）
1.14.4（CT3）

1.7.10就不说了，被时代遗弃的版本，不知道为啥还有那么多人停留在5年前的版本（BU）。
1.10.2是一个过渡版本，在两年前的人气会比较高，也昙花一现了一些优质整合包，但大都更新到了1.12.2。
1.12.2就是大部分现代魔改整合包基于的版本，拥有现今最多的模组库。
1.14.4由于模组略少，这里一笔带过，可能将来会更新相关内容。

这篇心得会大部分聚焦在1.12.2，也是我用的最多最熟悉的版本上，仅供制作其他版本的整合包的读者参考。

·版本控制系统以及多人合作
常言道，制作整合包犹如写程序：你需要做出一个fully functional的集成系统，that implement你的主题。
并且，一个整合包不可避免的会出现BUG：进度线混乱，脚本文件出错，任务写错等等，那么一个版本控制系统便必不可少了。
大部分情况下，一个大型整合包都是需要多人合作来制作的，但是使用文件传输来进行版本同步的繁琐步骤令人作呕。
这里推荐两个版本控制系统：
SVN 和 GIT
这两种系统各有不同，但是核心思想是一致的：在不同的客户端上实现项目的同步开发 及 回溯版本来进行纠错
本人使用的是GitHub作为Git的remote服务器来进行整合包的开发过程，一般情况下只需要新建一个文件夹，将你的minecraft文件夹中自定义的部分，以及开发文档放入项目中，就可以开始愉快的和你的小伙伴一起做包了。
推荐使用GitHub Desktop来作为一个GUI化处理项目Git仓库的软件
GitHub Desktop的新手教程：https://www.jianshu.com/p/06a960d991aa
合作时 最好要合理分工，譬如一个人构思科技线并存档，一人根据文档来进行对应的魔改，一人根据文档来制作相应的任务/进度；
这样做的效率和质量是非常高的。当然，沟通也是必不可少的。


3.制作时的那些事
写在前面：
阅读许多模组提供的文档都需要一定的外语水平，建议外语水平不是特别理想的伙伴们使用谷歌翻译插件来跨越语言的障碍


·模组的选择
当你确定了你的主题之后，模组的选择应该也不是难题了，JEI首先是大多数魔改整合包的标配，但也不代表它是必不可少的：如果你的主题和JEI不符（例如原始整合包），它也是可以删除的。
除了一些基础的信息显示和美化/优化/辅助模组之外，我会将模组分为三类：
核心模组 - 跟主题密切相关的并且在整合包游玩线路中不可取代的模组
非核心模组 - 跟主题相关但并不影响核心游玩体验的模组
自定义模组 - 用于添加自定义内容的模组（AKA 魔改模组）
由于核心模组和非核心模组大都基于你选择的主题，这里主要会讨论一些主流的自定义模组
模组的挑选也应遵从奥卡姆剃刀原则：如无需要，勿增实体
不要添加与你的主题没有太大关系的模组
模组一般从CurseForge上获取：https://www.curseforge.com/minecraft/mc-mods

·魔改
魔改模组可以全部分成两类：基于ZenScript（CT）以及 其他

常用的基于ZS的魔改模组有：
CraftTweaker(ZS核心老大哥) https://www.curseforge.com/minecraft/mc-mods/crafttweaker
GameStage(分阶段整合包必备) https://www.curseforge.com/minecraft/mc-mods/game-stages
以及一些对特定模组提供CT支持的XXX Tweaker模组和对各种东西分化阶段的XXX Stages模组
MT的使用技巧在之前提到过的【从零开始学魔改】一贴中有非常详尽的讲解了，这里就不冗述了。
这里稍微提一下很多新手掉进的坑：CT官方文档：https://docs.blamejared.com/1.12/en/
虽然CT的官方文档里涵盖了很多模组提供的ZS函数，但是还有一部分模组的ZS函数并没有列在其中，却写在了模组自己的WIKI里，譬如自然灵气的CT支持：https://github.com/Ellpeck/NaturesAura/blob/master/CraftTweakerCompat.md

除去CT阵营外，更广义的魔改指所有的，成体系的，对整合包的自定义修改
这里介绍几个常用的非ZS自定义模组：
模块化机械：制作自定义多方块机械的模组，在制作科技类整合包时非常好用，并且兼容ZS
CF页面：https://www.curseforge.com/minecraft/mc-mods/modular-machinery
更多实用设备2：提供制作单方块自定义机械接口的模组，可以简便的添加一些小型机器，但目前教程较少/压根没有（笑）
CF页面：https://www.curseforge.com/minecraft/mc-mods/extra-utilities
压缩机器3：提供了3D合成的可能性，但目前BUG较多，小型的3D合成制作起来还是蛮好用的
CF页面：https://www.curseforge.com/minecraft/mc-mods/compact-machines
自定义主菜单：提供了修改主菜单外观的模组，在前人著：【整合包制作教程&魔改教程！】中有介绍
CF页面：https://www.curseforge.com/minecraft/mc-mods/custom-main-menu
自定义加载界面：提供了修改加载界面外观的模组，国内相关介绍较少
CF页面：https://www.curseforge.com/minecraft/mc-mods/splashanimation

进度/任务相关：
Triumph：自定义进度的模组，也是我个人比较喜欢的进度模组，简单，轻量
CF页面：https://www.curseforge.com/minecraft/mc-mods/triumph
Better Questing（BQ）：论坛内使用的最多的任务模组，特点是可以GUI写任务
CF页面：https://www.curseforge.com/minecraft/mc-mods/better-questing
HQM：八说了，大家都懂，时代的眼泪
CF页面：https://www.curseforge.com/minecraft/mc-mods/hardcore-questing-mode
FTB Quest：新兴的任务模组，集成性较好，推荐使用
CF页面：https://www.curseforge.com/minecraft/mc-mods/ftb-quests

·配置文件（minecraft/config）
配置文件一般用于配置模组的一些触发条件，一些机器和多方块结构的数值，和配置模组和其他模组的条件。
好的配置条件修改可以取到锦上添花的效果，并且可以做到一些脚本做不到的功能。
当然，最普遍的，也是最简单的配置文件修改是统一矿石生成，和自定义世界生成。
由于大多数的模组配置文件条目也都不一样，这里就不冗述了





关于发布
一般而言，发布的压缩包就是由启动器导出的，包括：
-resources
-config
-mods/modlist.html
-scripts
-addons
文件夹/文件的文档。


使用Twitch制作的整合包可以快捷的在CF上发布，所有的依赖项都由系统自动添加，非常方便。
而使用MMC制作的整合包需要手动添加依赖项，所以推荐大家把MMC制作的整合包过一遍Twitch再在CF上发布。


在本坛发布的话也请大家都遵循这种格式，毕竟强制使用指定的启动器也是对玩家自由的一种侵害，且大家也不希望多下不包括整合包内容的文件。

关于BUG
在整合包发布之后，许多在测试阶段没有现形的BUG将会接踵而至。作为整合包的作者，我们有义务将BUG以列表的形式列在帖子里，来警示其他玩家。个人而言，我推荐玩家将BUG以GitHub Issue的形式提交，这样我便可以量化地处理他们。但是，迫于国内MC圈子的特殊性，我觉得在QQ群内/帖子下回复报错也蛮好的。

后记
