游戏版本：Java版1.13及以上

自我介绍


    大家好，我是论坛新人橙汁，首次发帖，如有不足，请各位多多指教，希望大家多多支持，谢谢。我是一个很随缘佛系的新手玩家，平时比较喜欢红石与命令方块。

效果介绍

    新的一年就要到来了，在这里给大家拜个早年，祝大家在新的一年里万事如意。说到过年，我就想起了小时候玩的一种鞭炮，叫做“二踢脚”，也就是双响爆竹了。真的是很怀念那段无忧无虑的童年时光。本帖就来展示如何使用命令方块制作“二踢脚”吧。

    效果是这样的：点燃一个TNT，当其引爆后会向天空飞射出第二个TNT，升空数米，并最终在空中爆炸。
    实际生活中“二踢脚”的原理是这样的：纸筒内分两层安放火药，下层火药将爆竹送上天空，上层火药在升空后爆响。
    但游戏中飞射升空的TNT并不是利用第一个TNT的爆炸冲击升空的，而是通过命令方块的召唤实体命令实现的。

（借物表：建筑 / 红尘客栈 - 龙族蝎子）




思路介绍


    看了具体的展示效果，我们开始进入实现过程的讲解部分吧。第一部分讲一下设计思路，第二部分再来讲述如何应用到游戏中。

    首先，用C语言风格的伪代码将总体设计思路列举出来。核心部分是这四个同步进行的循环，注意是同步进行的。
    总体设计思路就是，检测TNT点燃，等待它爆炸后召唤出升天TNT，之后再把一切恢复为初始状态即可。
    设计时困难的地方在于这四个循环是同步进行的，各循环之间很可能出现互相激活的状态，导致无限循环。因此需要设置延时。

【方块03】

复制代码
类型：连锁  不受制约  保持开启
解释：添加计分板项目“延时计数”。

【方块04】
  1. scoreboard objectives add delayTime dummy
复制代码
类型：连锁  不受制约  保持开启
解释：添加计分板项目“延时总数”。

复制代码

（二）循环检测部分

①循环一



【方块09】
  1. execute if score @p scoreA = @p scoreB
复制代码
类型：循环  不受制约  保持开启
解释：检测是否“分数A”等于“分数B”。

【方块10】
  1. execute if entity @e[type=tnt] run scoreboard players set @p scoreA 1
复制代码
类型：连锁  条件制约  保持开启
解释：如果检测到了点燃的TNT，就将 “分数A”设为1。

【方块11】
  1. execute at @e[type=tnt,limit=1,sort=nearest] run summon armor_stand ~ ~9 ~ {NoGravity:1,Invisible:1}
复制代码
类型：连锁  条件制约  保持开启
解释：在最近的引燃TNT上方9格处生成一个隐形的、不受重力影响的盔甲架（标记位置）。

②循环二



【方块12】
  1. execute if score @p scoreA > @p scoreB
复制代码
类型：循环  不受制约  保持开启
解释：检测是否“分数A”大于“分数B”。

【方块13】
  1. execute unless entity @e[type=tnt] run scoreboard players set @p scoreB 2
复制代码
类型：连锁  条件制约  保持开启
解释：如果没有检测到点燃的TNT，就将“分数B”设为2。

【方块14】
  1. execute at @e[type=armor_stand,limit=1,sort=nearest] run summon tnt ~ ~-7 ~ {Fuse:37,Motion:[0.0,2.4,0.0]}
复制代码
类型：连锁  条件制约  保持开启
解释：在最近的盔甲架下方7格处生成一个爆炸延时为37、向上加速度为2.4的引燃TNT。

【方块15】
  1. scoreboard players set @p scoreA 0
复制代码
类型：连锁  条件制约  保持开启
解释：将“分数A”设置为0。


③循环三.



【方块16】
  1. execute if score @p scoreA < @p scoreB
复制代码
类型：循环  不受制约  保持开启
解释：检测是否“分数A”小于“分数B”。

【方块17】
  1. execute if score @p delay < @p delayTime run scoreboard players add @p delay 1
复制代码
类型：连锁  条件制约  保持开启
解释：如果“延时计数”小于“延时总数”，则
“延时计数”+1。

④循环四



【方块18】
  1. execute if score @p delay >= @p delayTime
复制代码
类型：循环  不受制约  保持开启
解释：检测“延时计数”是否大于等于“延时总数”。

【方块19】
  1. scoreboard players set @p scoreB 0
复制代码
类型：连锁  条件制约  保持开启
解释：将“分数B”设为0，恢复初始状态。

【方块20】
  1. scoreboard players set @p delay 0
复制代码
类型：连锁  条件制约  保持开启
解释：将“延时计数”设置为0。

【方块21】
  1. kill @e[type=armor_stand,limit=1,sort=nearest]
复制代码
类型：连锁  条件制约  保持开启
解释：清除最近的一个盔甲架。

注意事项

    完成以上内容就可以享受燃放“二踢脚”的乐趣了！不过，请注意以下几点内容：

    ①由于对于盔甲架的处理命令没有加限制，因此，请注意使用时是否有其他盔甲架；

    ②TNT属于易燃易爆物品，请在游戏时配合水来封印其地形破坏的威力，以免造成存档毁图等困扰；

大概看了一下，想法不错，思路也理得还蛮清楚，但是做法稍显复杂了。
tnt有这么一个叫Fuse的nbt，你也用了，这个nbt的作用是标记这个tnt还有多久炸掉。这个nbt在点燃后是自减的，减到0时tnt就炸了。那么我们有没有什么办法直接通过这个nbt来作为标记以取代文中延时的机制呢？显然是可以做到的。
思路也很简单，检测Fuse:1s的tnt就完了嘛，因为下一刻它就不存在了，正好用来作为表征。唯一要注意的是需要用tag区分被summon出来的tnt。
  1. execute as @e[type=tnt,nbt={Fuse:1s},tag=!summoned] at @s run summon tnt ~ ~ ~ {Motion:[0.0,2.0,0.0],Fuse:10s,Tags:["summoned"]}
