正文

自然生成遗迹大家应该都知道是什么意思吧，比如村庄，要塞，废弃矿洞……
所以效果就不用展示了(因为真的没有什么观赏性，我生成的遗迹就是5×5×5石砖火柴盒里面有个钻石块)

思路
如果只用文字叙述则很难理解，所以有些部分用windows的画图画了一下示意图(您的好友灵魂画手已上线)
在生成建筑之前，要先确定该区块是否被玩家加载过，被玩家加载过的区块可不能生成建筑
如果被加载过的区块可以生成建筑，那玩家在某处造了个房子，跑图回来发现自己的房子变成了遗迹就……
所以在玩家经过的区块上必须被标记上无法生成遗迹，记号(marker)可以选用area_effect_cloud(药水云，简称aec)
因为一个地图同时加载较大量的aec并不会影响性能，但是如果一个区块标记一次，假如玩家跑了
面积为2560×2560=6553600方块，一个区块是16×16=256方块，则需要6553600÷256=25600个marker，
这样marker的数量会较大，但是如果一次个marker标记8×8=64个区块即64×256=16384方块，
只需要6553600÷16384=400个marker，以上都是理论值，marker标记的区域还可能重复
这里我们把8×8个mc区块在定义为1个区块，

现在玩家第一次进入世界，会对所在区块进行一次标记

玩家每次标记区块，之后都会尝试生成一次建筑
会spreadplayers(随机扩散)x个aec(标签为BuildMarker,下同)到64格内
(x位大于等于2的整数，大小与精度有关)
只有扩散到64格之外，即到第65个的aec才会生成建筑

现在假设x=2

x为什么要大于等于2，因为设置了aec之间的最小距离是64，这样就增大了扩散到外圈的几率
生成的x个aec只有y个是TrueMarker，只有TrueMarker才可以生成建筑，这样可以控制几率，
如果x=2，y=1，则几率非常高，当x=10，y=1的时候，几率可能要比地牢还低

如果玩家从这个区域内移动出就会生成新的marker

并再次尝试生成建筑，扩散x个aec，这次不仅需要满足在65格之外和需要时TrueMarker，还需要满足不在其他marker所标记的区块里，如果玩家尝试生成建筑范围全部被marker的范围覆盖，那么就一定不会生成建筑

简单点说，就是每次进入没有被标记过的区块，就尝试生成建筑，满足不在被标记的区块和其余条件，就可以生成建筑

实现
实现这个自然生成建筑，仅仅需要很少的命令
首先这是用到的三个mcfunction文件
generat\generat_main.mcfunction
  1. gamerule commandBlockOutput false
  2. gamerule logAdminCommands false
  3. gamerule sendCommandFeedback false
  4. execute @a ~-64 0 ~-64 function generat:generat_mark unless @e[dx=129,dy=0,dz=129,tag=ChunkMarker]
  5. entitydata @e[tag=ChunkMarker] {Age:0}
复制代码
generat\generat_mark.mcfunction
  1. execute @s ~ ~ ~ summon area_effect_cloud ~ 0 ~ {Tags:["ChunkMarker"],Duration:2147483647}
  2. execute @s ~ ~ ~ summon area_effect_cloud ~ ~ ~ {Tags:["GeneratBuild","TrueMarker"]}
  3. execute @s ~ ~ ~ summon area_effect_cloud ~ ~ ~ {Tags:["GeneratBuild"]}
  4. execute @s ~ ~ ~ spreadplayers ~ ~ 64 65 false @e[tag=GeneratBuild]

首先我们一点一点分析
main部分：
只有
  1. execute @a ~-64 0 ~-64 function generat:generat_mark unless @e[dx=129,dy=0,dz=129,tag=ChunkMarker]
复制代码
是实际有用的命令，其它都是设置消除命令提示和防止aec在三年之后消失(误)的命令这条命令的意思就是一直让玩家以~-64 0 ~-64为基准，如果129×1×129内没有marker，则执行mark部分
实际上就是当玩家走到的区块内和其它区块并不重合的时候，就会执行mark部分标记这个区块和尝试生成建筑

mark部分：
首先summon一个aec标记这个区块
  1. execute @s ~ ~ ~ summon area_effect_cloud ~ 0 ~ {Tags:["ChunkMarker"],Duration:2147483647}
复制代码
然后生成两个aec并扩散到65格内，但是只有一个aec是TureMarker
  1. execute @s ~ ~ ~ summon area_effect_cloud ~ ~ ~ {Tags:["GeneratBuild","TrueMarker"]}
  2. execute @s ~ ~ ~ summon area_effect_cloud ~ ~ ~ {Tags:["GeneratBuild"]}
  3. execute @s ~ ~ ~ spreadplayers ~ ~ 64 65 false @e[tag=GeneratBuild]
复制代码
如果想降低生成几率，那么就可以这样写：
  1. execute @s ~ ~ ~ summon area_effect_cloud ~ ~ ~ {Tags:["GeneratBuild","TrueMarker"]}
  2. execute @s ~ ~ ~ summon area_effect_cloud ~ ~ ~ {Tags:["GeneratBuild"]}
复制代码

扩散aec之后，如果aec在任何marker标记的区域内，就会被清除(kill)
  1. execute @e[tag=ChunkMarker] ~-32 0 ~-32 kill @e[tag=GeneratBuild,dx=64,dy=255,dz=64]
复制代码
这条就是对生成建筑条件的限制，必须自身TrueMarker，而且下面必须是草方块，且没有被清除，才会执行build部分
  1. <blockquote>execute @s ~ ~ ~ execute @e[tag=GeneratBuild,c=-1] ~ ~ ~ detect ~ ~-1 ~ grass -1 function generat:generat_build if @s[tag=TrueMarker]
复制代码
最后清掉所有的非marker的aec
  1. kill @e[tag=GenerantBuild]
复制代码
build部分：
就是当aec满足生成建筑条件之后会执行的部分，没什么好说的

补充
*用来标记区块的marker会被kill，所以就目前来看，还逼不死mod，哪有mod会受kill @e的影响的
除非把marker换成rcb，不过在最下面那层放上一个rcb感觉可能也不是太好
*利用1.12的advancement，可以检测玩家所在的生物群系，利用这点可以限制建筑生成的群系，
实际上还可以省下gameLoopFunction，比如进入生物群系即reward一个function，限制一个生物群系只能生成一个这样的建筑
*如果出现了这样的状况，可能会导致标记区块的空档(红色部分)，空档部分无法被标记，但是在上面尝试生成建筑可能会成功，也就是说就算你到过这个区块，也可能会生成建筑，不过这个问题影响并不算太大，解决办法其实就是得把dx和dz都从128改成64，但是我懒得改它了=-=而且哪样会大大增加marker的量

*可以给建筑都加上标记，利用单刻获得实体坐标伪locate帮助寻找遗迹
*最后，这个帖子里可能会有些难以理解的错误[滑稽]
