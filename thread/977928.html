在揭晓这个坑之前，我们先来思考一个简单的问题：
如何让两名玩家调换位置？
小A：这还不简单！！? 我反手放两个CB:
  1. tp A B
  2. tp B A
复制代码

相信在座的各位已经看出小A的问题，如果将A tp 至B，B再tp至A时，将tp到B的原位。
那么这个问题该如何解答呢？
小B：当然是现在A处生成一个隐形的盔甲架，然后将A tp 至B，再将B tp 至盔甲架，最后移除盔甲架。

小B的做法应该是大多数人第一反应的做法，但是这种方法不免有些麻烦，那有什么简便的方法呢？

来看以下mcfunction：
  1. tp @s B
  2. tp B ~ ~ ~
复制代码
然后我们让A执行这个指令，或是在CB中输入execute as A at @s run function mcfunction来调用

咋一看，大家可能会觉得，这不就是“先把A tp到 B，再把B tp到 A”吗？当然不行
然鹅，这样违反常识的做法，却的确正确！！


这就涉及到了今天我们要讲的东西：命令环境（command enviroment)

何为命令环境？如果你学过编程，可能可以这样理解：命令环境就是传入函数的参数
我们每个mcfunction，都可以看做一个有参函数，参数有：坐标，朝向，维度，执行者
是不是感觉挺熟悉？没错，它们就分别对应着execute指令的positioned，rotated，in，as四个子命令
当然，也可以是at和as两个子命令，因为at同时包括了坐标，朝向，维度
如此一来，函数abc就可以看做：
  1. //函数的返回值用于stored子命令
  2. int abc(int[] position,int[] rotation,mcdimension dimension,mob target){
  3.      ......
  4. }
复制代码


所以，如果你在聊天框执行了/function abc (也就是/execute as @s at @s run function a)
就好像执行了一个有参函数 abc(position,rotation,dimension,target)

好的，既然我们已经传入了四个参数，这些参数如何在mcfunction中调用呢？
坐标：函数中需要坐标的指令，可以用~指代命令环境中的x|y|z（即数组position的三个元素）

我们回到上面的例子。
A在执行了下列函数时，会把自己的position等传入函数，那么函数命令环境中的postion就应该变为了A执行该函数时的坐标
  1. tp @s B
  2. tp B ~ ~ ~
复制代码
也就是说，函数中的~ ~ ~已经变为A执行该函数时的x，y，z坐标，尽管第一条指令已经将A的坐标改变，但是命令环境并不会因此改变。
这也就是为什么，上面的函数可以完成互换A、B的任务。
执行者：函数中的@s，指代的是命令环境的执行者（target）
朝向：函数中需要朝向的指令，可以用~指代命令环境中的朝向（有两个元素）
栗子：如果把上面的函数改为
  1. tp @s B
  2. tp B ~ ~ ~ ~ ~
复制代码
那么它不仅会将B传送到A处，还会使B与A的朝向一致

维度：函数中所有指令执行的默认维度（除非用in子命令覆盖）
