插件介绍

DeluxeMenus 是一款功能较强的菜单插件

其功能众多个人感觉已超越 ChestCommands 等大部分菜单插件
该插件还兼容 PlaceHolderAPI 的上千种变量，功能更是强悍
还有许多的新特点，我会在接下来的插件教程中一一详述
并且该插件原作者声称将永久免费！

（原文：As this plugin is completely free to you....）



命令 / 权限列表

其中，<>为参数

< 命令部分 >

/dm open <菜单名称> <玩家名>
描述：为指定玩家打开一个DeluxeMenus菜单


/dm list
描述：列出所有菜单


/dm reload
描述：重载插件


< 权限部分 >


deluxemenus.admin
描述：管理员指令
默认：OP

deluxemenus.open
描述：可以使用指令 /dm open 来打开某个菜单 [本权限已在1.9版本中删除]
默认：OP


deluxemenus.open.others
描述：可以使用指令 /dm open <菜单名称> <玩家名> 来为某玩家打开菜单
默认：OP


deluxemenus.open.bypass
描述：打开菜单时无视菜单所需的权限
默认：OP


deluxemenus.menu.*
描述：所有菜单的权限
默认：OP


deluxemenus.openrequirement.bypass.*
描述：打开菜单后无视菜单内所有选项要求的任何可视/点击/打开需求
默认：OP






教程部分

注意，该教程只介绍插件版本1.10及以上的菜单部分
因为自DM1.10开始，关于点击效果/需求等有所变化

1. 如何创建一个菜单？

在你成功运载该插件后，在你的插件文件夹中会生成一个 DeluxeMenus 文件夹
在该文件夹内有一个 config.yml 文件，打开它，找到以下内容，然后复制以下内容粘贴进去

  1. gui_menus:
  2.   main:
  3.     file: main.yml #创建一个名为 main 的菜单文件
复制代码

输入好后，重载插件后就会在文件夹内生成一个 gui_menus 文件夹，里面就是你创建的新菜单文件.
然后点击下一步教程，继续学习菜单的制作吧！

哦对了，别忘了转码哦~ Windows系统使用 ANSI 编码，Linux系统使用 UTF-8编码
Minecraft 1.8版本服务器统一使用ANSI，1.9及以上统一使用 UTF-8 码


2. 菜单详解

我们先来看看关于Gui界面菜单的配置信息
打开新创建的 main.yml 文件，然后找到下面的内容 》

  1. menu_title: 'TEXT'   
  2.     open_command: TEXT
  3.     size: #
  4.     update_interval: #
  5.     items:
复制代码


先来解析一下上面的项目内容 》

Menu_Title
菜单的标题，显示在GUI界面的上方，可使用颜色代码

Open_Command
打开菜单可使用的快捷指令，不允许使用颜色代码（这玩意谁会用？

Size
菜单的大小，只能设置9的倍数，且大小在 9~54 之间

Update_Interval
菜单的刷新间隔，会刷新菜单内每个图标和变量，以 秒 为单位

接下来是菜单的项目配置解析
找到以下的配置信息 》

  1. items:
  2.       'ItemName':
  3.         display_name: 'TEXT'
  4.         lore:
  5.                - 'TEXT'
  6.                - 'TEXT'
  7.         material: TEXT
  8.         data: #
  9.         amount: #
  10.         slot: 0
  11.         priority: #
  12.         view_requirement:
  13.         open_requirement:
  14.         deny_commands:
  15.         update:
  16.         hide_attributes:
  17.         hide_enchantments:
  18.         hide_effects:
  19.         enchantments:
  20.         - enchantmentid;level
  21.         - enchantmentid;level
  22.         left_click_commands:
  23.         - '[player] command'
  24.         right_click_commands:
  25.         - '[player] command'
复制代码


Items
以下内容都是关于项目的配置

ItemName
项目的代码名称，支持中文填写

display_name
项目的显示名称，支持中文及颜色代码填写

lore
项目的显示文本，支持中文及颜色代码填写

material
项目的显示物品ID，可使用 数字/英文 ID

data
项目物品ID的附加值
例如绿色羊毛的数字ID为 35:5，则data值就填写 5


amount
项目的物品显示数量


slot
项目的显示位置，这里来特意说明一下，这里的填写方式和其他菜单插件有所不同
若要让这个项目在第 x 格显示，那么你填写时就要填写 x-1 的数字
因为从第一行第一格开始从左往右计算，第一格为0，第二格为1，以此类推...
例如我要让它在第 18 格（第二行最后一格）显示，那么填写slot时就要填写数字 17


priority
项目的优先级，优先级填写数字越低，越先显示
举个例子，有两个项目在同一位置上，且一个优先级为2，一个优先级为1
那么显示时会优先显示优先级为1的项目，而将优先级为2的项目屏蔽
该项可以和下方的 可视变量 搭配使用
关于详细内容我会在接下来的优先级教程中详细解析


view_requirement
项目的可视需求，此标签对应优先级
详细内容我会在接下来的 可视/点击需求 教程中详细解析


open_requirement
项目的点击需求，没有达到该需求时将会触发下面的 deny_commands
详细内容我会在接下来的 可视/点击需求 教程中详细解析


deny_commands
玩家未满足条件时实行的命令设置


update
项目的更新开关，可填写 true/false
开启时，刷新菜单时也会刷新该项目的图标及变量
关闭时，刷新菜单时不会刷新该项目的图标及变量


hide_attributes
是否显示物品的属性


hide_enchantments
是否显示物品的附魔
与 enchantments 标签共同使用时仅会隐藏附魔文本


hide_effects:
是否显示物品的药水效果


enchantments
物品的附魔属性，配置为 enchantmentid;level
<enchantmentid>附魔id 可填写英文/数字ID
<level>附魔等级，可填写数字
关于附魔ID 可以 点我查看


3. 项目点击效果

当玩家点击一个项目时可以执行不同的命令，这就需要我们配置了 》

  1. left_click_commands:
  2.         - '[player] COMMAND'
  3.         - '[console] COMMAND'
  4.         - '[commandevent] COMMAND'
  5.         - '[message] TEXT'
  6.         - '[openguimenu] MenuName'
  7.         - '[connect] ServerName'
  8.         - '[json] {"text":"message"}'
  9.         - '[refresh]'
  10.         - '[broadcastsound] SOUND'
  11.         - '[sound] SOUND'
  12.         - '[takemoney] #'
  13.         - '[close]'

  15. right_click_commands:
  16.         - '[player] COMMAND'
  17.         - '[console] COMMAND'
  18.         - '[commandevent] COMMAND'
  19.         - '[message] TEXT'
  20.         - '[openguimenu] MenuName'
  21.         - '[connect] ServerName'
  22.         - '[json] {"text":"message"}'
  23.         - '[refresh]'
  24.         - '[broadcastsound] SOUND'
  25.         - '[sound] SOUND'
  26.         - '[takemoney] #'
  27.         - '[close]'
复制代码

left_click_commands 是玩家左键点击该项目时执行的指令或功能，
而 right_click_commands 则是右键点击项目时执行的指令或功能。


下面就是所执行的操作了，可以执行一行或是多行的命令或功能
以下为整齐都使用大写形式，实际操作时可以改为小写。


[PLAYER]
以该玩家的身份执行一段指令，如：
  1. - '[PLAYER] spawn'
复制代码
就是以玩家的权限身份执行“spawn”指令，受玩家所有权限影响
你可以做到服务器内的快捷指令菜单或是其他功能


[commandevent]
执行一个特殊指令，即未在bukkit中注册的指令（就是没有插件注册写入的）
当有一个插件或是功能能够设置一个指令时，该项就能执行那个指令“以玩家身份”


[message]
输出/发送一段消息给点击的玩家（你可以使用颜色代码）如：
  1. - '[message] &a幽冥牛逼'
复制代码
就是发送颜色为绿色的“幽冥牛逼”消息给玩家


[openguimenu]
打开该插件的其他菜单/子菜单，如：
  1. - '[openguimenu] Main'
复制代码
则为玩家打开该插件一个名为Main的菜单
如果需要插入 [close] ，一定要在该项的上方插入，否则会导致菜单打开就关闭


[connect]
将玩家传送至BungeeCord下的其他子服，如：
  1. - '[CONNECT] RPG1'
复制代码
则将玩家传送到BC下的 RPG1 子服务器


[json]
发送一段json消息给玩家，“message”处就是发送给玩家的消息，如：
  1. [json] {"text":"你要是能十七张牌秒我我当众把这个显示器吞了"}'
复制代码
以上就是发送给玩家一段json消息，具体涉嫌消费过世主播就不说了233


[refresh]
刷新在菜单视图中的项目，可用于刷新变量等操作
直接填写该项就行，无附加内容


[broadcastsound]
发送一段声音广播到服务器中，但此项我也没用过，猜测是全体玩家可听到，如：
  1. - '[broadcastsound] xxx'
复制代码
发送 xxx 声音广播，具体声音内容及名称按照原版MC中的名称，请自行搜索


[sound]
发送一段声音给点击的玩家，具体内容同上


[takemoney]
扣除该玩家的金币，此项需要配合Vault的支持及所使用的经济插件


<delay=(TIME IN TICKS)>
延迟 xx ticks后执行下方的指令，具体格式如下：
  1. left_click_commands:
  2.         - '[message] 你将在 5 秒后传送回城'
  3.         - '<delay=100>'
  4.         - '[player] spawn'
复制代码
具体执行步骤为：点击后先发送一段消息给玩家
然后延迟 100ticks 后，执行下一段回城命令

执行步骤是依次从上到下的顺序，如上方所示
若在某行插入delay延迟执行，则该行下方所有操作将一起延迟
20ticks = 1second，1200ticks = 1minute


<chance=(CHANCE)>
点击项目时会有多少几率执行该行操作，具体格式如下：
  1. - '[message] The chance to get this message is 80% <chance=80.0>'
  2. - '[message] The chance to get this message is 25% <chance=25.0>'
复制代码
具体执行步骤为：点击后有 80% 几率发送第一条消息，有 25% 几率发送至第二条消息
几率以百分比计算，chance后方数字请按上方格式填写


[close]
点击后关闭菜单，没啥好说的
