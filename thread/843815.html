请不要直接使用 Player 作为 Map 的 Key！！！会引发内存泄漏！！！而且 Player 的具体实现没有对 equals 和 hashCode 的实现有任何保证，贸然直接使用 Player 作为键，不论是基于散列码和散列表的 HashMap 还是基于红黑树的 TreeMap（根据 https://docs.oracle.com/javase/8/docs/api/java/util/TreeMap.html 的说法，TreeMap 基于红黑树）都可能会让数据在玩家死亡等有可能产生全新的 Player 对象的情况下失去同步！[sup]手动实现 Comparator<Player> 的另说，这里不作讨论，且仍无法解决内存泄漏的问题（根据楼主提供的异常信息，SpongeForge/SpongeVanilla 上的 Player 的幕后应该是 net.minecraft.entity.player.EntityPlayerMP（MCP 名），它持有对 World 的引用，若不能正确回收会导致一连串东西堆积在内存中）[/sup]
简单的解决方案参考下面。
  1. import java.util.HashMap;
  2. import java.util.Map;
  3. import java.util.UUID;

  5. Map<UUID, Double> theMap = new HashMap(); // 不过为啥要用 TreeMap？HashMap 已经足够了。

  7. // Sponge 中获取玩家 UUID 的方法是 getUniqueId()。
  8. // 对于其他框架（Bukkit/Spigot、FML/Forge 等）来说操作可能有少许不同，但基本思路都是一致的，
  9. // 使用 UUID 等轻量、可比较（正确实现了 equals 和 hashCode）、可持久化且时刻保持唯一的标识符
  10. // 来作为 Map 的键。用玩家名自然也可以，但会在玩家改名后出现数据不同步的问题，请慎重考虑。
  11. theMap.put(player.getUniqueId(), data);
