效果


想如何探测的时候首先是方法的问题。原本是想在视线方向生成实体什么的...然后@1041159637 提出了检测玩家视角旋转（虽然事后觉得这个方法也没多难想到），即通过对比玩家上1tick和当前tick的rotation值来判断当前玩家旋转视角的方向，并在这个方向向反方向改变的时候将记录转向次数的记分板的数量+1，次数到达三次则判定为一次点头或摇头。


然后就引申出了以下几个子问题：

       * 临界点问题（水平rotation从0度到360度如何处理）

       * 误触问题（即如何更灵敏地区别点头和摇头）

       * MJSB问题

1. 临界点问题

参考命令段：

  1. execute as @a run scoreboard players operation @s calx = @s nowx
  2. execute as @a run scoreboard players operation @s calx -= @s prex
  3. scoreboard players remove @a[scores={calx=181..}] calx 360
  4. scoreboard players add @a[scores={calx=..-181}] calx 360
复制代码
     旋转方向是通过对前后tick的rotation进行作差得到的。若这个差值的绝对值超过180度就为这个值加上或减去360度。
      举个例子：
             比如我上一tick的Rotation[0]值是300度，而这一tick的Rotation[0]值是20度，两值作差得转过的角度是-280度，但是更有可能的情况是我过+80度这条劣弧旋转了过去。

2. 误触问题

参考命令段：

  1. execute as @a run scoreboard players operation @s calc = @s calx
  2. execute as @a[scores={calx=..-1}] run scoreboard players operation @s calc *= @s full
  3. execute as @a[scores={caly=..-1}] run scoreboard players operation @s calc += @s caly
  4. execute as @a[scores={caly=1..}] run scoreboard players operation @s calc -= @s caly
  5. execute as @a[scores={calc=1..,time=1..,calx=1..,rota=3}] run scoreboard players add @s time 1
  6. execute as @a[scores={calc=1..,time=1..,calx=..-1,rota=1}] run scoreboard players add @s time 1
  7. execute as @a[scores={calc=..0,time=1..,caly=1..,rota=4}] run scoreboard players add @s time 1
  8. execute as @a[scores={calc=..0,time=1..,caly=..-1,rota=2}] run scoreboard players add @s time 1
复制代码
      full是一个值衡为-1的记分板。
       明了地说，就是通过比较水平和竖直rotation变化量的相对大小，来确定这1tick鼠标移动的大致方向。

3. MJSB问题

参考命令段：

  1. execute as @a store result score @s nowx run data get entity @s Rotation[0]
  2. scoreboard players add @a[scores={nowx=..-1}] nowx 360
复制代码
      出于mojang sb的原因，直接data get store result有时会让记分板出现负值...
       所以额外添加一条命令吧记分板的值控制在0到360之内
