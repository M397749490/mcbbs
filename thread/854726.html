啊没错又是我，我又来问一些稀奇古怪的事了。
最近试图用盔甲架搞各种花样，已经有各种各样的大佬教我使用各种各样的命令了但是问题还是源源不断的往外跳啊。。
情况是这样，我的目的是在各种各样的掉落物上召唤手持对应道具的盔甲架，然而我发现在使用原版命令修改盔甲架的手持道具的过程中，无论是使用store result还是scoreboard，都只能存储数字信息，不能存储字符串，而即便使用tag或者name存储了字符串，也无法正常套到命令中使用，这导致一套命令只能对应一种道具，指令无法根据掉落物的不同动态调整手持物，这样一来代码量和执行量过大，势必对游戏过程造成影响。

象下面这些情况，就是现在的症结所在。

data merge entity @e[type=armor_stand,limit=1,sort=nearest] <nbt>
这个末尾的nbt部分，里面包含了我想要修改的HandItems的id与Count属性，写出来是这样的
{HandItems:[{id:"dirt",Count:1b}]}
试图在summon armor_stand的过程中填写nbt也是这个格式，指令套指令确实是不现实啊。。

然后另外一种改法
replaceitem entity @e[type=armor_stand,limit=1,sort=nearest] weapon.mainhand <item> [count]
在这个指令里面的item部分，只能直接填方块id，填其他的任何东西指令都不成立。于是抛掉它。

我不知道该如何把
data get entity @e[type=item,limit=1,sort=nearest] Item.id和data get entity @e[type=item,limit=1,sort=nearest] Item.Count
这两条指令获得的数据塞进去，加引号会变成字符串，不加命令根本不成立，有没有一种方法，就是把这得到的数据存储到一个变量里，再把这个变量塞到上面的nbt信息中？

或者是有没有一种手段能实现我这种设想？
跪求大佬。

好吧大佬也救不了我。看起来1.13.2就只能针对特定情况写指令了。

类似的办法，这次你用(中间那条)
  1. scoreboard players set @e[type=armor_stand,tag=take] countcheck0 0
  2. execute as @e[tag=take,type=armor_stand] store success score @s countcheck0 run data get entity @s HandItems[0].Count
  3. execute as @e[type=armor_stand,tag=take,scores=[countcheck0=1..] run say helloworld
复制代码

能成功获取到Count就代表手上有至少一件物品。(爪机码字可能有错...)
