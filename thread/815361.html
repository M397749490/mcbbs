1.权限分配的注意事项

①可能在ESS插件中经常会直接上*号来进行权限通配，在sponge服务端这样做会出大事情（我也不知道是什么，大家都这么说的[滑稽]，但还是谨慎）
②以前常用的op 玩家ID 来给予OP权限的方法可以说是几乎全面失效，而你需要做的则是给予你想要给予管理权限的玩家 * 权限，具体指令为 ： /lp user [玩家ID] set *（其他教程所说的permission加也行不加也行其实是同一个效果）
③在给予了玩家 * 权限后上线自动隐身而且貌似不会有进入游戏的提示，且afk状态失效，要关闭隐身直接输入/v指令即可
④请确保了你给予了你自己 * 权限后再进行下一步的阅读
⑤玩家的默认组为default，暂时未找到方法更改，因此请在给予普通玩家权限的时候都给到default这个组
⑥在使用lp插件时请多多使用tab键，你会发现你的输入速度会高不止一两个档次[几乎所有都可以用tab键连权限都可以]

2.如何管理一个组的权限？

①创建一个新组：/lp creategroup [组名]，使用以上指令来创建一个全新的权限组
②在创建了组后，肯定又要一条条的重新把权限从default组转移过来了？完全不用，我们要做的是继承default组的所有权限。假设我创建了一个名为vip的组[组名不分大小写],要继承default组的所有权限，那我们所要用到的指令则是/lp group vip parent default 即/lp group [继承组] parent [被继承组]
③那现在我们肯定要给组设定一些权限了，不然玩家什么都干不了可是会生气哦！以nucleus基础插件的back权限[nucleus.back.base]为例,我们要给予玩家权限组这个权限，则需要输入/lp group default set nucleus.back.base来给予default权限组这个nucleus.back.base的权限。那如果我一不小心手挫输错了权限那我该怎么取消呢？还是以上面的back权限为例，只需输入/lp group default unset nucleus.back.base即可

3.如何管理一个玩家的权限？

①如何给予一个玩家权限？很简单，只需要把上面的指令中的group改成user、把组名改成玩家ID即可，即/lp user [玩家ID] set/unset [权限]即可
②上面说了，我们要谨慎使用通配符*，但是在很多时候*符号可以帮助我们解决很多事情。以nucleus基础插件的lore权限为例，如果我想要给予玩家有关于lore的所有指令的使用权限,那么我们可以直接输入/lp user YoungGSL[这是我的ID] set nucleus.lore.set.*，那我就给予了玩家这个lore.set权限中所包含的所有子权限当然也包括命令，但其中就包含了很多指令，那如果我不想让玩家使用其中一个指令，比如说/lore add[对应权限nucleus.lore.set.base]，那么我可以输入/lp user YoungGSL set nucleus.lore.set.base false来禁用玩家使用这个包含权限的指令。
具体总结下来就是，给予玩家一个权限里面的所有子权限，输入：/lp user [玩家ID] set [权限名].([权限名]).*,而要禁用其中的一个权限，则需要输入/lp user [玩家ID] set [权限名].([权限名]).[要禁用的权限名] false,以上指令同样适用于权限组，方法还是一样，把user换成group即可
③如何将一个玩家移动到特定权限组？具体指令：/lp user [玩家ID] parent add [权限组名]

4.如何给予一个玩家临时[限时]权限[组]？

前言:sponge端的唯一VIP插件PixelVIP对于我的模组服务器貌似是用不了的，而且配置也较为对新手不友好，因此对于简单的VIP权限给予使用本节内容即可解决
假设我建了一个VIP组就叫vip，已经配置权限完成，现在有一个叫YoungGSL的玩家从我这里买了一个月的VIP，这时候我只需要在后台/游戏里输入:/lp user YoungGSL parent addtemp vip 30d

1.如何快速配置玩家基础权限

Nucleus插件的权限之多完全可以和ESS插件相媲美，要是一个一个权限的进行添加那手都要累死，不过Nucleus插件给出了一个快速配置玩家权限的指令:/nucleus setupperms user defalut,其中default可以换成其他任意组的名字，这样就可以一键配置出玩家的基础权限，但是需要注意的是，默认权限中无/back指令权限与/rtp[随机传送]权限，可以根据自己的需要进行添加

添加/back权限指令：/lp group default set nucleus.back.base

添加/rtp权限指令:/lp group default set nucleus.rtp.base

附：发现有的时候配置后玩家会默认出现/fly指令可用的情况，因此请手动输入/lp group default unset nucleus.fly.base,来取消玩家的飞行权限

4.如何配置礼包？
①如何设置新玩家进服的默认礼包
这个时候我们所要用到的就是kit指令了,先把你想要发放给新玩家的物品准备好在物品栏里，接着使用/kit create [礼包名]来打开一个礼包创建界面，把你准备好的物品全部放到GUI里面，接着关闭就可创建完毕了。
假设我这里创建的是一个名叫first的礼包[允许中文名，区分大小写],那么我接下来所需要输入的指令就是/kit setfirstjoin first，就可以将这个礼包设置为第一次加入的时候默认送出的礼包，即/kit setfirstjoin [礼包名],暂时不清楚能不能设置多个，有知道的可以留言回复告诉我！
②如何设置一个一次性礼包
还是以上面的first礼包为例，我们现在需要输入的则是/kit onetime first，即/kit onetime [礼包名]
③如何设置一个付费礼包
同上，如果我们想要把礼包定价为100元，则需要输入/kit cost first 100,即/kit cost [礼包名] [定价]
④如何设置一个需要特定权限才能领取的礼包
同上，在游戏里输入/kit permissionbypass first false，设置之后则会检测玩家是否有nucleus.kits.first权限，如果没有则无法领取，即设置指令为/kit permissionbypass [礼包名] false,对应权限为nucleus.kits.[礼包名]权限,想要关闭的话直接把上述指令的false改成true即可
⑤如何更改礼包内容以及礼包名字
更改礼包内容：/kit edit [礼包名]
更改礼包名字/kit rename[礼包名] [想要改成的名字]
4.如何配置多世界？

前言：Nucleus自带的多世界模块不可谓是不强大，甚至秒杀了同类的基本所有插件，因此完全不建议去安装sponge端的多世界插件ProjectWorld，下面我将会以如何创建一个普通世界、特定世界（末地/地狱）、从外部导入世界、如何设置一个世界的多种选项来进行讲解

建议先使用/world来查看所有指令

①如何创建一个普通世界？

使用指令/world create [世界名] 就可以创建出一个最普通的世界了，之后，可以将这个指令延长再延长来进行一系列的设置

④如何设置一个世界？

世界难度设置：/world setdifficulty [难度]（难度参考 和平:Peaceful 简单:Easy 正常:Normal 困难:Hard）

世界规则设置：/world gamerule [规则] true/false（可以不带world 只能设置在当前所在世界）

建议开关的规则：

开启死亡不掉落：/gamerule keepInventory true
(另如何开启全局死亡不掉落？给default组增加以下权限即可：nucleus.inventory.keepondeath)

开启生物防爆（TNT请自行ban了）：/gamerule mobGriefing false

关闭火势蔓延：/gamerule doFireTick fale

2.如何配置领地方块的获取？
前言：用过的人都知道，这款领地插件圈地所使用的是领地方块而并非金币，领地方块又是通过在线时间获取的，因此领地方块的个性化需求配置就显得很为必要了
①如何设置玩家/权限组最大可获取的领地数量？（指令）
具体指令为：/lp user/group [玩家名/组名] meta set griefprevention.max-accrued-claim-blocks [领地方块数量上限]
例如我要设置default组可获得的最大领地方块数量为10k，那么我应该输入的指令就是：/lp group default meta setgriefprevention.max-accrued-claim-blocks 10000
这样当这个玩家领地方块达到10k的时候就无法再继续获取了
②如何设置玩家/权限组最大每小时可获得的领地方块数量？（指令）
具体指令：/lp user/group [玩家名/组名] meta set griefprevention.blocks-accrued-per-hour [领地方块数量]
提示：如果设置为0的话即为关闭领地方块的在线赠送
③如何设置权限组进服默认拥有的领地方块数量？（指令）
具体指令：/lp group [组名] meta set griefprevention.initial-claim-blocks [领地方块数量]

先说明一下这两个选项是什么？
claim-block-cost选项即是领地方块**的价格，单位为元/块
claim-block-sell选项即是领地方块收购的价格，单位为元/块

前言：为什么写上个慎用？原因很简单，BUG一堆加上崩服风险（据说作者当初发出来的就是半成品）让我都很想把这个插件卸了，然而他作为Sponge端唯一可用的地皮插件和自己服务器的特殊需求，让我都不得不冒着风险去使用它，在此特别强调，如果非必要，请不要安装这款插件！另外，插件是否汉化对使用没有任何干扰，不用特地去寻找汉化版，使用英文版加上插件百科就已经足够了！
已知BUG：
1.请不要尝试使用插件自带的模版进行生成，尤其是town模版，极大可能出现报错并且崩服（如上面的埋下崩服隐患），请使用插件自带的/p setup进行生成
2.目前正常的模版有Skylands模板和比较正常的Bridege模板，Bridege模板也有几率会崩服，但是没town模板那么大，而且一个关键的问题是，玩家传送到地皮时，是在桥上，而桥上有栅栏，根本跳不下去，因此不推荐使用

3.玩家在死亡后会出现使用/p h和/p visit指令都无法回到地皮的情况，会显示“已传送(have been teleported)”，解决方法就是退出服务器再重新进入，或者推荐玩家在地皮设置家

5.整个地皮世界所有玩家都可以无视权限放置流体，包括mod里的流体

1./p setup（开始创建一个新的地皮世界）
2./p setup PlotSquared

（不用输英文名，直接输入ID，建议输入 3 泥土，如有特殊需要再进行更改）
7./p setup [地皮表面方块ID]（同上，建议为 2 草方块）
8./p setup [认领前的围墙ID]
（默认为44，不建议使用整块方块，建议使用栅栏或者是半转）
9./p setup [认领后的围墙ID]
（同上，可输入两个ID相同的方块）
10./p setup [道路宽度]（默认为7 自定义更改）
11./p setup [路面高度]（数值同上面的地皮高度）
12./p setup [铺设路面的方块]（随意，不建议使用发光方块）
13./p setup [墙下方块]（建议石头或是基岩）（如图圈起来的部分）
14./p setup [墙高]（数值同路面高度）
15./p setup true/false（底部是否开启基岩 根据需要 非常建议开启）
16./p setup [地皮世界名字]（不能中文 会乱码 请慎重起名）

使用/p save进行地皮保存[全部]，使用/p load进行地皮读取[全部]
