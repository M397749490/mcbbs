Slime World Manager
史莱姆世界管理
—— 优化性能加载世界 ——


SlimeWorldManager是一款Minecraft服务器插件，它根据Hypixel开发团队开发的Slime Region Format而诞生
其目的是为服务器管理员提供更容易使用并管理世界，还能更快地加载世界并节省空间


使用SWM插件存储并管理世界有四个主要的好处：
  • 速度：Minecraft是使用zlib压缩世界，虽然这个库更新得好，但是已经有24年了。而现在有了更新得压缩算法。SRF使用Zstd保存世界，它既更快又具有更大得压缩优势。你可以看到zlib和zstd的比较：
  • 减少硬盘占用：ARF（Minecraft用于存储世界的格式）包含了大量不必要的数据，因为它是为大型生存世界设计的，而不是为小型服务器设计的。当你存储迷你游戏地图或大厅时，实际上可以节省大量无关的东西。如果你想了解更多相关消息，可以看Minikloon制作的视频（需要科学上网，我木有梯子莫得办法）
  • 没有性能影响：SWM使用内存世界，这说明整个世界能立即加载。如果每次服务器需要加载一个区块时，它是从内容中读取的，而不是从文件系统中读取，然而将其转换为可用的内容。于是，这就实现了无缝加载区块
  • 允许存储世界于其它位置：传统的世界必须保存于服务器根目录中，不过，SWM允许你从各种渠道（如MySQL或MongoDB）加载世界。多亏这一点，你可以同时从多个服务器加载相同的世界，而无需重复创建它的副本。另外，如果你想使用SWM不支持的其它数据渠道中存储世界，你可以通过API创建自己的世界加载器


注意，SWM并非应用于大型生存世界，而是用于小型世界，诸如迷你游戏地图或服务器大厅

命令&权限（注：<>为必填参数，[]为选填参数，<data-source>在教程配置中提到）
/swm help
权限：无
说明：显示插件帮助，仅显示你有权访问的命令

/swm version
权限：无
说明：显示插件版本

/swm reload
权限：swm.reload
说明：重载配置文件

/swm goto
权限：swm.togo
用法：/swm goto <世界> [玩家]
说明：将自己或其它玩家传送到指定世界
（该命令也可以用于传统的世界）

/swm list
权限：swm.worldlist
用法：/swm list [ slime ] [页数]
说明：列出所有世界。包括非SRF世界，如果使用slime参数，则仅显示SRF世界

/swm dslist
权限：swm.dslist
用法：/swm list <data-source> [页数]
说明：列出指定数据渠道中所有世界。注意，该命令不仅列出配置文件中的世界，也会列出数据渠道中的世界

/swm import
权限：swm.importworld
用法：/swm improt <path-to-world> <data-source> [页数]
说明：将世界转换为SRF世界并存储到指定数据渠道中。你可以看更多相关信息：点击

/swm load
权限：swm.loadworld
用法：/swm load <世界>
说明：从配置文件中重载指定世界。请不要忘记在转换为SRF世界后去配置一下。更多相关信息：点击

/swm load-template
权限：swm.loadworld.template
用法：/swm load-template <template-world> <world>
说明：复制提供的模板世界。这样可以创建同一世界的需要副本

/swm create
权限：swm.createworld
用法：/swm create <世界> <data-source>
说明：创建一个空的世界并存储于指定数据渠道中。该命令还会自动将世界保存于配置文件中

/swm unload
权限：swm.unloadworld
用法：/swm unload <世界>
说明：从服务器中卸载该世界

/swm migrate
权限：swm.migrate
用法：/swm migrate <世界> <new-data-source>
说明：将世界从当前存储的数据渠道传输到指定的数据渠道

/swm unlock
权限：swm.unlockworld
用法：/swm unlock <世界> [data-source]
说明：从世界中删除锁定，因而可以在不使用只读模式下访问
当加载 没有启用只读模式的世界时，SWM会自动锁定世界，因此没有其它服务器可以同时加载它，以防世界损坏。但是，如果服务器崩溃，则可能永远无法删除该锁
注意：你必须在SWM告诉你使用此命令，否则你的世界可能会损害。为了确保你没有错误地执行该操作，你必须输入两次命令

/swm delete
权限：swm.deleteworld
用法：/swm delete <世界> [data-source]
说明：完整地删除世界。如果没有提供数据渠道，则将使用配置文件中指定地数据渠道
要注意，该操作的结果是永久性的，一旦删除世界，无法还原。为了确保你没有错误地执行该操作，你必须输入两次命令

安装插件方式

安装SWM是一个很容易的操作，首先从原帖下载最新版本
然后接着以下步骤操作
  • 打开下载的zip压缩包
  • 将 slimeworldmanager-plugin-.jar 放在服务器插件文件夹中

覆盖默认世界或Spigot-1.14中使用SWM的额外步骤
  • 将 slimeworldmanager-classmodifier-.jar 放在服务器的主目录中（而不是插件文件夹）
  • 在 bat 加上服务器启动参数
    1. -javaagent:slimeworldmanager-classmodifier-<version>.jar

如何使用SWM

SWM需要加载世界，否则是没用的。首先，你必须将世界转换为SRF，因而SWM可以加载它
将传统地世界转换为SRF
1.使用命令（推荐）
  • 将世界放在服务器的根目录中
  • 确保世界是未使用状态。因为被使用中的世界无法进行转换
  • 使用命令 /swm import <世界文件夹名称> <data-source> [new-world-name] 如果你希望世界与world文件夹具有相同的名称，只需要忽略[new-world-name]参数即可
  • 完成！世界现在被存储于你提供的数据渠道（data-source）
2.使用导入工具（也就是...编程那样的工具吧，后面文中会提到，即“导入工具”）
不推荐你使用该方式，因为上面提供的方式更快更容易。但是你如果仍想使用该方式，请按以下步骤进行操作
  • 将世界与导入工具放在一起
  • 打开cmd
  • 输入以下命令
    1. java -jar slimeworldmanager-importer-1.0.0.jar <世界文件夹名称>
    复制代码
    它会自动扫描世界并在你放置它的同一目录中生成.slime文件，那就是你的世界！

一旦你将世界存储到指定数据渠道中，你必须对其进行配置，以便插件知道存储世界的位置以及生成位置等
配置世界，请打开SWM配置文件夹中的 world.yml
以下是worlds.yml文件的示例：
  1. worlds：
  2.      my_great_world：
  3.          source：mongodb
  4.         loadOnStartup：false
  5.         readOnly：true
  6.         spawn：940,2 ，-370
  7.         allowMonsters：false
  8.         allowAnimals：false
  9.         difficulty：peaceful
  10.         pvp：false
复制代码
然后使用 /swm reload 命令保存并重新加载

配置说明
  • source
说明：存储世界的数据渠道名称
可选：file mysql mongodb，也可以使用第三方插件提供的任何其它数据渠道
  • loadOnStartup
说明：服务器启用时是否加载世界
可选：true false
  • readOnly
说明：如果为true，则永远不会存储世界的更改。如果为false，则世界将被锁定，因而没有其它服务器可以访问它
可选：true false
默认：false
  • spawn
说明：世界出生坐标
可选：x,y,z
默认：0,255,0
  • allowMonsters
说明：怪物可否在该世界生成
可选：true false
默认：true
  • allowAnimals
说明：动物可否在该世界生成
可选：true false
默认：true
  • difficulty
说明：世界的难度
可选：peaceful（和平） easy（简单） normal（普通） hard（困难）
默认：peaceful
  • pvp
说明：是否允许在该世界战斗PVP
可选：true false
默认：true

完成以上简单的操作就表示你已经保存并配置了新的世界，那么是时候加载它了，使用命令 /swm load <世界>
现在，你还可以使用命令 /swm goto <世界> 传送到这个世界

设置数据渠道
在使用MySQL或MongoDB存储你的世界之前，你必须配置它们
为此，请到plugins文件夹中的SWM配置文件夹，打开 sources.yml 文件，里面有你需要设置的所有参数
以下是 sources.yml示例
  1. file:
  2.     path: slime_worlds # 存储该世界文件的路径
  3. mysql:
  4.     enabled: true
  5.     host: 127.0.0.1
  6.     port: 3306
  7.     username: my_mysql_username
  8.     password: my_mysql_password
  9.     database: slimeworldmanager
  10. mongodb:
  11.     enabled: true
  12.     host: 127.0.0.1
  13.     port: 27017
  14.     username: my_mongo_username
  15.     password: my_mongo_password
  16.     auth: admin
  17.     database: slimeworldmanager
  18.     collection: worlds

迁移世界
迁移世界需要三件事：世界文件夹，世界名称和数据渠道
以下是世界迁移示例

  1. SlimePlugin plugin = (SlimePlugin) Bukkit.getPluginManager().getPlugin("SlimeWorldManager");

  3. String worldName = "my_world";
  4. SlimeLoader currentLoader = plugin.getLoader("mysql");
  5. SlimeLoader newLoader = plugin.getLoader("mongodb");

  7. try {
  8.     // 注意，此方法应是异步
  9.     plugin.migrateWorld(worldName, currentLoader, newLoader);
  10. } catch (IOException | WorldInUseException | WorldAlreadyExistsException | UnknownWorldException ex) {
  11.     /* 异常处理 */
  12. }

使用其它数据渠道
SWM本身支持三种数据渠道：文件，MySQL，MongoDB
但是在某些情况下你可能希望使用其它数据渠道，为此，你可以使用SlimeLoader接口实现
SlimeLoader是用于从特定数据渠道加载世界的类。在使用SlimeLoader接口时请先查阅文档，文档中包含需要内容
你还可以查阅FlieLoader类以获取SlimeLoader的示例
一旦你有了自己的SlimeLoader，请不要忘记注册它
  1. SlimePlugin plugin = (SlimePlugin) Bukkit.getPluginManager().getPlugin("SlimeWorldManager");

  3. plugin.registerLoader("my_data_source", new MyCustomSlimeLoader());
