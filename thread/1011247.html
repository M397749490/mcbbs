  2. "1个字符串"

接着在cs4mod.json里使用ANSI编码填写以下代码：
  1. {
  2.     "id": "mymod",
  3.     "name": "我的第一个cs4mod",
  4.     "version": "1.0.0"
  5. }
复制代码
【代码解析】
（以后所有加粗字体为必填项）
·id：这个mod的id，类型为字符串，只能填小写的英文字母和下划线
·name：这个mod在mc里显示的名字，类型为字符串
·version：该mod的mod版本，类型为字符串
然后在mcmod.info里使用UTF-8编码填写以下代码（除了cs4mod.json，所有文件都应该使用utf-8编码）：
  1. [
  2.     {
  3.         "modid": "mymod",
  4.         "name": "我的第一个cs4mod",
  5.         "version": "1.0.0",
  6.         "description": "这是我的第一个cs4mod！",
  7.         "url": "",
  8.         "updateUrl": "",
  9.         "authorList": ["woshi魔王","woshimowang"]
  10.     }
  11. ]
复制代码
【代码解析】
·modid：与cs4mod中的id意思相同，内容与cs4mod中的须相同
·name：与cs4mod中的name意思相同，内容与cs4mod中的须相同
·version：与cs4mod中的version意思相同，内容与cs4mod中的须相同
·description：mod的注释，在模组菜单上可以看到，类型为字符串
·url：mod的官网，在模组菜单上可以看到，类型为字符串
·updateUrl：mod的更新网页，在模组菜单上可以看到，类型为字符串
·authorList：mod的作者，在模组菜单上可以看到，类型为数组
其实还有其它的参数，但是基本上有用的就这几个
注意：当你更改了cs4mod.json或mcmod.info时，需要删除cs4mod文件夹再重新启动游戏。
完成这些后，我们就可以开启游戏再把它关掉，这样之后，那个文件夹里应该会出现一个assets文件夹，cs4mod文件夹中会出现一个class文件。

【代码解析】
首先，第一行（简称ln1）到第十五行的对象，就是整个json文本的打包对象。这个对象把所有的参数打包起来，让json得以消化。
ln2的content值的键是一个数组，这个数组将所有的添加内容包裹住，这个数组中包含的都是对象，一个对象代表一个添加的内容类。
ln3~ln12就是一个内容类，一个内容类中会包含多个内容，但是类别相同。
内容类参数：
    ·type：这个内容类的类别，如item:simple、creativeTab等等，类型为字符串
    ·entries：这个就要重点介绍了。entries就是储存这个内容类中添加的所有内容的列表，类型为数组，里面就是这个内容类的所有添加内容，每个都  由对象打包

你还可以使用

  1. {
  2.     "file": "xxx.json",
  3.     "requireModsLoaded": ["xxx","xxx"],
  4.     "requireModsNotLoaded": ["xxx","xxx"]
  5. }
复制代码
【代码解析】
·requireModsLoaded：这个文件在已经加载了数组中的所有mod的情况下才能被加载，需要填写该mod的modid，类型为数组
·requireModsNotLoaded：这个文件在没有加载数组中任何一个mod的情况下才能被加载，需要填写该mod的modid，类型为数组

创造模式物品栏就是储存了所有创造模式物品的快捷拿取栏。
作为一个做mod的mod，cs4当然可以添加创造模式物品栏，但是这个自己添加的创造栏里面，只能添加这个mod的物品/方块。

  7.         }

  9. }

【代码解析】

·id：该创造模式物品栏的id，为全端通用，所以尽量id号取生僻点，类型为字符串
·icon：该创造模式物品栏的图标物品id号，类型为字符串

嗯？是不是有些怪怪的？
没错，它的名字是一串乱码：
itemGroup.my_first_creativetab
如果有些观察力强的人一定能发现，itemGroup就是创造模式物品栏，而后面就是我们这个creativeTab的id。
这个时候，有一定好奇心的人肯定发现这个mod少了语言文件。
我们先来看看语言文件的定义：
语言文件，即后缀名是.lang的文件，一般放到assets/modid/lang文件夹里，用于将mod中的乱码变成所有人都可以看懂的文字。

懂了没？
我们现在就来做一个语言文件：
首先要在assets/你的modid/lang文件夹中创建一个后缀名为.lang的文件，然后改名：
如果是语言为英语的语言文件，名字改成en_US.lang；
如果是语言为简体中文的语言文件，名字改成zh_CN.lang；
如果是语言为繁体中文的语言文件，名字改成zh_TW.lang。
当然还有其它语言的语言文件Minecraft一百多个语言可不是吹的你们可以问度娘。

名字更改完了之后，打开语言文件，我们以刚才那个my_first_creativetab为例子：
还记得刚才这个creativeTab因为语言缺失而显示的乱码吗？
没错，是itemGroup.my_first_creativetab。
我们只需要在语言文件中输入：
  1. itemGroup.my_first_creativetab=我的第一个创造模式物品栏
复制代码
【代码解析】
其实语言文件的道理很简单，他就是把原来的乱码添加一个“别名”，而我们刚才的乱码是itemGroup.my_first_creativetab，所以我们只要给这团乱码添加一个别名，用[乱码]=[别名]来添加。
语言文件自动忽略空行和双斜杠//后面的文字。
添加完之后，再次启动游戏，你就可以看到那个乱码变成你想要的名字了！

5、添加熔炉合成
要知道，一个mod就算再怎么好，合成也是必不可少的东西。
而cs4正好给我们提供了一个添加熔炉合成的方式。
来大家跟我一起步伐整齐划一默写出这串内容类：
  1. //type:smeltingRecipe
  2. {
  3.     "input": "",
  4.     "result": {
  5.         "item": "",
  6.         "amount": 3
  7.     }
  8.     "xp": 0.233
  9. }
复制代码
【代码解析】
我觉得会一点英语的人已经懂了。
对了，//是注释的意思，后面的内容不会被读取。
·input：输入熔炉的物品id，类型为字符串
·result：烧熔炉获得的成品，类型为对象
·item：烧出的物品id，类型为字符串
·amount：烧出的物品数量，类型为数值
·xp：烧制一次获得的经验数量，类型为数值
其实我个人觉得xp是烧制一次获得经验的几率，毕竟无论我怎么调经验都是获得同样的经验。根据我的实验，我发现xp小于1的有几率获得经验，xp大于1的一定获得经验。

7、物品·初级篇
众所周知，一个mod的精髓，不是精美的特效，不是精巧的逻辑，而是最基础的物品和方块。
这次，我们就来做一个最简单的物品。
因为物品通常有很多，所以我们把它放在另一个文件里。
首先在mod里新建一个json文件，名字随意。

然后在里面跟main.json一样填写：
  1. {
  2.     "content": [
  3.     ]
  4. }
复制代码
同理，跟main.json一样输入这个内容：
  1. //type:item:simple
  2. {
  3.     "id": "",
  4.     "model": "",
  5.     "creativeTab": "",
  6.     "information": ["",""],
  7.     "maxDamage": 10,
  8.     "tint": "red",
  9.     "burnTime": 888
  10. }
复制代码
【代码解析】
这次的type有点不一样，为item:simple，这前面的item代表这是一个物品，而后面的simple代表这个物品什么也不做，一般是一种材料。
这些参数并不是item类的所有参数，但这是所有全部的物品都能使用的参数。
还有一个仅仅适用于item:simple和item:food的最大堆叠参数maxStack，范围为1~64，过于简单不再赘述。
·id：该物品的id，类型为字符串
·model：该物品的模型文件，格式为所属mod:模型文件名（不需要后缀名），默认文件为该mod:该物品id，会查找该mod文件夹（也就是assets/modid）/models/item/模型文件名.json的文件，类型为字符串
·creativeTab：该物品所属的创造模式物品栏id，不需要写所属mod，因为创造模式物品栏全服通用，类型为字符串
·infomation：这个物品的注释，会出现在物品名字下面，默认颜色为灰色，可以用§改变，数组中的每一个项都是一行注释，类型为数组
·maxDamage：该物品的最大耐久，一般不会损耗，可以用于合成，类型为数值
·tint：该物品要被涂上什么颜色，如red、orange等等，类型为字符串
·burnTime：见熔炉燃料篇，默认值为-1（不能当做燃料），类型为数值
你当然可以使用mc或者其他mod自带的模型，比如minecraft:barrier，这样这个物品的外形就是屏障的样子。
但是有的时候，你需要自己创建一个模型文件。
你当然可以使用blockbench等来做3d模型，所以这次我就讲解一下最简单的2d物品模型的做法。
首先在assets/modid/models/item文件夹中创建一个名为你设置的模型文件名的json文件。

然后打开这个json文件，输入这些东西：

【代码解析】
·parent：说明这个模型是以什么为原型的，也就是这个模型的“父类”，比较难理解，我们只需要知道item/generated（就是一般的物品的显示方式）和我们后续提到的几个种类就行了，类型为字符串
·textures：这是几种parent种类的特有参数，定义这个模型的材质，类型为对象

8、物品·Damage篇
如果你是技术人员，那肯定知道Damage是什么。
但是……肯定有些人不知道，在疑惑为什么物品篇中会有一个Damage。
我们来康康一些资料：
物品损耗值（即Damage）有两个用处：
1、定义工具已经损耗的值（比如用过一次的钻石剑损耗值为1）；
2、定义同类物品的不同形态（如染料使用的都是同一个物品id，但形态不同，这是因为他们的Damage不同）。

懂了不？
cs4也支持损耗值，但在wiki中被称为元数据类型（Metadata Subtypes）。

  1. {

  7.     }
  8. }

【代码解析】

·model：model应该大家都熟悉，定义这个物品的模型。但是，在这个物品支持Damage（也就是有subtypes参数）的情况下，参数中填写的东西发生了改变。支持的Damage为键，这个Damage值使用的模型为值。类型为对象

9、物品·斧镐铲剑篇
cs4的物类别品可谓是无比丰富，这次我们来康康它如何添加斧、镐、铲、剑这些简单的工具。只是没有锄

【代码解析】
·material：定义工具的材料，根据材料决定工具各个参数的默认值、挖掘速度和采掘等级。采掘等级分为石头（0）、铁（1）、钻石（2）、黑曜石（3）。材料分为wood（木）、stone（石）、iron（铁）、gold（金）、diamond（钻石），类型为字符串

11、物品·食物篇
说实话，我觉得cs4的食物方面是做得比较鸡肋的，尤其是药效方面，没法控制药效等级，也没法添加多个药效。
但毕竟这是全面的cs4教程，我就把这个写进去了。
cs4的食物是这样添加的：
  1. //type:item:food
  2. {
  3.     "id": "",
  4.     "maxStack": 16,
  5.     "healAmount": 10,
  6.     "saturation": 0.5,
  7.     "alwaysEdible": true,
  8.     "potionEffect": {
  9.         "id": "minecraft:speed",
  10.         "duration": 200
  11.     },
  12.     "potionEffectProbability": 0.5,
  13.     "isWolfFood": true,
  14.     "result": "",
  15.     "useAction": "drink"
  16. }
复制代码
【代码解析】
·maxStack：物品的最大堆叠值，范围为1~64，默认为64，类型为数值
·healAmount：物品回复的饱食度，默认为2（半格饱食度算1），类型为数值
·saturation：物品回复的饱和度，饱和度是新版本加入的机制，改变了旧版本机制，使战斗中可以快速回复血量。关于什么是饱和度：http://mc.163.com/strategy/guide/2017/07/27/26471_702806.html，默认为0.6（半格饱和度为0.05，满饱食度为1），类型为数值
·alwaysEdible：定义这个物品能不能在饱食度为满的情况下食用，默认为false（不能在饱食度为满的情况下食用），类型为布尔
·potionEffect：定义这个物品食用后给玩家添加的效果，默认什么都没有，类型为对象
·id（potionEffect）：添加的效果的id，如速度id为minecraft:speed，类型为字符串
·duration：效果的持续时间，单位为tick，类型为数值
·potionEffectProbability：药效添加的几率，默认为1（一定会添加），类型为数值
·isWolfFood：定义该物品是否能给狼吃（给狼回血，当然，如果你要驯服它还是得用骨头），默认为false（不能），类型为布尔
·result：吃掉该物品返回的物品id，如喝掉药水返回了玻璃瓶，默认什么都不会返回，类型为字符串
·useAction：该食物的类型，可以填入drink（喝的）和eat（吃的），食物类型决定了食物吃的音效和粒子效果，默认为eat，类型为字符串
值得一提的是，食物的所有参数都支持Damage值。
就像这样：
  1. {
  2.     "subtypes": [0,1,2],
  3.     "maxStack": {
  4.         "0": 1,
  5.         "1": 2,
  6.         "2": 3
  7.     },
  8.     "model": "minecraft:diamond"
  9. }

针对于物品的问题，这是因为你没有在main.json中将这个文件导入，因为cs4本身只读取main.json而不去理其它文件
针对于物品栏的问题，这是因为你的main.json的结构弄错了。
main.json
  1. {
  2.     "content": [
  3.         {
  4.             "type": "creativeTab",
  5.             "entries": [
  6.                 {
  7.                     "id": "xxx",
  8.                     "icon": "xxx:xxx"
  9.                 }
  10.             ]
  11.         },
  12.         {
  13.             "file": "item.json"
  14.         }
  15.     ]
  16. }
复制代码
item.json
  1. {
  2.     "content": [
  3.         {
  4.             "type": "item:simple",
  5.             "entries": .............
  6.         }
  7.     ]
  8. }
复制代码
每个json文件都是以content开头，其它的内容塞进数组里
