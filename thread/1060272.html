据我所知没有「正规的方法」。不过你或许可以尝试临时OP逻辑，即临时给玩家设置OP/具体权限，执行命令后再取消。
关于运行原版指令，可以直接使用 getServer().dispatchCommand(getServer().getConsoleSender(), "execute ..."); 让控制台代替执行。
另外如果插件提供了 API，比如 we 或者 vault，那么你更应该使用 API 而不是强迫玩家使用命令操作。比如让玩家给其他账户转账，那么你更应该使用 Java 方法(比如withdraw和give) 操作，而不是让玩家执行 money pay (..)

getConsoleSender() 返回了一个 ConsoleCommandSender, 也就相当于是你在控制台里执行命令, 是不存在选中某个玩家的情况的。Console 是没有位置的, 也不能通过 execute 获取 "位置", 因为控制台没有加入游戏也不是实体, 不存在 "控制台的位置" 这一说。
这个属于MC里面命令的范畴了, 另外 @p 是获取实体附近的玩家的.
我问了一下 spigot 开发论坛, 官方说服务端 CONSOLE 选择器位置就是 x=0,y=0,z=0. 所以 @p 实际上是选择了距离 x=0,y=0,z=0 最近的玩家。

> 它是如何保证被.getConsoleSender选中的玩家一定是那个触发了InventoryClickEvent事件的玩家呢？
这个我觉得你应该和>2个玩家一起做测试, 因为 @p 是代表的最近玩家, 而不是触发事件的玩家, @p 和 bukkit 没有关系的
