前言：关于JSON编写的技巧与诀窍
JSON是一个完美的数据文件，但是对于新手来说，仍然有一些细节会让入门者感到困惑。

首先，为了识别一个新的物品，我们需要在代码前后使用一个大括号“{}”来声明。在大括号中便是我们对该对象的描述了，我们通常称这两个大括号间的内容为一个“对象”。

对于一行描述，我们需要两个内容来让它能够被识别：名称和赋值。如果在一个对象中有多行声明，呢么我们需要在每一行的代码后加上一个逗号。完整的代码格式如下：

  1. {
  2.     "field1":"text 1",
  3.     "field2":true,
  4.     "filed3":100
  5. }
复制代码

需要注意的是，如果声明的内容是一个字符串，呢么在内容前后必须加上引号“ "" ”，如果声明是一个数字或是布尔值（true,false），呢么就不需要引号。

许多个对象写在一起就组成了一个类，我们需要在一个类的前后加上一个中括号“[]”。在每两个类之间，也需要用逗号来连接。具体格式如下：

  1. [
  2.    {
  3.       "field1-1":"text 1",
  4.    "field1-2":true
  5.    },
  6.    {
  7.       "field2-1":"text 2",
  8.    "filed2-2":false
  9.    }
  10. ]
复制代码

另外，如果在参数中出现字符组，请在参数前后也加上 [] ，否则游戏将会报错！！

最后还要提醒一句，在一些JSON文件中你会发现一些“根类”，这些类中的内容可能牵涉到游戏中的重要设置。所以在不完全了解他们的作用的情况下最好不要去修改他们。

名称 类型 描述 默认值
container 字符串 装载物品的容器，即物品在工作台合成后返还的容器，比如合成蛋糕返还桶 null
oreDictNames 字符组 这个物品归属的矿物字典id，格式为["矿物字典注册名"，"&&&&注册名2"] null
maxStackSize
 整数型 物品的最大堆叠数 64
burnTime 整数型 在熔炉中可以燃烧的时间（0即不是燃料） 0
rarity 字符串 物品的稀有度（通常为在地牢宝箱中的稀有度），可用值为
common（普通）, uncommon（不寻常）, rare（稀有）, epic（绝迹）		 "common"
enchanted 布尔值 是否在合成时自带附魔属性 false

自定义合成表
CustomThings的自定义合成表功能和MineTweaker的功能十分类似，但就目前来看它只能对于模组的兼容性还没有ModTweaker呢么简单明了。
工作台合成
要添加一个工作台合成的合成表，首先打开config/customthings中的shapedRecipes.json文件（有序合成）或shapelessRecipes.json文件（无序合成）。
一段有序合成的代码拥有3个变量：
名称 类型 描述 默认值
input 2维字符组 一张合成表的原料，格式是[["item1","item2],["item3","item4"]]。必填
output字符串 一张合成表的产物。必填
outputAmount 整数型 产物数量。 1

举个例子，用9个铁矿合成5个金矿（大雾）的代码如下：

  1. {"data":
  2.     [
  3.         {
  4.             "input": [["oreIron", "oreIron", "oreIron"],
  5.                       ["oreIron", "oreIron", "oreIron"],
  6.                       ["oreIron", "oreIron", "oreIron"]],
  7.             "output": "oreGold"
  8.         }
  9.     ]
  10. }
复制代码
无序合成的代码只需要将input中的每个中括号去掉即可（"input": ["oreIron", "oreIron", "oreIron", "oreIron", "oreIron", "oreIron", "oreIron", "oreIron", "oreIron"]）。

烧制合成
要添加一个烧制合成的合成表，首先打开config/customthings中的smeltingRecipes.json文件。
烧制合成的代码与有序合成也十分类似，但是它多了一个要填的值：
xp小数型 每次烧制可以获得几点经验点 0.0
烧制合成的合成表不光适用于熔炉，其他任何支持熔炉合成表的机器皆可适用。
