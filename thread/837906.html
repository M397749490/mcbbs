关于本次论坛的更新，我有几句话想说。

  • 论坛更新后，Empty Response 问题得以解决，但是 403 的问题还是持续存在。
  • 最外层的 CDN 应该还是腾讯云的 CDN，个人对于腾讯云的 CDN 感觉并不是很好，以前用过，体验不佳，防护效果较差。
  • 使用了一些工具进行扫描，发现论坛安装的插件数量较多，不排除是有部分插件优化不佳导致拖慢整体运行速度。
  • 之前在部分页面加载时，根据底部的统计数据可以看到，执行时间超过了 0.2s，现在快了一点。
  • 感觉是 MCBBS 的服务器配置不够，容我瞎猜一下，大概不超过 8 核 8G？

为什么会得出上面的部分结论呢？

首先，MCBBS 目前用的这套主题感觉上优化不是特别好，根据控制台的统计，首页加载的 CSS 共 3 个，JS 共 12 个。
有些 Js 像 JQuery 其实可以用很多公共的 CDN 服务代替，例如百度的前端公共 DNS，BootCss 等等。
然后就是请求数，一般来说请求数越少加载越快，可以尝试将多个 CSS、JS 合并为一个以缩短加载时间。

最后就是 CDN 和服务器，如果我没记错 MCBBS 之前的服务器用的是扬-州高防秒解，现在迁移了以后不清楚。
8 核 8G 是我之前通过拿自己的机器做对比测试得出的结果，实际上可能不止。
目前的配置可能是比之前高了，或者更换了 PHP 版本提升了执行效率，总体感觉比之前快了不少。

之前总是容易被别人攻击就挂掉，感觉还是服务器配置低了或者优化不好，之前我在半夜做过测试（也只是唯一的一次，一次没有恶意的测试），使用了 1024 线程 + 代理 CC 了一下，直接就 502 Bad Gateway 了，但是我用同样的线程数量攻击我自己的论坛，完全打不动，直到我把线程开到 8192 才打死，并且我的论坛是没有任何 CDN 防护的，纯靠单机硬扛 CC。不过我的 CPU 是 32 核 64 线程……所以抗打还是有原因的。

防御 CC 光靠 CDN 也是没用的，别人很容易绕过 CDN 直接攻击源站，具体原因可以看我的一篇文章：https://lo-li.cn/942
文章内容写的很详细，介绍了几种绕过网站 CDN 的方法，以及防御的方法。
CDN 顶多也就扛个 DDoS，缓存一下静态页面，如果别人 CC 动态页面，还是一样回源。而让数万 QPS 的包转发率进入后端，网站早死了。

最后也希望 MCBBS 继续发展，越做越好。
混乱和全体管理组，你们辛苦了。

嗯，关于插件和论坛优化，我有几个建议：

  • 在 SQL 查询方面，尽量做成连接复用，减少查询数量
  • 服务器 PHP 如果支持 Zend OPcache，可以考虑打开，这是一个高性能的缓存
  • 在储存临时用户数据时可以用 Redis，如果数据量大可以考虑上 Memcached
  • 公共前端资源 CDN 服务尽量选择可靠的，例如百度。360 的不良记录太多了不可信
  • 首页、帖子列表做静态化，推荐首页缓存时间 10 分钟，帖子列表缓存时间 5 分钟，帖子内容缓存 5 分钟。
  • 限制单 IP 搜索查询速率，重点防护搜索页面，通常 CC 攻击对于 Search 是致命的
