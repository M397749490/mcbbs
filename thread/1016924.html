它可以：区域禁止使用指令；检测禁止物品并做惩罚；检测禁止lore物品并做惩罚；禁止使用物品、方块；检测非法op并做惩罚；检测非法创造并做惩罚；地狱门卡玩家修复方案；禁止生成某生物；记录指令输出；禁止指定权限；可开关式指令配置[针对萌新啊喂！]；对于某个玩家可跳过以上安全措施。

支持Mods物品、生物，理论全支持。

可自定义检测惩罚指令，更自由，更方便！
实际上，这个插件结合了多个插件的功能。




功能
区域禁止使用指令：
以一个圆形形成的区域 或 以一块领地形成的区域 可设置在这些区域内禁用(禁止使用)某些指令。

检测禁止物品并做惩罚：
检测背包内是否存在某些物品，若检测到则执行config.yml设置的指令。

检测禁止lore物品并做惩罚：
检测背包内是否存在某些lore物品，若检测到则执行config.yml设置的指令。

禁止使用物品、方块：
禁止玩家右键使用某些物品、方块。如熔炉 兼容一部分Mods方块。

检测非法op并做惩罚：
若检测到非白名单的op则执行config.yml设置的指令。

检测非法创造并做惩罚：
若检测到非白名单的创造则执行config.yml设置的指令。

地狱门卡玩家修复方案：
因玩家可能被困地狱门，所以特此推出这个功能。假若检测到玩家卡在地狱门可在下次登录游戏时执行config.yml设置的指令。

权限节点黑名单:
禁止某项权限节点 例如众所周知的essentials.*

指令输出记录:
记录所有指令输出 例如玩家执行指令 菜单越权执行 后台执行等

禁止生成某生物：
禁止生成某些生物，让讨厌的生物去屎吧。

自定义处罚:
高度自定义每一项检测的处罚

*独立白名单：
假若进入这个白名单则检测不会对白名单用户进行。

重点！
可开关式指令配置！萌新专属！配置完务必关掉指令模式



*注：插件使用部分功能可能需要使用到 部分 前置插件、Mods。

教程:

*本教程仅适合指令用户 配置文件用户请查看配置文件注释进行修改 可参考指令教程

*黑名单生物 禁止指令 以及 地狱门修复 只能手动配置 以防出错

1 下载V1.1.0版本 拖入到服务端下plugin文件夹 重启服务器

2 开始配置

type类: op creative item lore use permission 依次代表 OP检测 创造检测 物品检测 物品Lore检测 方块使用检测 权限检测

   1.输入/tgss help查看指令帮助 并且确定指令加载

   2.添加白名单输入/tgss white list <type> ID 进行添加 添加op类默认添加所有白名单

      出现该字样则添加完成

 [后台内与游戏内显示略有不同]

   3.添加黑名单 即检测项 输入/tgss ban <type> 将手上物品添加至指定type类 这里的type类仅限于 item use

       输入/tgss ban <type> <path> 即可把指定<path>[path指需要封禁的项 比如权限]添加到指定type类

       实例/tgss ban permission essentials.* , /tgss ban lore &4我是封禁lore

   4.添加处罚项输入/tgss custom <name> <command> 此处的<name>指你要添加的处罚项名字 <command>即指令 可以添加多个指令

       实例/tgss custom opban ban %player% 涉嫌非法OP请联系管理员处理  即可添加一个名为opban的处罚类型

   5.为检测类添加处罚类 输入/tgss punish <type> <name> 此处的name指你上一步配置好的处罚类

       实例/tgss punish op opban 即为op检测类 添加一个名为opban的处罚类 当玩家获得非法OP自动指向opban处罚类内的指令

      *注:插件自带处罚 recovery 指回收非法物品

3.最后一步 也是最重要的一步！！ 输入/tgss switch 关闭指令模式！！！以获得最佳保护效果！





配置文件

  1. #是否开启指令模式 仅可以后台开启
  2. Command: true
  3. #是否开启指令记录模式 开启后所有指令都会在TGServerSecurity文件夹内的log.txt进行记录
  4. Log: true
  5. #处罚开关 可以开关每项的处罚是否启用
  6. PunishmentSwitch:
  7.   OPPunishmentSwitch: true
  8.   CreativePunishmentSwitch: true
  9.   ItemPunishmentSwitch: true
  10.   LorePunishmentSwitch: true
  11.   UsePunishmentSwitch: true
  12.   PermissionPunishmentSwitch: true
  13. #OP检测模式 模式1自动检测 模式2当玩家移动时检测
  14. Mode: 1
  15. #玩家被卡地狱门后重新上线执行的指令
  16. NetherCommand: spawn %player%
  17. #违规物品ID 填写数字ID
  18. Item:
  19. - 6666
  20. - 8888
  21. #违规lore
  22. Lore:
  23. - BanLore1.
  24. - BanLore2.
  25. #禁止使用的方块 填写英文名称 使用/itemdb进行查询
  26. Use:
  27. - BANBLOCKTYPE
  28. #被Bsn生物名称 填写英文名称 支持mod生物
  29. BanMobs:
  30. - Zombie
  31. #区域内禁止使用指定指令
  32. #格式- "世界名称:X,Y,Z:半径:指令:使用后的提示." XYZ代表圆心坐标
  33. LocBanCommands:
  34. - worldname:10,10,10:6:spawm:禁止使用 <command> 在这个区域.
  35. #指定领地禁止使用指令
  36. #格式:- "领地名称:指令:使用后的提示."
  37. LocResBanCommands:
  38. - name:spawn:在此区域禁止使用 <command> 这个指令
  39. #权限黑名单
  40. PermissionBlackList:
  41. - '*'
  42. #两种处罚customPunishment代表自定义处罚 recovery代表没收物品
  43. #独立处罚机制 customPunishment需要填写customPunishment配置的指令处罚
  44. OPPunishment: ban
  45. CreativePunishment: ban
  46. ItemPunishment: recovery
  47. LorePunishment: recovery
  48. UsePunishment: recovery
  49. PermissionPunishment: tempBan
  50. #独立的检测白名单
  51. #OP白名单
  52. WhiteListOP:
  53. - OPWhiteList
  54. #创造白名单
  55. WhiteListCreative:
  56. - CreativeWhiteList
  57. #违规物品白名单[让指定玩家拿到违规物品不会被处罚]
  58. ItemWhiteList:
  59. - ItemWhiteList
  60. #违规lore白名单[让指定玩家拿到违规lore物品不会被处罚]
  61. LoreWhiteList:
  62. - LoreWhiteList
  63. #非法物品白名单[让指定玩家可以使用非法物品不会被处罚]
  64. UseWhiteList:
  65. - UseWhiteList
  66. #禁止权限的白名单
  67. PermissionWhiteList:
  68. - PermissionWhiteList
  69. #执行CustomPunishment处罚执行的指令 兼容多命令 多处罚类型
  70. CustomPunishment:
  71.   ban:
  72.   - ban %player%
  73.   tempBan:
  74.   - tempban %player% 1h
  75. #执行recovery 处罚的提示
  76. RecoveryMessage: 物品 <item> 被回收.
